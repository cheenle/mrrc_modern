# Repository Guidelines

## Project Structure & Module Organization

This repository contains a Python FastAPI server for remote radio control (Yaesu FT-710 and Icom IC-7300/IC-7300MK2 via pluggable backends) plus a static browser UI. Core backend modules live at the repository root:

| Module | Responsibility |
| -------- | ---------------- |
| `server.py` | FastAPI app, auth, 6 WebSocket endpoints (`/WSradio`, `/WSspectrum`, `/WSaudioRX`, `/WSaudioTX`, optional `/WSatr1000`, `/WSterminal`), REST APIs, lifespan management; `/WSspectrum` negotiates a per-socket bandwidth tier from a `{"type":"spectrumCaps",…}` text frame and defaults to the byte-for-byte-legacy `high` tier until one arrives (`spectrum_profile.py`, AD-025); `/WSaudioRX`+`/WSaudioTX` negotiate a per-socket PCM16 profile from an `{"type":"audioCaps","profile":"pcm16"}` text frame (`audio_profile.py`, AD-038) — undeclared sockets keep the byte-for-byte legacy Opus48/PCM48 stream; RX splits listeners into legacy/PCM16/PCM48 groups with **one shared soxr LQ 48→16 conversion per tick** (PCM16-only skips Opus encode; conversion failure closes only the PCM16 group with 4004; PCM48 is the terminal's codec-free raw-PCM group — never Opus regardless of libopus availability), TX carries `input_rate` explicitly (`_feed_tx_from_uplink`/`_rec_tap_tx`/`feed_tx_audio`, default 48000 unchanged; only the `0x02` branch passes 16000) and a PCM16 conversion failure — bad rate, missing soxr, vanished handler — forces RX via `_force_rx_for_audio_error()` without closing the socket and without ever reading profile state; `/WSterminal` (AD-039, amended 2026-11-17) also consumes `audioCaps` but with **two raw-PCM names, `pcm48`/`pcm16`** (`parse_terminal_caps`; the dedicated endpoints' `parse_caps` stays pcm16-only): one declaration registers RX+TX together and answers **once** (`_terminal_audio_caps` — calling the per-direction handler twice would double-ack a firmware waiting for one), unknown names answer `unknown-profile`, PCM16 without a usable TX path answers `pcm16-tx-unsupported`, listen sockets register RX only, and `_terminal_disconnect` drops both per-socket profiles + retires the idle PCM16 converter **before its first await**; undeclared terminals keep the legacy stream so the `/terminal` reference page is unchanged; `_tx_session_decode_fail` counts Opus decode failures **and PCM16 conversion throws**; 每个终端 socket 的下行媒体走自己的有界队列（`TERMINAL_QUEUE_FRAMES=64`，扇出只 `put_nowait`、单 pump 写，慢消费者丢帧不丢 socket），`_TerminalMailbox` 记**音频毫秒**而不只是帧数（`audio_profile.frame_duration_ms()`）—— 断开时一行 `Terminal media losses` 回答「盒子丢的 / 链路丢的」，`Terminal audio over-rate` 回答「盒子产出的比电台多」（2026-11-20 手持端 68–84 帧/秒 vs 实时 50 只能被时长比值判出来，帧数在 pcm16/pcm48/Opus 三档下含义不同）；两个「卡住」是分开记的 —— `max pump stall` 是**一次写**卡了多久（在 `finally` 里结算，所以永不返回的那次也进账），`max queue wait` 是**帧在队列里等了多久**（pump 被饿）；2026-11-23 之前只统计已完成的写，于是一条被对端晾住的 socket（丢 40–96%）和一个健康 socket 在日志里一模一样；`_audio_rx_loop` 另按 `RX_LOOP_STATS_S`（60 s）打一行 `RX loop shape: … ms of audio per tick (real-time | QUANTIZED burst | backlog)`—— 「平均 50 帧/秒」既可能是 20 ms 一拍，也可能是每 100 ms 突发送 5 帧（2026-11-23 在健康 LAN 客户端上量到的正是后者：`MRRC_RX_BUFFER_MS` 的 100 ms 宿主缓冲 + `read_rx_chunk()` 一次要 4 块，把整个投递路径量化成了读的粒度），平均值永远看不出这个分别；**持键的 socket 在这一刻不收 RX 音频**（半双工：电台在发射，操作员听不到一个字节；而一条 TCP 上这条下行会抢设备 32 KB/s 的 PCM 上行 —— 2026-11-22 现场设备端 `esp_transport_write()` 阻塞 1 s、websocket 库把连接拆了，表现是「PTT 自己放开」而按键还按着 16.5 s；它不作为丢帧计数，因为电台本来就没产出音频）; TX uplink ownership follows the PTT client and is resolved per **socket**, never per token — a session token is a 30-day cookie, so one browser session can hold several `/WSaudioTX`sockets at once (a reload's half-open predecessor, two tabs of one login): the key-up claim takes the **last-connected** one (`_register_tx_socket` / `_forget_tx_socket`connect order), and a same-session socket that is actually streaming takes the uplink over on its first frame (`_same_session_uplink_takeover`), while a different session cannot steal it by connecting *or* by streaming; **PTT control-plane arbitration** (`_ptt_key_ws`, SDD §15 Layer 4b): while a client holds the key only its own release is honored — a foreign`ptt:false` is ignored and answered with the authoritative `tx_status` + `ptt_keyed_by_other`push (the sender's browser watchdog stands down), and a keyer disconnect forces RX even with other clients connected; spectrum loop schedules at 30 Hz and sends real scope data only when the frame counter advances; listen-only role (`MRRC_LISTEN_PASSWORD` → `_listen_tokens`,`/listen` page): server-side gate allows only freq/mode sets + memRecall on `/WSradio`, closes`/WSaudioTX`+`/WSatr1000` with 4003, and makes REST read-only (non-GET `/api/*` → 403)；电台电源（V2.86+）在 ☰ 菜单里分「重开电台…」（关机 + 有界可取消的持续唤醒，每轮复用 `_power_on_radio` 的 `PS1`≤3 + 回读校验）与「关机…」（只关机、绝不自发上电）两项，守卫：发射中（含 FT8）拒绝、`PS1` 后 15 s 窗口拒绝 `PS0`、`PS0` 双发、端口未连时不写；☰ 菜单页脚显示**正在跑的版本**；静态资源由 `serve_static` 按类型发 `Cache-Control`（HTML/JSON/`sw.js` 每次都重新校验、其余 1 小时，**刻意不写 `immutable`**：`?v=` 是手工 bump 的）并对 `If-None-Match`/`If-Modified-Since`回 304，有扩展名的缺失路径回 404（`/favicon.png` 以前会拿到 40 KB 的 `index.html`）——hub 边缘按同一套值加 gzip 与 1 小时缓存，见`../mrrc_hub/deploy/nginx/`）；**客户端集合（`ctrl_clients`/`atr_clients`/`audio_rx_clients`/`audio_tx_clients`/`spectrum_clients`/`_terminal_ws`）上的循环只要循环体里`await`，就必须迭代`list(…)`快照** —— 七个广播函数曾直接迭代活集合，`await`期间另一条协程的 add/discard 让迭代器失效（`RuntimeError: Set changed size during iteration`）：从`_on_scope_frame →_broadcast_state` 冒出去会**杀掉 scope 子进程**（瀑布冻结 1–2 s），从连接路径的 `_broadcast_client_count()` 冒出去会在 `try`之前打死新 socket 并**漏掉六处登记**（幽灵，永远不会被清理，2026-11-17 现场 143 次、终端 socket 30→32）；连接路径上的广播另外包 try/except，`tests/test_ws_terminal.py::ClientSetIterationGuardTests` 用 AST 钉住这条 |
| `cat_controller.py` | Compatibility shim — real module moved to `backends/ft710/cat_controller.py`: Serial CAT protocol (pyserial + asyncio.to_thread), 40+ command helpers |
| `radio_state.py` | `RadioState` dataclass with dirty-field change tracking and derived properties |
| `poll_scheduler.py` | 7-task adaptive background polling (100ms→5s) with skip-on-command, post-query stale-read discard, and a pre-broadcast staleness check (a frequency read taken before a user set must not be applied after it — the two read-time guards cannot see a set that lands while `MD0`/`SM0` are still queued behind the operator's writes; field 2026-11-26, AD-009 amendment); watchdog re-runs scope init (`on_reconnected`) after serial reconnect |
| `audio_handler.py` | PyAudio sound card capture/playback with per-backend device rate and name hints (FT-710: fixed 44.1kHz with 960→882 resample before TX; IC-7300: 48kHz native, no resample), Opus encode, radio USB-audio auto-detection (FT-710/YAESU name, "USB Audio CODEC"/"USB Audio Device" Windows names, mono/full-duplex heuristics); an explicit choice is honoured and warned about, and `/api/devices` marks each entry with `loopback` so the picker can say 「电脑自带，非电台」; the -9999 retry path now distinguishes "device missing" from "device present but just failed to open", and does so **only after closing both live streams under a lifecycle lock** (`_reinit_pyaudio()` terminating under a live RX read is a native access violation that kills the process with no traceback, leaving a keyed radio with nobody to send TX0 — 2026-10-16); | `audio_profile.py` | Per-audio-socket PCM profile contract (AD-038 + AD-039 terminal amendment): `PROFILE_LEGACY`/`PROFILE_PCM16`/`PROFILE_PCM48`, `PCM16_RATE=16000` / `PCM16_FRAME_MS=20` / `PCM16_FRAME_BYTES=640`, `PCM48_RATE=48000` / `PCM48_FRAME_BYTES=1920`（名义 20 ms，追赶 tick 可连发多块，与旧 PCM 回退同形）, `AUDIO_TAG_PCM16=0x02`, `parse_caps()`（只认 `{"type":"audioCaps","profile":"pcm16"}`，其余一律 None、永不抛）供专用音频端点；`parse_terminal_caps()`（只认 `pcm48`/`pcm16`）供 `/WSterminal` —— 放宽终端解析绝不放宽专用端点；`accepted_caps(profile=pcm16)`/`rejected_caps(reason, profile=pcm16)`（默认参数保持旧调用形状）；`OPUS_FRAME_MS=20` + `frame_duration_ms(frame)` —— 把一帧（`tag+body`）换算成音频毫秒，供 `/WSterminal` 的每会话度量用（PCM16 恒 20 ms、PCM48 是可变长样本流、Opus 变字节不变时长，所以只有时长在三个档位间可比；`opus_rx` 反过来 import 本模块，故 Opus 节拍在这里重复一次并由测试钉住相等）。纯标准库、零应用 import —— 与 `spectrum_profile.py`（AD-025）同形，可独立单测、可热修。`0x00`/`0x01` 永远表示 48 kHz，绝不按连接重新解释 |
| `audio_resample.py` | 44.1kHz ↔ 48kHz frame-aligned SRC (numpy linear interp; 882↔960 = 20ms) — legacy 路径一字未动；另有 AD-038 的 `StreamingPcmResampler`（soxr `ResampleStream`，**LQ 强制**：QQ 实测把 12 kHz 满幅混叠进带内，RMS 0.707 vs LQ 0.000366；有状态跨块、奇数字节尾样本保留、`reset()` 重建）与 `Pcm16RxEncoder`（共享 48→16 转换 + 完整 641 B `0x02` 分帧；`push()` 返回变长列表——预卷积期为空、追赶期一拍多帧，长度不是 tick 数） |
| `opus_rx.py` | libopus ctypes wrapper: `RxOpusEncoder` (48kHz), `TxOpusDecoder` (48kHz)；从 `audio_profile` 再导出 `AUDIO_TAG_PCM16`，三个标签一处导入 |
| `recorder.py` | Server-side QSO recording (AD-017): `RecordingSession` = 16 kHz mono timeline (monotonic timestamps, 50 ms jitter tolerance, silence gap fill, incremental lameenc MP3 with per-block `flush()`), `_StreamingDecimator` (96-tap FIR 48k→16k), mrrc-compatible naming `<freq>kHz_<date>_<time>.mp3` and `recordings.json` index helpers. `server.py` owns the single writer, which is one-shot per session by design — `_ensure_rec_writer()` recreates it for every session (start / block / stop), because a boot-only writer silently dropped every block of every later recording (2026-09-12 field report: correctly-sized, 100 % silent MP3s); a full queue is the only drop path, and a stop is queued, never run on the event loop **16 kHz is a storage domain, not the codec/device domain** — 44.1k→48k goes through `audio_resample`, nothing here re-enters the audio path |
| `cq_player.py` | One-touch CQ call (AD-020): WAV parse → 48 kHz mono normalise → 20 ms frames, fed to the existing TX queue only while the device queue is shallow (`CQ_LOW_WATER_FRAMES`, so a call never manufactures `queue_drops`); one call per press, abortable; key/unkey/broadcast callbacks are injected by `server.py` so the module stays hardware-free. `server.py` checks the TX gate before the asset, drops browser mic frames while calling (`_tx_cq_mic_drops`), refuses PTT/TUNE, aborts when the initiating client or the last client disconnects, and warns at startup when the asset is unusable |
| `support_bundle.py` | Support diagnostics bundle (AD-021): key-allow-listed config redaction + secret-value pass, bounded/log-aligned log tails with a 512 KB/128 KB degradation ladder, auto-triage `summary.txt` matching this repo's real log lines, version detection (`version.txt` → `.iss` → CHANGELOG) and zip assembly with per-file SHA-256, newest-5 retention; also collects the DSP worker's own `ft8-worker.log` (+`.1`) — the only place a Fortran `stop`/`error stop` in the decoder survives, since the launcher's startup tee stops writing to a file once the server answers HTTP (2026-10-16). **Two log directories on a box**: the app's own (`server.log`, `ft8-worker.log` under `~/.local/share/MRRC-Modern/logs`) and the install dir, where systemd appends stdout/stderr (`$MRRC_HOME/logs/server-stdout.log`). Only the second carries a **traceback raised off the event loop** (a `threading.Timer` callback, a worker thread), and until 2026-11-16 the resolver never looked there — so a box bundle could be missing the one file the answer lived in while `summary.txt` said 「无崩溃痕迹」 (bundle `20261116-000702-36fa`: `Exception in thread Thread-2` was in the tee, not in `server.log`). Stdlib only and no app imports, so it stays unit-testable and hot-fixable |
| `launcher_log.py` | Startup tee: drains the child's stdout/stderr into `logs/server-stdout.log` during the startup window (the only witness of a server that dies before its own logging exists), then keeps draining without writing so a chatty server can never block on a full 64 KB pipe; echoes to the console as before |
| `help_session.py` | The customer's 「远程协助」 window (customer docs: `docs/remote_help.md`): a paramiko SSH door that binds **loopback only** (`127.0.0.1:0`), one fresh credential pair per window, password-only (a public key would be a passwordless backdoor), 3-hour ceiling, no auto-renew, and the single close path (`close(reason)` — user / expired / portal / auth_failures). The hub never sees the password: `ssh hub -W 127.0.0.1:port` is a plain TCP relay, so the SSH protocol runs end to end between the supporter's machine and the instance. **`PIPE_SHELL = (os.name == "nt")`** — Windows has no `pty`/`fcntl`/`termios`, and until 2026-11-12 the pty path's `import fcntl` raised *before* a shell existed while paramiko had already answered the shell request: every Windows help window authenticated, answered the exec probe, and then said nothing at all (first Windows instance behind the Cloud Hub, BG7YQV). | `spectrum_profile.py` | Spectrum bandwidth tiers (AD-025): a profile is **two orthogonal factors** — frame `shape` (`full` = `0x01`+wf1+wf2 = 1701 B, `wf1` = `0x01`+wf1 = 851 B) × broadcast-tick `divider` — bundled into named presets `high`/`mid`/`low` plus the server-internal `listen`. The short frame is a **slice** of the full one (`full[:851]`), so `scope_handler` and the 11 backends are untouched and there is no second framing path to drift. Also owns `parse_caps()` for the `{"type":"spectrumCaps","profile":…}` whitelist. Compatibility is a server-side gate, not a client upgrade: a socket that never declares stays on `high`, byte-for-byte the pre-AD-025 stream — the shipped Android parser hard-rejects any length that is not 1701 (`SpectrumFrame.kt:14-15`). Stdlib only, no app imports |
| `net_bt.py` | Bluetooth pairing for the remote, and **the only code that talks to bluez** (stdlib only, every call takes an injectable runner, so the tests need neither a controller nor root). Serves the `/settings` panel — scan (BR/EDR inquiry, ~12 s), pair, forget — because a customer has no SSH. ## Tooling Guards (do not remove)

Two legacy frontend files — `static/ft710_main.js` and `static/ft710_ui.js` — must not be
reformatted or "autofixed" by tooling:

- They are tab-indented with double quotes, while `biome.json` configures 4-space/single-quote
  for the rest of the project. Letting biome format them rewrites ~3200 lines for no behavior
  change (and breaks the whitespace-sensitive frontend contract tests in
  `tests/test_server_ws_protocol.py`).
- Their top-level names (`radioCapabilities`, `AUDIO_TAG_PCM`, `RX_RECORDER_MIME`, …) are
  **cross-file globals** (classic `<script>` files, read from the other file). A single-file
  "unused variable" analysis calls them unused and renames them with a leading underscore —
  which silently breaks the capability-driven UI in the browser, invisible to the Python suite.

Guards in place (both verified against biome 2.5.6, the binary pi-lens runs):

| File | Guard |
| --- | --- |
| `biome.json` | `overrides` for both files: `formatter.enabled=false` plus the six rules whose autofixes mutate them (`noUnusedVariables`, `noUnusedFunctionParameters`, `noInnerDeclarations`, `useParseIntRadix`, `useTemplate`, `useOptionalChain`, `noGlobalIsNan`) turned off — verified: even a direct `biome check --write --unsafe` leaves both files byte-identical |
| `.pi-lens.json` | `ignore` for both files, so no diagnostic/autofix dispatch touches them |

Important: `biome.json` must stay **strict JSON** — a comment makes this biome fall back to its
built-in defaults (2-space/double-quote) and reformat every file it touches. Keep the rationale
here instead. If those two files ever come back dirty with tab→space or `catch (e)` → `catch (_e)`
churn, `git checkout -- static/ft710_main.js static/ft710_ui.js`.

## FT8 模式（feat/ft8）铁律

- **`os.environ.setdefault("OMP_STACKSIZE", "10M")` 必须在导入 NumPy / 加载
  `libwsjt_core` 之前执行**（见 `ft8/core/worker.py` 的 worker 入口与
  `tests/ft8/dsp/conftest.py`）。WSJT-X Improved 的 `sync8var` 在线程栈上分配大型工作数组，
  栈不足的表现是段错误而不是异常——所以这条契约由测试盯住，不能"顺手"挪动。
  **`OMP_STACKSIZE` 只覆盖 OpenMP 工作线程**：解码是从**请求循环所在的那个线程**进入的，
  所以 `worker_main` 把整个请求循环放在一个显式设过大栈的线程上（`WORKER_STACK_BYTES = 64 MB`
  与 `_run_with_large_stack()`）。`sync8var` 单帧要 ≈4.1 MB（`s(NH1,NHSYM)` = 1920×372×4 ≈ 2.7 MB，
  加 `sync2d`/`syncq` 的 ±62 dt 窗口 ~1.2 MB），而 Windows 给线程的 PE 预留是 **2 MB** ——
  溢出是当场静默消失（`worker_exit … status None`，没有任何 Fortran 提示）。本机子进程实测：
  2/3 MB 栈 → SIGBUS，4/8/64 MB → 存活。把 while 循环挪回 `worker_main` 的语句体会让这条失效，
  `tests/ft8/core/test_worker.py` 的结构化断言就是盯这个的。
- **`ALLCALL7.TXT` 必须进包，并且 worker 要把 cwd 挪到它所在的目录**：Fortran 用
  `share_dir = '.'`（`ft8/dsp/vendor/prog_args.f90:4`）**相对 cwd** 打开呼号库，且没有 setter。
  源码 checkout 的 cwd 正好是仓库根，所以本地永远看不见；装好之后 cwd 是启动器所在目录，
  呼号库静默变空（`ldbvalid = .false.`，日志只有一句 `ALLCALL7.TXT is too short or broken?`）。
  打包侧由 `packaging/pyinstaller/mrrc_modern_server.spec` 把它收到 `_internal` 根，
  运行侧由 `ft8.core.worker.share_dir()` + `worker_main` 的 `os.chdir()` 保证。
  守卫：`tests/test_ft8_packaging.py::CallSignDatabaseTests`。
- **DSP 原生代码永远不得终止宿主进程**：`ft8/dsp/` 里的 Fortran `stop` / `error stop` 会当场杀掉
  DSP worker（它是服务器进程的 spawn 子进程）。`wsjt_improved.f90` 的 FFTW 线程初始化已从
  `error stop` 改为返回 `WSJT_E_INTERNAL`（2026-10-16，现场每槽一次 `worker_exit` 的元凶）；
  `patched/four2avar.f90` 与 `vendor/packjt.f90` 两处 `stop` 仍在。**worker 自己的 fd 1/2 由
  `worker_main` 的 `_redirect_worker_output()` 落到 `$MRRC_LOG_DIR/ft8-worker.log`**（超 2 MB 轮转）——
  launcher 的启动 tee 在服务器答 HTTP 后就不再写盘，这是唯一能看到子进程原生死亡信息的地方；
  `support_bundle` 收集它。
- DSP 源在 `ft8/dsp/`：编译子集 `vendor/`（由 `tools/ft8/extract_wsjtx_subset.sh`
  从 CMake 清单派生）、7 个补丁副本 `patched/`、原始基线 `vendor-refs/`；
  `build.sh` 幂等构建 `ft8/dsp/build/libwsjt_core.*`（设备上原生编译）。
- 移植自 MRRC-FT8（`HAM/ft8`）：`ft8/{core,engine}` 保持 verbatim，平台耦合只允许在
  `ft8/platform/`、`ft8/web/`、`ft8/mode.py` 与 `server.py` 的接线处。
- **RX tap 的时间轴会在采集中断后重新锚定（`RESYNC_AFTER_S` = 0.5 s）**：`ft8/platform/rx_tap.py`
  的 12 kHz 环只在**第一个**块上锚定 epoch，之后只按已投递样本数前进 —— 采集一旦停
  （USB 重枚举、TX 后的 `restart_rx()`、ALSA 卡死），它就永久落后墙钟，而时隙网格由墙钟
  派生，于是每一槽都是 `SKIPPED (no data within grace)`（2026-10-17 现场：113 s 中断 →
  `drift=+118 s` → `slots_skipped` 66/67、`decodes=0`）。`feed()` 现在拿调用方本来就传的块
  epoch 与自身时间轴比，超阈值就重锚并且 `UtcRing` 把空洞记成 gap。同时**采集停滞的恢复
  不能只认浏览器**：`_audio_rx_loop` 的恢复门是「有人在用这段音频」（浏览器 / FT8 tap /
  录音）—— FT8 页面从不订阅 `/WSaudioRX`，只认 `audio_rx_clients` 会让解码器无限期饿死。
- **解码默认走快路径，按需级联到深路径**：`ft8/dsp/wsjt_fast.c` 是 `kgoba/ft8_lib`
  （C、kiss-fft）编进**同一个** `libwsjt_core` 的 `wsjt_ft8_decode_fast`（无 AP / 无 OSD /
  单趟，全部取上游默认旋钮 —— 降旋钮只换走弱信号鲁棒性，见
  `docs/ft8-w103d-decode-perf-analysis.md` §9 的 A53 spike）；
  `ft8/engine/cascade.py` 的 `CascadingDecoder` 在命中升级判据（AP 上下文 / 疑似漏解 /
  用户显式请求）时对**同一时隙**补跑深路径并合并两批（`merge_batches`：键
  `(frequency, dt)` 带容差、deep 胜出），预算不足则**宁可不升级**（计 `deadline_risk`），
  快路径整个失败时回落 improved —— **绝不少解码**。计数在 `orchestrator.counters` 的
  `fast_decodes`/`escalations` 与 `runtime.cascade_stats`。
- **原生库是四个平台各自构建出来的**，不是仓库里的一份二进制：两条镜像线在镜像构建期
  就地编译（`packaging/common/mrrc-service-layer.sh`，工具链来自 `packages.txt`；`linux/mrrc_update.sh`
  按源码摘要重编，**失败不阻断升级**），macOS 由 `packaging/macos/ft8_bundle.py` 连 5 个依赖一起
  收进 app（load command 全改 `@loader_path`，构建前硬门禁），Windows 用 MSYS2 MinGW 编译并把
  运行期 DLL 闭包（走 objdump 走出来）一起进包。**改了 `ft8/dsp/` 就要重跑这四条路径。**
  Boost 不再需要安装：`<boost/crc.hpp>` 的包含闭包 vendored 在 `ft8/dsp/vendor-boost/`
  （`tools/ft8/vendor_boost_headers.sh` + `tests/ft8/dsp/test_vendor_boost_policy.py`）。

## Security & Configuration Tips

Never commit passwords, serial-device paths, or local driver assumptions. Use environment variables for deployment-specific values. All WebSocket endpoints require a session token, resolved by `_token_from_ws_handshake()` as `Authorization: Bearer` → `mrrc_auth` cookie → deprecated `?token=` query param (AD-024). The browser sends the cookie automatically on the same-origin handshake, so the frontend never builds a token URL (a 30-day credential in a URL lands in access logs, browser history and Referer). Auth tokens are **persisted** in `data/auth-tokens.json` (0600, 30-day lifetime, atomic write) so a routine upgrade restart does not log every session out; the store is runtime state and never committed. Transmit safety: every release path keys off a disconnect, so a connection that dies without a TCP close (dropped NAT, Wi-Fi switch) needs `MRRC_REMOTE_SESSION_TX_HEARTBEAT_S` (default 0 = off; the cloud hub enables it). Only sessions that send `txhb` are gated, and only the session holding the key can be released (ch15 §15.6). While transmitting, **an uplink audio frame from the keying socket also counts as liveness** (2026-11-19): `txhb` shares one socket with 50 frames/s of PCM, so on a congested link the heartbeat is the packet that loses, and a device that was demonstrably sending audio got unkeyed at key-up + 5 s seven times on box BA4EG. A session that dies without a TCP close delivers neither audio nor heartbeats, so the release still fires there; streaming never *declares* capability (a client that never sent `txhb` stays ungated). `_schedule_restart()` (config save / cloud-certificate restart) releases PTT on the running loop before `os._exit(42)`, which would otherwise skip the lifespan Force-RX.

**侦听地址约定**：真实安装 / 现场机器的 `MRRC_WEB_HOST` 一律用 **`0.0.0.0`**（所有接口）—— 这也是随包默认值、`config.py` 的 `::` 与 SDD/12 "Uvicorn on 0.0.0.0:8888" 三处一致的意图，因为这个界面本来就要能从手机或局域网另一台机器打开。Windows 曾经只在模板里写 `127.0.0.1`，与另外两个平台相反，现场表现为「文档说能局域网访问、实际连不上」（2026-10-03 实测，并已由 `tests/test_listen_default.py` 盯住）。**例外：隔离的验收 / 洁净室测试**显式写 `127.0.0.1`，那是为了让测试实例不被网络碰到，不是发货默认值。代价必须知道：所有接口时 Web 口令是唯一一道门，而这个应用能按下发射键。

## Cloud Hub（多实例远程接入）上下文

本仓同时充当「实例侧」，可被置于云端入口之后运行。改动时注意：

- **前缀安全**：入口可能是 `<呼号>.mrrc.vlsc.net`（根路径）或 `www.vlsc.net/mrrc_modern/<呼号>/`（路径前缀），
  因此新增资源/请求必须前缀安全 —— 断言规则见 `tests/test_path_prefix.py`（文档资源相对、`sw.js` 预缓存绝对）
- **令牌不进 URL**（AD-024）：新增接口用 cookie / Bearer，不要用 query 传令牌
- **隧道状态必须可见**：`/api/cloud/state` 的 `tunnel_running` / `tunnel_error` 是这一节唯一的自证通道。
  缺 `fleet/frpc` 或 `fleet/frpc-<label>.toml` 时 `_cloud_start_tunnel()` **不得**静默 `return`
  （要点名缺失路径，并按内容去重只警告一次）；页面也不得用一个“已接通”绿标代替隧道状态
  （2026-10-22：`bh7kyz` 入口 502 四天，盒子设置页写着“已接通”）
- **新增会话级行为请打点**：Hub 侧的容量决策（如 RX 扇出 AD-H12）依赖 `session_metrics`
- **env 文件里一个键只能出现一次**：读者（`env_store.parse_env_text` 与 systemd 的
  `EnvironmentFile`）都是**后者胜**，而写入器只改第一个匹配行 —— 2026-10-26 现场
  （W103D + IC-7300，`20261026-194408-16d0`）就是 `MRRC_SERIAL_PORT` 后置了一条空行，
  于是「连接设置」保存 6 次全部无效、CI-V 26 天没打开过端口。现在：写入器把命中的键收成一行、
  `config.py` 启动时自愈（空值表示「没设」而不是覆盖，并让本次启动即生效）、
  `POST /api/setup` 写后回读不一致就 500 且不重启。空端口会在启动日志里点名，
  IC-7300 后端失败时也打印 `Available serial ports:`。
- **PTT 改动必须双防线**：`MRRC_REMOTE_SESSION_TX_HEARTBEAT_S`（活性闸门，`txhb` 或**持键 socket 的上行音频帧**都算活着）与 `MRRC_PTT_MAX_TX_SECONDS`（时长上限）
- **Hub 端文档**：设计记录 `../mrrc_hub/SDD/`（实况 §12.8）、部署与证书 `../mrrc_hub/deploy/README.md`
- **勿动**：`atr1000_tuner.json`、`mem_channels.json`、`website/js/global-nav.js`（用户运行期文件，未提交）
