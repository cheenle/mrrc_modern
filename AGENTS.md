# Repository Guidelines

## Project Structure & Module Organization

This repository contains a Python FastAPI server for remote radio control (Yaesu FT-710 and Icom IC-7300/IC-7300MK2 via pluggable backends) plus a static browser UI. Core backend modules live at the repository root:

| Module | Responsibility |
| -------- | ---------------- |
| `server.py` | FastAPI app, auth, 5 WebSocket endpoints (`/WSradio`, `/WSspectrum`, `/WSaudioRX`, `/WSaudioTX`, optional `/WSatr1000`), REST APIs, lifespan management; `/WSspectrum` negotiates a per-socket bandwidth tier from a `{"type":"spectrumCaps",…}` text frame and defaults to the byte-for-byte-legacy `high` tier until one arrives (`spectrum_profile.py`, AD-025); TX uplink ownership follows the PTT client and is resolved per **socket**, never per token — a session token is a 30-day cookie, so one browser session can hold several `/WSaudioTX` sockets at once (a reload's half-open predecessor, two tabs of one login): the key-up claim takes the **last-connected** one (`_register_tx_socket` / `_forget_tx_socket` connect order), and a same-session socket that is actually streaming takes the uplink over on its first frame (`_same_session_uplink_takeover`), while a different session cannot steal it by connecting *or* by streaming; **PTT control-plane arbitration** (`_ptt_key_ws`, SDD §15 Layer 4b): while a client holds the key only its own release is honored — a foreign `ptt:false` is ignored and answered with the authoritative `tx_status` + `ptt_keyed_by_other` push (the sender's browser watchdog stands down), and a keyer disconnect forces RX even with other clients connected; spectrum loop schedules at 30 Hz and sends real scope data only when the frame counter advances; listen-only role (`MRRC_LISTEN_PASSWORD` → `_listen_tokens`, `/listen` page): server-side gate allows only freq/mode sets + memRecall on `/WSradio`, closes `/WSaudioTX`+`/WSatr1000` with 4003, and makes REST read-only (non-GET `/api/*` → 403)；电台电源（V2.86+）在 ☰ 菜单里分「重开电台…」（关机 + 有界可取消的持续唤醒，每轮复用 `_power_on_radio` 的 `PS1`≤3 + 回读校验）与「关机…」（只关机、绝不自发上电）两项，守卫：发射中（含 FT8）拒绝、`PS1` 后 15 s 窗口拒绝 `PS0`、`PS0` 双发、端口未连时不写；☰ 菜单页脚显示**正在跑的版本**；静态资源由 `serve_static` 按类型发 `Cache-Control`（HTML/JSON/`sw.js` 每次都重新校验、其余 1 小时，**刻意不写 `immutable`**：`?v=` 是手工 bump 的）并对 `If-None-Match`/`If-Modified-Since` 回 304，有扩展名的缺失路径回 404（`/favicon.png` 以前会拿到 40 KB 的 `index.html`）——hub 边缘按同一套值加 gzip 与 1 小时缓存，见 `../mrrc_hub/deploy/nginx/`） |
| `cat_controller.py` | Compatibility shim — real module moved to `backends/ft710/cat_controller.py`: Serial CAT protocol (pyserial + asyncio.to_thread), 40+ command helpers |
| `radio_state.py` | `RadioState` dataclass with dirty-field change tracking and derived properties |
| `poll_scheduler.py` | 7-task adaptive background polling (100ms→5s) with skip-on-command and post-query stale-read discard; watchdog re-runs scope init (`on_reconnected`) after serial reconnect |
| `audio_handler.py` | PyAudio sound card capture/playback with per-backend device rate and name hints (FT-710: fixed 44.1kHz with 960→882 resample before TX; IC-7300: 48kHz native, no resample), Opus encode, radio USB-audio auto-detection (FT-710/YAESU name, "USB Audio CODEC"/"USB Audio Device" Windows names, mono/full-duplex heuristics); startup/open logs include host API plus default/actual rates and channels; TX session stats include oldest-frame `queue_drops`; `restart_rx()` reopens RX capture on every TX→RX transition (full-duplex codec recovery); on TX/RX stream-open failure re-initializes PortAudio once and retries with a name-resolved index (USB re-enumeration on radio power cycles invalidates cached device IDs — macOS -9999), and does so **only after closing both live streams under a lifecycle lock** (`_reinit_pyaudio()` terminating under a live RX read is a native access violation that kills the process with no traceback, leaving a keyed radio with nobody to send TX0 — 2026-10-16); `read_rx_chunk()` takes that lock non-blockingly so a rebuild never blocks the event loop |
| `audio_resample.py` | 44.1kHz ↔ 48kHz frame-aligned SRC (numpy linear interp; 882↔960 = 20ms) |
| `opus_rx.py` | libopus ctypes wrapper: `RxOpusEncoder` (48kHz), `TxOpusDecoder` (48kHz) |
| `recorder.py` | Server-side QSO recording (AD-017): `RecordingSession` = 16 kHz mono timeline (monotonic timestamps, 50 ms jitter tolerance, silence gap fill, incremental lameenc MP3 with per-block `flush()`), `_StreamingDecimator` (96-tap FIR 48k→16k), mrrc-compatible naming `<freq>kHz_<date>_<time>.mp3` and `recordings.json` index helpers. `server.py` owns the single writer, which is one-shot per session by design — `_ensure_rec_writer()` recreates it for every session (start / block / stop), because a boot-only writer silently dropped every block of every later recording (2026-09-12 field report: correctly-sized, 100 % silent MP3s); a full queue is the only drop path, and a stop is queued, never run on the event loop **16 kHz is a storage domain, not the codec/device domain** — 44.1k→48k goes through `audio_resample`, nothing here re-enters the audio path |
| `cq_player.py` | One-touch CQ call (AD-020): WAV parse → 48 kHz mono normalise → 20 ms frames, fed to the existing TX queue only while the device queue is shallow (`CQ_LOW_WATER_FRAMES`, so a call never manufactures `queue_drops`); one call per press, abortable; key/unkey/broadcast callbacks are injected by `server.py` so the module stays hardware-free. `server.py` checks the TX gate before the asset, drops browser mic frames while calling (`_tx_cq_mic_drops`), refuses PTT/TUNE, aborts when the initiating client or the last client disconnects, and warns at startup when the asset is unusable |
| `support_bundle.py` | Support diagnostics bundle (AD-021): key-allow-listed config redaction + secret-value pass, bounded/log-aligned log tails with a 512 KB/128 KB degradation ladder, auto-triage `summary.txt` matching this repo's real log lines, version detection (`version.txt` → `.iss` → CHANGELOG) and zip assembly with per-file SHA-256, newest-5 retention; also collects the DSP worker's own `ft8-worker.log` (+`.1`) — the only place a Fortran `stop`/`error stop` in the decoder survives, since the launcher's startup tee stops writing to a file once the server answers HTTP (2026-10-16). Stdlib only and no app imports, so it stays unit-testable and hot-fixable |
| `launcher_log.py` | Startup tee: drains the child's stdout/stderr into `logs/server-stdout.log` during the startup window (the only witness of a server that dies before its own logging exists), then keeps draining without writing so a chatty server can never block on a full 64 KB pipe; echoes to the console as before |
| `net_tls.py` | Outbound TLS trust — **the one place that decides whom our own HTTPS calls trust, and it never silently defers to the machine** (`MRRC_CA_BUNDLE` → shipped `vendor/ca/cacert.pem`; the platform store is a last-resort fallback with a warning). History: 2026-10-04 (macOS bundle inherited the build host's OpenSSL, whose compiled-in CA path `/opt/local/...` exists nowhere else ⇒ empty store ⇒ portal / 🐞 upload / update check all failed `CERTIFICATE_VERIFY_FAILED`) and 2026-10-16 (a Windows store held an *expired, same-name, same-key* copy of a chain element; OpenSSL built the chain through it ⇒ `certificate has expired` while the browser was fine). Both are one defect — outsourcing the verdict to the machine — so the policy is now "our bundle only", and `tests/test_tls_trust_store.py` reproduces the poisoned store offline with a real handshake (negative control included). `urlopen()` is the single entry point for every outbound request (an AST test keeps new call sites on it). Build gate: `dev_tools/tls_trust_gate.py` empties the CA environment on purpose and requires a live handshake |
| `upgrade_core.py` / `dev_tools/make_latest_json.py` | Update channel, slice 1 (AD-022): manifest fetch/validate/compare, the `state.json` schema that makes an upgrade **provable** (only the new version's boot may write `ok`), and the manifest generator whose size/SHA-256 come from the artifacts themselves. Read-only: `GET /api/update/check`. Slice 2 (download → verify → PTT gate → installer → self-proof) is deliberately not started. The **box line** is versioned independently (`latest.json` → `boxLine`, since 2026-10-19) and carries a **display-only fix-pack number** (`boxLine.fixpack` = `FP1`, `FP2`…: global, incremented with every box fix delivery, never reused, allowed to skip) shown as `version · FPn` in the update card and the menu footer. It is **never** an input to `compare_versions()` — the field boxes' parser only understands three-part versions, so folding it into the version (`1.28.5.1`) makes the release invisible to them. `CHANGELOG`'s `## [镜像线 vX.Y.Z · FPn]` heading is where both values are read from (`make_box_source.version_of()`), and `tests/test_release_artifacts.py::BoxLineFixPackTests` keeps that heading and the published manifest in step |
| `spectrum_profile.py` | Spectrum bandwidth tiers (AD-025): a profile is **two orthogonal factors** — frame `shape` (`full` = `0x01`+wf1+wf2 = 1701 B, `wf1` = `0x01`+wf1 = 851 B) × broadcast-tick `divider` — bundled into named presets `high`/`mid`/`low` plus the server-internal `listen`. The short frame is a **slice** of the full one (`full[:851]`), so `scope_handler` and the 11 backends are untouched and there is no second framing path to drift. Also owns `parse_caps()` for the `{"type":"spectrumCaps","profile":…}` whitelist. Compatibility is a server-side gate, not a client upgrade: a socket that never declares stays on `high`, byte-for-byte the pre-AD-025 stream — the shipped Android parser hard-rejects any length that is not 1701 (`SpectrumFrame.kt:14-15`). Stdlib only, no app imports |
| `net_bt.py` | Bluetooth pairing for the remote, and **the only code that talks to bluez** (stdlib only, every call takes an injectable runner, so the tests need neither a controller nor root). Serves the `/settings` panel — scan (BR/EDR inquiry, ~12 s), pair, forget — because a customer has no SSH. The verdict it returns is **`keys_work`** (a keyboard input device from that address exists in `/proc/bus/input/devices`), not bluez's ``Paired: yes``: the measured trap is a remote that reports paired and bonded while the link stayed unencrypted, in which case `hog` never builds the device and every key is dead (`docs/W103D_REMOTE_GUIDE.md` §2). The page acts on that field and offers 重配 (remove + controller power-cycle) when it is false. |
| `local_speaker.py` | Local speaker tap (AD-028): the radio's RX audio on a device beside the box — a Bluetooth headset standing next to the radio is the operator's ears when nobody has a browser open. Taps the same 48 kHz mono PCM the browser path encodes, decimates it to the device rate (a SCO link is 8 kHz mono; A2DP takes 48 kHz stereo, so each sample is duplicated) and plays it through an `aplay` child — a Bluetooth device is addressed by an **ALSA PCM name** (`bluealsa:SRV=…,PROFILE=a2dp`), which PortAudio cannot reach. Bounded queue, drops and counts instead of blocking, respawns a dead child with a 1 s backoff and **one** warning per streak (a per-frame warning flooded the log at 20 Hz until it was fixed). `MRRC_LOCAL_SPEAKER_DEVICE`/`_RATE`/`_CHANNELS`, off by default; the RX loop's idle gate counts it as a listener. Measured on the W103D: A2DP plays RX audio fine, **HFP/SCO carries no data in either direction** (the controller advertises SCO support, the board does not wire the voice path), so a headset microphone cannot be used — the local TX source must be a USB microphone. |
| `audio_levels.py` | Box-level audio gains (AD-032): the two numbers the box owns — `tx_mic_db` (−20…+25 dB, applied in `_feed_tx_from_uplink` and **only** to the browser mic; CQ playback and the FT8 waveform never pass through it, and the TX recording tap sits after the gain so a recording is what the radio was actually given) and `rx_db` (−20…+30 dB, applied to the copy encoded for listeners; the recording tap, the FT8 decoder and a local speaker all take the capture unmodified, because a software gain cannot add information and clipping them corrupts a decode). **0 dB returns the caller's own bytes object** — the default stream is byte-for-byte the pre-feature one, which is why no other client had to change; the price is that the box RX level multiplies with each browser's 🔊 boost, and the card says so. A bad value is **refused (400 + the range), never clamped** (a hand-edited file is the one exception, clamped with a warning); the JSON store is atomic and never fatal. Clipping is counted per direction and warned about at most once per 30 s. `GET/POST /api/audio/levels`, `fullState.audioLevels` and the `audioLevels` push carry **one shape**. Surfaced in the ☰ menu (two dB sliders, `slider-txdb`/`slider-rxdb`), the `settings.html` 「音频电平」 card, and the browser mic trim (🎙 Vol, now −20…+25 dB instead of 2×). Stdlib + numpy, no app imports |
| `local_ctl.py` | Local control surface (AD-028): a Bluetooth HID remote driving the radio on-box — the operator stands next to it with no browser. Reads `/dev/input/eventN`, keys on the **HID usage** from `MSC_SCAN` (three buttons on the measured remote all report keycode 240 = `KEY_UNKNOWN`), and writes one JSON line per command to the server's local control socket (`/run/mrrc/localctl.sock`, 0600, same user — the permission is the authentication; routing a physical button through the web login tripped the 5-per-5-minutes guard). Pure logic (event decoding, `KeyMap`, `NumericEntry` kHz entry, in-band frequency wrap, PTT edge semantics) split from I/O so it tests without hardware. **A paired remote is not a working remote until the link is encrypted** — a stale LTK left `Encryption: Disabled`, every GATT read answered ATT `0x0E`, and bluez's `hog` never built the HID device; bluez state survives reboots, so the cure is remove + controller power-cycle + re-pair (`docs/W103D_USER_GUIDE.md`). The service layer sets `HandlePowerKey=ignore` (the 电源 key reports `KEY_POWER`, which logind would turn into a power-off mid-QSO), and every release path sends `ptt:false`. Scope: control only — the remote's microphone is a vendor BLE service and `audio_handler` still takes TX audio from the browser alone. |
| `nano/` | NanoVNA-H antenna bench (AD-030): `analysis.py` is pure math (Γ→SWR/Z/resonance/CSV/s1p, no I/O), `vna.py` is the **only** module that talks to the instrument — port discovery (env → `by-id` ChibiOS → `cu.usbmodem*` → `/dev/ttyACM*`, never the CAT port) plus the `scan_bin` binary frame (`u16 mask + u16 points + u32 freq + f32×2` per point), and `server.py` only adds routes and four guards. **Three field-found defects live in the transport**: a command written right after `reset_input_buffer()` is dropped (device still talking — measured as `scan_bin` answering nothing at all), a quiet-period frame terminator truncates a 401-point sweep between segments, and stripping only the CRLF of the echo line leaves `data 0` as a "data" row. So: sync to `ch> ` before writing (`in_waiting` first, or every command costs 0.6 s), read **exactly** `4 + points × (4 + 8×(1+s21))` bytes, and reject any frame that is not exactly that length — half a frame draws a plausible fake curve. Guards: refuse everything while transmitting (CH0 sits on the antenna — tens of watts is a burnt front end), one operation at a time, never steal the CAT port, `listen`/`sdr` sessions 403. Every scan restores the device's on-screen sweep. `tcxo`/`clearconfig`/`touchcal`/`sd_delete` are deliberately not exposed (the 50 kHz–900 MHz default is 101 points; 401 points take 1.26 s, Chinese UI at `/Nano`). The page is an **antenna bench, not an instrument panel**: a verdict card (band max SWR → 免调 / 天调可修 / 勉强 / 不建议) plus a trim hint derived from `(resonance − band centre) / centre` ≈ relative element length, a cursor tooltip, and a click that moves the device's marker. **Field preset** sets the device's own sweep to 1–54 MHz/401, leaves a single S11 SWR trace (scale 1.0, refpos 0), puts the marker mid-span and writes SAVE slot 4 — because trace format and sweep live **outside** `config`, so `saveconfig` (and even the firmware's remember-state flag) cannot persist them; only `save`/`recall` carries the whole state, hence `RECALL 4` when used standalone. `docs/nano/field-baseline.json` is a captured known-good state and `GET /api/nano/baseline?compare=1` diffs the live device against it. `docs/nano_vna.md` is the operator manual |
| `sdr_pipe.py` / `sdr_frames.py` | SDR receiver device process (AD-029): owns the SDRplay device for the whole box — `libsdrplay_api` is **exclusive**, so one process takes it and everything else goes through this subprocess. Two sources share one block loop: `--device` (via `sdr_api_shim.so`) and `--offline <iq file>` (lets the whole chain be tested on a machine with no SDR). Each 20 ms block: FFT → 1024-bin u8 spectrum frame, one `libsdr_dsp` call per demodulator → PCM → Opus → audio frame. Commands arrive on stdin (`tune`/`channel`/`clear`/`gain`/`quit`); a `DeviceRemoved` event exits 3 so the server can back off and restart. `sdr_frames.py` is the **only** framing contract between pipe and server (`P1` status / `S1` spectrum / `A1` audio / `C1` command). **A1's layout is `chid u8 / seq u16 / level u8 / len u16` (`<BHBH`)** — packing seq as u8 (`<BBHH`) killed the pipe as soon as the counter passed 255 (field, 2026-10-18). |
| `sdr_hub.py` | SDR sharing rules, pure logic (AD-029): tuning arbitration (30 s hold; the holder's own release is the only accepted one; a holder's disconnect frees it immediately), demodulator pool keyed by `(offset, mode, bw)` so ten listeners on 7.074 USB cost **one** demodulator (squelch/volume are per-subscriber and applied at fan-out, never in the key), client/channel caps that **refuse the request instead of hanging up**, and the spectrum tier drop (1024 → 512 bins past 12 listeners). Every rule is testable with a fake clock and a fake pipe — no hardware, no sleeps. |
| `sdr_dsp.c` / `sdr_dsp.h` / `sdr_dsp_binding.py` | Native channelizer + demodulator (AD-029): **two-stage**, because one stage cannot be both anti-alias and sideband-selective (measured: numpy at 0.075 core/channel could not reject the opposite sideband at all). Stage 1 mixes the carrier to 0 and decimates to 96 kHz; stage 2 is a sharp **complex** filter at 48 kHz whose frequency shift is what selects USB/LSB/CW. AM/NFM use a symmetric stage 2 and are correspondingly cheaper. Measured on the W103D: **0.086 core/channel AM, 0.151 USB** — the reason `MRRC_SDR_MAX_CHANNELS` defaults to 8. WFM takes a third path (discriminate at 480 kHz, then decimate the audio). `sdr_dsp_binding.py` is the ctypes wrapper (`Channelizer.process(iq, nchan) -> (pcm_bytes, rms)`) and degrades to `None` when the library is absent. |
| `sdr_api_shim.c` | The only code that touches `libsdrplay_api` (AD-029): ~200 lines of C exposing flat functions (`open/config/start/read/stop`) because the vendor's `DeviceParamsT` nests a dozen levels — mirroring it in ctypes is how offset bugs happen. IQ lands in a C ring buffer; **no Python callback ever runs on the API thread**. Build needs the vendor headers (`/usr/local/include`) and `-lsdrplay_api`. |
| `host_perf.py` | 性能负载页的数据源（AD-031）：`/proc` 与 `/sys` 的 CPU/负载/内存/磁盘/网络/温度/主频，加上进程级 CPU（名字取自 `cmdline` —— 否则每个进程都叫 `python`）。**所有速率都是两次采样的差值**，第一拍返回 `available:false` 而不是 0；**读不到的字段是缺失，不是 0**（0 °C 在这台盒子上等于「很凉快，继续跑」）。分区不计入磁盘速率（它的扇区已经算在整设备里）、`lo` 与隧道不计入网络；判定文字只有一处定义（`host_perf.verdict`）：先看**事件循环延迟**再谈 CPU —— CPU 不高而循环卡 900 ms 是「服务端自己堵了」，不是「该换更强的盒子」。页面 `/Perf`（☰ 菜单「性能负载」），接口 `GET /api/perf`，`listen`/`sdr` 会话 403。Stdlib only、无 app imports |
| `session_metrics.py` | Remote-session metering (AD-023): live sockets per (role, kind), distinct sessions (one listener = one token even with three sockets), lifetime + windowed peaks, and uplink bytes for the two fan-out paths (`spectrum`, `audio_rx`) — the measured listener concurrency the hub's RX fan-out decision waits on (hub AD-H12 / I-H1). Counts and bytes only: tokens are opaque keys that never reach the snapshot, so the numbers are safe to expose at `GET /api/session_metrics` and to log. Stdlib only, no app imports |
| `support_answers.py` / `dev_tools/support_autopilot.py` | Support chain 2/4 (AD-021 amendment): the autopilot polls the receiver, unpacks a bundle, builds the digest and has `pi` (read-only tools, repo as cwd) answer through a fixed JSON contract; `support_answers.py` holds the contract, the card/page renderer and the **public-page privacy filter**. Drafts by default, `--publish` updates the answers page + commits + rsyncs that one file, `need_more_info` never publishes; idempotent state, ≤2 bundles per run, 540 s pi timeout |
| `support_board.py` / `dev_tools/fde_board.py` | FDE loop board (support chain 4/4): every finished analysis lands classified on a public kanban (<www.vlsc.net/mrrc_modern/board/>) — **classification is the decision**: `noise` closes as 已答复 (answer published, no code work), `bug` auto-schedules into the unattended implementation queue, `feature` waits in 待决策 for the operator (`fde_board.py decide`); an un-answered report (`need_more_info`) never closes. `autopilot --implement` then runs unattended implementation — `pi` proposes a unified-diff **JSON contract**, guarded (protected paths: tooling-guard JS files, `certs/`, `packaging/`; ≤8 files), applied only to an isolated `fde/<id>` branch and committed only when the full unittest suite is green; `main` is never touched unattended. Same redaction filter as the answers page |
| `tools/support_receiver/` | Vendored stdlib receiver for this product's own instance (port 8098, `/var/www/support-modern`, `product` in meta.json); `deploy_support_receiver.sh` deploys the unit + nginx path idempotently |
| `deploy_listen_proxy.sh` | Public listen-only URL (V2.59): idempotently inserts the `/mrrc_modern/listen` block (page + login + listen.js + worklet + modules + api + `/WS*` with upgrade headers) into <www.vlsc.net's> nginx and reloads. | `scope_handler.py` | Spectrum data container: FT4222 real FFT + S-meter Gaussian fallback. | `scope_pipe.py` | Compatibility shim (still the PyInstaller entry) — real module moved to `backends/ft710/scope_pipe.py`: standalone subprocess for FT4222 SPI I/O (avoids asyncio/ctypes conflicts); 1s len=0 stdout heartbeat + stdin-EOF for dead-parent detection; stdin `TX:1`/`TX:0` control — SPI reads pause while TX (radio garbles scope stream); resync = device close/settle/reopen (byte-by-byte resync impossible: per-byte SingleRead = separate SPI transaction); server kills it via process tree (`taskkill /T`) on Windows; launched unfrozen as `python -m backends.ft710.scope_pipe` with cwd=repo root |

| `launcher_net.py` | Shared launcher network probe (v1.24.6): `answers()` decides whether a URL is served — **any** HTTP status counts, including `401` — and `served_url()` asks the preferred scheme first, then the other one. Deliberately dependency-light: it lives at the repo root so PyInstaller's import analysis picks it up from either entry script without a spec change (it is inside the PYZ, so this fix ships with a release, not a hotfix). |

## Tooling Guards (do not remove)

Two legacy frontend files — `static/ft710_main.js` and `static/ft710_ui.js` — must not be
reformatted or "autofixed" by tooling:

- They are tab-indented with double quotes, while `biome.json` configures 4-space/single-quote
  for the rest of the project. Letting biome format them rewrites ~3200 lines for no behavior
  change (and breaks the whitespace-sensitive frontend contract tests in
  `tests/test_server_ws_protocol.py`).
- Their top-level names (`radioCapabilities`, `AUDIO_TAG_PCM`, `RX_RECORDER_MIME`, …) are
  **cross-file globals** (classic `<script>` files, read from the other file). A single-file
  "unused variable" analysis calls them unused and renames them with a leading underscore —
  which silently breaks the capability-driven UI in the browser, invisible to the Python suite.

Guards in place (both verified against biome 2.5.6, the binary pi-lens runs):

| File | Guard |
| --- | --- |
| `biome.json` | `overrides` for both files: `formatter.enabled=false` plus the six rules whose autofixes mutate them (`noUnusedVariables`, `noUnusedFunctionParameters`, `noInnerDeclarations`, `useParseIntRadix`, `useTemplate`, `useOptionalChain`, `noGlobalIsNan`) turned off — verified: even a direct `biome check --write --unsafe` leaves both files byte-identical |
| `.pi-lens.json` | `ignore` for both files, so no diagnostic/autofix dispatch touches them |

Important: `biome.json` must stay **strict JSON** — a comment makes this biome fall back to its
built-in defaults (2-space/double-quote) and reformat every file it touches. Keep the rationale
here instead. If those two files ever come back dirty with tab→space or `catch (e)` → `catch (_e)`
churn, `git checkout -- static/ft710_main.js static/ft710_ui.js`.

## FT8 模式（feat/ft8）铁律

- **`os.environ.setdefault("OMP_STACKSIZE", "10M")` 必须在导入 NumPy / 加载
  `libwsjt_core` 之前执行**（见 `ft8/core/worker.py` 的 worker 入口与
  `tests/ft8/dsp/conftest.py`）。WSJT-X Improved 的 `sync8var` 在线程栈上分配大型工作数组，
  栈不足的表现是段错误而不是异常——所以这条契约由测试盯住，不能"顺手"挪动。
  **`OMP_STACKSIZE` 只覆盖 OpenMP 工作线程**：解码是从**请求循环所在的那个线程**进入的，
  所以 `worker_main` 把整个请求循环放在一个显式设过大栈的线程上（`WORKER_STACK_BYTES = 64 MB`
  与 `_run_with_large_stack()`）。`sync8var` 单帧要 ≈4.1 MB（`s(NH1,NHSYM)` = 1920×372×4 ≈ 2.7 MB，
  加 `sync2d`/`syncq` 的 ±62 dt 窗口 ~1.2 MB），而 Windows 给线程的 PE 预留是 **2 MB** ——
  溢出是当场静默消失（`worker_exit … status None`，没有任何 Fortran 提示）。本机子进程实测：
  2/3 MB 栈 → SIGBUS，4/8/64 MB → 存活。把 while 循环挪回 `worker_main` 的语句体会让这条失效，
  `tests/ft8/core/test_worker.py` 的结构化断言就是盯这个的。
- **`ALLCALL7.TXT` 必须进包，并且 worker 要把 cwd 挪到它所在的目录**：Fortran 用
  `share_dir = '.'`（`ft8/dsp/vendor/prog_args.f90:4`）**相对 cwd** 打开呼号库，且没有 setter。
  源码 checkout 的 cwd 正好是仓库根，所以本地永远看不见；装好之后 cwd 是启动器所在目录，
  呼号库静默变空（`ldbvalid = .false.`，日志只有一句 `ALLCALL7.TXT is too short or broken?`）。
  打包侧由 `packaging/pyinstaller/mrrc_modern_server.spec` 把它收到 `_internal` 根，
  运行侧由 `ft8.core.worker.share_dir()` + `worker_main` 的 `os.chdir()` 保证。
  守卫：`tests/test_ft8_packaging.py::CallSignDatabaseTests`。
- **DSP 原生代码永远不得终止宿主进程**：`ft8/dsp/` 里的 Fortran `stop` / `error stop` 会当场杀掉
  DSP worker（它是服务器进程的 spawn 子进程）。`wsjt_improved.f90` 的 FFTW 线程初始化已从
  `error stop` 改为返回 `WSJT_E_INTERNAL`（2026-10-16，现场每槽一次 `worker_exit` 的元凶）；
  `patched/four2avar.f90` 与 `vendor/packjt.f90` 两处 `stop` 仍在。**worker 自己的 fd 1/2 由
  `worker_main` 的 `_redirect_worker_output()` 落到 `$MRRC_LOG_DIR/ft8-worker.log`**（超 2 MB 轮转）——
  launcher 的启动 tee 在服务器答 HTTP 后就不再写盘，这是唯一能看到子进程原生死亡信息的地方；
  `support_bundle` 收集它。
- DSP 源在 `ft8/dsp/`：编译子集 `vendor/`（由 `tools/ft8/extract_wsjtx_subset.sh`
  从 CMake 清单派生）、7 个补丁副本 `patched/`、原始基线 `vendor-refs/`；
  `build.sh` 幂等构建 `ft8/dsp/build/libwsjt_core.*`（设备上原生编译）。
- 移植自 MRRC-FT8（`HAM/ft8`）：`ft8/{core,engine}` 保持 verbatim，平台耦合只允许在
  `ft8/platform/`、`ft8/web/`、`ft8/mode.py` 与 `server.py` 的接线处。
- **RX tap 的时间轴会在采集中断后重新锚定（`RESYNC_AFTER_S` = 0.5 s）**：`ft8/platform/rx_tap.py`
  的 12 kHz 环只在**第一个**块上锚定 epoch，之后只按已投递样本数前进 —— 采集一旦停
  （USB 重枚举、TX 后的 `restart_rx()`、ALSA 卡死），它就永久落后墙钟，而时隙网格由墙钟
  派生，于是每一槽都是 `SKIPPED (no data within grace)`（2026-10-17 现场：113 s 中断 →
  `drift=+118 s` → `slots_skipped` 66/67、`decodes=0`）。`feed()` 现在拿调用方本来就传的块
  epoch 与自身时间轴比，超阈值就重锚并且 `UtcRing` 把空洞记成 gap。同时**采集停滞的恢复
  不能只认浏览器**：`_audio_rx_loop` 的恢复门是「有人在用这段音频」（浏览器 / FT8 tap /
  录音）—— FT8 页面从不订阅 `/WSaudioRX`，只认 `audio_rx_clients` 会让解码器无限期饿死。
- **解码默认走快路径，按需级联到深路径**：`ft8/dsp/wsjt_fast.c` 是 `kgoba/ft8_lib`
  （C、kiss-fft）编进**同一个** `libwsjt_core` 的 `wsjt_ft8_decode_fast`（无 AP / 无 OSD /
  单趟，全部取上游默认旋钮 —— 降旋钮只换走弱信号鲁棒性，见
  `docs/ft8-w103d-decode-perf-analysis.md` §9 的 A53 spike）；
  `ft8/engine/cascade.py` 的 `CascadingDecoder` 在命中升级判据（AP 上下文 / 疑似漏解 /
  用户显式请求）时对**同一时隙**补跑深路径并合并两批（`merge_batches`：键
  `(frequency, dt)` 带容差、deep 胜出），预算不足则**宁可不升级**（计 `deadline_risk`），
  快路径整个失败时回落 improved —— **绝不少解码**。计数在 `orchestrator.counters` 的
  `fast_decodes`/`escalations` 与 `runtime.cascade_stats`。
- **原生库是四个平台各自构建出来的**，不是仓库里的一份二进制：两条镜像线在镜像构建期
  就地编译（`packaging/common/mrrc-service-layer.sh`，工具链来自 `packages.txt`；`linux/mrrc_update.sh`
  按源码摘要重编，**失败不阻断升级**），macOS 由 `packaging/macos/ft8_bundle.py` 连 5 个依赖一起
  收进 app（load command 全改 `@loader_path`，构建前硬门禁），Windows 用 MSYS2 MinGW 编译并把
  运行期 DLL 闭包（走 objdump 走出来）一起进包。**改了 `ft8/dsp/` 就要重跑这四条路径。**
  Boost 不再需要安装：`<boost/crc.hpp>` 的包含闭包 vendored 在 `ft8/dsp/vendor-boost/`
  （`tools/ft8/vendor_boost_headers.sh` + `tests/ft8/dsp/test_vendor_boost_policy.py`）。
- 规格与计划：`docs/superpowers/specs/2026-10-12-ft8-work-mode-design.md`、
  `docs/superpowers/plans/2026-10-12-ft8-work-mode.md`（工作模式本体）；
  `docs/superpowers/specs/2026-10-13-ft8-fast-path-cascade-design.md`、

## Security & Configuration Tips

Never commit passwords, serial-device paths, or local driver assumptions. Use environment variables for deployment-specific values. All WebSocket endpoints require a session token, resolved by `_token_from_ws_handshake()` as `Authorization: Bearer` → `mrrc_auth` cookie → deprecated `?token=` query param (AD-024). The browser sends the cookie automatically on the same-origin handshake, so the frontend never builds a token URL (a 30-day credential in a URL lands in access logs, browser history and Referer). Auth tokens are **persisted** in `data/auth-tokens.json` (0600, 30-day lifetime, atomic write) so a routine upgrade restart does not log every session out; the store is runtime state and never committed. Transmit safety: every release path keys off a disconnect, so a connection that dies without a TCP close (dropped NAT, Wi-Fi switch) needs `MRRC_REMOTE_SESSION_TX_HEARTBEAT_S` (default 0 = off; the cloud hub enables it). Only sessions that send `txhb` are gated, and only the session holding the key can be released (ch15 §15.6). `_schedule_restart()` (config save / cloud-certificate restart) releases PTT on the running loop before `os._exit(42)`, which would otherwise skip the lifespan Force-RX.

**侦听地址约定**：真实安装 / 现场机器的 `MRRC_WEB_HOST` 一律用 **`0.0.0.0`**（所有接口）—— 这也是随包默认值、`config.py` 的 `::` 与 SDD/12 "Uvicorn on 0.0.0.0:8888" 三处一致的意图，因为这个界面本来就要能从手机或局域网另一台机器打开。Windows 曾经只在模板里写 `127.0.0.1`，与另外两个平台相反，现场表现为「文档说能局域网访问、实际连不上」（2026-10-03 实测，并已由 `tests/test_listen_default.py` 盯住）。**例外：隔离的验收 / 洁净室测试**显式写 `127.0.0.1`，那是为了让测试实例不被网络碰到，不是发货默认值。代价必须知道：所有接口时 Web 口令是唯一一道门，而这个应用能按下发射键。

## Cloud Hub（多实例远程接入）上下文

本仓同时充当「实例侧」，可被置于云端入口之后运行。改动时注意：

- **前缀安全**：入口可能是 `<呼号>.mrrc.vlsc.net`（根路径）或 `www.vlsc.net/mrrc_modern/<呼号>/`（路径前缀），
  因此新增资源/请求必须前缀安全 —— 断言规则见 `tests/test_path_prefix.py`（文档资源相对、`sw.js` 预缓存绝对）
- **令牌不进 URL**（AD-024）：新增接口用 cookie / Bearer，不要用 query 传令牌
- **隧道状态必须可见**：`/api/cloud/state` 的 `tunnel_running` / `tunnel_error` 是这一节唯一的自证通道。
  缺 `fleet/frpc` 或 `fleet/frpc-<label>.toml` 时 `_cloud_start_tunnel()` **不得**静默 `return`
  （要点名缺失路径，并按内容去重只警告一次）；页面也不得用一个“已接通”绿标代替隧道状态
  （2026-10-22：`bh7kyz` 入口 502 四天，盒子设置页写着“已接通”）
- **新增会话级行为请打点**：Hub 侧的容量决策（如 RX 扇出 AD-H12）依赖 `session_metrics`
- **env 文件里一个键只能出现一次**：读者（`env_store.parse_env_text` 与 systemd 的
  `EnvironmentFile`）都是**后者胜**，而写入器只改第一个匹配行 —— 2026-10-26 现场
  （W103D + IC-7300，`20261026-194408-16d0`）就是 `MRRC_SERIAL_PORT` 后置了一条空行，
  于是「连接设置」保存 6 次全部无效、CI-V 26 天没打开过端口。现在：写入器把命中的键收成一行、
  `config.py` 启动时自愈（空值表示「没设」而不是覆盖，并让本次启动即生效）、
  `POST /api/setup` 写后回读不一致就 500 且不重启。空端口会在启动日志里点名，
  IC-7300 后端失败时也打印 `Available serial ports:`。
- **PTT 改动必须双防线**：`MRRC_REMOTE_SESSION_TX_HEARTBEAT_S`（活性闸门）与 `MRRC_PTT_MAX_TX_SECONDS`（时长上限）
- **Hub 端文档**：设计记录 `../mrrc_hub/SDD/`（实况 §12.8）、部署与证书 `../mrrc_hub/deploy/README.md`
- **勿动**：`atr1000_tuner.json`、`mem_channels.json`、`website/js/global-nav.js`（用户运行期文件，未提交）
