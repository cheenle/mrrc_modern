# 协谷 G7250 接入说明：两条线、怎么连、连上之后怎么验

协谷 G7250（100 W HF/6 m 直采 SDR）在我们这套系统里是**实验性机型**，而且情况比以往任何一台都特殊：
它在协议上给了**两条互不相干的控制面**，很多人第一次接不上，都是因为把两条线混成了一条。

这一页按顺序解决四件事：**这机器有哪两条线**（§1）→ **USB 怎么连**（§2）→ **真频谱怎么开**（§3）→
**发射怎么开、开之前先验什么**（§4）。后面是首次上车检查清单（§5）、排障（§6）、边界（§7）和速查（§8）。

---

## 1. 先说清楚：这台机器有两条线

| 线路 | 走什么 | 能给你什么 | 缺了它 |
| --- | --- | --- | --- |
| **USB 线**（机头 USB 口 → 电脑） | Icom CI-V（CAT）+ 内置 USB 声卡 | 频率/模式/滤波/电平/表头/PTT/天调，以及**发射音频** | 什么都做不了——这是主控制面 |
| **网线**（主机 RJ45 → 同一个交换机） | 裸 IQ 基带（UDP） | **真频谱 + 瀑布**（±24 kHz），**以及接收音频**（软件从 IQ 解调） | 仍然能调谐、能发射，但瀑布变成 S 表合成曲线；接收音频退回 USB 声卡 |

关键一句话：**网口的 IQ 流里没有 CAT、没有 PTT、没有模式**。所以网线不插，机器照样能用；
USB 不插，网页只能看个空壳。

网口还解决了一件 USB 声卡不一定能解决的事：**接收音频**。填了「网口 IQ 地址」之后，
网页上听到的 RX 音频就是这段 IQ 解调出来的（±24 kHz，模式与边带跟着 CAT 走），
不再依赖电台内置声卡在 Windows/macOS 上是否老实。发射音频仍然走那条 USB 线
——网口协议本身不带发射音频。代价是**解调吃 CPU**（这台机器上是单核百分之几到十几，
取决于盒子型号）；想改回声卡，把配置文件里的 `MRRC_G7250_LAN_AUDIO=0`。

这条改动来自 2026-11-12 的现场（BG7YQV，诊断包 `20261111-212640-e397`）：CAT 一直是通的，
Windows 也把电台的 USB 声卡枚举成 `麦克风 (USB Audio Device)`，但那一路采集三天都是
`rms=2 peak=9`（≈ −70 dBFS），客户说的「网口传的是基带 IQ」才是这条路该有的样子。

顺便把两个常见误会消掉：

- 网口**不是** wfview / Icom 那套「远程控制」协议。它是裸 IQ：电台在 **UDP 50002** 收一条 14 字节的调谐命令，
  往电脑的 **UDP 50001** 推 768 字节的 I/Q 包（48 kS/s）。协谷官方文档里对应的用法是 Windows + HDSDR + 他们给的 DLL，**只给接收**。
- 我们**没有**现成的 wfview 机型文件可以抄——2026-11-07 核对过：wfview 的机型库里没有任何协谷机型，
  Hamlib 停在 X6200，协谷自己也没发布 G7250 的 CI-V 文档。所以下面所有命令事实都是
  第三方逆向 + X6100/X6200 文档 + 待实测三者的混合，代码里每条都标了来源。

## 2. USB 怎么连（五分钟）

| 步骤 | 做什么 | 判断成功的标志 |
| --- | --- | --- |
| 1 | 一根 USB 线：**机头（那块 7 寸屏）上的 USB 通信口** → 电脑 | 系统里出现**一个串口**和**一个 USB 音频设备** |
| 2 | 网页 ☰ →「连接设置」→ 机型选 **Xiegu G7250（实验性，仅接收）** → 串口选那个新出现的口 | 保存后服务会重启，日志出现 `Radio model: g7250, serial port: … @ 115200 baud` |
| 3 | 看日志里这一行 | `Xiegu G7250 answered on CI-V 0x__ at /dev/… (115200 baud), N Hz` |
| 4 | 转一下电台的频率旋钮或换个模式 | 网页上的频率/模式跟着动（这一步证明 CAT 通了） |
| 5 | 在「连接设置」里把 RX/TX 音频设备选成实际存在的那个名字 | 网页能听到接收音频（若已填网口 IQ 地址，RX 走网口，这里的 RX 选择不参与） |

第 3 步那一行是**这台机器特有的**：协谷不公布 G7250 的 CI-V 地址，所以服务会把
**`0xA4` → `0x88` → `0x70`** 依次试一遍（X6100/X6200 是 A4，G90 是 88/70），谁答了频率读取就用谁，
并把这个地址写进日志。看到 `0x` 后面那两个十六进制数，就是这台机在你手上时的真值——
**请把它记下来**（§5 要回报）。

波特率默认 **115200**。如果电台菜单里的 CAT 速率被改过，两边要对齐：
在配置文件里写 `MRRC_BAUD_RATE=<电台菜单里的值>`，或把电台菜单改回 115200。

### 两个串口怎么办

协谷以往的机器（X6200）一根 USB 线会枚举出**两个**串口：一个是 Linux 控制台（登录 shell），一个是 CAT。
G7250 的机头也有人抓到过在 115200 上的启动打印，而同一根线上随后跑的是 CI-V 风格的二进制流量
（**这条未确认**：也可能像 X6200 那样分成两个口，只能说「同一个口串着用」是更可能的那种）。
不管是哪种，**选错口的表现都一样：连上了，但一个字节都不回来**。

做法很简单：把出现的那几个串口**逐个试**，每次保存后看日志里有没有上面那句 `answered on CI-V 0x__`。
答不上来的那个会在日志里留 `did not answer on any CI-V address`，并列出所有可用串口，换下一个即可。

## 3. 真频谱：网口怎么开

默认**不开**。没有配置时，瀑布是 S 表合成的曲线（和八重洲那几台一样）：能看出「有人在、在变强」，
但分不开相隔 3 kHz 的两个信号。要真频谱，三步：

1. **插网线**：主机后部的 RJ45 → 与电脑同一个交换机（或直连）。
   电台默认地址是 **192.168.3.199**（厂家 DLL 的默认值）。如果你的网络不是这个网段，
   要么把电脑临时改到 `192.168.3.x`，要么进电台菜单看它实际拿了什么地址。
2. **填地址**：网页 ☰ →「连接设置」→「网口 IQ 地址」写电台的实际地址，保存并重启。
   （早期版本这里只能手改配置文件里的 `MRRC_G7250_LAN_IP=`，1.28.51 起有输入框；
   留空 = 退回 S 表合成瀑布。）

   日志里应出现：

   ```
   G7250 LAN IQ listening on UDP 50001 (radio 192.168.3.199:50002), +/-24.0 kHz
   ```

   同时会多一行 `G7250 RX audio from the LAN IQ stream …`：**接收音频从此也从网口来**。
   不想这样就加 `MRRC_G7250_LAN_AUDIO=0`（瀑布不受影响）。

3. **放行防火墙**：电脑侧要允许**入站 UDP 50001**。Windows 第一次会弹窗，选「允许」；
   盒子/Linux 上如果开了防火墙，同样要放行。

### 网口这边的四个坑

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| 日志 `G7250 LAN IQ: cannot bind UDP 50001` | 端口被占了——最常见的是 **HDSDR 正在跑**（协谷官方那套接法） | 关掉 HDSDR 再重启服务。一个 UDP 端口只能有一个主人 |
| 日志有 `listening`，但瀑布是空的、日志里包计数不动 | 网线没通 / IP 写错 / 防火墙挡了 | 服务跑满 5 秒后会点名一次：`no packets for N s from <ip>`。`ping 192.168.3.199`；确认端口；确认防火墙 |
| 有瀑布，但**没声音** | 接收音频已切到网口 IQ；没包就没有音频 | 先看瀑布有没有在动：瀑布也在冻就是上面那条（线/IP/防火墙）；瀑布正常而声音异常，看日志里的解调模式行 |
| 声音**边带反了**（SSB 听不清） | 倒频流的边带与 CAT 的模式对不上 | 先确认电台面板的模式（USB/LSB）与网页一致；仍反就把 `MRRC_G7250_SWAP_IQ=1` 的语义再核一遍（它同时影响频谱与解调） |
| 频谱对，但**发射没声音** | 发射不走网口 | 那是 USB 声卡的事：把 TX 音频设备选成 `扬声器 (USB Audio Device)` |
| 有瀑布，但信号在中心线的**错误一侧** | I/Q 极性反了（厂家 DLL 没写死这个） | 加一行 `MRRC_G7250_SWAP_IQ=1`，重启 |
| 瀑布只在 VFO 附近 ±24 kHz | **这是正常的**：IQ 流就是 48 kS/s | 想看整个波段，靠电台自己的屏；网页上拖 VFO 会把 IQ 中心一起带走 |

一条还没验证的事：机头与主机之间那条链路**也是以太网**。厂家没说同一个 RJ45 能不能既连机头又连局域网。
如果你的机器上插了网线就出别的毛病（机头失联之类），把这条记进 §5 回报。

## 4. 发射：默认是关的，为什么，怎么开

第一次按 PTT，日志里会是这一句：

```
Xiegu G7250 is not hardware-verified — transmit refused.
Set MRRC_ALLOW_UNVERIFIED_TX=1 and restart to enable TX after checking the radio with _diag_civ.py.
```

这不是故障，是我们的门禁：这台机型的 profile **没有在任何一台真机上验证过**。
发射命令差一个字节，后果可能是「按了没反应」，也可能是「按下去不松」。

开之前先做一件事——**接假负载**（或确认天线确实正常、SWR 正常），然后：

1. 打开配置文件（位置见下），加一行 `MRRC_ALLOW_UNVERIFIED_TX=1`（已有就改，不要写两行）；
2. 保存并重启服务；
3. 用**最小功率**、**最短时间**试一次「喂」，同时盯着：网页功率表、SWR 表、电台面板的功率条；
4. 松开 PTT，确认电台真的回到接收（面板 TX 灯灭、日志出现 `TX0`）；
5. 这三件事都对，再考虑长发射；**不要**一上来挂一键 CQ 或 FT8 自动发射。

配置文件在哪：

| 平台 | 路径 |
| --- | --- |
| Windows | `%LOCALAPPDATA%\MRRC-Modern\mrrc_modern.env` |
| macOS | `~/Library/Application Support/MRRC-Modern/mrrc_modern.env` |
| 盒子 / Linux 镜像 | `/opt/mrrc_modern/env/mrrc.env` |

**松开没反应怎么办**：立刻用电源开关断开电台，然后把当时日志贴来（§6）。宁可断电源，不要等。

## 5. 首次上车检查清单（这一步最值钱）

这台机器的 profile 里有十来处 `TODO(hw-verify)`。你在真机上跑一遍，就能把它们变成事实。
按顺序做，能一次拿全：

| # | 做什么 | 记什么 | 回填到哪 |
| --- | --- | --- | --- |
| 1 | 启动服务，看第一行 | `answered on CI-V 0x__` 的地址 | `CANDIDATE_CIV_ADDRESSES` 的首位 |
| 2 | 跑一次只读自检（见下） | 报告里 `refused (...)` 的那些行 = 这台机不认的命令 | 对应能力位/轮询表 |
| 3 | 面板与网页对比 S 表 / 功率 / SWR / ALC | 差几格、哪个方向 | `MeterCal`（现在沿用 IC-7300 曲线） |
| 4 | 按一次 TUNE（天调） | 有没有真的调谐（继电器响、SWR 下降） | `1C 01 02` 是否需要改 |
| 5 | 设备管理器 / 系统音频里看声卡名 | 精确名字 | `audio_name_hints` |
| 6 | 接网线，看瀑布 | 有没有、正不正（§3） | `SWAP_IQ` 默认值、LAN 常量 |
| 7 | 发射 2–3 秒 | 功率、SWR、ALC，以及**发射时瀑布有没有断** | 决定 `notify_tx` 要不要暂停 |

第 2 步的命令（**只发查询、不按 PTT**，除非你显式加 `--tx-check --allow-tx`）：

```bash
python _diag_civ.py --model g7250 --port /dev/ttyUSB0            # macOS: /dev/cu.usbmodemXXXX
```

它会自己按 `0xA4 → 0x88 → 0x70` 找一个能答的地址，然后把只读查询（频率、模式、S 表、功率设置、
前放、衰减、`19` 机型 ID、`1A 05` 设置项、各表头原始值）跑一遍，写出一份 `diag_civ_g7250_*.md`。
**被电台拒绝的查询不会中断整轮**，而是记成 `refused (...)` —— 那些行本身就是发现。

跑完把报告贴来，就能一次性把地址、表头、可用命令集合三件事定下来。

## 6. 出问题怎么报

三件事，按顺序：

1. **先在网页上把问题做一遍**（改一次频率、按一次模式、按一次 PTT）——让日志里有这次 CAT 交换；
2. **☰ → 🐞 遇到问题 → 生成诊断包并上传**（口令已隐去）；
3. 描述里写清：哪一步、期望看到什么、实际看到什么。

我们会先看这几行：

| 日志里的行 | 含义 |
| --- | --- |
| `Radio model: g7250` | 机型选择生效了 |
| `answered on CI-V 0x__` | CAT 通了，且这是电台的真实地址 |
| `did not answer on any CI-V address 0xA4, 0x88, 0x70` | 串口找对了但没人答：换串口 / 对波特率 / 试 `MRRC_G7250_CIV_ADDR` |
| `G7250 LAN IQ listening on UDP 50001` | 频谱线开始收包了 |
| `cannot bind UDP 50001` | 端口被占（HDSDR？） |
| `transmit refused` | 发射门禁（§4） |
| `TX session: frames=… written=…` | 发射音频有没有真送进声卡 |

## 7. 这台机型上我们明确不做 / 不做主张的事

| 事项 | 说明 |
| --- | --- |
| 网口发射（远程 PTT） | 网口协议里**没有** PTT；协谷官方也说网络侧「当前只给接收」。要远程发射，走的是本软件的浏览器/手机端 |
| 超出 ±24 kHz 的瀑布 | 厂家只给 48 kS/s 的 IQ 流 |
| CI-V 频谱（`0x27`） | 这台机没有这条命令（X6100/X6200 也没有），所以我们也不发、不轮询 |
| 表头当刻度用 | 曲线还是 IC-7300 的（同为 100 W 级），未在 G7250 上校准 → **以面板读数为准** |
| 天调自动调谐 | 形式（`1C 01 02`）未验证；先用电台面板的 TUNE |
| 双天线选择 / 语音呼叫器 / CW 预置电文 / 驻波扫描 | 都是电台自己的能力，CAT 里有没有对应命令未知，暂时只走面板 |

## 8. 速查

| 项 | 值 |
| --- | --- |
| 机型键 | `g7250`（界面上叫「Xiegu G7250（实验性，仅接收）」） |
| CAT | Icom CI-V，`FE FE <to> <from> <cmd> … FD`，**115200** 8N1 |
| CI-V 地址 | 未知/自动化：`0xA4` → `0x88` → `0x70` 探测；`MRRC_G7250_CIV_ADDR` 可钉死 |
| 频谱 | 网口 IQ：收 `UDP 50001`，电台听 `50002`，默认 IP `192.168.3.199`，48 kS/s（±24 kHz） |
| USB 音频 | 48 kHz（内置声卡）；**接收**在配了网口 IQ 地址后改由 IQ 解调 |
| 功率 | HF 100 W / 6 m 90 W |
| 频段 | 0.5–30 MHz、50–54 MHz（无 2 m / 70 cm） |
| 天调 | 内置，20–150 Ω（控制形式待实测） |
| 发射 | 默认禁止；`MRRC_ALLOW_UNVERIFIED_TX=1` 解锁（先接假负载） |
| 相关配置 | `MRRC_G7250_LAN_IP`、`MRRC_G7250_LAN_AUDIO`（默认 1）、`MRRC_G7250_CIV_ADDR`、`MRRC_G7250_SWAP_IQ`、`MRRC_BAUD_RATE` |
| 设计记录 | [G7250 后端设计](superpowers/specs/2026-11-07-xiegu-g7250-design.md) |
