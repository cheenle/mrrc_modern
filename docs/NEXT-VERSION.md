# 下一版（backlog）

> 记录"已经想清楚、只差做"的东西。每条都带**验收标准**——没有验收标准的条目只是愿望。

## 1. 应用内一键：接入 / 升级 / 打补丁

**背景**（2026-10-03）。今天把三件事做成了"下载一个 `.cmd`、双击"：
`MRRC-Modern-Connect.cmd`、`MRRC-Modern-Patch.cmd`、`MRRC-Modern-Cleanup.cmd`。
这比让客户敲命令好，但客户仍然要：下载文件 → 过一次 UAC → 看一个黑底白字窗口。
对一个业余无线电用户来说，**这三步都是多余的**。

**目标**：把这三件事搬进应用界面——每个都是"点一下"。

| # | 做什么 | 现状 | 还差什么 |
| --- | --- | --- | --- |
| ① | **接入云端** | 设置对话框已有申请/口令/刷新 ✓；**v1.25.0 起批准后无需任何点击** —— 服务端每 30 s 自查一次（`server.py` 的 `_cloud_autoconnect_loop`），发现已批准就自动落证书、登记入口、提示重启 ✓（手动「刷新状态」保留为立即触发） | **已交付**（代码 + `tests/test_cloud_endpoints.py` 里 5 个专项用例：轮询到授予即接入 / 已接入不再轮询 / 与手动登记互斥 / 无申请不起轮询 / 状态端点报告轮询器）。**真机上的自动路径还没跑过**：现场机 `192.168.1.53`（bg6lh）那次登记是人工触发的，"装完不点任何东西、只等批准"这条等着在真机上走一遍 |
| ② | **升级整包** | 有 `upgrade_core` + `latest.json` + 只读端点 `GET /api/update/check` ✓（**界面尚未接**：全仓没有任何界面代码调用它，`static/` 里也没有升级按钮 —— 原写"有一键升级按钮 ✓"经 2026-10-03 实测为假） | 端到端复跑一遍，特别是**静默安装后自己拉起应用**（今天实测：静默安装不会启动应用 ⇒ 装完必须由客户端或安装器拉起 ✓） |
| ③ | **打静态补丁** | 补丁通道已有（`patches/patch.json` + 施加脚本 ✓） | 应用内读取清单 → 按 `version.txt` 匹配 `appliesTo` → 下载 → 校验 SHA-256 → 覆盖 `_internal/static` → 自重启 |

**验收标准**

1. **干净机器**：装包 → 界面点「接入」→ 填呼号 → 等批准 → **自动完成** → 入口 `https://<呼号>.mrrc.vlsc.net/` 返回 401。
   全程不下载任何 `.cmd`、不开命令行。
2. **有补丁时**：界面提示"有可用补丁" → 点一下 → 应用重启 → 新界面生效（可用 `served js 含新符号` 验证）。
3. **每一次失败都必须在界面上说明原因**——今天那场"黑屏"的代价就是**静默降级**：缺证书退成 HTTP、界面只说"起不来"。
   宁可显示一条丑但准确的错误，也不要静默地换一条路走。

**边界（明确不做 / 做不到）**

- 不做默认开启的**静默自动升级**：升级与补丁都必须由用户知情并点一下。
- 热修**只覆盖 `_internal/static/**`**（网页界面与资源）；Python 逻辑冻在可执行文件里，**必须整包升级**。
- 补丁**改版本号**：不改。补丁是同一版本上的替换，`version.txt` 不动（清单用 `appliesTo` 表达适用性）。

**相关**

- 施加脚本（可作为应用内逻辑的参考实现）：`tools/windows/MRRC-Modern-Patch.ps1`。
- 接入脚本：`tools/windows/MRRC-Modern-Connect.ps1`。
