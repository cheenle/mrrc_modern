# MRRC Web 遥控 — 操作指南

> 适用于当前 MRRC Modern 界面（**基线 v1.28.x**；**权威版本号是安装目录里的 `version.txt`** —— 菜单底部那个 `v1.0` 是前端资源串，见 §0.10）。支持 Yaesu FT-710、Icom IC-7300 / IC-7300MK2（另含 IC-705 / IC-7610 / IC-7760 预览配置）与 Yaesu SDR 机型族 FTDX10 / FTDX101D / FTDX101MP / FTX-1F / FT-891（实验性、默认只收不发，`MRRC_ALLOW_UNVERIFIED_TX=1` 解锁；这些机型无真机频谱源，界面用 S 表合成频谱。**FT-891 另有两个例外**：USB 口只做 CAT、不带 USB 声卡，音频须外接接口到 DATA/ACC 口并在设置里显式选设备；无内置天调，界面不显示 ATU 键，TUNE 发载波供外接天调调谐）。本文档逐项说明界面上每一个按钮、滑杆、下拉框的功能与用法，编号与文末插图（图 1 主界面、图 2 菜单）中的琥珀色序号一一对应。云端接入见 §0.9，版本与更新见 §0.10。

## 0. 开始之前：连接与登录

| 步骤 | 说明 |
| ------ | ------ |
| 1. 启动服务 | 在电台电脑上运行 `python server.py`（或 Windows 安装版/桌面启动器），服务默认监听 `0.0.0.0:8888`，HTTPS 优先（首次运行自动生成自签名证书）。 |
| 2. 打开页面 | 手机/电脑浏览器访问 `https://<服务器IP>:8888`。**两处都写 `https://`** —— 服务只为 TLS 监听，同一端口的明文 HTTP 不应答（v1.24.5 的"装完黑屏"正是这么来的：启动器把人送到 `https://`，而服务器退回了 `http://`）。自签名证书首次会警告一次，点「继续」即可。默认监听所有接口（`MRRC_WEB_HOST=0.0.0.0`），所以局域网内直接用 IP 就能打开；只想本机可达就把它改回 `127.0.0.1`。iPhone 上建议用 Safari 并「添加到主屏幕」以获得 PWA 全屏体验。 |
| 3. 登录 | 输入共享密码（服务启动时由 `MRRC_WEB_PASSWORD` 或安装向导设置），点 **Login**。成功后在 `mrrc_auth` Cookie（30 天有效）；密码错误返回 401，5 分钟内连续 5 次失败会触发 429 限流，需等待后再试。 |
| 4. 建立连接 | 手机端：点顶栏 **⏻** 开始连接（见控件 5）；桌面端打开页面后自动连接。状态栏 ●Serial 变绿表示与电台的 CAT 串口已连通。 |

> ⚠️ 顶栏 **⏻** 只控制浏览器与服务器的 Web 连接，**不是**电台电源开关。电台电源在 ☰ 菜单里，
> 分成「重开电台…」与「关机…」两项（见 §2.11 末尾）——为什么要分成两项、以及为什么开机不保证成功，那里写清楚了。
> 页头状态栏的 `PWR 开/关`（救援期间显示 `PWR 唤醒中 N`，点一下可取消）反映的是电台真实的电源状态。

## 0.5 电台型号差异

服务器通过 `MRRC_RADIO_MODEL` 选择后端，前端会根据后端上报的 `capabilities` 自动调整可用控件。
已注册的型号键（连接设置对话框的下拉列表与之一致）：

- **完全支持**：`ft710`（Yaesu FT-710）、`ic7300`（Icom IC-7300）、`ic7300mk2`（IC-7300MK2）
- **实验性（默认只收不发，`MRRC_ALLOW_UNVERIFIED_TX=1` 解锁）**：Icom CI-V 族 `ic705` / `ic7610` / `ic7760`；
  Yaesu ASCII-CAT 族 `ftdx10` / `ftdx101d` / `ftdx101mp` / `ftx1`（FTX-1F）/ `ft891`（FT-891）

**选型只有一条硬规矩（v1.28.2 起）**：连接设置里选中的机型会被**保留**，启动器的串口探测只填空、
不会覆盖它 —— 在此之前任何不在旧白名单里的机型（FT-891 / FTX-1 / FTDX10 / IC-705 / 7610 / 7760）
每次启动都会被改回 `ft710`，然后用 FT-710 的后端去驱动它（现场症状正是"选了 FT-891 但什么都对不上"）。

**Yaesu 族的串口速率**：FT-710/FTDX/FTX-1 出厂 38400；**FT-891 的菜单 05-06 `CAT RATE` 出厂是 4800**
（Yaesu 手册；常见改法是 38400）。配置的速率下电台一个字节都不回时，控制器会自己按
4800 → 9600 → 19200 → 38400 试一遍，命中后**本次会话**就用它并在日志里留一条告警 ——
它不会改你的配置文件；要让下次启动也用对，把电台菜单和连接设置改成一致即可。

下表以最常用的两台为例对比；**CI-V 族（ic7300/mk2/705/7610/7760）行为对齐 IC-7300 一列**
（细节按型号配置档略有差异，如 IC-7610/7760 的 ATT 为 0–45 dB 每 3 dB 一档、频谱几何不同），
**Yaesu ASCII-CAT 族行为大体对齐 FT-710 一列**，但无 FT4222/CI-V 真频谱源，界面一律用 S-meter 合成频谱。

| 功能 | FT-710 | IC-7300 / IC-7300MK2 |
| ------ | -------- | --------------------- |
| 串口协议 | Yaesu CAT，38400 baud | Icom CI-V，115200 8N1，默认地址 `0x94` |
| 频谱来源 | FT4222 SPI（或 S-meter 回退） | CI-V `0x27` 帧（或 S-meter 回退） |
| USB 音频 | 44.1 kHz，需重采样到 48 kHz | 48 kHz，无需重采样 |
| AN（自动陷波） | 有 | **无**，界面隐藏 |
| Vd / Id 仪表 | 有 | **无**，界面隐藏 |
| 滤波器 | 多档语音/窄带宽度 | FIL1–FIL3 循环 |
| ATT | `OFF` / `6dB` / `12dB` / `18dB` 四档 | `OFF` / `20dB` 两档（7610/7760 为 3 dB 步进 16 档） |
| VFO-B 直接选择 | 有 | 无 |
| 内置天调 | 无（ATU 键控制外接 FC-40 类天调；也可外接 ATR1000） | 有 |
| 70 MHz | 无 | 视地区版本而定 |
| 发射时频谱 | 暂停并显示「频谱暂停」 | 继续显示（CI-V 频谱不受发射影响） |

## 0.6 Windows 配置与运行

本章说明 IC-7300 与 FT-710 在 **Windows 桌面版（MRRC-Modern-Setup.exe）** 下分别如何配置并使其工作：装驱动 → 确认串口 → 编辑配置 → 电台侧设置 → 启动验证。

> 配置统一写在 `%LOCALAPPDATA%\MRRC-Modern\mrrc_modern.env`（开始菜单里的 **Edit Configuration** 快捷键会打开它）。变量名用新的 `MRRC_*` 前缀；旧的 `FT710_*` 前缀仍被兼容接受（`MRRC_*` 优先），升级用户可保留原配置。修改后需重启 MRRC Modern 生效。

### 0.6.1 通用步骤（两台都适用）

1. 安装 **MRRC-Modern-Setup.exe**（开始菜单出现 `MRRC Modern` 与 `Edit Configuration` 两个快捷方式）。
2. 用 USB 线连接电台到电脑，并**开机**。
3. 打开 **设备管理器**，在「端口 (COM 和 LPT)」下确认电台的串口：
   - **IC-7300**：一个 COM 口（USB CI-V）。
   - **FT-710**：两个 Silicon Labs CP210x COM 口（较低编号通常是 CAT 用的 Enhanced COM Port）。
4. 打开 `mrrc_modern.env`，设置 `MRRC_RADIO_MODEL`（`ic7300` / `ic7300mk2` / `ft710`，或 §0.5 列出的其它实验性型号键），并确保 `MRRC_SERIAL_PORT` 指向第 3 步确认的串口。
5. 启动 `MRRC Modern`，浏览器自动打开登录页。输入 `MRRC_WEB_PASSWORD` 后，状态栏 ●Serial 变绿即表示 CAT 已连通。

> 换电台时**不需要重装**：改 `MRRC_RADIO_MODEL` 和串口/波特率即可，其余步骤照对应小节核对。

### 0.6.2 IC-7300 / IC-7300MK2

**驱动**：IC-7300 用标准 Windows USB-serial 驱动（通常自动安装），**不需要** FTDI 驱动。

**设备管理器确认**：「端口 (COM 和 LPT)」显示一个 COM 口，即 USB CI-V。

**`mrrc_modern.env` 完整示例**：

```ini
MRRC_RADIO_MODEL=ic7300        # 或 ic7300mk2
MRRC_SERIAL_PORT=COM5          # 改成设备管理器里看到的 CI-V COM 口
MRRC_BAUD_RATE=115200
MRRC_WEB_HOST=0.0.0.0        # 随包默认值（所有接口）；改成 127.0.0.1 则仅本机可达
MRRC_WEB_PORT=8888
MRRC_WEB_PASSWORD=change_this_password
MRRC_AUDIO_RX_DEVICE=USB Audio
MRRC_AUDIO_TX_DEVICE=USB Audio
# IC-7300 地址覆盖（默认 0x94）：
#IC7300_CIV_ADDR=0x94
# IC-7300MK2 地址覆盖（默认 0xB6）：
#IC7300MK2_CIV_ADDR=0xB6
# IC-7300 用 CI-V 0x27 频谱，无需 FTDI 库——删掉/注释 MRRC_FTDI_LIB_DIR
```

**电台侧设置**（面板菜单，开机时设置一次）：

- `CI-V USB Port` = **Unlink from [REMOTE]**。
- `CI-V USB Baud Rate` = **115200**，必须明确选择 115200，不能保留 `Auto`；Icom 规定 `27 11` 波形输出仅在 Unlink + 115200 下可设置。选择 `ic7300`/`ic7300mk2` 后服务端默认即为 115200；显式设置 `MRRC_BAUD_RATE` 时必须一致。
- `CI-V Address`：IC-7300 默认 **94h**（`IC7300_CIV_ADDR`）；IC-7300MK2 默认 **B6h**（`IC7300MK2_CIV_ADDR`）。
- 建议开启 `CI-V Transceive`（连接时服务端会按型号自动发送开启命令：IC-7300 项目 0071，MK2 项目 0089）。
- **`SET` → `Connectors` → `MOD Input`（语音发射必查：这一组不对，PTT 按下只有载波、没有调制）**：
  - `DATA OFF MOD` = **`USB`** —— **非 DATA 模式**（SSB / AM / FM 语音）的调制输入源。停在 `MIC` 时对方听到的是「有发射、没声音」（FM 死载波），SSB 则表现为「功率很小或没有」（SSB 无调制＝无射频功率）。想同时保留手咪就选 `MIC, USB`。
  - `DATA MOD` = **`USB`** —— 数字 / DATA 模式的调制输入源。
  - `USB MOD Level` = **50 左右**（不要为 0）—— USB 调制输入电平。
- `SET` → `Connectors` → **`USB SEND` 保持 `OFF`**（MK2 同组另有 `USB Keying (CW/RTTY)`）：它把 USB 口的 DTR/RTS 当作 PTT，一旦设为 `USB(A) DTR/RTS`，电脑打开串口就等于按下 PTT。
- 接收侧：`SET` → `Connectors` 里的 USB 音频输出选择保持 **AF**（不是 IF）、输出电平不为 0，否则网页接收无声（日志出现 `RX audio is near-silent`）。

**音频**：IC-7300 的 USB 音频是 **48 kHz 原生**，服务端直接透传，**无需重采样**。Windows 下该声卡以 `USB Audio CODEC` / `USB Audio Device` 形式枚举（本地化系统可能是「麦克风 (USB Audio Device)」）。`MRRC_AUDIO_RX_DEVICE` / `MRRC_AUDIO_TX_DEVICE` 填 `USB Audio` 即可同时匹配两种形式。启动及 RX/TX 打开日志会列出 `host`、`default`、`actual`、`channels`；IC 正常值应为 `actual=48000Hz`。

**频谱**：来自 CI-V `0x27` 帧，走 CAT 串口，**不需要 FT4222**。启动时依次发送 Scope Display ON（`27 10 01`）、Center、±100 kHz Span、Data Output ON（`27 11 01`）；两个 ON 开关缺一不可。分片队列最多保留 44 个片段，积压时丢弃最旧数据；WebSocket 以 30 Hz 调度且只发送新完成的真实帧。菜单 SPAN 可调跨度，SPD 对 IC 只提供 FAST/MID/SLOW。

**验证清单**：

1. 状态栏 ●Serial 变绿。
2. 频率、模式、S 表跟随电台面板变化（面板改动也会回传——Transceive）。
3. 浏览器能听到接收声音（📶 音量滑杆、状态栏无「无声」告警）。
4. 瀑布图有信号（频谱来自 CI-V `0x27`；发射期间**仍会刷新**，这是与 FT-710 不同之处）。
5. 长按 PTT 说话，功率/ALC 表有反应（首次发射请用小功率确认）；**ALC 表不动＝调制没进来**，回去核对上面的 `MOD Input` 三项。

### 0.6.3 FT-710

**驱动**：

- **必须**：Silicon Labs CP210x Universal Windows Driver（CAT 串口用）。
- **可选**：FTDI D2XX 驱动 —— 仅当需要 **FT4222 真频谱**时。没装则自动回退到 S-meter 合成频谱（可用但不含真实 FFT 数据）。

**设备管理器确认**：「端口 (COM 和 LPT)」显示**两个** Silicon Labs CP210x COM 口。**较低编号**的那个通常是 CAT 用的 **Enhanced COM Port**；另一个是 FT4222 频谱口（`MRRC_SCOPE_PORT`，留空即自动探测）。

**`mrrc_modern.env` 完整示例**：

```ini
MRRC_RADIO_MODEL=ft710
MRRC_SERIAL_PORT=COM3          # 改成 Enhanced COM Port（两个 CP210x 里较低编号）
MRRC_BAUD_RATE=38400
MRRC_WEB_HOST=0.0.0.0        # 随包默认值（所有接口）；改成 127.0.0.1 则仅本机可达
MRRC_WEB_PORT=8888
MRRC_WEB_PASSWORD=change_this_password
MRRC_AUDIO_RX_DEVICE=USB Audio
MRRC_AUDIO_TX_DEVICE=USB Audio
MRRC_FTDI_LIB_DIR=vendor\ftdi\windows\bin\x64
#MRRC_SCOPE_PORT=              # 留空自动探测 FT4222 频谱口
```

**电台侧设置**（FT-710 面板，四项都设好再开始）：

1. **`FUNC` → `RADIO SETTING` → 各模式 `MOD SOURCE` = `USB`**。SSB 必设；AM / FM / PSK/DATA 若要用也设 USB，否则 PTT 按下没有调制。
2. **`FUNC` → `RADIO SETTING` → `RPTT SELECT` = `OFF`**。PTT 由 CAT 命令控制，不走 RTS/DTR。
3. **`FUNC` → `OPERATION SETTING` → `GENERAL` → `SCU-LAN10` = `ON`**，并把同一页最底下那条
   **`CAT-1 RATE` = `38400`**。本服务端走 USB CAT（`MRRC_BAUD_RATE=38400` 要与之相同），
   但**很多第三方远程软件靠 SCU-LAN10 这条通道取频谱**；把 CAT-1 速率固定成 38400，
   两边（本项目与第三方）就都读得懂，不必来回改菜单。
4. **`FUNC` → `OPERATION SETTING` → `GENERAL` → `TX TIME OUT TIMER`（TOT，发射超时定时器）**：
   连续发射到设定时间后**自动切回接收**，防止 PTT 卡住打出一条长时间的死载波。

**TOT 怎么设**：`FUNC` 旋钮 → `OPERATION SETTING` → `GENERAL` → `TX TIME OUT TIMER` →
旋转 `FUNC` 或点数值两侧的 `<` / `>` 选值 → **再按一下 `FUNC`**（或等约 3 秒自动保存）→
多点几次 `BACK` 回到正常画面。可选 `OFF` 或 **1–30 分钟**；出厂默认 `OFF`（欧洲版默认 10 分钟）。

**设好后的表现**：只要开始发射就倒计时，快到点时**提前约 10 秒「嘀」一声**提醒，时间一到
强制回到接收状态。远程操作建议设 **3 分钟**做兜底；**FT8 / RTTY 这类长时间连续发射的数字模式
建议设 `OFF`**，否则一个时隙序列会被中途切断。

> **别设错的那一项**：同一页里还有 `CAT-1` / `CAT-2` / `CAT-3` 的 `TIME OUT TIMER`，
> 那是 **CAT 指令超时**（单位毫秒），与发射超时是两码事。名字很像，位置相邻。

**两层兜底各管一段**：电台侧 TOT 管「物理上不许一直发」，服务端 `MRRC_PTT_MAX_TX_SECONDS`
（W103D 镜像默认 `120`）管「远端会话断了也要松键」。两个都开才是完整的——只开一个，
另一条路上仍然可能留下长发射。

**音频**：FT-710 的 USB 音频是 **44.1 kHz 原生**，服务端会把它重采样到 48 kHz 再走网络。Windows 下该声卡同样以 `USB Audio CODEC` / `USB Audio Device` 形式枚举，`MRRC_AUDIO_RX_DEVICE` / `MRRC_AUDIO_TX_DEVICE` 填 `USB Audio` 即可。

**频谱**：真频谱来自 **FT4222 SPI**（需要 `MRRC_FTDI_LIB_DIR` 指向含 `FT4222.dll` / `ftd2xx.dll` 的目录）；缺失时回退到 **S-meter 合成频谱**。发射期间频谱**暂停**并显示「频谱暂停」，属正常现象。

**验证清单**：

1. 状态栏 ●Serial 变绿。
2. 频率、模式、S 表跟随电台。
3. 浏览器能听到接收声音。
4. 瀑布图有信号；若只有 S-meter 合成频谱，说明 FTDI 库缺失或未指向正确目录。
5. 长按 PTT 说话，功率/ALC 表有反应（确保 `MOD SOURCE=USB`）。

### 0.6.4 常见问题（FAQ）

| 问题 | 解答 |
| ------ | ------ |
| 我该选 `ft710`、`ic7300` 还是 `ic7300mk2`？ | 看你手头的电台：Yaesu FT-710 用 `ft710`；Icom IC-7300 用 `ic7300`；IC-7300MK2 用 `ic7300mk2`。MK2 默认地址为 0xB6，且 Transceive 菜单项与普通 7300 不同，不能混选。其它型号（IC-705/7610/7760、FTDX10/101D/101MP、FTX-1F、FT-891）见 §0.5 的实验性列表 —— 默认只收不发。 |
| 换了一台电台，要重装软件吗？ | 不用。改 `MRRC_RADIO_MODEL` 和串口/波特率，重启即可。 |
| Serial 一直是红点 / 灰点 | CAT 未连通。逐项检查：电台开机、USB 线、`MRRC_SERIAL_PORT` 是否指向设备管理器里的正确串口、波特率（IC-7300=115200、FT-710=38400）与电台菜单一致。 |
| IC-7300：设备管理器里没有 COM 口 | 驱动未装或 USB 线是纯充电线。换数据线，检查「端口 (COM 和 LPT)」是否有 `USB Serial Port`。 |
| FT-710：两个 COM 口，选哪个？ | 选**较低编号**的 CP210x（Enhanced COM Port，CAT）。`MRRC_SCOPE_PORT` 留空自动探测另一个。 |
| 没声音 / 只听到电脑音箱声音 | 音频设备没锁对。把 `MRRC_AUDIO_RX_DEVICE` / `MRRC_AUDIO_TX_DEVICE` 设为 `USB Audio`；若有多台同类 USB 声卡，用启动日志里 `PyAudio initialized. Available devices:` 列出的**索引号**锁定。 |
| FT-710：瀑布图有图形但不是真频谱 | 这是 S-meter 合成频谱。确认 `MRRC_FTDI_LIB_DIR` 指向含 `FT4222.dll` / `ftd2xx.dll` 的目录，并已装 FTDI D2XX 驱动。 |
| IC-7300：瀑布图不动 | 确认 `CI-V USB Port=Unlink from [REMOTE]`、`CI-V USB Baud Rate=115200`（不是 Auto）、CI-V 地址及 `MRRC_SERIAL_PORT`，再运行 `python _diag_ic7300_scope.py <PORT> 115200 0x94`（MK2 用 `0xB6`）；脚本会开启显示+数据输出，并在退出时关闭数据输出。 |
| 状态栏出现红色「无声」 | RX 音频流 20 秒全零，电台 USB 音频接口可能卡死。重启电台或重插 USB 线。 |
| 改了配置没生效 | 改完 `mrrc_modern.env` 必须**重启 MRRC Modern**（关掉窗口重新启动）。 |
| 双击没反应 / 黑窗口一闪就没了 | 先看 `launcher.log` 与 `server.log`，再用开始菜单里的 **MRRC Modern Server** 绕开启动器判断是谁的问题 —— 见 §6.1。 |
| 卡在 `Detecting the radio on N serial port(s)` 不动 | 有一个「不是电台的串口」占着号（最典型是 Intel AMT 的 Serial over LAN）。**v1.25.0 起会跳过这类口、探测写入带 1 秒超时**，不再卡死；老版本请先在设备管理器里禁用那个口。见 §6.1 第 4 条。 |

## 0.7 macOS 安装与初始化

本章面向 **macOS 桌面版（`MRRC-Modern-v1.28.2-arm64.dmg`）**：安装 → 首次启动（零配置）→ 连接设置 → 局域网访问。**全程不需要打开终端、不需要编辑配置文件**；安装包把最常用的设置都做成了图形化。

> 适用：Apple Silicon（M1/M2/M3/M4），macOS 11 及以上。应用是**自包含**的，拖到「应用程序」只是标准做法；从桌面/下载文件夹直接双击也能运行。

### 0.7.1 安装（5 步）

1. 打开官网 <https://www.vlsc.net/mrrc_modern/> ，点 **Download for macOS** 下载 `MRRC-Modern-v1.28.2-arm64.dmg`（约 81 MB）。
2. 双击刚下载的 `.dmg` → 弹出窗口里看到 **MRRC Modern** 图标和一个 **Applications** 文件夹。
3. 把 **MRRC Modern** 图标**拖进 Applications** 文件夹（松手即完成安装）。
4. **第一次启动**请右键点 Applications 里的 **MRRC Modern** → 选 **打开** → 弹窗里再点一次 **打开**（因为免费签名，系统会拦一次；只第一次需要）。
5. 以后双击即可直接打开。

> **两种弹窗必须分清**（含义完全不同）：
>
> - 「**无法验证开发者**」/「无法检查是否包含恶意软件」= **正常**。本应用使用自签名（ad-hoc），系统"不认识"它 → 用第 4 步的 **右键 → 打开 → 打开** 放行一次即可，之后双击可用。
> - 「**已损坏，无法打开。你应该将它移到废纸篓**」= **不正常**：应用签名无效，**这个提示右键也绕不过去**。说明你拿到的是 **v1.18.0 或更早**的包 —— 请重新下载 **v1.18.1 或更新**版本。
>
> 详见 `docs/MACOS_INSTALLER_GUIDE.md` 第 3 章（含 `xattr` 应急解封与签名自检命令）。

> **FT-710 USB 驱动：macOS 11.3+ 免驱**（2026-09-18 实测：macOS 15.3 从未装过任何第三方驱动，内核日志显示 CP2105 `0x10c4/ea70` 由系统直接枚举）。仅 **macOS 10.11–11.2** 需要先装 Silicon Labs CP210x VCP 驱动 v6.0.3：下载 <https://www.vlsc.net/mrrc_modern/downloads/SiLabsUSBDriverDisk.dmg> → 挂载 → 双击「Install CP210x VCP Driver」→ 系统设置里批准内核扩展；**Apple Silicon 需先把启动安全性降到「允许用户管理内核扩展」**（恢复模式 → 启动安全性实用工具）——所以能免驱就不要装。验证：插入电台后 `ls /dev/cu.usbserial-*` 应出现设备。FT4222 真频谱库已随应用打包，无需另装 D2XX。

### 0.7.2 首次启动：零配置 + HTTPS

启动后**什么都不用配**，软件会自动完成：

1. 屏幕**右上角菜单栏**出现 `MRRC Modern :8888` 图标。
2. **浏览器自动打开**登录页。首次访问是 HTTPS，浏览器会提示**「连接不安全 / 您的连接不是私密连接」**——这是**正常的**，因为用的是软件自动生成的**自签名证书**：点 **高级 → 继续访问** 即可（只需这一次）。
3. 登录页顶部显示**自动生成的登录密码**；忘记就点菜单栏 **Show Password…** 随时查看。
4. 用这个密码登录，进入主界面。
5. **插上电台**（FT-710 或 IC-7300/MK2，USB 线 A→B 或 C→B）：首次运行自动探测电台型号、串口和音频设备，**插上就能用**。
6. **首次启动会弹一次「麦克风」权限询问 → 点「允许」**：这是**接收**电台声音所必需（macOS 把"音频输入"统一归入麦克风权限类，不是只有麦克风才需要）。

> **为什么需要麦克风权限？** 应用要把电台 USB 声卡收到的声音送到浏览器播放，就必须读取"音频输入"。macOS 对"未授权"的回应**不是报错，而是沉默**：捕获流照样显示"已启动"，但数据全为 0 —— 于是**控制、频谱、PTT 都正常，就是接收没有声音**。当时点了「不允许」也可以补救：**系统设置 → 隐私与安全性 → 麦克风** → 打开 **MRRC Modern**。注意**每次升级都会再问一次**（自签名应用的授权绑定当次构建，属正常现象）。

> **为什么默认 HTTPS？** 局域网里密码和遥控数据默认加密传输，避免被同网段的人抓包。自签名证书不代表"不安全"，只是浏览器不认识签名者；点一次「继续访问」即可。

### 0.7.3 连接设置（改电台 / 串口 / 音频 / 密码）

想换电台、换串口、换声卡或改密码，**不用重装、不用碰配置文件**：

1. 登录后点网页**顶栏菜单 →「连接设置…」**。
2. 在弹出的对话框里修改：
   - **电台型号**（下拉列出全部已注册型号：FT-710 / IC-7300 / IC-7300MK2 + 实验性型号，见 §0.5）
   - **串口**（下拉列表自动列出可用的 `/dev/cu.*`）
   - **RX 音频设备** / **TX 音频设备**（下拉列表列出本机音频设备，FT-710 一般是 `USB Audio Device`，IC-7300 一般是 `USB Audio Codec`）
   - **登录密码**
3. 点 **保存并重启** —— 软件自动重启生效；只点 **重启服务** 则不改设置、仅重启。

### 0.7.4 进阶：Edit Configuration（可选）

普通用户用不到。高级用户可在菜单栏 **Edit Configuration…** 用文本编辑器打开配置文件：

```
~/Library/Application Support/MRRC-Modern/mrrc_modern.env
```

- 变量用 `MRRC_*` 前缀（旧的 `FT710_*` 仍兼容）；改完在菜单栏 **Restart Server** 重启生效。
- **HTTPS 默认开启**（无需任何配置）；仅当想退回明文 HTTP 时才加一行 `MRRC_SSL=off`。
- 配置、自签名证书、记忆频道都在这一个目录里；**彻底卸载**时把应用拖进废纸篓、再删掉 `~/Library/Application Support/MRRC-Modern/` 即可完全清除。

### 0.7.5 手机 / 其他设备访问（局域网）

1. Mac 和手机连**同一个 Wi-Fi / 局域网**。
2. 查看 Mac 的 IP：**系统设置 → Wi-Fi → 详细信息 → IP 地址**（或以太网同理）。
3. 手机上浏览器打开 **`https://你的Mac的IP:8888`**（例如 `https://192.168.1.50:8888`）。
4. 首次同样会提示证书不受信任，点**高级 → 继续访问**。
5. 用登录页上的密码登录，手机就能遥控电台、看频谱、说话。

| 浏览器红色「您的连接不是私密连接」 | **正常**。自签名证书未被浏览器厂商信任，点**高级 → 继续访问**即可，只第一次出现。 |

| 手机上连不上 `https://ip:8888` | 确认同一网络、IP 正确、地址写的是 `https://`（不是 http）、Mac 的防火墙允许接收连接。 |

## 0.8 与第三方电台软件共用串口（WSJT-X / JTDX / FLDIGI / rumLogNG 等）

在 WSJT-X 等软件里直接对照以下参数填入（FT-710，macOS 串口名为例；Windows 填对应的 Enhanced COM 口）：

| 参数 | 填入 | 为什么 |
| --- | --- | --- |
| Serial Port | **`/dev/cu.usbserial-0121DB3A0`** | 必须 `cu.` 开头——`tty.` 是等载波的调制解调器语义，极易报「Port busy」 |
| Baud Rate | **38400** | Yaesu 官方默认；电台菜单 **CAT RATE 必须同为 38400**（MRRC Modern 默认值相同） |
| Handshake / Flow Control | **None**（或 Hardware RTS/CTS） | **禁选 Xon/Xoff**——软件流控会把 0x11/0x13 当控制字节，CAT 问答直接失灵 |
| Data/Parity/Stop | 8N1 | 与电台菜单 CAT 设置一致 |

> ⚠️ **串口独占法则（最容易撞的坑）**：同一时刻**只能有一个程序**打开 CAT 串口。要用 WSJT-X/JTDX/FLDIGI，先退出菜单栏的 MRRC Modern（它持有 CAT 口）；反过来 MRRC 启动时串口打不开，先关掉正在运行的其它电台软件。FT-710 的 CP2105 双口里只有 **Enhanced**（`…A0`）是 CAT，另一个 `…A1`（Standard）跑不了 CAT。占用排查：`lsof /dev/cu.usbserial-0121DB3A0`。

## 0.9 接入云端（Cloud Hub）

给这台机器一个公网入口 `https://<你的呼号>.mrrc.vlsc.net/`：**不需要**自己有公网 IP，也**不用**在路由器上开端口。
应用**出站**连到中转（hub），入口的 TLS 在中转处终结，中转再回连本机。

**准备**：一个有效呼号。门户地址 `https://portal.mrrc.vlsc.net/`（对话框顶部「服务器」一行显示的就是它）。

**申请**（两条路，进的是同一个队列）：

1. **应用里申请**（推荐；抽屉菜单 → **接入云端（Cloud Hub）…**）：填 **呼号**（大小写不敏感；
   `BG1SB/P`、`4X/BG1SB` 这类便携/前缀写法会被拒绝 —— 登记的是身份，而且标签要当 DNS 名用），
   可选的 **联系方式** 便于运维核对，点 **申请入口 / 接入**。
2. **网页上申请**：任何浏览器打开 `https://portal.mrrc.vlsc.net/` 提交呼号。批准后运维会给一串
   **登记口令**；回到应用的同一个对话框，把它填进「登记口令」一栏点接入即可。为什么网页申请的
   要这么绕一圈：应用只能看见**它自己提交**的那条申请，凭口令「认领」才能把网页上批准的那条接回来。

**核验与批准**：呼号命中 **Club Log** 呼号库（27 万余条）会**当场自动核验**；查不到的转人工核验。
核验通过后才由运维**分配入口**（标签 + 端口）—— 这一步是人工的，通常在核验后很快完成。

**等待时**：对话框中部有一行 **自动接入** 状态，写着本机上次询问 hub 的时间与结果
（已提交 / 已核验 / 已批准 / 已接入 / 联系不上 hub…），**不必守着这个窗口**。
想立刻问一次就点 **刷新状态**（它一直可以点 —— 早先版本里它看着像禁用，其实不是）。

**批准之后什么都不用做**：服务端每 30 秒自查一次（v1.25.0 起），发现批准就自己签证书、登记入口、
把隧道拉起来。

**首次接入**会提示 **重启应用以启用新证书**：TLS 上下文是在进程启动时建立的，新证书要重启才生效
（不重启入口会一直 502）。接入完成后对话框显示入口链接、证书与隧道状态。

**入口地址的规则**：就是呼号本身，**没有端口、没有路径、没有产品后缀**（早期的 `:9988` 与
`/mrrc_modern/<呼号>/` 写法都已取消）。同一个呼号再次申请会**复用原来的标签与端口**，不会越排越多。

**别把入口名当安全边界**：呼号是公开标识、入口可枚举，所以防线在「核验通过才给访问」，
而不在「别人猜不到」；入口后面仍是本机的登录口令（§0 第 3 步）。

**出问题**：抽屉菜单 → **🐞 遇到问题** → 生成并上传诊断包（§6），答复发布在
`https://www.vlsc.net/mrrc_modern/answers/`。

## 0.10 版本与更新

- **真实版本号**：安装目录里的 `version.txt`（Windows 默认 `C:\Program Files\MRRC Modern\`，
  macOS 在 `MRRC Modern.app/Contents/Resources/`）；诊断包里也带一份。
  **抽屉菜单底部那行**（形如 `FT-710 v1.0`）里的 `v1.0` 是**前端资源串**，既不是发布版本也不是电台固件版本 ——
  报版本时别拿它当依据。
- **应用能查新版，但还不能自己装**：服务端有只读的 `GET /api/update/check`，拿运行版本与站点上的
  `latest.json` 比对，只回答「有没有更新」，**不下载、不写任何文件**；**界面上目前没有升级按钮** ——
  升级器会改动它运行的机器，所以要么完整要么不做，不做半成品。
- **升级怎么做**：到 <https://www.vlsc.net/mrrc_modern/> 下载对应平台的安装包**覆盖安装**一次即可。
  配置、证书、录音都在**用户数据目录**（Windows `%LOCALAPPDATA%\MRRC-Modern`，
  macOS `~/Library/Application Support/MRRC-Modern`），不在安装目录里，所以覆盖安装不会动它们。
  想彻底重来见 §6.2。
- **换电脑**：不要重配。用下载页的 `MRRC-Modern-Backup.cmd` 把用户数据目录（配置 + 证书 +
  记忆频道 + 天调学习值 + 云隧道配置）打成一个包，在新机器上装好应用后一次恢复。**证书不能重签**
  （云入口钉的是它），详见网站指南 §6.5。

## 0.11 分享一个「只收听」入口

想让别人听你这里的守听声、但不给发射与设备设置，就再设一个**互不相同的口令**：`MRRC_LISTEN_PASSWORD`
（空 = 关闭）。用这个口令登录会直接进入 `/listen` 收听页（而不是主界面）：

- **能做的**：改频率 / 模式（含波段快捷与记忆频道调出）、S 表与瀑布、接收音频 + 浏览器侧音量，
  外加一个「测试音」按钮；
- **不能做的**：发射（PTT / TUNE / CQ / FT8）、天调、录音，也改不了任何设备设置。

这是**服务端**限制，不是把按钮藏起来：`/WSradio` 只放过频率/模式/记忆类命令，`/WSaudioTX` 与 `/WSatr1000`
直接以 4003 关闭，非 GET 的 `/api/*` 返回 403。页面底部那行写着「收听模式仅允许调整频率与模式」。
**两个口令设成同一个值 = 不再有只读角色**，能看到主界面的全部能力。

要把收听页开放到公网（`deploy_listen_proxy.sh` 默认发到 `https://www.vlsc.net/mrrc_modern/listen`），
用仓库里的那个脚本即可（幂等，直接反代到本机服务，见 README 的 Listen-only 一行）。

**电台电源那两项**（v1.27.x 起）刻意分成两种意图，因为「开机」在 FT-710 上**不保证成功**：
实测（2026-07-27/28）`PS1;` 唤醒在健康电台上也常常被忽略，而且 `PS0;` 若落在 `PS1;` 之后十几秒的启动窗口内
会把电台的 CAT 单片机卡死（要拔电才能救）——当年的做法是把整个电源键撤掉。现在的做法是把守卫做进服务端，
并让两种意图互不混淆：

- **重开电台**：关机之后每 30 秒再试一次，直到电台回话（用 `FA;` / CI-V 回读确认，不是「我发过命令」）、
  或 15 分钟用尽、或你点顶栏 PWR 取消。每轮都会重新武装那条 15 秒保护窗口，所以**救援期间点「关机」会被拒**
  （消息里带剩余秒数）——想停下来请用「取消」，它不发任何电台命令。
- **关机**：先取消可能在跑的救援，然后只发关机命令，**绝不**自己上电。确认框里写明了「远程将不可用」。
- 两种动作在**发射中（含 FT8 正在发射）都会被拒绝**；`PS0` 连发两次（第一次偶发丢失）；关机前会跳过一次电源轮询。
- 如果 15 分钟没醒，界面会明说「需要到现场按面板开机」——这是诚实的结论，不是失败重试的提示。

> 菜单底部那行里的型号来自当前后端；`v1.0` 是**前端资源串**，既不是发布版本也不是电台固件版本 ——
> 真实发布版本看安装目录的 `version.txt`（§0.10）。

## 4. 安全须知（请先阅读）

1. **PTT 是「按住才发射」**，没有任何自锁模式；松开即停。若页面或浏览器崩溃，服务端死手开关会在最后一个客户端断开时自动强制释放发射（`TX0`）。
2. **TUNE 同理**，长按出载波、松手即停——调谐时请确认天线已接好、SWR 正常，长时间发射前建议先用小功率。
3. 发射期间**频谱暂停**（FT-710 电台会干扰频谱数据流），瀑布图显示「TX 发射中 — 频谱暂停」是正常现象。IC-7300 使用 CI-V `0x27` 频谱，发射期间通常继续刷新。
4. **无声（🔇）告警**：状态栏出现红色「无声」表示 RX 音频流 20 秒全零——电台 USB 音频接口可能卡死，请重启电台或重插 USB 线。
5. 多人共用时，PTT 所有权按 **socket** 仲裁，不按登录令牌：按下时服务端把上行音频交给这台浏览器**最近连接**的那条音频 socket；同一会话里另一条 socket 一旦真的开始送音频，会在一帧（约 20 ms）内接管 —— 这是给「一个登录开了两个标签页」用的。**别人的会话**既不能靠连接、也不能靠发流抢走你的发射；你在按键期间收到别人的 `ptt:false` 也不会松开，界面会收到 `ptt_keyed_by_other` 提示。别在别人发射时抢按。
6. 无线局域网内建议使用 HTTPS（自签名证书首次会有浏览器警告，属于预期行为）；`http://` 明文下浏览器会禁用麦克风与音频工作线程（AudioWorklet），iPhone 上尤其如此。

## 5.5 FT8 工作模式

主菜单 → **FT8 模式** 打开独立的 FT8 界面（`/static/ft8.html`）：左侧是解码列表（呼号 / 网格 / SNR / 距离），
中间是音频瀑布，右侧是 TX 面板（CQ / 呼号、Grid、射频模式设置）与 QSO 面板。

- **切换语义**：进入 FT8 时电台切到 FT8 频点与 DATA-U，滤波 3 kHz；点右上「←」回到 SSB 时，
  频率 / 模式 / 滤波 / 功率 / AGC / ATT / PREAMP **逐字段恢复**。两个模式共用同一条 TX 门控，
  **结构上不可能同时键控**——所以在 FT8 里发射时，SSB 页面的 PTT 不会（也不能）抢走发射。
- **解码**：默认走快路径（C 解码器），命中判据（正在通联的 AP 上下文、疑似漏解、或按「深度解码本槽」）
  才对**同一时隙**补跑 WSJT-X 深路径并取并集——解出的条数不会比纯深路径少。
- **引擎开关（v1.28.x 起）**：菜单 `Settings` 区的 `FT8 ON/OFF`（§2.11 序号 52）与 FT8 页设置抽屉里的
  「引擎常驻」写的是**同一个** `engine_always_on`。`ON` = 服务启动即开始解码、出瀑布（**只收不发**）；
  `OFF` = runtime 停、DSP worker 退出、RX tap 释放 —— 在小盒子上是**一个核**的差别，
  不用 FT8 时关掉更划算。切换立即生效并落盘，重启后保持。
- **设置**：呼号 / Grid / 射频模式（`DATA-U` / `USB`）/ 发射音频频率 / 引擎常驻，在 FT8 页面的设置抽屉里，
  与 Cloud Hub 呼号无关。
- **紧急停止**：任意已认证会话都可以按 STOP，FT8 的发射立即中止并释放 PTT。
- **只读角色**：`listen` 角色可以看解码与瀑布，不能切模式、不能发射。

设计与验收：`docs/superpowers/specs/2026-10-12-ft8-work-mode-design.md`、
`docs/superpowers/specs/2026-10-13-ft8-fast-path-cascade-design.md`、`docs/ft8-m5-acceptance.md`。

## 6. 遇到问题怎么报（诊断包）

菜单（图 2）→ **🐞 遇到问题**，会新开一个标签页（不打断当前的电台连接）：

1. 写清现象：什么表现、什么时候开始、电台型号与频率（越具体越省一轮往返）；
2. 点 **生成诊断包** —— 服务端收集日志尾部、脱敏配置、环境/电台/音频状态快照与自动体检结论；
3. 点 **上传给维护者**（需要这台机器能访问互联网），界面会给出一个**编号**；
   答复会发布在 <https://www.vlsc.net/mrrc_modern/answers/>：自动分诊每 10 分钟看一次新包，
   结论以卡片形式出现在该页（可用编号或关键词搜索；证据不足时会被标为「需要更多信息」）；
4. 没有网络时（例如脱网的树莓派）点 **只保存到本地**，把生成的 `support-<编号>.zip` 用邮件/微信发给我。

同一页下方还有一张 **远程协助** 卡片：不想先传包、想让维护者直接进来看时用它（§6.4）。

**包里有什么**：`logs/`（日志）、`state/config-redacted.env`（脱敏配置）、
`diagnostics/summary.txt`（**先看这个**：启动次数/崩溃痕迹/数据新鲜度/音频与串口事实）、
`diagnostics/env.json`（机型、串口、频谱模式、音频设备表与采样率）、`diagnostics/client.json`（浏览器侧上下文）。

**包里绝不包含**：登录密码、证书私钥、任何令牌，也不包含录音、记忆频道与天调学习值 ——
生成时按白名单裁剪 + 值替换，替换次数写在 `manifest.json` 里。

日志位置：桌面安装版在用户数据目录（Windows `%LOCALAPPDATA%\MRRC-Modern\logs`，
macOS `~/Library/Application Support/MRRC-Modern/logs`）：`server.log`（轮转 2 MB × 2）与
`server-stdout.log`（启动窗口，每次启动重建）；源码与树莓派模式写在程序目录的 `logs/` 下。

### 6.1 启动器打不开（黑窗口、闪一下就没了）{#launcher-trouble}

按层排查，别急着重装：

1. **看日志**：同目录下的 `launcher.log` 与 `server.log`。启动器会把服务器的输出也抄一份到那里 ——
   黑窗口里来不及看清的东西，日志里通常在。
2. **绕开启动器**：开始菜单 → **MRRC Modern Server**（macOS：`MRRC Modern Server.app`）。
   它直接把服务器跑起来、把地址与口令打印在窗口里，不碰浏览器 —— 用它区分"是启动器的问题"还是
   "服务器起不来"。
3. **端口被占**：日志里若有 `Address already in use`（或启动器提示已自动换端口），把配置文件里的
   `MRRC_WEB_PORT` 改成别的（如 8889），或先关掉占用它的进程。
4. **首次探测看着像卡住**：第一次启动会逐个试串口，日志里是
   `Detecting the radio on N serial port(s): ...`。若停在这里，多半是有一个"不是电台的串口"占着号
   （最典型的是 Intel AMT 的 Serial over LAN）。**v1.25.0 起这类口会被跳过、探测写入带 1 秒超时**，
   不会再卡死；升级前的老版本则可能一直停住 —— 先把那个口在设备管理器里禁用即可。
5. 还是黑屏：按下面从零开始，或按上一节给我一份诊断包。

### 6.2 一键清理脚本（从零开始）{#clean-slate}

Windows 用站上 **下载页 → 清理脚本**：`downloads/MRRC-Modern-Cleanup.cmd`
（源码在仓库 `tools/windows/MRRC-Modern-Cleanup.ps1`）。它会：

1. **先列出**它找到的一切：程序目录、历代用户数据目录（`%LOCALAPPDATA%\MRRC` 与 `MRRC-Modern`
   两代名字）、开始菜单/桌面快捷方式、注册表里的卸载项；
2. **把用户数据目录里的配置、证书、日志、fleet 复制到桌面**的 `MRRC-backup-<时间戳>\`，**再**删除；
3. 让你确认后才动手（输入 `clean`），卸载项走静默卸载（`/VERYSILENT`）。

**两件必须知道的事**：

- **录音（`recordings/`）不进备份**（可能上 GB），但**会被一起删除** —— 要留就先自己拷走；
- 清完等于全新机器：首次启动会重新探测串口、重新生成自签名证书，密码回到你安装时设的那个。

macOS 没有对应脚本，手动即可：先备份 `~/Library/Application Support/MRRC-Modern/mrrc_modern.env`
与其中的证书，再删 `~/Library/Application Support/MRRC-Modern` 与 `/Applications/MRRC Modern.app`。

### 6.3 接入云端报 certificate has expired（Windows）{#cloud-cert}

**现象**：设置里点「申请入口 / 接入」，界面报这么一句，但**同一个浏览器**打开
`https://portal.mrrc.vlsc.net/` 却一切正常：

```
portal did not answer (https://portal.mrrc.vlsc.net): cannot reach the portal
(URLError: <urlopen error [SSL: CERTIFICATE_VERIFY_FAILED] certificate verify failed:
certificate has expired (_ssl.c:1000)>)
```

**这不是门户、也不是网络的问题**：这句话本身就说明 DNS、TCP、TLS 握手都已打通 —— 是应用在
**拿到证书之后自己拒绝**的。原因是这台 Windows 的**本机证书库**里留着一份与被服务链条同名同密钥、
却已经过期的证书（Windows 会把见过的中间证书缓存进 CA 存储；Let's Encrypt 的中间证书会换代重签，
缓存那份到期后正是这个形态）。应用走的那条 Python/OpenSSL 路径只认本机证书库，于是把库里那张
放进链里判它过期 —— 而**浏览器用自己那套根与链构建，不吃本机 CA 缓存**，所以照常能开。
「浏览器能上、应用不能」正是这个故障最好认的特征。

**处理办法**：下载 [MRRC-CertDoctor.zip](downloads/MRRC-CertDoctor.zip)（约 4.6 MB，**整个解压**后
双击 `MRRC-CertDoctor.cmd`；源码在仓库 `tools/windows/MRRC-CertDoctor.ps1`）。它只做三件事：

1. **体检（默认只读，不改任何东西）**：时钟/校时、代理设置、DNS 与 TCP、应用日志里那条报错原文、
   门户实际下发的证书链、本机四张证书库里 Let's Encrypt / ISRG 家族的清单；
2. **判定**：把本机证书库导出成 PEM，用随包自带的 openssl 对那条链做 `verify` —— 给出的判词与
   应用那条路径一致（这就是它自带 openssl 的原因：换别处的 openssl，判词就不可比了）；
3. **修复（`MRRC-CertDoctor.cmd -Fix`）**：把能证明是它的过期证书**备份后**删掉；删完若变成
   「找不到签发者」，再问你是否导入当前的两张 Let's Encrypt 根证书。每删一张都先备份，
   报告里写着 `certutil` 恢复命令。

结束后桌面会多出 `MRRC-CertDoctor-<时间>\report.txt` 与同名 `.zip`：修好了就退出应用、重启它，
再点一次接入；**修不好就把那个 zip 发给我们** —— 报告里已经包含继续判断所需的全部事实。
另外注意：**诊断包上传与软件更新检查走的是同一条 HTTPS 路径**，会一起坏，属同一个原因
（所以那时也没法自己升级，得手工装新包）。

### 6.4 远程协助（限时窗口，你自己开、自己关）{#remote-help}

「🐞 遇到问题」页上的 **远程协助** 卡片（v1.26.0 起）：维护者不用先拿到诊断包，直接进来看。

1. **选窗口**：30 分钟 / 60 分钟 / 3 小时 —— 到点**自动关**，**不自动续期**；
2. **点「开启协助」**：页面给出 **用户名 + 口令**（口令只显示在这个页面上，请口头或短信告诉维护者），
   并显示剩余时间与「已连接」状态；
3. **维护者从 hub 侧用原生 `ssh` 进来**：SSH 只绑本机回环，公网上没有任何 SSH 端口，
   窗口一关监听与口令一起消失；
4. **随时可以停**：点「停止协助」即可（门户侧也能强制结束）；会话拿到的是 MRRC Modern 自己的权限
   （盒子 / 树莓派上是 `mrrc` 用户，**不会提权**），连接与认证失败都写审计。

维护者那一侧的操作与排障见 `docs/remote_help.md`。

### 6.5 换电脑：配置与证书一键备份/恢复（Windows）{#move-computer}

**换机时不要把安装目录拷过去，也不要手抄配置**：真正要带走的是用户数据目录
`%LOCALAPPDATA%\MRRC-Modern` —— 里面有电台机型/串口/声卡名/网页口令、HTTPS 证书与私钥、
记忆频道、天调学习值、云入口隧道配置。其中**证书尤其不能重签**：云入口钉住的就是这张证书，
换一张那条入口会 502。

用站上 `downloads/MRRC-Modern-Backup.cmd`（源码在仓库 `tools/windows/MRRC-Modern-Backup.ps1`）。
**不需要管理员权限。**

1. **旧电脑**：双击 `MRRC-Modern-Backup.cmd` → 选 `1`。桌面会多一个
   `MRRC-Modern-backup-<主机名>-<时间>.zip`，包里附清单（每个文件的大小与 SHA-256）。
   它**不含** `logs\` 与 `recordings\` —— 录音要留请自己拷走。
2. **想加口令**：用 `-Export -Encrypt`（会提示输两遍，口令不经过命令行、不落盘）。
   加密后是一个 `.zip.enc`，**丢了口令只能重新配置**。
3. **新电脑**：先装好 MRRC Modern（先不要打开），把 `.cmd` 与 `.ps1` 放同一个文件夹，
   双击 `.cmd` → 选 `2` → 选中那个包。脚本会先把新电脑现有的配置备份到桌面
   `MRRC-restore-pre-<时间>\`，再逐项写入。

**三件必须知道的事**：

- 包里同时有**网页口令、TLS 私钥和云隧道凭据** —— 像对待钥匙一样对待它，别放公共网盘、别发聊天群；
- 恢复 `auth-tokens.json` 只是**服务端那一半**，浏览器里的 cookie 不会跟着走，
  新电脑仍然要输一次登录口令（口令就是恢复过来的那个）；
- 证书来自另一台机器，浏览器会照常对自签名证书告警一次；**不要为了消警告重新签证书**，
  那会让已接入的云入口变成 502。

### 升级到含录音的版本（与旧安装/旧镜像的差异）

`requirements.txt` 在 v2.42 增加了 **`lameenc`**（服务端 MP3 编码器）。升级代码后**必须同步依赖**，否则 REC 会拒绝并提示原因（不会影响 CAT/音频/频谱）：

```bash
# 源码/脚本部署（start.sh 用的 venv/）
venv/bin/pip install -r requirements.txt
./restart.sh
```

启动日志会出现二者之一，据此判断是否就绪：

```
[INFO] mrrc: Recording ready: /opt/mrrc_modern/recordings (16 kHz mono MP3)
[WARNING] mrrc: Recording disabled: the MP3 encoder is missing — run `pip install -r requirements.txt` …
```

**已烧录的树莓派镜像**里没有 `lameenc`（镜像构建时该依赖还不存在）：在设备上执行 `venv/bin/pip install lameenc && sudo systemctl restart mrrc-modern` 即可；或重新烧录由 v2.42 之后源码构建的新镜像（其构建门禁已含该依赖）。

## 一键 CQ 呼叫（服务端，v1.17 起）

点按底部 **CQ** 键即可发起一次完整呼叫：**服务端**按下 PTT、播送内置的 CQ 录音、
播完自动松开。再点一次（按钮此时显示 **STOP**）可立即中止。

- 音频：`static/audio/cq.wav`（48 kHz 单声道，约 6.1 秒）。整段音频从服务器磁盘直接
  送进声卡，**不经过网络**，因此网络抖动不会影响发出去的内容。
- 状态：按钮与所有已连接客户端同步显示 `cqState`——`idle`（就绪）→ `calling`（呼叫中，
  1 秒刷新进度）→ `complete`（已完成）/ `aborted`（已中止，鼠标悬停显示原因）。
- 替换录音：把任意 16-bit WAV（单声道或立体声、任意采样率）放到服务器上，启动时用
  `MRRC_CQ_FILE=/path/to/cq.wav` 指定即可；服务端启动日志会打印
  `CQ ready: <路径> (…)`。文件缺失/损坏/超过 30 秒时日志打印
  `CQ key disabled: <原因>`，按钮失效但**不会静默失败**。
- 安全：一次呼叫只有一个音频来源——呼叫期间浏览器麦克风不上行、PTT 与 TUNE 会被拒绝。
  发起呼叫的页面断开、最后一个客户端断开、外部松键（含 `MRRC_PTT_MAX_TX_SECONDS` 看门狗）
  或服务端退出，都会立即切断载波。未验证机型（TX 门禁）下 CQ 与 PTT 一样被拒绝。
- 常见现象：呼叫刚开始就有 `aborted`，先看悬停提示——`unkeyed` 表示载波被外部释放
  （常见于开了最大发射时长看门狗），`client_gone` 表示发起端页面断开了。

## QSO 录音（服务端，v2.42 起）

点按 **REC** 开始录制、再点按停止。录制在**服务端**进行（不是浏览器），
因此：页面切到后台/关闭标签、甚至电台 CAT 断线都仍在录。

- 内容：接收音频 + 你的麦克风（单声道 MP3，16 kHz，64 kbps ≈ 28.8 MB/小时）。
  发射期间不录接收（避免录到电台自监听），电台暂停处补静音，时间轴与真实时间一致。
- 位置：`MRRC_RECORDINGS_DIR`（打包安装默认在用户数据目录；
  树莓派镜像为 `/opt/mrrc_modern/recordings`；源码运行默认 `recordings/`）。
- 回放：菜单 →「录音 Recordings」，列表里点「播放」（可拖动进度），
  也可「下载」或「删除」。**正在录制的那一份不能删除**。
- 保留：**不自动删除**。面板顶部显示条数与总占用；磁盘紧张时请手工清理
  （或把 `MRRC_RECORDINGS_DIR` 指向更大的卷）。
- 保护：单次录音超过 `MRRC_RECORDINGS_MAX_SESSION_MIN`（默认 240 分钟）会自动停止
  （只停，不删），防止忘记停止把磁盘写满。

### 录音出现"丢失 N 块"怎么办

录制按钮提示或面板行里出现 `⚠ 丢失 N 块`，表示**写入端跟不上音频输入**，该录音会有空洞。服务端日志会打印首条丢弃与原因。常见原因：磁盘/网络盘写入太慢（把 `MRRC_RECORDINGS_DIR` 换成本地盘）、CPU 长时间满载。编码本身极快（实测 80 ms 音频块约 0.04 ms，约 1900 倍实时），所以几乎不会是编码器的问题。

**整段录音全哑（能播但没声音）**：若日志里 `Recording started` 之后**立刻**出现「正在丢弃」、丢弃数一路涨，最后以 `Recording queue full on stop` 收尾 —— 或录音面板每次都显示 `⚠ 丢失 N 块`、文件明显是静音 —— 那是 v1.16.0 的录音写入端生命周期缺陷（同一进程里从第二次录音起没有消费者）。升级到含该修复的版本并**重启服务**即可；判定办法：`REC` → 停止 → 从菜单「录音」播放，听第一秒有没有声音。
