# SCU-LAN10 接入说明：一根网线，没有 USB，不能发射

FTDX101MP / FTDX101D / FTDX10 / FT-710（以下统称「这几台雅司」）跟别的机型**不一样**：

> 它们的瀑布不在 USB 口上。USB 口只有 CAT 和音频；瀑布走背后 13-pin ACC 的 SPI，
> 或者走雅司自己那台 **SCU-LAN10** 网络盒。

所以这一页讲的是**一条完全不同的接线**：盒子和电台之间**没有 USB 线**，只有一根网线到
SCU-LAN10。代价和收益都很直白：

| | 走 USB（别的机型那样） | 走 SCU-LAN10（本页） |
| --- | --- | --- |
| 盒子到电台 | USB 一根 | **一根网线到单位**，无 USB |
| 串口 / 声卡 | 需要 | **都不需要**（电台的 USB 口被单位占着） |
| 瀑布 | 这几台拿不到（只有 S 表合成的假瀑布） | **真瀑布** |
| 发射 | 正常 | **关闭**（见 §6） |
| 谁在用这台电台 | 盒子独占串口 | **单位独占**：雅司自己那套软件和盒子只能二选一 |

顺序：**接线（§2）→ 电台菜单三条（§3）→ 抄参数（§4）→ 填我们这页（§5）→ 看结果（§6）**。
后面是排障（§7）、给愿意跑命令的人的现场自检（§8）、边界（§9）。

---

## 1. 前提：客户得已经有那台 SCU-LAN10

这台单位是**另买的雅司配件**（约 ¥2000）。没有它，这几台雅司在我们软件里只能跑
「S 表合成的假瀑布」——那是已知限制，不是故障。

本文假设客户**已经在用**雅司官方的「SCU-LAN10 网络远程控制软件」，也就是说单位已经配好、
能连上、能听到声音。**我们要做的只是把它的参数抄到我们盒子里。**

---

## 2. 接线

```
电台 ──ACC(13-pin) + USB──> SCU-LAN10 ──网线──> 客户路由器/交换机
                                                    │
                                              盒子（网线优先）
```

- 单位**占着电台的 USB 口** ⇒「盒子插 USB」和「盒子走网络」是**二选一**，不能同时。
- FTDX101/DX10 不用给单位另接电源；**FT-710 要给单位接 DC 9–16 V / ≥800 mA**。
- 盒子建议**插网线**：这条链路持续约 **1.4 Mbit/s**（频谱 822k + 音频 542k），
  盒子的 Wi-Fi 是 1×1 2.4 GHz，是这条路上最弱的一环。

---

## 3. 电台菜单里的三条（缺一条单位自己就不通）

| 菜单 | 值 |
| --- | --- |
| **CAT RATE** | **38400**（单位到电台侧固定 38400，网线侧才是 115200） |
| CAT TIMEOUT | 10 ms |
| CAT RTS | ON |

另外：电台的**瀑布显示必须打开**（scope display ON），否则我们这边收不到扫描数据。
建议把 **TX TIME OUT** 设成 1–3 分钟，它是按键卡住时的最后一层保护。

---

## 4. 参数从哪儿抄（雅司软件的「连接设置」）

客户机器上那套雅司软件的 `Setup → Connection Setup` 长这样，**每个值都能直接对上**：

| 雅司软件里 | 抄到我们 `/settings` |
| --- | --- |
| 远程地址 `192.168.49.49` | **单位地址** |
| 用户 `king7565` | **用户名** |
| 密码 `••••••••` | **口令**（填过一次就存住，以后留空 = 不改） |
| 控制端口 `50000` | **端口**（只填这一个） |
| CAT 端口 `50001` / 音频 `50002` / 频谱 `50003` | **不用填**：我们按 base+0..+3 自己加 |
| 音频质量 `PCM(48kHz)` | 不用管：服务端按帧里声明的速率自适应（16k/48k 都行） |
| 音频发送/接收缓冲 `300ms` | 不用管：那是雅司客户端自己的缓冲 |

出厂值是 `defaultuser` / `defaultuser`；客户改过就用他改的。
**口令错的表现是「单位一声不响」**——雅司这套协议对错口令不返回错误，所以别指望报错。

---

## 5. 在盒子上打开它

浏览器进 **`http://<盒子地址>/settings`**，滚到接近底部，顺序是
`音频电平 → CQ 呼叫录音 → 电台 → 实验机型的发射 →` **`SCU-LAN10 网络接入`** `→ 安全门禁`。

1. 勾上「用 SCU-LAN10 代替串口与声卡」；
2. 填上面的**单位地址 / 用户名 / 口令 / 端口**；
3. 点 **「测试连接」**（它只握手，不保存任何东西）——
   - 成功会回报：`会话 0x28`、`CAT 回话 FA007007000;`、`频谱 N / 音频 N 包`；
   - 失败会直接说原因：口令不对（单位不应答）、地址不通（核对 IPv4/网段/防火墙）；
4. 点 **「保存」**，页面提示 **要重启服务**（接线是在后端启动时定的），弹窗里可以直接重启。

> 盒子**正在用**这条链路时，「测试连接」是灰的 —— 多开一个客户端会把盒子自己的会话顶掉。

**看不到这张卡片？** 依次查三件事：

| 查什么 | 结果说明什么 |
| --- | --- |
| ☰ 菜单页脚版本 | 要 ≥ `1.28.62 · FP49`。没到 = 升级没落地，去看「软件更新」卡片 |
| 浏览器硬刷新（Ctrl/Cmd+Shift+R） | HTML 每次回源，但老标签页会挂着旧页面 |
| 浏览器直接开 `/api/box/scu-lan` | 返回 JSON = 服务端已是新版，只是页面没刷；**404 = 服务端还是 FP48 之前的** |

**桌面版（Mac/Windows 程序）没有这一页** —— 那边改配置文件（见 §9）。

---

## 6. 打开之后：能做什么、不能做什么

| 能力 | 状态 |
| --- | --- |
| 改频率 / 模式 / 滤波器 / 表头 / 记忆频道 | ✅ 走网络 CAT |
| **瀑布** | ✅ 真扫描数据（850 点，约 25 行/秒） |
| 接收音频（浏览器 / App / 只读页 / 录音 / FT8 / 本地音箱） | ✅ |
| **发射（PTT / TUNE）** | ❌ **后端主动拒绝**：单位的 TX 音频帧格式还没解出来，按键只会得到**静音载波** |
| 同时和雅司官方软件一起用 | ❌ 单位**会话独占**，二选一 |

发射被拒绝是**产品行为**，日志里会点一次名。解出 TX 音频帧之后才会打开。

## 7. 排障

| 症状 | 原因 | 处置 |
| --- | --- | --- |
| 「测试连接」说口令不对（或启动日志 `session not up … rejected the credentials`） | 用户名/口令错。**单位对错口令不回应任何包**，静默就是全部证据 | 照雅司软件的「登录账户」重填 |
| 「测试连接」说连不上 | 地址不通：不是同一网段 / 写了 IPv6 / UDP 被防火墙拦 | 从盒子 `ping` 单位；确认是 **IPv4**；单位 LAN 灯常亮 |
| 会话通了、CAT 不回话 | 电台 CAT RATE 不是 38400 | 照 §3 改电台菜单 |
| 有 CAT、没有瀑布 | 电台瀑布没开；或单位正被雅司软件占着 | 打开电台瀑布；**退出**雅司软件（不是最小化） |
| 声音慢、音调低 | 旧版本把采样率写死 16 kHz，而单位按 48 kHz 送 | 升到 `1.28.64 · FP51` 以上（按帧内头自适应） |
| 盒子突然"卡住"不动 | 雅司软件抢先连上，把盒子的会话顶掉了 | 关掉雅司软件；盒子会自动重连。日志里有一条点名 |
| 音频断续 | 盒子在 Wi-Fi 上，1.4 Mbit/s 撑不住 | 插网线 |
| 瀑布画得出来、但频率刻度不对 | 这台的 `SS`（span/mode）应答与我们的解析不符 | 跑 §8 的脚本，把报告发我们 |

## 8. 愿意跑命令的：现场自检（不碰服务器，不按键）

```bash
python _diag_scu_lan.py --host 192.168.49.49 --user king7565 --pass 口令 \
    --spans --wav rx.wav --report scu1.md
```

它做四件事，报告是 Markdown，直接发我们：

1. 七阶段握手（会话号、能力字节）；
2. CAT 往返（`ID` / `FA` / `MD` / `SM` / `SS` 各多少毫秒）；
3. 频谱：边界标记位置、可用点数、幅度范围；`--spans` 会把九档 span 逐档扫一遍；
4. 音频：包率、声明采样率、峰值/RMS，并把声音存成 `rx.wav`（能直接听）。

`--tx --allow-tx` 是**另一回事**：它会真的按键 2 秒，用来验证 `TX;` 读回 —— 只在需要时用。

---

## 9. 边界与已知未知（写在这里，免得当故障）

1. **发射关闭**：单位的 TX 音频帧（668 字节）内层头没解出来。
2. **FTDX101 没被第三方验证过**：这份协议是别人从 FTDX10 抓包逆向的（76k 包，含一个跑通的
   客户端），README 明写欢迎 FTDX101/FT-710 的抓包。协议层大概率同构，但频谱编码需要真机确认。
3. **`SS`（跨度/模式）的应答形状**是按手册推断的，没在真机上抓过；解析失败时保持原轴，
   不会画一条编造的刻度。
4. **桌面版（Mac/Windows）没有设置页**：只在 `.env` 里写
   `MRRC_SCU_LAN=1 / MRRC_SCU_LAN_HOST / _USER / _PASS / _PORT`。
5. **不要把单位的端口暴露到公网**：这套协议没有加密也没有抗重放。远程一律走我们的云入口。
