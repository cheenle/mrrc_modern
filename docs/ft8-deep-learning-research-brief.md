# FT8 弱信号解码的深度学习研究：方法与阶段性结果简报

> 目的：向算法研究者请教方向选择、损失设计与数据效率问题。
> 日期：2026-10-15。所有数字均为本项目实测，除标注"文献"外无引用。

## 3 分钟提要（给没时间的专家）

**要解决的问题**：在**已经接近最优**的经典链路（匹配滤波 + LDPC 置信传播 + CRC）之上，
用深度学习多解出弱信号（−24 … −26 dB 区间，那里经典链路漏掉 40–70%）。

**已经量清楚的三件事**：
1. 经典解码器的调参空间**已经榨干**（十个配置的并集 = 单配置 s3 的 100%）；真正的缺口在
   **弱信号尾部**（−22 dB 100% / −24 dB 63% / −26 dB 31%），不在同频重叠（s3 已解决 98.8%）。
2. **纯解调器的学习版本注定追平**：实测端到端模型在 −20 dB 拿到 93.7% 比特准确率，
   但报文级 **0/30**（经典 30/30）——因为 0.937¹⁷⁴ ≈ 1e-5，逐比特目标拿不到编码增益。
3. **把码结构写进损失这条路我们走不通**：两种可微 syndrome 形式梯度都消失
   （符号-幅值软 XOR 1e-19；LDPC tanh 规则在高置信处恰为 0）。图注意力译码器（ECCT 式）
   在 8000 步 / 0.79 M 参数下**收敛到恒等映射**（输出=输入，四位小数），而同一份 LLR 上
   经典 BP 是 BER 0.0018（σ=0.7）。

**三个最想请教的问题**：
① 码结构进损失的正确做法（re-encoding？unrolled BP？学习阻尼？）；
② 在这个规模（174 比特 + 已知 Tanner 图）上，图 transformer 是否必要，还是 unrolled BP 就够；
③ 学习到底该打哪个场景——单信号 AWGN 下经典接近最优，价值是否只能在**非 AWGN**
（衰落 / 多用户 / 干扰）？若是，判据该怎么设计。

**我们能提供**：精确的编解码器与标签管线（无限仿真数据、标签精确到比特）、
2000+ 槽真实音频、已验证的校验矩阵与 Tanner 图、一个正确的 BP 基线、
以及一条已上线的部署链路（盒子 → 16 线程主机，可接 GPU 服务）。

## 0. 一句话

在一个**已接近最优的经典解码链路**（匹配滤波 + LDPC 置信传播 + CRC）之上，用深度学习
提升弱信号解码成功率。我们已经把"靶子在哪"量清楚了，也把三条路线各自撞到的墙量清楚了——
下面把方法、数据、结果和撞墙的具体位置摆出来，请指教。

## 1. 问题背景与硬约束

### 1.1 FT8 信号的参数（决定了所有设计）

| 项 | 值 |
|---|---|
| 调制 | 8-FSK，音调间隔 6.25 Hz |
| 时长 | 79 符号 × 0.16 s = 12.64 s（时隙 15 s） |
| 同步 | 7×3 固定音调图案，位于符号 0–6 / 36–42 / 72–78 |
| 数据 | 58 个数据符号 × 3 比特 = **174 比特码字** |
| 编码 | (174, 91) LDPC，**系统码**：`codeword(1:91) = 77 比特报文 + 14 比特 CRC` |
| 典型工作区 | −24 … −10 dB（解码器报告值，2500 Hz 参考带宽） |

### 1.2 现有解码链路（我们的"判官"）

```
音频 12 kHz
 → 同步搜索（freq × dt 网格，按符号相关）
 → 每个候选：8 音调软值（79 × 8）
 → LDPC 置信传播（最多 9 趟）+ OSD 兜底
 → 每个数据符号内做 9 趟减除（SIC），再解一轮
 → CRC-14 + 呼号库/结构过滤（假解过滤）
```

### 1.3 产品形态与约束（这些约束塑造了方法，也限制了方案）

- **部署**：接收端是 4×A53 的嵌入式盒子；深解跑在 16 线程的 x86 主机上（经 HTTPS 云升级，
  每槽 360 KB PCM 上行）。**盒子的依赖与协议不能改**（它是产品）。
- **判据是产品指标**：在真实语料上"多解出多少条报文"，而不是仿真 BER。
  我们已经建立了伪参照集（多个经典配置的并集）+ 精度检查（呼号结构 / QSO 时序一致性）。
- **精度必须可验证**：任何学习型方案都不能"生成"报文——只能输出比特，
  再由 CRC-14 + 码校验 + 呼号结构验证。**我们不允许"相信模型"，只允许"验证模型"**。
- **不改 DSP 库**：`ft8/dsp/`（Fortran/C 源码，四平台各自编译）动一次要重跑四条打包路径，
  明确不做。所有实验都在 Python 侧。

## 2. 靶子在哪：三组实测（这决定了后面所有设计）

### 2.1 经典配置空间已经榨干

对 150 槽真实语料（2936 条报文），扫描 profile/cycles/sensitivity/threshold 共 10 个配置：

| 配置 | 对可靠参照集的召回 |
|---|---|
| c2-p3（此前线上） | 95.2% |
| 三配置并行并集 | 99.1% |
| **s3 单配置**（profile1 + cycles3 + sensitivity3 + low_threshold） | **100.0%** |

⇒ 想提升召回，**只能换判据或换输入**，调参已无空间。

### 2.2 真正的靶子是弱信号尾部

用自建仿真器（见 §3）在真实噪底上扫 SNR，同一把尺：

| 标称 SNR | fast 路径 | s3 路径 |
|---|---|---|
| −26 dB | 6% | **31%** |
| −24 dB | 19% | **63%** |
| −22 dB | 56% | 100% |
| −20 dB | 81% | 100% |

真实语料的解码 SNR 分布：**≤ −18 dB 占 10.0%，≤ −20 dB 占 2.9%**（峰值在 −15 dB）。
⇒ 悬崖边上确有信号，**69% 的 −26 dB 信号被漏掉**。

### 2.3 同频重叠**不是**靶子（与直觉相反）

每槽有约 16 对信号处于"时间重叠 + 频差 ≤25 Hz"，但 s3 单配置已拿到十配置并集的 **98.8%**
——经典链路内部的 9 趟减除（SIC）就是为这个设计的。**这里没有多少可捡。**

## 3. 方法与数据管线（可复用资产）

### 3.1 标签来自编码器自身（而不是重写标准）

ABI 暴露了 `wsjt_ft8_encode`。我们的做法：

```
报文 → 编码器 → 干净 12 kHz 波形（精确）
     → 逐符号 8 音调 DFT → 79 个音调（无噪声，精确）
     → 逆 Gray 映射 → **174 比特码字**（训练标签）
```

**不重写 FT8 的打包规则**——那是一份标准副本，是训练目标悄悄漂移离开"空中的信号"的
标准路径。同步图案（已知先验）被写成测试：**它是"整条链对齐"的唯一无歧义证人**
（dt 量化、STFT 帧格、token 池化、频率映射，任何一处错都会让它消失）。

### 3.2 两套校验矩阵：都对，但用途不同（一个踩过的坑）

| 矩阵 | 来源 | 形状/权重 | 用途 |
|---|---|---|---|
| 稠密 `H = [G \| I]` | 编码器源码 `ldpc_174_91_c_generator.f90`（83 行 × 23 位十六进制） | 每行 ~45 | **验证**：`H·c = 0` |
| 稀疏 Tanner 图 | 解码器源码 `ldpc_174_91_c_parity.f90` 的 `Mn` 表（每比特 3 个校验） | 每行 7 | **译码**：BP / 图注意力 |

我第一版拿稠密 H 去跑 BP，结果是 **syndrome 权重下降、BER 反而上升**
（42→36 / 12.2%→16.2%）——这是"解码器的图不是码的图"的典型症状。

### 3.3 噪声与信道：真实噪底 + 传播增强

- **噪声取自真实语料**（340–2000 槽）：真实 QRN/QSB/带内干扰，不是白噪声。
  忙槽先在时频域**陷波去内容**（−34 dB）再当噪底——否则床里别人的信号进"噪声目标"，
  会教模型压制真实信号。
- **SNR 定标经过实测**：白噪底上标称与解码器报告值吻合到 **1 dB 内**；
  真实噪底上报告值系统性 **+3 dB**（非平稳噪声的 Jensen 效应：解码器平均逐符号比值，
  偏向安静时刻）。所以仿真用标称轴，与语料对比时用解码器自己的刻度。
- **传播类增强**：衰落深度 0–0.4、衰落率 0.02–0.6 Hz、±0.6 Hz 漂移（确定性 variant）。

### 3.4 判据工具

`recall-vs-SNR 曲线`（本仿真器）+ 真实语料 A/B（并集 + 精度检查）。
后续任何方案都必须在这两把尺上对拍同一份数据。

## 4. 三条路线的阶段性产出

### 4.1 路线一：经典配置搜索 + 两段式发布（**已上线，有效**）

- 组合解码与 sensitivity 扫描把召回从 95.2% 推到 **100.0%**（对可靠参照集）。
- **两段式发布**：快路径批次先发（用户可早 **2.4 s** 看到解码），深答案到达后覆盖同一槽。
  安全边界：**状态机每槽只吃一个批次（完整那个）**，提前发布止步于 UI；一槽只计数一次。
- 端到端延迟实测：槽边界后中位 **2.0 s**（其中主机深解 1.5–2.1 s 是大头，
  盒子的音频管线滞后 0.8 s，传输 0.2 s）。

### 4.2 路线二：ML 掩蔽增强（**已上线，边际收益**）

- **建模**：U-Net 预测理想幅度掩蔽（IAM），输入是带内对数幅度 + 单位相位向量，
  掩蔽域 = 解码器自己的网格（6.25 Hz × 40 ms）。
- **α（噪底保底）是关键杠杆**：α=1.0 时增强份**丢 20%** 真实信号（合成信号学得太准，
  真实信号被当噪声压制）；α=0.7 时损伤降到 2.4%，收益不变。
- **实测**：真实域并集净增 **+0.5~0.9%**（150 槽），精度检查 10/18 有 QSO 结构证据。
- **部署形状**：增强份是**额外输入**，与原始份并集 ⇒ 只增不减。
- **域差是它的天花板**：把训练目标改成"包含真实信号"（重生成进 clean 目标）后，
  结果**没有改善**（−2.4% vs −2.2%，噪声内）——说明卡住它的不是域差，而是掩蔽本身。

### 4.3 路线三：端到端 transformer 解码器（**负面结果，本轮重点**）

**设计**：DETR 式集合预测——输入整个时隙的复时频图（相位必须留，低 SNR 的判据来自相干
积累），输出 N 个查询，每个出 `(存在, 频率, dt, 174 比特码字)`；
**只出比特不出文本**，文本走标准打包 + H 校验。

#### 尝试 A：解调器（给定候选，解出码字）

给模型"对齐后的 ±50 Hz 裁片"（相当于经典解调器拿到的输入），逐符号预测 3 比特。

架构演进中抓到的两个 bug（都由"看数据"抓出，不是猜的）：

| bug | 症状 | 修法 |
|---|---|---|
| head 在全部 token 上 mean-pool | 顺序信息丢失，卡 65% | **逐符号 head**（每 token 3 比特） |
| STFT 帧格（40 ms）vs dt 连续 | 4 帧组跨符号边界，+10 dB 也读不出音调 | dt 量化到帧格（S1 阶段的刻意简化） |

修好后训练正常（比特准确率 96%+）。**但它对"报文级"毫无产出**：

| SNR | 模型整码字 | 经典解码器 |
|---|---|---|
| −26 dB | **0/30**（比特 74.3%） | 13/30 |
| −24 dB | **0/30**（比特 81.1%） | 22/30 |
| −22 dB | **0/30**（比特 88.6%） | 28/30 |
| −20 dB | **0/30**（比特 93.7%） | **30/30** |
| −14 dB | 8/30（比特 97.3%） | 30/30 |

原因可以算清楚：−20 dB 处 93.7% 比特准确率 ⇒ P(174 位全对) = 0.937¹⁷⁴ ≈ **1e-5**。
**逐比特目标学不到码结构**——编码增益（约 10 dB）是 LDPC 挣来的，模型一点没沾上。

#### 尝试 B：把码结构做成损失（**失败，最想请教的一点**）

动机：既然逐比特目标不行，就把"是否是合法码字"直接写进损失（可微的 syndrome）。

| 形式 | 数值行为 | 梯度 |
|---|---|---|
| 符号-幅值软 XOR（`P(XOR=1)=(1−Π(1−2p))/2`） | 值正确（有效码字 0.05 / 翻一位 0.98 / 随机 0.5 = −log0.5 ✓） | **1e-19** ✗ |
| LDPC tanh 规则（`Π tanh(L/2)`，+1 = 校验满足） | 值正确（有效 0.005 / 翻一位 2.9） | **高置信处恰为 0** ✗（把 LLR 夹到 ±6 也无效） |

⇒ 这个方向我目前没有可靠做法，**这是本次最想请专家指点的问题**（§7 问题 1）。

#### 尝试 C：ECCT 式神经译码器（图注意力）

把"译码"独立成一个组件：输入 174 个 LLR，输出精炼后的 LLR；**注意力被 Tanner 图掩蔽**
（共享校验的比特互相可见——"图的注意力就是消息传递"）。

先修好基线（BP 必须跑在稀疏图上，见 §3.2）。修好后 BP 很强：

| σ | 裸判决 BER | **BP BER** | BP 整码字 |
|---|---|---|---|
| 0.70 | 0.0759 | **0.0018** | 97.2% |
| 0.80 | 0.1074 | **0.0321** | 65.2% |
| 1.00 | 0.1591 | **0.1421** | 3.3% |

神经译码器（0.79 M 参数、3 层、8000 步、~26 分钟）：

| σ | 裸判决 | BP | 神经（1/3/8 轮迭代） |
|---|---|---|---|
| 0.70 | 0.0759 | **0.0018** | 0.0759 = 裸判决 |
| 0.80 | 0.1074 | **0.0321** | 0.1073 |
| 1.00 | 0.1591 | **0.1421** | 0.1592 |

**输出 = 输入（恒等映射，四位小数）** ⇒ 落进恒等这个局部最优。
探针显示结构/梯度/掩码都正常（head 梯度 2.8e-1、每比特可见 17 个邻居、掩码无退化）——
就是训练规模不够：文献（ECCT 一类）用 **10⁵–10⁶ 步**加 re-encoding 等技巧，本实验差 1–2
个数量级。

## 5. 训练与工程实现

### 5.1 CPU 是真正的瓶颈（GPU 会闲置）

| 阶段 | 耗时 |
|---|---|
| 单样本数据生成（1 信号 + 裁片） | **46 ms**（单线程） |
| batch 16 的 MPS 训练步 | 161 ms |
| ⇒ 数据/训练比 | **4.5×** |

两个关键优化：
1. **线程池**（重活都释放 GIL：编码器走 ctypes、其余走 numpy）；
2. **码字缓存**：原来每个样本都要重跑"编码 + 音调回读"（20–40 ms）来拿标签——纯浪费。

⇒ 单步 **771 → 133 ms**（5.8×），已低于纯模型步 ⇒ GPU 重新成为瓶颈。

### 5.2 踩过的工程坑（都可复现）

- **符号约定**：BCE 的"logit > 0 ⟺ y = 1"与 LLR 的"正 = bit 0"相反 ⇒ 模型学成**取反**
  （BER 95.2% = 1 − 裸判决 4.8%，这个"1 减"的特征值是识别它的关键）。
- **设备掩码**：Tanner 掩码必须注册成 buffer，否则 MPS 上报设备不匹配。
- **`0 × NaN = NaN`**：关掉的损失项要**不计算**，不是乘 0。
- **索引语义**："第 k 个数据符号"与"它在 79 符号里的位置"是两个不同的数，
  混用会越界或静默错映射。

### 5.3 算力估算（用于决定是否租卡）

| 任务 | M2（8 核 MPS，实测/外推） | 24 GB GPU（估算） |
|---|---|---|
| 单信号裁片探针 | 161 ms/步（batch 16） | — |
| 神经译码器（174 输入） | 397 ms/步（batch 256） | ~10–20 ms |
| **整槽 DETR**（3×465×376 输入 + 40 query） | ~4.8 s/步 ⇒ 10 万步 ≈ **5.5 天** ✗ | ~0.15–0.3 s/步 ⇒ **4–8 小时** ✓ |

## 7. 想请教的具体问题

1. **码结构如何进损失？** 我们试过的两种可微 syndrome 形式梯度都消失
   （1e-19 / 高置信处恰为 0）。文献里的 re-encoding、直接学 BP 迭代（unrolled BP）、
   "学习阻尼系数"等路线，哪条在**短码 + 已知图**上最稳？有没有我们没意识到的标准做法？
2. **架构选择**：在"174 比特码字 + 已知 Tanner 图"这个规模上，
   图注意力 transformer / unrolled BP / 经典 BP + 学习先验（如学习 LLR 修正）——
   哪条性价比最高？我们是否需要 transformer，还是 unrolled BP 就够了？
3. **端到端值不值得做？** 单信号 AWGN 下经典链路（匹配滤波 + LDPC）接近最优，
   所以学习的价值只能来自**非 AWGN**（衰落、多用户重叠、干扰）。如果是这样，
   判据应该怎么设计？我们手上有真实语料和精确仿真，能构造哪些"经典必输"的场景来验证？
4. **数据效率与域迁移**：我们实测过"合成信号训练 ⇒ 压制真实信号（丢 20%）"的域差，
   也实测过"把真实信号重生成进训练目标"**没有改善**。在只有上千槽真实音频
   （但仿真无限、标签精确）的条件下，怎样把仿真域能力迁移到真实域最有效？
5. **LLR 从哪来？** 原生解码链路不暴露 LLR。我们的选项：主机侧自建音频→LLR 解调、
   或只在学习型链路内部闭环。有没有第三条路（例如用学习模型输出置信度做经典链路的
   候选排序/AP 先验）？
6. **算力怎么花？** 若只搏一次：整槽 DETR 100k 步 / 一张 24 GB 卡 4–8 小时是否值得？
   还是把同样的预算花在更小但更对症的实验上（例如问题 1/2 的对照实验）？
7. **评价方法**：我们的判据是"真实语料上的并集增量 + 精度检查"。对研究型工作，
   是否有更严格、更能说明问题的协议（例如按 SNR 分层的召回曲线 + 假解率的置信区间）？

---

## 8. 我们的初步判断（欢迎反驳）

- 端到端"音频 → 报文"在单信号 AWGN 下**不可能超过**经典链路；价值只可能在非 AWGN 场景。
- 纯解调器的学习版本**注定追平**，不值得投入。
- 真正可能赢的两处：**(a)** 图结构上的学习型译码器（若能在小模型下超过 BP+OSD，
  或大幅降低 OSD 的开销）；**(b)** 多信号联合检测/分离（经典链路是逐候选贪心的）。
- 我们最缺的不是算力，而是**损失与架构的选择经验**——这也是这份简报存在的理由。
