# FT8 弱信号解码：一次思辨研究

> 2026-10-15。这不是实验报告，是一次**从第一性原理重算靶子**的推演，外加两个为验证推演
> 而做的测量。结论会推翻本项目前两轮研究（P3 掩蔽增强、P4 端到端解码器）的前提，
> 所以先把算术摆出来，再摆实测，最后说下一步该做什么、以及哪些还没被证明。

---

## 0. 一句话

**在白噪声里，经典 FT8 解码器已经站在它自己码率的有限块长香农门限上（相差约 0.5 dB），
余量是零。** 因此"提升弱信号解码率"这个目标在白噪声里**没有算法空间**——P4 的 0/30 不是
实现问题，是算术问题。唯一能把门限往下推的经典杠杆是**降低有效信息率**，也就是 AP
（先验）解码：把盒子已经知道的两个呼号、网格、QSO 进程喂进去，有限块长门限理论上从
约 −21 dB 移到约 −31 dB，**约 10 dB**。而这条链路在本仓**从协议到原生库全线接通、
`ap` 默认还是 `True`，却因为呼号与网格是空串而永不武装**。第一轮探针没量到收益，
落差的原因在 §6 逐条列出。

## 1. 算术：靶子到底在哪

### 1.1 FT8 的码率

一条 FT8 报文 = 174 个码比特，其中 77 是信息（含 14 位 CRC 开销），83 是校验：

```
R = 77 / 174 = 0.4425  信息比特 / 码比特
每符号 3 比特（8-FSK），符号 0.16 s ⇒ 匹配滤波带宽 = 音调间隔 = 6.25 Hz
```

CRC 是**开销不是信息**——它买的是低假解率，不占香农意义上的信息率。

### 1.2 两个尺子要对齐

WSJT-X 报告的 SNR 是 **2500 Hz 参考带宽**下的值。匹配滤波的噪声带宽是 6.25 Hz，所以

```
Es/N0 = SNR(2500 Hz) + 10·log10(2500 / 6.25) = SNR + 26.02 dB
Eb/N0 = Es/N0 − 10·log10(3)                   = SNR + 21.25 dB
```

本仓仿真器 `ml_simulate.noise_floor_power()` 的 docstring 自己写着这条换算
（"the same conversion the decoder makes with its −26.5 dB correction"），
所以**标称 SNR 与解码器报告值是同一把尺**——这一点后面很关键。

### 1.3 渐近香农极限

```
Eb/N0_min = (2^R − 1) / R = (2^0.4425 − 1) / 0.4425 = 0.8112 = −0.91 dB
⇒ SNR_min(2500 Hz) = −0.91 + 4.77 − 26.02 = −22.16 dB
```

### 1.4 有限块长门限（n = 174，这才是真实的门）

正态近似 `R = C − √(V/n)·Q⁻¹(ε)`：

| 目标块错率 ε | V = 0.5 nat² | V = 1.0 nat² |
|---|---|---|
| 10% | **−21.12 dB** | **−20.74 dB** |
| 1% | −20.39 dB | −19.78 dB |

n=174 太短，`√(V/n)·Q⁻¹(ε)` 这一项相对 R 并不小——**有限块长门限比渐近极限高 1.0–1.4 dB**。

### 1.5 实测悬崖正好落在这条线上

同一批仿真（真实噪底 × s3 深配置）：

| 标称 SNR | 召回 | 解码器**自己报告的** SNR 范围 |
|---|---|---|
| −26 dB | 25% (2/8) | **−21 … −19** |
| −24 dB | 87.5% (7/8) | **−21 … −7** |
| −22 dB | 100% (8/8) | −21 … −15 |
| −20 dB | 100% (8/8) | −18 … −8 |

两件事同时成立：

1. **报告值的下界是 −21 dB**——四个标称档位、跨越 6 dB，报告值从未低于 −21。
   这正好是 ε≈10% 的有限块长门限（−21.1 … −20.7 dB）。**解码器的悬崖压在理论门上，
   相差约 0.5 dB。**
2. **标称与报告差 3–7 dB，且离散度极大**（−24 dB 档报告值横跨 −21…−7）。
   这是此前已量过的 Jensen 效应（真实噪底非平稳，解码器逐符号取比值偏向安静时刻）。
   ⇒ **召回曲线的横轴不是绝对 SNR。** 这一条是方法论警告，见 §5。

### 1.6 推论：白噪声里余量为零

如果悬崖已在门限上，那么任何**不改变有效信息率、也不改变信道**的算法改进，
在白噪声里的收益上界就是有限块长与渐近极限之间那 1 dB 量级——而且经典链路已经用
BP + OSD + 9 趟 SIC 把这一段吃掉了。

**P4（端到端/学习型解码器）的 0/30 因此不必归因于实现。** 一个学习解码器最好的结局是
*追平* BP+OSD，而 BP+OSD 已经在门上。这解释了一个此前无法解释的现象：比特准确率
93.7% 却整码字 0/30——不是模型不够好，是**这个工作点上根本不存在"更好"**。

**P3（掩蔽增强）的 +0.5–0.9% 同样自洽**：掩蔽改变的是噪声的时频形状，不是白噪声下的
理论门限；它赚到的那一点，来自真实噪底**非白**的那部分结构。

## 2. 唯一能把门限往下推的经典杠杆：降低有效信息率

香农门限是 R 的函数。R 由协议定死（改不了），但**解码器面对的 R 不由协议决定，
由"解码前已经知道多少"决定**。

一条 `BA4EG JA1VAT -12` 的 77 比特里，若已知：

| 已知项 | 省掉的比特 |
|---|---|
| 我的呼号 BA4EG | ~25 |
| 对方呼号 JA1VAT | ~25 |
| 报文类型（报告交换阶段） | ~6 |
| 剩下真正未知的：报告值 −12 | **~5–6** |

```
R_eff ≈ 6 / 174 = 0.034
渐近极限：Eb/N0 = (2^0.034 − 1)/0.034 = 0.700 = −1.55 dB   （趋近 −1.59 dB 的宽带极限）
有限块长（n=174, ε=10%, V=1）：所需 C ≈ √(V/n)·Q⁻¹(ε) = 0.143 bit/use
                              ⇒ Eb/N0 ≈ 0.099 = −10.0 dB
                              ⇒ SNR_min(2500 Hz) ≈ −31.2 dB
```

**从 −21 dB 到 −31 dB，约 10 dB。** 这就是 AP 解码的全部理论依据，也是本项目
剩下的**唯一**一块有量级空间的地方。

（注意低速率下的反直觉之处：门限不再由 R 决定，而由 `√(V/n)·Q⁻¹(ε)` 决定——
块太短，无法把低速率的红利全部兑现。即便如此，10 dB 仍然成立。）

## 3. 代码现实：一台装好了却没加油的机器

AP 在本仓是**全线接通**的：

| 层 | 状态 |
|---|---|
| 协议 schema（`ft8/core/protocol.py`） | 22 个字段，含 `ap`/`ap_width`/`my_call`/`dx_call`/`dx_grid`/`qso_progress`/`utc_hhmmss`/`rx_frequency` ✓ |
| worker（`ft8/core/worker.py:98`） | 22 个字段全部忠实转发 ✓ |
| binding（`ft8/core/binding.py:503`） | `flags` bit0 = `ap`，其余字段逐个写入原生结构 ✓ |
| 原生（`wsjt_improved.f90` / `vendor/ft8_decode.f90`） | `ft8apset` + `ft8_a7d` + `ft8_a8d` 三条路径都在 ✓ |
| 结果字段 | `ap_type`、`quality` 都在 schema 里 ✓ —— **AP 解码是带标记的** |

而运行时只填了两个字段（`ft8/runtime.py:220`）：

```python
DecodeConfig(profile=profile, threads=auto_thread_count())
```

`DecodeConfig` 的默认值是 **`ap=True`**、`my_call=""`、`dx_call=""`、`dx_grid=""`、
`qso_progress=0`、`rx_frequency=1500`。于是原生的武装条件

```fortran
ltry_a8          = ap_enabled .and. len_trim(hiscall) >= 3 .and. len_trim(hisgrid4) >= 4
lenabledxcsearch = ap_enabled .and. len_trim(hiscall) >= 3
```

**恒为假**。准确的说法不是"AP 关着"，而是"**AP 开着、被饿着**"：`ft8apset('','',0,…)`
拿到空串，iaptype 停在 0，a8 从不武装。

### 3.1 三条 AP 路径分别是什么（读源码得出，非文档转述）

| 路径 | 先验从哪来 | 能干什么 |
|---|---|---|
| `ft8apset(mycall12,hiscall12,ncontest,apsym2,aph10)` | 配置里的呼号 + QSO 进程 | 经典符号掩码 AP（iaptype 1–6），给主解码循环加先验 |
| `ft8_a7d(dd,newdat,call_1,call_2,grid4,…)` → iaptype=7 | **频带本身**：循环遍历*已经解出的*报文 `msg0(i,jseq,0)`，从中切出 call_1/call_2/grid4 | **精修**已解出的报文。**不能发现新信号** |
| `ft8_a8d(dd,mycall12,hiscall12,hisgrid,f1=nfqso,…)` → iaptype=8 | 配置里的 my/his 呼号 + his 网格，**且固定在 nfqso 上** | 单假设检验，带概率 `plog` 与 `qual`（`plog<−147` 时 qual 降到 0.16）。**这才是能"无中生有"的那一条** |

a8 的门槛（`vendor/ft8_decode.f90:251`）：`lft8apon` ∧ `ncontest∉{6,7}` ∧ `nzhsym==50`
∧ `la8` ∧ `len(hiscall12)≥3` ∧ `len(hisgrid)≥4` ∧ `ltry_a8`。其中 `la8` 的含义是
**"这条报文还没被正常解出过"**——所以 a8 只在常规解码失败处才出手，这是它的设计意图，
也决定了它该在悬崖以下才被观测到。

## 4. 第一轮探针（`tools/ft8/ap_probe.py`）

三方对照，16 个真实噪底 × 6 次试验 × 3 个 SNR × 3 个 qso_progress：

| 一致报文 `BA4EG JA1VAT -12` | −26 dB | −25 dB | −24 dB |
|---|---|---|---|
| `ap_off`（真关） | 2/6 | 3/6 | 6/6 |
| `ap_starved`（**今天的生产状态**） | 3/6 | 2/6 | 5/6 |
| `ap_fed` p0 / p2 / p4 | 3,2,4 /6 | 4,3,4 /6 | 6,6,5 /6 |

| 矛盾报文 `CQ VK3ABC QF22`（先验与空中事实相反） | 结果 |
|---|---|
| **AP 发明出期望报文** | **0 / 36 次试验** |

三条读数：

1. **`ap_starved` 与 `ap_off` 在噪声内不可区分** ✓ —— 与 §3 的预测一致：饿着的 AP 等于没有 AP。
2. **喂上先验后，召回没有可测提升**（n=6，全部差异在 ±2/6 内）✗ —— 与 §2 的 10 dB 预期相反。
3. **精度风险没有兑现**：36 次"先验与事实矛盾"的试验里，AP 一次也没有把期望的报文编出来 ✓✓。
   这一条比收益更重要——它意味着**即便收益为零，喂先验也不是危险动作**。

## 5. 方法论教训：先换算横轴，再谈优化

本项目前两轮把力气花在 ML 上，依据是"−26 dB 处 69% 的信号被漏掉"。但那条曲线的横轴是
**真实噪底上的标称 SNR**，而 §1.5 量到它与解码器自己的尺子差 **3–7 dB**、离散度极大。

⇒ "−26 dB" 这个说法在绝对意义上不成立。**任何以 SNR 为横轴的结论，都必须先声明用的是
哪把尺**：标称（仿真器的增益律）、解码器报告值（Jensen 抬高的）、还是理论门限所在的
Es/N0。三者在真实噪底上可以差 7 dB，而 7 dB 足以把"还有很大空间"变成"已经在门上"。

这条教训的一般形式：**在优化之前，先把测量轴换算到理论轴上。** 否则会把一个已被
信息论关闭的方向，误读成一个工程问题。

## 6. 理论与实测的 10 dB 落差：四个候选解释，以及各自的判决实验

| # | 候选解释 | 判决实验 | 我的先验判断 |
|---|---|---|---|
| a | **原生状态跨调用泄漏**：`ft8_a7_save` 把解码结果存进表、`la8` 是模块级变量，探针在同一进程里连续跑三个臂 ⇒ 臂之间不独立。证据：`ap_off` 臂竟出现 `ap_type≠0` 4 次（`ap=False` 时 a7/a8 都不该跑） | 每个臂用**独立进程**跑；或在每臂前重置原生状态 | 很可能成立，且会同时污染三臂 |
| b | **nfqso 是否等于 `rx_frequency`** 未确认。`clear_a8_near_rx(ltry_a8, freq, request_rx_frequency)` 暗示相关，但 a8 用的是 `f1=nfqso`，其来源需追 | 在原生侧打印 nfqso，或构造"信号频率 ≠ rx_frequency"的对照 | 中等 |
| c | **样本太小 + a8 只在常规解码失败处出手**（`la8` 门）。−26 dB 档只有 6 次试验，而 a8 恰只在该档有机会 | 把试验数提到 50+，并**只统计常规解码失败的子集** | 很可能，这会让 6 次试验里的 1–2 次差异变成可读的信号 |
| d | **理论 10 dB 假设的是"在缩减空间上做最优译码"**，而 a8 是在**一个频率、一个 dt、一条报文**上做单假设检验。它确实吃到了速率缩减的红利，但只在假设**完全正确**时；频率或 dt 稍偏，红利就没了 | 扫描 a8 的假设与真实 (f, dt) 的偏差，看收益随偏差的衰减 | **我认为这是主因**：§2 的 10 dB 是"最优 AP 译码器"的上界，不是 a8 的保证 |

(d) 值得展开：a8 的 `plog` 与 `qual=0.16`（当 `plog<−147`）说明它自己也知道这是
一个可能失败的假设检验。10 dB 是**信息论上界**，实现它与"检验多少个假设"直接相关——
若在 (f, dt) 的一个网格上做多次 a8 检验，就能逼近上界，代价是假解率上升与算力上升。
**这才是真正值得设计的东西**，而它不需要任何机器学习。

|---|---|---|---|---|

## 8. 本文没有证明的东西

- 没有证明 a8 在真实 QSO 中能提升召回——第一轮探针**没有**量到收益，§6 的四条解释
  一条都还没被判决实验排除。
- 没有证明 10 dB 可达；那是**最优 AP 译码**的有限块长上界，不是任何现有实现的保证。
- 没有在 GPU 上训练过任何模型；所有算力数字是外推。
- 没有验证 `ap_type` 字段与原生 `iaptype` 的一一对应（§6(a) 的泄漏疑点正来自它）。
- 没有在真实电台上跑过 AP（探针用的是合成信号 + 真实噪底）。
- 有限块长计算用了正态近似与 V ∈ {0.5, 1.0} 两个取值；n=174 时正态近似本身误差不可忽略，
  表中数字应读作"量级与位置"，不是小数点后一位的承诺。
- 香农极限按**相干** 8-FSK 计算。若实际链路存在未知的相位噪声/频偏残余，真实门限会更差，
  这只会让"余量为零"的结论更强，不会更弱。
