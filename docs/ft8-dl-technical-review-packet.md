# FT8 弱信号解码：技术审查包

> 给算法研发的版本。目标读完后能直接判断"是方法不行还是管线有问题"，并给出具体建议。
> 所有数字为本项目实测；每一条都注明**验证到什么程度**。日期 2026-10-15。

---

## 0. 请优先看这三条

1. **§4.2 的标度捷径**：BCE 训练出的"译码器"学成了 `out ≈ 2.005 × in`（符号一致率 99.88%，
   BER 几乎不变）。**BCE 对 LLR 尺度敏感，而硬判决不敏** ⇒ 存在一条"不改善解码但降低损失"
   的通道。这是我们认为最有价值的一条发现。
2. **§4.1 的算术**：解调器在 −20 dB 拿到 93.7% 比特准确率，报文级 **0/30**（经典 30/30）。
   `0.937^174 ≈ 1e-5`。逐比特目标拿不到编码增益。
3. **§6 的"未验证清单"**：其中一条是**我们自己的 syndrome 损失实现未经验证**（两次重写后
   数值互相矛盾）。我们把它降级为"实现失败"，不作为研究结论 —— 请按这个前提给建议。

## 1. 系统与硬约束

### 1.1 信号与编码（全部来自源码，非记忆）

| 项 | 值 | 出处 |
|---|---|---|
| 调制 | 8-FSK，音调间隔 6.25 Hz | `gen_ft8wave` 参数 |
| 符号 | 79 × 0.16 s = 12.64 s（时隙 15 s） | 同上 |
| 同步 | 7×3 固定音调：`3,1,4,0,6,5,2`，位于符号 0–6 / 36–42 / 72–78 | `genft8.f90:14,33-35` |
| 码字 | 58 数据符号 × 3 比特 = 174 比特 | 同上 |
| 编码 | (174, 91) 系统 LDPC：`codeword(1:91) = 77 比特报文 + 14 比特 CRC` | `encode174_91.f90:60` |
| 音调映射 | `itone = graymap[3 bits]`，`graymap = 0,1,3,2,5,6,4,7` | `genft8.f90:41-42` |

### 1.2 经典链路（我们要超越或追平的对象）

```
12 kHz 音频
 → 同步搜索（freq × dt 网格，逐符号相关）
 → 每候选：79 × 8 音调软值
 → LDPC 置信传播（cycles 1/2/3 → npass 3/6/9）+ OSD 兜底
 → cycles 内部每趟 call subtractft8var（SIC）
 → CRC-14 + 呼号结构/库过滤（假解过滤）
```

生产配置（线上）：`profile=1, cycles=3, sensitivity=3, low_threshold=True`（记为 s3），
跑在主机侧 16 线程，盒子经 HTTPS 把 360 KB/槽 的 PCM 送过来。

### 1.3 三条硬约束

1. **判官不可替换**：解码器既是产品的一部分，也是唯一可信的裁判。学习型方案只能作为
   *额外输入*（并集）或*替换其中一级*，且必须能被验证（`H·c = 0` + CRC + 呼号结构）。
2. **不改 DSP 库**：`ft8/dsp/`（Fortran/C，四平台各自编译）动一次要重跑四条打包路径。
   所有实验在 Python 侧（numpy + torch，torch 只在研究环境）。
3. **判据是产品指标**：真实语料上"多解出多少条报文"＋精度检查，不是仿真 BER。
   但我们同时维护一把仿真尺（§3.3），两者都要过。

## 2. 靶子在哪：三组实测（决定所有后续设计）

### 2.1 经典配置空间已榨干

150 槽真实语料、2936 条报文、10 个配置（profile 0–3 × cycles 1–3 × sensitivity 1–3 ×
low_threshold）：

| 配置 | 对可靠参照集召回 |
|---|---|
| c2-p3（此前线上） | 95.2% |
| 三配置并行并集 | 99.1% |
| **s3 单配置** | **100.0%** |

可靠参照集 = 至少两个配置都认得的报文（排除单配置独有的疑似假解；实测单配置独有仅
7/2936 = 0.2%）。

### 2.2 真靶子是弱信号尾部

仿真器（§3）在真实噪底上扫标称 SNR，30 次/点：

| 标称 SNR | fast | s3 |
|---|---|---|
| −26 dB | 6% | **31%** |
| −24 dB | 19% | **63%** |
| −22 dB | 56% | 100% |
| −20 dB | 81% | 100% |

真实语料解码 SNR 分布：≤ −18 dB 占 10.0%，≤ −20 dB 占 2.9%（峰值 −15 dB）。

### 2.3 同频重叠**不是**靶子

150 槽内时间重叠且频差 ≤25 Hz 的信号对：2397 对（每槽 16 对）。但 s3 单配置已拿到十配置
并集的 **98.8%**（内部 9 趟 SIC 就是为此设计）。⇒ 这里空间很小。

## 3. 数据管线（请重点审这里，它是所有结论的地基）

### 3.1 标签：从编码器自身反推，不重写标准

```
报文 → wsjt_ft8_encode（ABI）→ 干净 12 kHz 波形
     → 逐符号 8 音调 DFT → 79 音调（无噪声 ⇒ 精确）
     → 逆 graymap → 174 比特码字
```
断言（测试）：`tones_from_codeword(codeword_from_tones(tones)) == tones`，
且**同步图案逐符号命中**——它是"dt 量化 / STFT 帧格 / token 池化 / 频率映射"整条链对齐的
唯一无歧义证人。两个曾经的 bug（帧格 40 ms vs 符号 160 ms 错位；把数据符号序号当符号位置）
都是靠它抓出来的。

### 3.2 两套校验矩阵（都对，用途不同）

| 矩阵 | 来源 | 行重 | 用途 | 验证方式 |
|---|---|---|---|---|
| 稠密 `H = [G \| I]`（83×174） | `ldpc_174_91_c_generator.f90`（83 行 × 23 位十六进制） | ~45 | **验证** `H·c = 0` | 编码器码字 syndrome 权重 0；翻 1 位 → 43 个校验报错 |
| 稀疏 Tanner 图（83 × 522 边） | `ldpc_174_91_c_parity.f90` 的 `Mn` 表（每比特 3 个校验） | 6–7 | **译码** BP / 图注意力 | 编码器码字同时满足两者；BP 解对的码字稠密 syndrome 全 0、解错的全非 0 |

**踩过的坑（值得同行知道）**：第一版拿稠密 H 跑 min-sum，结果是 **syndrome 权重下降而 BER
上升**（42→36，12.2%→16.2%）。这是"解码器的图不是码的图"的典型症状——min-sum 定义在稀疏
图上。换成稀疏图后 BP 立刻正常（§4.3）。

### 3.3 噪声、增强与 SNR 定标

- **噪底取自真实语料**（340 槽主机 + 2000 槽设备）。忙槽先在时频域**陷波 −34 dB** 去掉
  已解出的信号——否则别人电台进"噪声目标"，模型学到的是压制真实信号（后来真的发生了，
  §4.4）。
- **传播类增强**：衰落深度 0–0.4、衰落率 0.02–0.6 Hz、漂移 ±0.6 Hz（确定性 variant）。
- **SNR 定标经实测**：白噪底上标称与解码器报告值吻合 ≤1 dB；真实噪底上报告值系统性
  **+3 dB**。原因是 Jensen 效应——解码器逐符号平均 `xsig/xnoi` 的比值（偏向安静时刻），
  我们算的是"信号/平均噪声"。**与真实语料对比时统一用解码器的刻度**。

### 3.4 判据

`recall-vs-SNR` 曲线（合成信号，真值精确）+ 真实域并集增量 + 精度检查（新报文须有 QSO
结构证据：同一对呼号在 ±2 槽内成对出现）。

## 4. 三个失败案例（每个都给出诊断数据）

### 4.1 解调器：报文级零产出 —— **已验证**

**设置**：给定"对齐的候选裁片"（±50 Hz × 316 帧 = (3, 17, 316)，通道 = 对数幅度 +
单位相位 cos/sin），逐符号预测 3 比特。
模型：conv stem(3→48→96, 3×3) → 频率塌缩 → 4 帧池化 = 每符号 1 token → 3 层 transformer
(d=96, 4 头) → 逐符号 head(3)。2.08 M 参数。
训练：8000 步，batch 16，AdamW 3e-4，BCE，SNR 从 −4 dB 退火到 −22 dB。
数据生成：8 线程并行（重活释放 GIL）+ 码字缓存 ⇒ 133 ms/步，与模型步同量级。

**gate 结果**（同一批合成槽，30 次/点，与 s3 对拍）：

| SNR | 模型整码字 | 模型比特准确率 | s3 |
|---|---|---|---|
| −26 dB | **0/30** | 74.3% | 13/30 |
| −24 dB | **0/30** | 81.1% | 22/30 |
| −22 dB | **0/30** | 88.6% | 28/30 |
| −20 dB | **0/30** | 93.7% | **30/30** |
| −14 dB | 8/30 | 97.3% | 30/30 |

**诊断**：`0.937^174 ≈ 1.1e-5`。s3 在该点的编码增益约 10 dB，模型没有。
**结论**：该架构是解调器，不是译码器；逐比特目标学不到码结构。**这个结论我们认为可靠。**

### 4.2 神经译码器：学成标度增益 —— **已验证，且比"恒等"更精确**

**设置**：174 个 LLR 输入，输出精炼 LLR；注意力掩码 = Tanner 图（共享校验的比特互见）。
`out = in + head(3 层 transformer(d=96, 4 头, FFN 4×, norm_first))`。0.79 M 参数。
训练：8000 步，batch 256，AdamW 3e-4，σ ∈ [0.6, 1.0]，BCE（目标按 LLR 约定取补：
正 = 比特 0）。

**对拍**（同一批 600 块、同一噪声；基线为归一化 min-sum，50 次迭代）：

| σ | 裸判决 BER | BP BER | 神经 BER |
|---|---|---|---|
| 0.70 | 0.0759 | **0.0018** | 0.0759 |
| 0.80 | 0.1074 | **0.0321** | 0.1073 |
| 1.00 | 0.1591 | **0.1421** | 0.1592 |

**诊断（关键）**——先排除"输出恒等"这个误判，逐项实测：

```
|out − in| 均值 1.70（输入幅度均值 1.68）
线性拟合: out ≈ 2.005 × in，相关系数 0.9998
标准差: 输入 2.001 → 输出 4.012
逐比特符号一致率: 99.88%
BER: 0.1058（裸）→ 0.1059（模型）
```

**它学的是一条标度增益，不是译码。** LLR 的尺度是人为约定，硬判决与它无关；而 BCE 对
尺度敏感（把 LLR 放大 2 倍会略微降低 BCE，因为二分类对数损失更"自信"就更大一点）。
⇒ **BCE 存在一条"不改善解码却降低损失"的通道，模型找到了它。**

补充测量：从身份到完美输出的 BCE 落差是 **0.299**
（身份 0.3019，BP 输出 0.0713，完美 0.0025）——空间存在，优化器没走进去。

### 4.3 基线本身：BP 该跑在哪张图上 —— **已验证（这条是正收获）**

修好稀疏图后，BP 在 σ=0.7 时 BER **0.0018**、整码字 **97.2%**；σ=0.8 时 0.0321 / 65.2%。
这是神经译码器要打的靶子，也说明**经典链路在这一段极强**。

### 4.4 另一条实测的域差（来自上一轮掩蔽增强工作）

用合成信号训练的增强模型，在真实槽上会让增强份**丢 20%**的已解码报文（α=1.0）；
把真实信号重生成进训练目标后（α=0.7）**没有改善**（−2.4% vs −2.2%，噪声内）。
⇒ 域差不是那一条路的瓶颈，掩蔽本身才是。

## 5. 工程账（供判断"投入产出"）

| 项 | 实测 |
|---|---|
| 单样本数据生成（CPU 单线程） | 46 ms |
| batch 16 训练步（M2 8 核 MPS） | 161 ms（数据生成是它的 4.5 倍） |
| 并行生成（8 线程）+ 码字缓存后 | **133 ms/步**（瓶颈回到加速器） |
| 神经译码器训练步 | 397 ms（batch 256，174 输入） |
| **整槽集合预测模型（3×465×376 输入 + 40 query）** | M2 ≈ **4.8 s/步**（10 万步 ≈ 5.5 天） |
| 同上，24 GB 台式卡（外推） | ≈ 0.15–0.3 s/步（10 万步 ≈ 4–8 小时） |

**四个工程坑（都已复现、都已修）**：
① 掩码须注册为 buffer（否则加速器上设备不匹配）；
② 被关掉的损失项必须**不计算**（`0 × NaN = NaN`，一个默认关闭的项能让训练发散）；
③ 符号约定：BCE 的"logit>0 ⟺ y=1" vs LLR 的"正 = bit 0"，搞反会让模型学成整体取反
（**指纹：BER 95.2% = 1 − 裸判决 4.8%**）；
④ "第 k 个数据符号"与"它在 79 符号里的位置"是两个不同的数，混用会越界或静默错映射。

## 7. 想请教的问题（每条都指向一个具体决定）

### Q1 标度捷径怎么堵（对应 §4.2，最重要）
BCE 允许"放大 LLR"这条捷径，模型 8000 步后收敛到 `out ≈ 2×in`。
**该改损失、改输出参数化，还是改训练协议？** 我们想到的三条：
(a) 固定输入尺度、只在固定 σ 上训练，让"标度"不再是自由度；
(b) 用**对单调正变换不变**的目标（例如校验满足度——它只看符号，与尺度无关）；
(c) 去掉残差 `out = in + head(...)`，改为输出判决本身并配一个锚定尺度的损失。
哪条在短码 + 已知图上更稳？有没有第四条？

### Q2 码结构进损失的正确做法（对应 §6 那条"实现失败"）
我们明确**没有**做对。想请教的不是"我们哪里错了"，而是：在 (174, 91) 加已知 Tanner 图、
目标函数需要可微的条件下，**工业界/文献里到底用哪一套**？
具体想知道：re-encoding（先验投射到码字流形）与 unrolled BP 相比，哪种在**短码**上更有效；
以及 unrolled BP 的层数 / 阻尼是否需要与图的度分布匹配。

### Q3 架构选择（对应 §4.1、§4.3）
在"174 比特 + 已知图"这个规模：
- 图注意力 transformer（ECCT 式）vs unrolled BP vs 经典 BP + 学习先验（学 LLR 修正 /
  学候选排序）——**哪条性价比最高**？
- 我们是否需要 transformer？还是 unrolled BP 就够（参数更少、可解释、可验证）？
- 如果把模型缩到"只做 OSD 的重排/候选排序"，是否比端到端更划算？

### Q4 学习到底该打哪里（方法论问题）
单信号白噪声下经典链路接近最优（匹配滤波 + LDPC）。我们的判断是：学习的价值只能来自
**非白噪声**（衰落、多用户重叠、干扰）。如果同意——**判据该怎么设计**才算严谨？
我们手上有 2000+ 槽真实音频（含真实 QRN/QSB/带内干扰）与精确仿真，
能构造哪些"经典必输、学习有机会"的场景？如果不同意，请指出我们哪里想错了。

### Q5 数据效率（对应 §4.4）
真实样本上千、仿真无限、标签精确。我们实测过：合成训练 ⇒ 压制真实信号（丢 20%），
把真实信号重生成进目标 ⇒ 无改善。**在这种条件下，迁移最有效的做法是什么？**
（我们的候选：在真实 LLR 上做校准 / 域随机化 / 用真实语料做测试集选择而非训练）

### Q6 算力怎么花
如果只搏一次：整槽集合预测模型 10 万步、一张 24 GB 卡 4–8 小时。**值不值**，
还是同样的预算花在 Q1–Q3 的小对照实验（174 输入、分钟级训练）更划算？

### Q7 LLR 从哪来（部署约束）
原生链路不暴露软信息。选项：主机侧自建"音频 → LLR"解调（可行，但是新组件）、
或让学习链路内部闭环、或只让模型做**候选排序与前验修正**（不动译码）。
有没有第四条路？

## 9. 我们的现状判断（欢迎反驳）

- 端到端"音频 → 报文"在单信号白噪声下**不可能超过**经典链路；价值只可能在非白噪声。
- 纯解调器的学习版本注定追平，不值得投入（§4.1 已量）。
- 真正可能赢的两处：**(a)** 学习型译码器（若能在小模型下超过 BP+OSD，或大幅降低 OSD 开销）；
  **(b)** 多信号联合检测与分离（经典链路逐候选贪心）。
- 我们最缺的不是算力，而是**损失设计与架构选择的经验**——特别是一个**对尺度不变**、
