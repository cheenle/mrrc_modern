# FTX-1 的连接面：除了 USB/CAT，还能接什么、能换来什么

**结论先行**：FTX-1 **没有网口**。它的"联网"只能由中间那台机器提供 —— 现在的盒子就是这个角色，所以换一条线不会多出网络能力。真正的余量在三处：**第二个 USB 串口（CAT-2）**、**后背那个复用的 LINEAR/TUNER 座（CAT-3）**、以及**协议里还没用上的那几十条命令**（`RI`、`RM0/7/8`、`LM`/`PB`、`KY`、`EX`）。至于频谱，**哪条线都拿不到**，因为扫频数据根本没上总线。

本文只写可以核对的事实与推断，标注沿用 `docs/ftx1-technical-analysis.md`：**fact** / **inference** / **unverified**。

---

## 一　先纠正前提：这台机器没有网络口

- **fact**　Yaesu 的网络远程单元 SCU-LAN10，支持列表是 FTDX101MP / FTDX101D / FTDX10 / FT-710（`SCU-LAN10_Installation_Manual_ENG_2311-D`，截至 2023-10）。**不含 FTX-1**。
- **fact**　FTX-1 的选装件清单里没有网络单元：`SBR-52LI`（电池）、`FC-80` / `FC-90`（天调）、`SCF-1`（风扇）、`SPG-1`（防护罩）、`FGPS-5`（GPS 天线）、**`BU-6`（蓝牙单元）**。
- **fact**　手册里的对外接口只有：USB-C、microSD、后背 10-pin mini-DIN（LINEAR/TUNER）、CW 键插座、DC IN、天线座。没有 RJ45，也没有 Wi-Fi 菜单项。

所以"给 FTX-1 插根网线"这件事不存在。**能远程操作，是因为中间有一台机器把 USB 变成了网络** —— 桌面版是那台 PC，盒子版是 W3 系列的板子。换连接方式的讨论，只能在这个前提之下进行。

顺带一句：FTX-1 支持 **WIRES-X 的 HRI 模式**（不需要 HRI-200 盒子，用一台 PC 当 node）。那是 Yaesu 自己的数字中继功能，走 PC 上的官方软件，不是我们能接的口子，但它说明一件事 —— **USB 这条线本身就是这台机器的"网络入口"**。

## 二　接口全景

| 路径 | 物理形态 | 协议 | 我们今天用了吗 |
| --- | --- | --- | --- |
| **USB-C** | CP210x **双 UART** + USB 音频 | CAT-1 38400 / CAT-2 4800 / UAC 44.1 kHz | 用了 CAT-1 与音频；**CAT-2 闲置** |
| **CAT-2 硬件线** | 同一个 CP210x 的第二个口，RTS/DTR | `RPTT SELECT` / `PC KEYING` | 没用 |
| **后背 10-pin（LINEAR/TUNER）** | 5V CMOS，菜单四选一：EXT-TUNER / LINEAR / **CAT-3** / GPO | CAT-3 38400；LINEAR 模式给 BCD 波段数据 + TX GND + EXT ALC；GPO 四路输出（3 mA） | 没用 |
| **microSD** | 机侧插槽 | 无 CAT 接口（**fact**：手册里没有 SD 读写命令） | 不可能用 |
| **BU-6 蓝牙**（选装） | 装在 Field head 内部 | 音频（耳机/麦克），菜单 `MOD SOURCE` 可选 Bluetooth | 没用 |
| **FGPS-5**（选装） | Field head 外部 | 定位（APRS / WIRES-X） | 没用（与我们无关） |
| **面板 / 手咪 / 手键** | — | `TX` 的 `2` 值会告诉你"别人在发" | 部分（我们轮询 `TX`） |

对照一下：FT-710 的扫频走 FT4222 的 SPI（一根独立芯片），IC-7300 走 CI-V `0x27`（总线上的数据帧）。**FTX-1 两条都没有**：SDR 采样进去，DISPLAY CPU 画在屏上，`SS` 只给你调"怎么画"。

## 三　逐条分析

### 3.1 CAT-2：闲置的第二个串口，它原本的工作是"拉线"

**fact**　CP210x 给了两个 UART。手册里叫 Enhanced COM Port（CAT-1，38400）与 Standard COM Port（CAT-2，**4800**，固定 1 停止位）。CAT-2 的出厂速率低，是因为它的原职不是搬数据，而是**用 RTS/DTR 直接拉 PTT、发 CW**（菜单 `RPTT SELECT`、`PC KEYING`）。

**能拿到什么**

- **硬件 PTT**：`RTS` 一变电平，电台就发。不用等 CAT 文本往返，也不与轮询抢那把串口锁。
- **真 CW 键控**：`PC KEYING` 让 DTR 变成手键输入，点划由服务端时序决定 —— 这是远程 CW 唯一"像样"的做法（`KY` 命令也能发 CW 文本，但那是让电台自己发，见 3.6）。
- **一条独立于文本通道的释放路径**：现在的 `TX0` 和轮询挤在同一个串口锁上；硬件线是另一根线。

**代价与坑**

- 需要在面板上把 `RPTT SELECT` 设成 RTS/DTR —— **这是面板动作，CAT 改不了**，用户必须做一次。
- 手册专门警告：CAT-2 跑 CAT 又开 RTS/DTR 流控时，电脑一开机就可能把电台顶进发射。要开这条线，客户端必须在打开串口时**先确保两线为低**，且不复用流控。
- 发射入口之间**没有互斥**：软件发 `TX0`、硬件线还拉着 —— 这是新的卡键面，必须与 SDD §15 的多层释放一起设计。

**值不值得**：值。它同时改善"键控延迟"和"卡键后的释放能力"，而后一条正是这个项目历史上最贵的一类事故。

### 3.2 CAT-3（LINEAR/TUNER 座）：唯一一条电气上独立的第二通道

**fact**　第三条串口不在 USB 上，在后背 10-pin 座里，5V CMOS，默认 38400。菜单 `TUN/LIN PORT SELECT` 四选一：EXT-TUNER / LINEAR / CAT-3 / GPO。**互斥**：选了 CAT-3 就不能同时用外置天调或线性功放。

**fact**　SPA-1（100 W 功放）与 FC-80（天调）**各有自己的 CPU**（`VE` 的 P4 / P5），并且是以总线设备身份挂在 CAT-3 上的。

**能拿到什么**

- **USB 掉线时的后备控制通道**。这一条最有现实价值：本仓的头号现场故障就是 USB 链路（串口重枚举 `ENXIO`、PortAudio `-9999`、FT4222 打不开）。今天 USB 一掉，控制面全瞎；接一根 CAT-3 的线，频率/模式/PTT 还能走另一条物理路径。
- **直接跟 SPA-1 / FC-80 说话**：功放的功率与天调状态不必从主机的表计里猜。
- **BCD 波段数据 + TX GND + EXT ALC**（LINEAR 模式）：给外置功放用，或者反过来 —— **把 TX GND 当"电台真的在发射"的硬件回读**，这比轮询 `TX;` 快且不占带宽。
- **GPO 四路**：波段开关、天线切换器的前级。注意只有 3 mA，驱动继电器要加一级。

**代价与坑**：多一根线、多一个串口、多一套仲裁（两个控制器同时写同一台电台）；且与天调/功放互斥，用户要选。工程上比 3.1 大一个量级。

**值不值得**：对一个"必须无人值守跑几个月"的盒子，值。对桌面版，收益小。

### 3.3 microSD：电台自己能录音，但 CAT 碰不到

**fact**　FTX-1 可以把**接收音频录到 microSD**（单个文件上限约 16 小时 / 3.5 GB，面板上 `RECORD` / `STOP`）。也能存读信道表、备份设置。
**fact**　手册里没有任何 SD 文件读写命令（`docs/ftx1-technical-analysis.md` 摘要的 `excluded` 一节）；`EX` 里有**动作型**菜单项（写下去就执行），其中是否包含录音开关 —— **unverified**。

**能拿到什么（如果那个动作项存在）**

- **电台侧录音**：不经 Opus、不经服务端 CPU、不受 USB 声卡抖动影响，服务端崩了录音还在。相比现在 `recorder.py` 的 16 kHz 单声道时间线，这是"原厂音质"。
- 但**取不出来**：文件在卡上，CAT 读不到。要取只能拔卡，或者人工拷。所以它更像我方的"黑匣子"，不是"QSO 录音库"。

**值不值得**：作为**证据链**值（出问题时有原厂录音），作为**产品功能**不值（用户拿不到文件）。

### 3.4 BU-6 蓝牙：只做音频，不做 CAT

**fact**　`MOD SOURCE` 的枚举是 0 MIC / 1 USB / 2 **Bluetooth** / 3 AUTO；选装 BU-6 装在 Field head 里；菜单里 `Bluetooth → AUDIO` 有 `FIX`（耳机与机身喇叭同时响）/ `AUTO`（只走耳机）。
**fact**　手册里没有任何"CAT over Bluetooth"的入口，BU-6 是音频单元。

**能拿到什么**：一条**绕过 USB 声卡**的收发音频路径（耳机+麦克）。对远程控制意义有限 —— 我们本来就要把音频搬到浏览器里；但对"盒子旁边站着人"这个场景，它和本仓的 `local_speaker.py` 正好是反方向的两条路（一个把音频送到盒子旁边的喇叭，一个送到电台旁边的耳机）。

**坑**：配对是面板动作；`MOD SOURCE` 要跟着切（可以走 `EX`，见 4.3）；插了 BU-6 之后 TX 音频源一旦被切到蓝牙而人不在，就是"键控了没声音"那类事故 —— 与本仓 IC-7300 的 `MOD Input` 现场报告同形。

### 3.5 面板/手咪/手键：不是"连接方式"，是"别人也在按键"

**fact**　FTX-1 能被点着的地方有三个：CAT 的 `TX`、硬件线（RTS/DTR 或手键）、面板与手咪。`TX` 的应答里，`2` 的含义是**电台在发、但不是 CAT 要的**。
**fact**　`RI` 的第四位是 **TX INHIBIT**。

**能拿到什么**：一个**交叉校验点**。服务端以为自己在发、而 `TX` 回 `2`，说明有人在现场按了手咪；`RI` 告诉你"允许不允许发"。这两条今天都没接（`RI` 一条没发过，`TX` 只拿来看自己）。

**值不值得**：值，而且**不需要任何新硬件** —— 就在现有的 USB/CAT 上。

## 五　真正值得做的四件事（按性价比排）

### 5.1 `RI` + `TX=2`：不买任何硬件，先把"对面在干什么"读回来

`RI` 一次回八位：Hi-SWR、录音/回放、TX / TX INHIBIT、天调是否在调、扫描、静噪。配上 `TX` 的 `2`，服务端第一次能回答"**现在这把键是谁按的**"。代价：一条查询、一个解析函数、一组测试；风险：位定义要按手册逐位试。这是安全项，不是功能项。

### 5.2 CAT-2 硬件 PTT：把"卡键"的解法从软件挪一部分到线上

现状的 `TX0` 与轮询抢同一把锁，锁被占住时释放要排队。硬件线是第二根线，天然并行。前置：面板设一次 `RPTT SELECT`；客户端开串口时先压低两线（防开机顶发射）。**这条要与 SDD §15 的释放链路一起设计，不能单加。**

### 5.3 `LM`/`PB` 语音键控：一键 CQ 可以交给电台自己放

- **fact**　FTX-1 的命令表里有 `LM`（LOAD MESSAGE，Set/Read/Ans = O O O）与 `PB`（PLAYBACK，O O O）。手册 89 条命令里我们一条也没发。
- **unverified**　`PB` 在 FTX-1 上是"只本地放"还是"发射出去"。同类机型上两种都有（FT-450 的讨论里 `PB7` 能上发，也有机型只本地放）。
- 若能上发：我们的 CQ 就变成"上传一次、以后按 `PB`"，**不再需要服务端喂音频、不再受 Opus 与队列深度影响**，CQ 期间也不会占用 TX 音频链路。代价：一条真机实验。

### 5.4 CAT-3 作为后备控制通道：为"USB 掉线"这个头号故障买保险

只在盒子上有意义（无人值守），代价是双控制器仲裁与"与天调/功放互斥"的用户选择。工程量大，但它是**唯一能改变故障面**的一项 —— 其余三项都只是把现有路径用满。

## 六　无论接哪条线都拿不到的

| 想做的事 | 为什么拿不到 |
| --- | --- |
| 真频谱 / 真瀑布 | 数据不上总线；`SS` 只有显示参数（速度/峰值/标记/颜色/电平/跨度/模式/AF-FFT） |
| 双收两路音频分别下发 | 不归 CAT 管；USB 声卡给什么就是什么 |
| 读/写 microSD 里的文件 | 手册没有 SD 读写命令（只能面板操作） |
| 固件升级的搬运 | `EX` 里有 `FIRMWARE UPDATE` 这个**动作项**，但镜像必须先躺在卡里 |
| 远程改"CAT 速率 / 端口复用 / RPTT"这类硬开关 | 在面板菜单里，CAT 只能读到 `EX` 表里的一部分；`TUN/LIN PORT SELECT` 换了就换掉一整条通道，不能在会话中来回切 |

## 七　待真机确认的清单

1. `PB` 会不会发射（配 `LM` 上传的一段语音），以及 `LM` 的数据格式。
2. `RI` 八位在真机上的实际位序（静默时、发射时、调谐中、开 TX INHIBIT 时各读一次）。
3. `RM7`/`RM8` 的读数与量程，以及 `RM0` 双读的偏移。
4. CAT-2 上 `RPTT SELECT=RTS` 与 `PC KEYING=DTR` 的实测时延；电脑开机那一下会不会自己顶发射（手册警告过）。
5. `TUN/LIN PORT SELECT=CAT-3` 时这套引脚的实际能力（能否同时给 BCD 与 CAT-3），以及 SPA-1 挂在总线上的握手行为。

前三条只用现有的 USB 线就能做完 —— **不需要先改硬件**。
