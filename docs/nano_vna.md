# NanoVNA 天线诊断台（`/Nano`）操作手册

> 适用版本：AD-030（SDD V3.02 起）。平台：盒子（W103D / Linux aarch64）优先；
> 桌面包可用（USB 直连本机），但没有 `dfu-util` 就升不了固件。
> 设计与实现见 `docs/superpowers/specs/2026-10-18-nano-vna-design.md`。

---

## 1. 它是什么

插在盒子 USB 上的 **NanoVNA-H / H4** 被做成一台**天线诊断台**：量的是天线本身的
**复数 S11**，而不是拿反射功率反推。

它的目标只有一个：**野外架好天线，一眼看出能不能用、要不要剪**。所以主视图是一张
判定卡，而不是仪表盘；仪器式的设置都折进「设备」抽屉里。

| 能力 | 数字 |
|---|---|
| 扫频 | 1–54 MHz，401 点，**约 1.0 秒**（二进制 `scan_bin` 帧，4.8 KB） |
| 同时给出 | 驻波、阻抗 R±jX、谐振点、Smith 圆、`|Z|`、谐振平台 |
| 存盘 | 单文件库 `nano_sweeps.json`（与 `atr1000_tuner.json` 同形态），可导出 CSV / s1p |
| 对比 | 存为基准后叠加，判定卡直接给「中心 SWR ±0.xx」 |
| 独立使用 | 一键「野外配置」把设备自己的屏幕配成 S11 驻波曲线，存进 SAVE 槽 4 |

## 2. 硬件与接线

| 项 | 说明 |
|---|---|
| 设备 | NanoVNA-H 4（实测 `0483:5740` / `NanoVNA-H 4`）；H 与 H4 都支持 |
| 端口 | 盒子上另起一个 CDC-ACM：`/dev/serial/by-id/usb-…ChibiOS…`（1.2.50 后是 `usb-nanovna.com_NanoVNA-H4_400`）|
| 与电台的关系 | **不共享 CAT 口**。CAT 是 CP2105（`ttyUSB*`）、频谱是 FT4222、声卡是 C-Media，VNA 独占自己的口 |
| 接天线 | 天线接 **CH0（PORT1）**；CH1（PORT2）只在测 S21/滤波器时才用 |
| 服务账号 | 服务以 `mrrc` 跑，`mrrc` 必须在 `dialout` 组（镜像已配好） |

> **天线不能同时接电台和 VNA。** 如果天线还连着电台，扫描时电台一发射就是几十瓦进 CH0
> —— 会烧前端。页面在**发射中**（PTT / TUNE / FT8 / 一键 CQ）会拒绝一切设备操作
> （`409 tx_active`），这是硬闸门，不是提示。

发现问题时先看这三个口：

```bash
ls -l /dev/serial/by-id/          # 有 ChibiOS 或 nanovna.com 那条就是它
lsusb | grep 0483                 # 5740 = 应用模式，df11 = DFU
sudo dmesg -T | grep -i "ttyACM\|usb 1-" | tail
```

## 4. 页面怎么用

### 4.1 判定卡（主视图）

扫一次，从上到下就是答案：

```
40m                              ┌ 天调可修（段内最高 1.87）
驻波 SWR     阻抗 Z             谐振点
  1.42       63.4 −j12.1Ω       7.08 MHz (1.21)
────────────────────────────────────────────────
谐振偏低 1.0%（7.08 vs 中心 7.15）→ 振子偏长，需要缩短约 1.0%：
每 10 m 剪 10 cm。
```

- **判定分档**：段内最高 SWR `≤1.5` 免调可用 / `≤2.0` 天调可修 / `≤3.0` 勉强 / `>3.0` 不建议用
- **修剪建议**：谐振频率与波段中心的**相对偏差 ≈ 振子长度的相对偏差**（谐振频率与长度
  近似反比），所以直接给出「每 10 m 剪/加多少 cm」。谐振**偏高 = 偏短**（要加长），
  **偏低 = 偏长**（要剪）
- **阻抗**：R ± jX，能看出容性 / 感性

### 4.2 曲线

- 橙色 = 本次扫描；**蓝色虚线 = 基准**（修剪前）
- 高亮竖带 = 当前波段的窗口；虚线 = 1.5 / 2.0 判定线；绿色竖线 = 谐振点
- **鼠标/手指按住**：指针旁浮出 `频率 / SWR / Z（/Δ基准）`
- **点一下曲线**：把设备屏幕上的 1 号标记挪到那一点（野外不用抠那块小屏）

### 4.3 波段与自定义

波段按钮：80 / 60 / 40 / 30 / 20 / 17 / 15 / 12 / 10 / 6m + HF 全段。点了**自动扫描**；
扫描范围比波段窗宽一点，谐振点才看得见。

自定义在「自定义频段 / 扫描点数」折叠里：填**中心**与**带宽**（MHz）即可，也可改点数
（101 / 201 / 401，分别约 0.3 / 0.6 / 1.0 秒）。

### 4.4 存盘与对比

- **存为基准**：把当前曲线设为对比基准（不落盘，刷新即失效）
- **保存**：写进 `nano-data/nano_sweeps.json`（单文件库）
- **设为基准**：从历史里挑一条叠加
- **导出 CSV / s1p**：s1p 是 Touchstone v1，别的 VNA 软件也能读

## 5. 标定（必做，否则数不可信）

标定按**频段**生效，且必须有 50Ω 基准。设备菜单和串口都能做；一键做法是用串口逐项采集：

```bash
# 设备先进到你要用的范围（页面上的「设为设备范围」或串口）
sweep 1000000 54000000 401

cal reset
cal open      # CH0 接 OPEN（或什么都不接）
cal short     # CH0 接 SHORT
cal load      # CH0 接 50Ω 负载
cal done      # 计算
cal on        # 应用
save 0        # 存进设备槽（掉电不丢）
```

验证：**50Ω 负载接着时全段 `|S11| ≈ 0`、`SWR = 1.000`**。达不到就重做，先怀疑负载。

> `cal` 之后**不要**再 `clearconfig` —— 那会连标定一起清掉。

## 6. 野外独立使用（拔下来只看设备屏幕）

设备自己那块 480×320 的屏上显示什么，取决于**它自己的迹线设置**，与网页无关。
页面「设备」抽屉里的 **一键套用野外配置** 会把设备配成：

1. 扫 **1–54 MHz / 401 点**（HF + 6m 一次覆盖）
2. **关掉其它三条迹线**，只留 **trace 0 = S11 的 SWR**，刻度 1.0/格、参考 0
   （屏幕从下到上就是 0→10 的驻波），并打开网格数值
3. 标记 1 放到扫描中点（转旋钮就能拖到谐振点）
4. `saveconfig` + **`save 4`**

**带出去：开机 → 主菜单 RECALL → 4。**

为什么必须 `save`：**迹线格式不在 config 里**，`saveconfig`（甚至固件的「记住关机前状态」）
都留不住它；只有 SAVE/RECALL 槽存的是**整套状态**（扫描范围 + 迹线 + 标记 + 标定）。
真机实测：改完迹线 `saveconfig` + 重启 ⇒ 回默认；`save 4` + `recall 4` ⇒ 整套回来。

> 槽 4 是这个功能占用的；`recall 4` 会把**当时的标定**一起恢复，所以重做标定后请重新
> 点一次「一键套用野外配置」。

## 7. 基准配置

仓库里有一份从真机倒出的基准：`docs/nano/field-baseline.json`
（设备型号/固件、扫描范围、迹线、标记、测量设置、标定状态）。

页面「设备 → 基准配置 → 与基准对比」会列出**所有偏离项**：

```
扫描终点：基准 7800000 → 现在 30000000
迹线 0 格式：基准 SWR/S11 → 现在 LOGMAG/S21
平滑：基准 0 → 现在 4
```

只能对比**读得回来**的项（扫描范围 / 迹线 / 标记 / 测量设置）。`config` 里那些开关
（网格、翻转、自动命名…）固件没有查询命令，页面显示的是"本页记下的意图"。

## 8. 固件升级

官方镜像来自 `hugen79/NanoVNA-H` 的 Releases；变体有 **MS / SI / ZK** 三种，
**看机器标签的硬件版本结尾**（官方 1.2.43 说明）。SI/MS 选错可以在
`CONFIG → EXPERT SETTINGS → MORE → MODE` 里切换，只有 ZK 是混频器硬件区别。

### 8.1 进 DFU 的三种方式

| 方式 | 适用 |
|---|---|
| **按住旋钮/拨杆不放 → 开机**（屏幕保持全黑 = 工程模式） | H4，**所有固件版本都可** |
| `CONFIG → EXPERT SETTINGS → ▶ DFU` | 固件编译时开了 `__DFU_SOFTWARE_MODE__`（1.2.50 有，1.2.14 没有）|
| 拆机把 `BOOT0` 短到 `Vdd` 后上电 | 兜底 |

### 8.2 刷写

```bash
curl -L -o NanoVNA-H4.bin \
  https://github.com/hugen79/NanoVNA-H/releases/download/1.2.50/NanoVNA-H4-MS_20260516.bin
sha256sum NanoVNA-H4.bin     # edaccbe2fad8b192f585639babb427acf32d7bd171756353eecb92bc9b1b9322

dfu-util -d 0483:df11 -a 0 -s 0x08000000:leave -D ~/NanoVNA-H4.bin
```

- 判据只有一个：结尾出现 **`File downloaded successfully`**
- 中间那片红字（`dfuERROR … Device's firmware is corrupt`）是**正常的**，刷完自行清除
- **升级会整片擦除 flash**：标定与设置全清，事后必须重做标定
- 刷后行为异常：`CONFIG → RESET AND CLEAR`，再重做标定
- ROM bootloader 不可擦写：**刷坏只会停在 DFU，再刷一次即恢复，不会砖**

网页端也有一键升级，但默认上锁：`MRRC_NANO_ALLOW_FLASH=1` 并重启服务后才出现。

## 9. 排障

| 现象 | 原因 / 处理 |
|---|---|
| 页面报「设备掉线」 | USB 掉过或重新枚举。服务端会自己丢死句柄并在 2 秒后重连；换个 USB 口（尽量直连，别经分线器）|
| 扫描期间显示「设备忙」 | 正常：一次只允许一个设备操作，忙 ≠ 掉线 |
| 报 `device reports readiness to read … multiple access` | 另一个进程也开着串口（比如你自己在盒子上跑脚本）。停掉它，或 `systemctl stop mrrc-modern` 后再动 |
| 曲线是平的 / 一片 99.9 | CH0 上什么都没接（开路 ⇒ SWR 顶到量程上限）|
| 接了 50Ω 但 SWR 不为 1 | 标定没做或做坏了；也可能是变体选错（MS/SI）|
| 野外配置后屏幕上还是老样子 | 需要 `RECALL 4`；见 §6 |
| 开两个标签页 | 能共存，但同一时刻只有一个设备操作，另一个会看到「忙」|

## 10. 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `MRRC_NANO` | `on` | `off` 关掉整个入口 |
| `MRRC_NANO_PORT` | 空（自动发现）| 显式指定串口（运维逃生口）|
| `MRRC_NANO_DIR` | `<运行目录>/nano-data` | 扫描库、`state.json`、镜像与升级凭证（**不要指到 `nano/` 代码目录**）|
| `MRRC_NANO_ALLOW_FLASH` | `0` | `1` 才出现网页升级入口 |

## 11. 已知边界

- **只做 S11**（一端口）。S21 需要转接头与双端口夹具，协议支持但页面不画。
- **不做校准向导**：OPEN/SHORT/LOAD 是物理动作，页面只给命令与验证方法。
- **`config` 开关读不回来**，`tcxo`（频率基准）与破坏性命令（`clearconfig`/`touchcal`/`sd_delete`）
  不进页面白名单。
- 扫描会临时改设备屏幕的范围，**每次扫完自动还原**（约 +0.3 秒）。
- 401 点约 1.0 秒 / 101 点约 0.3 秒——它是仪器，不是流。
