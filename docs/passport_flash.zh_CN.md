# 在盒子网页上刷 Passport

一台刚出厂的 MRRC-Passport 什么配置都没有：用户得先连它自己开的热点（iOS 还会警告「本网络无法上网」），
再在手机小键盘上敲 Wi-Fi 名、Wi-Fi 口令、盒子地址、盒子口令。

而盒子本来就知道这一切，而且它是现场唯一既有 USB 口又整天开着的机器。所以：把终端插到盒子上，
打开 `/passport` 点一次 —— 固件与配网一起写进去。

这份是操作指南；设计记录在 `docs/superpowers/specs/2026-11-25-passport-flash-design.md`。

---

## 0. 它到底做了什么

五个步骤，顺序固定（`passport_flash.plan_flash()`）：

| # | 步骤 | 含义 |
| --- | --- | --- |
| 1 | `chip id` | 认芯片。不是 ESP32-C3 的板子在**第一次写之前**就被拒绝 |
| 2 | `firmware <version>` | 合并镜像写到 `0x0`（bootloader + 分区表 + app），带 `--verify` |
| 3 | `wifi config` | NVS 分区写到 `0x9000`（Wi-Fi 名/口令、服务器地址、盒子口令），带 `--verify` |
| 4 | `read back` | 把 `0x9000` 读回来，与要写进去的配置逐项比对 |
| 5 | `reset` | `hard_reset run`，板子带着新配置启动 |

它换来的两件事：

- **不用在手机上敲字。** 盒子把自己的 Wi-Fi 和服务器地址写进终端的 NVS。
- **不会「看起来成功」。** 第 4 步是真的回读；不一致就失败，而不是留下一块带着错误口令启动的板子。

---

## 1. 前提

| 项 | 要求 |
| --- | --- |
| 盒子镜像 | **1.28.99 及以后。** 刷机工具**跟着代码走**：`vendor/esptool/` 是 esptool 及其依赖铺成的一个普通目录，服务以 `PYTHONPATH` 交给 `python -m esptool`。不需要 pip、不需要网络、不需要重启 —— 一次「搬文件」的热修就够。（2026-11-27 在 `192.168.1.217` 上把 pip 包**卸载**后验证：`esptool.py v4.14.0`、页面 `esptool: true`。）没有这个 bundle 的树（桌面构建，或比它更老的盒子）才需要装一次：`sudo /opt/mrrc_modern/venv/bin/pip install 'esptool>=4.7,<5'` |
| 终端 | 一块 Passport / ESP32-C3 板子 |
| 线 | **数据线**（充电线什么都不会出现） |
| 网络 | 盒子能访问 `www.vlsc.net`（固件从官网下载，盒子不自建也不托管镜像） |

**先拔掉电台线。** W103D 只有两个 USB 口，FT-710 的 CAT 与 scope 两根线占满了；拔掉时电台会掉线，
刷完插回去会自动恢复。

---

## 2. 打开页面

```
https://<盒子>:8888/passport
```

页面顶部是状态胶囊和一个 `← 返回电台` 的链接。第一张卡片报告环境：

- `本机 esptool` —— **有** / 没有
- `固件目录` —— 目录地址
- `串口` —— 候选，例如 `/dev/ttyACM0 (原生 USB)`

只列 ESP32 类串口，而且**电台自己的串口永远不在候选里** —— 把 1.7 MB 写进 FT-710 的 CAT 口
不是「刷失败」，是事故。

---

## 3. 第一步 · 固件（`1 · 固件`）

1. 点 **读取目录**。盒子去取
   `https://www.vlsc.net/mrrc_modern/downloads/passport/firmware.json`，填进下拉框。
   这一步失败是 `502`，原因显示在日志面板里。
2. 选一个版本。
3. 点 **下载并校验**。镜像在**开始刷写之前**就下载完并核对 SHA-256，所以写入阶段不含下载。

已经下过的版本的会被复用（下拉框里带 `downloaded` 标记）。

## 4. 第二步 · 设备（`2 · 设备`）

插上板子；没出现就点 **重新识别**。下拉框会给每个端口标类型：

- `（原生 USB）` —— USB-Serial-JTAG，正常情况
- `（USB 转串口）` —— 桥接芯片

**板子不出现？** 按住板子上的 **BOOT** 键再插 USB（进下载模式），然后点 **重新识别**。

## 5. 第三步 · 要写进设备的配网（`3 · 要写进设备的配网`）

| 字段 | 预填 | 说明 |
| --- | --- | --- |
| `Wi-Fi 名称（SSID）` | 盒子当前连着的那个网络 | 可以改 |
| `Wi-Fi 口令` | **空** | 每块板子手输一次。NetworkManager 不会把口令交给非 root 用户，服务端也刻意不向页面索取 |
| `设备要连的地址` | 本盒子的局域网地址 | 终端要在外面用，就改成公网入口（`w103d.vlsc.net`） |
| `盒子网页口令` | 空 | **留空 = 用本盒子自己的网页口令。** 这个值既不出现在响应里，也不进日志 |

## 6. 第四步 · 写入（`4 · 写入`）

点 **开始刷写**。日志面板（`pre#log`）显示 esptool 自己的输出，任务运行期间页面每秒轮询
`/api/passport/state`。

一次刷写大致长这样：

```
chip id
  ... Chip is ESP32-C3 ...
firmware 1.3.1
  ... Writing at 0x00010000... (100 %)
wifi config
  ... Writing at 0x00009000... (100 %)
read back
reset
done
```

任务是一把**单槽锁**：跑着的时候再点开始会得到 `409 已经有一次刷写在进行`。
状态胶囊会变成 `done`（绿）或 `failed`（红）并给出原因。

### 验证了什么，没验证什么

- **已验证**：每一个写入的字节（`--verify`），以及 NVS 分区被读回来逐项比对。
- **页面没有验证**：板子是否真的连上 Wi-Fi 并到达盒子。那是下面的验收步骤 —— 需要一根电源线和一分钟。

---

## 7. 验收（每次都做）

1. 把 USB 线从盒子上拔下来，板子插到 USB 电源上。
2. 看板子：它应该启动到主界面并连上。
3. 在盒子上打开 `/`（或终端会话列表）。Passport 应该以一个终端会话出现，`role=operator`。
4. 用它调一下频率：电台跟着变。

**刷成功了但连不上**，几乎总是 Wi-Fi 口令错了、或地址它够不到 —— 用同一个固件重跑第三步即可
（NVS 写入很快；合并镜像没变就不会重写）。

---

## 8. 排障

| 现象 | 原因 / 处理 |
| --- | --- |
| 开始按钮灰的，`本机 esptool 没有` | venv 和 `vendor/esptool/` 都提供不了 esptool。随包带 bundle 的树按构造不会出现这条，所以这意味着树旧了或不完整 —— 更新它，或者装一次：`sudo /opt/mrrc_modern/venv/bin/pip install 'esptool>=4.7,<5'` |
| `那个串口不在可选列表里`（400） | 端口在「列出」与「开始」之间消失了，或者那是电台的口。点 `重新识别` |
| `固件版本不在目录里`（400） | 页面加载后目录变了。再点 `读取目录` |
| `已经有一次刷写在进行`（409） | 同时只允许一次。等它结束，或结束后刷新页面 |
| `catalog: ...`（502） | 盒子够不到 `www.vlsc.net`。检查它的网络 / DNS（`/settings` → 网络） |
| `download: ...`（502） | 目录拿到了，但镜像下载失败或 SHA-256 不一致。重试；持续出现说明发布的产物是旧的 |
| 按住 BOOT 插上也没有端口 | 换一根数据线；或者板子不是 ESP32-C3（即便如此芯片检查也会拒绝） |
| `read back` 不一致 | 任务会**故意失败**（短回读不算「截断成功」）。重跑；反复出现说明板子的 flash 在坏 |
| 刷成功但板子起来进了配网热点 | NVS 没写进去，或 SSID/口令不对。重跑第三步 |

---

## 9. 安全边界（由实现保证）

- **Wi-Fi 口令不离开盒子自己的进程**：它只进内存里的 NVS 镜像，而
  `passport_flash.redact()` 会把每一行进页面和 `server.log` 的行都洗一遍
  （日志面板会被截图、会进支持包）。
- **盒子的网页口令在字段留空时不会被页面索取**，由服务端自己代入。
- **电台 USB 设备的所有接口都被排除**，不只是 `cat.port` 那一个路径：FT-710 的 CP2105 把 CAT（`if00`）与 scope（`if01`）暴露成两个 tty，一直等到 2026-11-27，页面还在把 scope 口列成 Passport 候选。现在 `candidate_ports()` 按 by-id 的设备身份（`usb_device_key()`）分组，整颗芯片一起排除。
- **错芯片在第一次写之前就停**，插错的板子不会被刷一半。
- **`listen` / `sdr` 会话一律 `403`** —— 刷机是操作员动作。

## 10. 状态

代码与测试就绪（`passport_flash.py`、`tests/test_passport_flash.py`，21 个测试全过，
其中包含与 ESP-IDF 官方 NVS 生成器**逐字节相等**的比对）。随 **1.28.99 · FP86** 发布。

**2026-11-27 已在真机上部分验证**（盒子 `192.168.1.217`，1.28.99）：装上 `esptool` 后
`GET /api/passport/state` 报 `esptool: true`；不插任何设备时端口列表为空（此前会列出电台的
`ttyUSB1`）；SSID 预填返回 `CMCC-cnham`；`POST /api/passport/firmware` 成功拉到目录（`1.3.1`）。

**真正的刷写尚未做**（CHANGELOG 也这么记着）：一块 Passport + 一台盒子，刷完、拔线、上电，
确认它自己连上 Wi-Fi 并在盒子上显示为一个终端会话。第 7 节就是那张清单。
