# 静噪（SQL）使用与排障

**一句话**：网页上的 SQL 滑杆只做一件事——把 0–100 的静噪电平写给电台（Yaesu 发
`SQ0xxx;`，Icom 走 CI-V `14 03`）。它改不了电台内部「声音要不要经过静噪门」的接法。所以「拉到最大还是没静噪」通常不是滑杆坏了，而是下面两种情况之一：

1. 你听的那路音频在静噪**之前**就被取走了（IC-7300 的出厂设置就是）。
2. 电台的静噪旋钮压根没被启用（FT-710 出厂把那个旋钮设成了 RF 增益）。

---

## 一、先分清两件事

| | 谁决定 | 在哪改 |
| --- | --- | --- |
| **静噪门槛**（多强的信号才开闸） | 我们写的电平值 | ☰ →「电台参数」→ SQL 滑杆 |
| **静噪有没有接在你要听的那路音频上** | 电台的菜单与旋钮状态 | 电台面板（见下表） |

第二列不解决，第一列调到天上也不会响。

顺带一条常被忽略的事实：**SSB/CW 多数机器不用静噪**。IC-7300 的 `RF/SQL` 旋钮出厂是
Auto，在 SSB、CW、RTTY 下它当 RF 增益用，静噪只在 AM/FM 生效。频段上安静调机时以为
静噪失灵，其实那台机器在那个模式下没有静噪这回事。

---

## 二、各机型必须先做的设置

| 机型 | 必须先改的设置 | 出厂状态 | 不改的后果 |
| --- | --- | --- | --- |
| **IC-7300** | `MENU → SET → Connectors → ACC/USB AF SQL` 改成 `ON` | `OFF (OPEN)` | 机内喇叭会静，**网页听到的 USB 音频一直响** |
| **IC-7300MK2** | 同上（同族菜单，未逐项核对） | 同上 | 同上 |
| **FT-710** | `FUNC → OPERATION SETTING → GENERAL → RF/SQL VR` 改成 `SQL` | `RF` | 那个旋钮当 RF 增益，静噪没接上 |
| **FTDX10 / FTDX101 / FTX-1F / FT-891** | 同族的 `RF/SQL` 相关菜单，**未逐台核对** | 以面板为准 | 同上 |

`RF/SQL VR` 有三档：`RF`（默认）、`SQL`、`SQL(FM only)`。第三档只在 FM / FM-N /
DATA-FM / D-FM-N 下当静噪，其余模式仍作 RF 增益——想全模式可调就选 `SQL`。

参考（手册原文）：

- [IC-7300 Basic Manual](https://www.icomeurope.com/wp-content/uploads/2023/04/IC-7300_ENG_IM_Basic_9.pdf)
  ——`ACC/USB AF SQL`，默认 `OFF (OPEN)`：`Selects whether or not to output the audio
  from [ACC] and [USB], according to the squelch state.`
- [FT-710 中文手册](https://yaesu.com.cn/uploads/allimg/20251021/3-2510210A355C5.pdf)
  ——`[RF GAIN/SQL]` 一节：「操作前，将 [RF GAIN/SQL] 控制的操作设为 'SQL'。默认设置为
  'RF'。」
- [FT-710 日文手册](https://www.exseli.com/pdf/uploaded/manual_trn_453178882.pdf)
  ——`RF/SQL VR` 三档的逐条说明。

## 三、三步验证

1. **看机内喇叭**：把 SQL 拉到 100，等两三秒。喇叭静了没有？
2. **看网页**：同一时刻，网页里的底噪静了没有？
3. **看写有没有落地**：关掉弹窗再打开，滑杆停在 100 吗？IC-7300 系列每 5 秒回读一次，跳回别的值就说明电台没采纳我们的写；Yaesu 侧不回读（设计如此），滑杆显示的是最后
   下发的值。

把三步的结果对着下表看，基本能一次定位：

| 机内喇叭 | 网页音频 | 滑杆 | 结论 |
| --- | --- | --- | --- |
| 静了 | 还在响 | 停在 100 | 音频在静噪**之前**被取走。IC-7300：改 `ACC/USB AF SQL`；FT-710 多半也是同样接法，只能靠软件静噪（见第五节） |
| 静了 | 还在响 | 跳回旧值 | 电台收下了，但被面板或另一台设备改了回来。先确认没人在动电台 |
| 没静 | 还在响 | 停在 100 | 电台收到了值却没执行。先查模式（SSB/CW 下多数机器无静噪），再查上面的旋钮设置 |
| 没静 | 还在响 | 跳回旧值 | 写被拒。看服务端日志有没有 `set_squelch` 的报错，没有就是 CAT 链路的问题 |

## 四、滑杆本身的边界

- **量程 0–100**：0 是常开，100 是最强门限。FT-710 的 CAT 接受 000–100，Icom 侧我们
  映射到 CI-V 的 0–255。
- **松手才发**：拖动时只更新读数，松开鼠标或手指才发命令。拖动过程不会把串口刷满。
- **不做回读轮询**（Yaesu 家族）：每两秒一条额外 CAT 查询换不来对等收益，这个取舍是
  明写的。Icom 本来就有 5 秒回读，写进去的值会被它纠正到真值。
- **值记在本机**：cookie `ft710_sql`，重开弹窗或刷新页面能拿回上次下发的值。

---

## 五、已知限制

1. **IC-7300 出厂设置下，网页音频不受静噪控制**。这是电台的设计，不是缺陷；改菜单即可。
2. **Yaesu 家族不回读**，滑杆无法自证写有没有落地。
3. **写后校验尚未实现**：计划是 `set_squelch()` 之后读一次 `SQ0;`，不一致就在界面上报错，现在只能靠第三节第 3 步人工判断。
4. **软件静噪尚未实现**。若那台机器的 USB 音频确实在静噪之前取（改不了菜单，或菜单
   改了仍如此），唯一可行的路是在盒子侧按音频能量或 S 表做门限。这属于新功能：门限
   迟滞、录音与 FT8 解码要不要一起掐，都得先设计。

## 六、给维护者的一句话

命令格式在 `backends/ft710/cat_controller.py`（`SQ0xxx`）、`backends/yaesu/cat_core.py`
（同形）、`backends/ic7300/civ_controller.py`（`_level_set(LVL_SQL, pct→raw)`）；服务端
落点在 `server.py` 的 `squelch` 分支（0–100 钳位、写状态、随 `stateUpdate` 广播）。现场
复现不了的现象，先用这两级证据夹：**导出的字节**，与**电台自己的喇叭**。
