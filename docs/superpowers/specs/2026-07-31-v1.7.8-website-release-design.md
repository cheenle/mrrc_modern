# v1.7.8 Stable Website Release Design

**Date:** 2026-07-31

**Release:** v1.7.8 Stable

**Status:** Approved approach; written specification ready for review

## Objective

Publish the verified Windows x64 installer as MRRC FT-710 v1.7.8 Stable on the
project website, synchronize the English and Chinese release documentation,
and remove stale website claims that Windows TX bypasses the FT-710's fixed
44.1 kHz device boundary.

The release classification is Stable. Public copy must still distinguish the
completed software/installer verification from physical RF acceptance: the
Win11 build and smoke-test environment had no FT-710 USB passthrough and cannot
prove over-the-air speech quality by itself. This preserves traceability to
SC4 and NFR-051 without changing the chosen release channel.

## Chosen Approach

Update the existing bilingual landing pages and direct-download flow instead
of adding a new release-page subsystem. Keep the permanent installer URL for
existing links and add a versioned artifact for reproducibility.

GitHub Releases is not a publication dependency. The website must provide a
complete, independently downloadable release even while GitHub CLI
authentication is unavailable.

Both files must hash to the value above before and after deployment.

## Website Content

Update `website/index.html` and `website/zh/index.html` together:

- Promote the hero, download card, install instructions, footer, and metadata
  from v1.7.6 to v1.7.8 Stable.
- Point the primary download action to the evergreen filename and offer the
  versioned filename in the release details.
- Publish the exact SHA-256 and 35.1 MB display size.
- Summarize the Windows TX fixes: browser/Opus stays at 48 kHz; every decoded
  960-sample frame is converted to 882 samples at the fixed 44.1 kHz FT-710
  device boundary; PortAudio reinitialization preserves that rate; TX-session
  diagnostics expose `queue_drops`; reconnecting same-session audio sockets
  replace stale ownership safely.
- Remove the obsolete v1.7.6 claim that Windows TX uses a native WASAPI 48 kHz
  output path.
- State that the Windows build, 439-test suite, installer lifecycle, required
  bundled files, server listen check, and authenticated health boundary were
  verified. Do not claim that the KVM performed an over-the-air audio test.

The existing layout, amber visual identity, navigation, and responsive design
remain unchanged.

## Documentation Synchronization

Synchronize release metadata and operator guidance in the repository:

- `README.md`: current stable version, Windows download, verification summary,
  and fixed 48 kHz codec / 44.1 kHz device-domain wording.
- `CHANGELOG.md`: classify v1.7.8 as Stable and record the shipped installer.
- `docs/WINDOWS_INSTALLER_GUIDE.md` and `win_pack.md`: release filename, size,
  hash, and Windows TX diagnostic acceptance counters.
- `SDD/README.md` and `SDD/14-version-history.md`: record the public Stable
  release decision while retaining the physical-RF verification limitation.
- Generated `website/sdd/*.html`: rebuild from the synchronized SDD source with
  `website/build_sdd.py` so the published design record matches Git.

No runtime behavior, protocol, or audio-rate decision changes in this release
publication. AD-004, AD-008, AD-011, NFR-060, NFR-065, and SC4 remain the
governing design references.

## Deployment Flow

1. Copy the verified installer into both website download paths.
2. Update bilingual pages and release documentation.
3. Rebuild generated SDD HTML.
4. Verify local HTML references, version strings, artifact hashes, syntax, SDD
   constraints, and the full hardware-independent test suite.
5. Commit and push the website/documentation release changes.
6. Run `website/deploy.sh` to publish only `/mrrc_ft710/`. The script creates a
   timestamped server backup, extracts the site, validates nginx, and reloads
   it.
7. Fetch both live installer URLs and compare their SHA-256 values with the
   source artifact. Check the English and Chinese pages for v1.7.8 Stable and
   confirm stale v1.7.6/WASAPI-48k release claims are absent.

## Failure Handling and Rollback

- Abort before deployment on any hash mismatch, missing bilingual update,
  failed SDD build, failed test, or SDD constraint violation.
- Abort publication if nginx validation fails.
- If live HTML or downloads do not match local output, restore the timestamped
  `/tmp/mrrc_ft710_backup_*` directory created by the deployment script and
  reload nginx.
- Preserve the user's local `atr1000_tuner.json` and `mem_channels.json`
  modifications; they are runtime data and are outside this release.
  This preserves AD-010, UC-007, SC9, and the still-open I7 behavior exactly as
  it is; publication work neither rewrites nor claims to validate that data.

## Acceptance Criteria

- English and Chinese pages identify v1.7.8 as Stable.
- Both live download URLs return HTTP 200 and exactly 36,820,041 bytes.
- Both live artifacts have SHA-256
  `c1e474b58f9948206990efbc9f8bdb5b183d03e4f462828b56d2d3f8c0b493bb`.
- Website and documentation consistently describe the 48 kHz codec domain and
  fixed 44.1 kHz FT-710 device domain on Windows.
- Generated SDD pages reflect the source SDD release status.
- Hardware-independent tests pass and `sdd_context.py check --staged` reports
  clean before commit.
- The published page reports software-chain evidence accurately and does not
  represent the KVM smoke test as physical RF acceptance.
