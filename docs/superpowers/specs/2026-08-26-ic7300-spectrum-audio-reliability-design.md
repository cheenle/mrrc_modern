# IC-7300 频谱与音频可靠性修复设计

日期：2026-08-26
状态：已批准

## 目标

修复 IC-7300/IC-7300MK2 在默认配置下可能以错误串口速率启动、频谱数据积压和瀑布刷新仅 5 FPS 的问题；修正现场诊断脚本的 CI-V 帧格式，并增强声卡选择与采样率日志。在所有改动中保持 FT-710 的 38400 baud、44.1 kHz 设备域和既有频谱生产链不变。

## 成功标准

1. 未显式配置 `MRRC_BAUD_RATE` 时，FT-710 使用 38400，IC-7300/IC-7300MK2 使用 115200。
2. 显式配置 `MRRC_BAUD_RATE` 或兼容变量 `FT710_BAUD_RATE` 时，所有后端尊重配置值。
3. CI-V 频谱队列有固定上限；生产快于消费或没有客户端时，只保留最新数据，不无限增长。
4. `/WSspectrum` 在有客户端时以约 30 Hz 调度，并只在真实频谱生成新帧时发送新帧；S-meter 回退仍可按调度周期生成。
5. `_diag_ic7300_scope.py` 发送标准 `FE FE ... FD` CI-V 帧，不插入校验和，并使用项目正式编解码器解析地址、频率与波形分片。
6. 启动日志能明确显示音频后端型号、设备索引、设备名、host API、设备默认采样率和实际打开采样率。
7. IC-7300 音频保持 48 kHz 原生直通；FT-710 音频保持 48 kHz Opus 域与 44.1 kHz 设备域之间的既有重采样。

## 相关设计约束

- SDD AD-006 / §9.5：IC-7300 的真实频谱来自 CI-V `0x27`，并转换为共享 850 点格式。
- SDD NFR-003 / SC6：真实频谱目标约 20–30 FPS，二进制帧格式不变。
- SDD AD-008 / NFR-065：音频设备按显式配置、后端名称提示、通用 USB 名称和通道启发式选择。
- SDD AD-011 / NFR-060：IC-7300/MK2 使用 48 kHz 原生设备率；FT-710 使用 44.1 kHz 设备率。
- 不改变 PTT 释放、安全看门狗、TX 所有权或 Opus 标签协议。

## 方案选择

### 采用：最小、后端感知修复

- 在配置加载阶段根据 `MRRC_RADIO_MODEL` 选择串口默认速率，环境变量仍具有最高优先级。
- 保持 `CivScopeProducer` 的客户端按需启动方式，在 CI-V demux 边界限制队列容量并丢弃最旧分片。
- 共享频谱广播循环恢复约 30 Hz 调度；真实频谱通过 `ScopeHandler` 帧序号判断是否有新数据，避免重复发送同一真实帧。
- 诊断脚本复用 `backends.ic7300.civ_codec`，消除第二套协议实现。
- 只增强音频日志，不改变采样和重采样算法。

### 未采用：仅要求用户手工配置

该方案无法修复默认启动错误、诊断脚本误报和无界队列，不满足可靠性目标。

### 未采用：把整个频谱生命周期移入后端

在客户端连接/断开时下发 `27 11 01/00` 可以减少串口流量，但会扩大生命周期与重连改动范围，并增加多客户端竞态。当前先用有界最新数据队列解决积压问题。

## 组件设计

### 1. 后端感知的串口默认速率

`config.py` 根据规范化后的 `RADIO_MODEL` 选择默认值：

- `ft710` → 38400
- `ic7300` / `ic7300mk2` → 115200

`MRRC_BAUD_RATE` 与旧 `FT710_BAUD_RATE` 继续覆盖默认值。`server.py` 继续把最终解析值传给 backend，避免改变构造接口。

### 2. CI-V 最新数据队列

`CivController.scope_queue` 使用有限 `maxsize`，容量至少覆盖多个 11 分片 USB 波形。收到新分片而队列已满时，先丢弃最旧分片，再放入新分片，并累计丢弃计数用于低频诊断日志。

分片丢失会使当前波形被 `ScopeAssembler` 放弃；下一条 sequence-1 会自动重新同步。因此不拼接新旧波形，也不会显示损坏数据。

### 3. 20–30 FPS 广播

广播调度周期设置为约 33 ms。对于真实频谱，广播循环记录最后发送的 `_frame_count`，只有该计数增长时才发送；对于 S-meter 回退，每个周期先生成一次回退数据再发送。

客户端首次连接时立即得到当前帧；之后真实频谱没有更新则不重复发送。网络格式继续为 v2：1 字节版本 + 850 字节 RX1 + 850 字节 RX2。

### 4. CI-V 诊断脚本

诊断脚本直接使用：

- `build_frame()` 构造标准帧；
- `CivFrameParser` 增量解析串口字节；
- `decode_freq_bcd()` 解码频率；
- `parse_scope_segment()` 验证并统计 scope 分片。

脚本只执行频率读取、PTT 状态读取、scope data output ON 和 center mode，不发送 PTT key 命令。退出前发送 scope data output OFF，避免诊断结束后持续占用串口带宽；若关闭命令失败则输出警告但仍关闭串口。

### 5. 音频可观测性

`AudioHandler` 在设备枚举和 RX/TX 打开日志中加入：

- active backend 传入的设备率；
- PortAudio host API 名称；
- 设备默认采样率；
- 实际打开的采样率和通道数；
- 匹配层级（显式配置、radio hint、generic USB、heuristic、default）。

日志文案使用“radio USB audio”，不再把通用 USB 设备固定称作 FT-710。设备选择顺序和音频数据处理不变。

## 错误处理

- 不支持的显式串口速率仍允许传入，由真实连接结果决定是否成功。
- 频谱队列满只丢旧分片，不阻塞 CI-V reader，也不影响 CAT 查询响应。
- 诊断脚本没有收到帧时明确区分端口/波特率、CI-V 地址和 scope stream 三类失败。
- 音频日志增强不得使设备信息读取失败阻断 stream open；缺失字段显示 `unknown`。

## 测试策略

1. 配置子进程测试：分别设置/清除模型和波特率环境变量，验证默认值与覆盖优先级。
2. CI-V 控制器测试：连续推送超过队列容量的合法 scope 分片，验证队列有界且保留最新分片。
3. 频谱广播测试：模拟 `_frame_count` 不变与增长，验证真实频谱不重复、更新后发送；验证调度目标为约 30 Hz。
4. 诊断脚本测试：断言频率查询等于 `FE FE 94 E0 03 FD`，解析标准无线电响应，并验证不依赖校验和。
5. 音频测试：伪造 host API 与设备信息，验证日志字段和选择结果；复跑 IC 48 kHz passthrough 与 FT-710 44.1 kHz resample 测试。
6. 运行完整 Python unittest，并执行 SDD harness 检查。
