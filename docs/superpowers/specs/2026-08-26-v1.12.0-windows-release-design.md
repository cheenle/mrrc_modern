# v1.12.0 Stable Windows Release Design

**Date:** 2026-08-26

**Release:** v1.12.0 Stable

**Status:** Approved approach; written specification ready for review

## Objective

Publish the completed IC-7300 and IC-7300MK2 runtime-reliability and official
CI-V conformance work as the MRRC Modern v1.12.0 Stable Windows x64 installer.
Push the reviewed source to `origin/main`, build on the established Windows 11
KVM, publish identical evergreen and versioned installer downloads, synchronize
English and Chinese release material, and create the annotated `v1.12.0` tag.

The Stable classification applies to the software and installer pipeline. It
does not convert hardware-independent CI-V vectors or the KVM build into proof
of physical USB enumeration, over-the-air RF behavior, real-radio ACK timing,
or RX/TX audio quality. Those remain operator acceptance checks.

## Chosen Approach

Use the existing PyInstaller plus Inno Setup pipeline and the existing
`www.vlsc.net/mrrc_modern` bilingual static-site deployment. The release uses a
minor-version increment because it adds and hardens externally visible
IC-7300/MK2 capabilities while preserving the FT-710 behavior and configuration
contract.

The release proceeds in two commits:

1. A pre-build release-preparation commit sets version `1.12.0`, adds the
   changelog entry, and updates build/deployment manifests that must be present
   in the Windows source archive.
2. A post-build publication commit records the measured installer size and
   SHA-256 in all public documentation and website pages.

This ordering prevents guessed artifact metadata from entering the release.

## Source and Release Content

v1.12.0 includes the already-reviewed commits through the IC-7300 CI-V
conformance merge. The release summary covers:

- backend-aware serial defaults: FT-710 at 38400 and IC-7300/MK2 at 115200;
- bounded newest-data CI-V scope queue and 30 Hz spectrum scheduling that sends
  real scope data only when the hardware frame counter advances;
- production-codec-based diagnostic framing without a fictitious checksum;
- native 48 kHz Icom audio selection diagnostics while preserving FT-710's
  44.1 kHz device-domain resampling;
- required `27 10 01` display-on and `27 11 01` data-output-on scope sequence;
- SCROLL-C low/high edge metadata;
- model-specific Transceive items (`0071` and `0089`);
- documented `03` online probe and baud-dependent `18 01` power-on preamble;
- IC ALC raw-120 calibration and FAST/MID/SLOW-only scope speed capabilities;
- official frame vectors, virtual-serial tests, and synchronized operator and
  hardware-acceptance documentation.

FT-710 CAT, audio-rate, PTT, and spectrum behavior remain unchanged.

## SDD Traceability

The release preserves NFR-033 cross-platform compatibility and documents the
Windows operational path without changing the Linux/macOS runtime. Startup and
device diagnostics continue to satisfy NFR-040, while packaged configuration
retains the NFR-041 environment-variable contract. The explicit driver, COM
port, and CI-V guidance mitigates R1 (missing or incorrect serial port).

Publication does not alter AD-010's external tuner persistence or UC-007 tuner
flow. It preserves operator-owned `atr1000_tuner.json` and
`mem_channels.json`, does not claim to resolve open issue I7's memory-file
validation gap, and therefore does not expand the SC9 persistence claim.

## Versioned Files

Before the Windows build:

- `packaging/windows/MRRC-Modern.iss` sets `MyAppVersion` to `1.12.0`.
- `CHANGELOG.md` adds the v1.12.0 Stable release entry.
- `website/deploy.sh` requires the v1.12.0 versioned artifact.

After the Windows build, the measured size and SHA-256 are synchronized in:

- `README.md`;
- `docs/WINDOWS_INSTALLER_GUIDE.md`;
- `win_pack.md`;
- `website/index.html`;
- `website/zh/index.html`;
- `SDD/README.md` and `SDD/14-version-history.md`;
- generated `website/sdd/*.html`.

## Build Environment and Artifact

Build on the documented Windows 11 x64 KVM using Python 3.12.4, pinned
PyInstaller 6.21.0, and Inno Setup 6.7.3. The source archive excludes Git
metadata, virtual environments, prior build output, certificates/private keys,
mobile projects, website deployment payloads, caches, and promotional media.
It retains `.agents/` because the Windows test suite exercises the SDD harness.

The canonical recovered artifact is:

- `dist/windows/MRRC-Modern-v1.12.0-Windows-x64-Setup.exe`

The website exposes identical bytes at:

- `https://www.vlsc.net/mrrc_modern/downloads/MRRC-Modern-Setup.exe`
- `https://www.vlsc.net/mrrc_modern/downloads/MRRC-Modern-v1.12.0-Windows-x64-Setup.exe`

The actual byte count, display size, and SHA-256 are derived from the completed
Windows build and inserted into release metadata before publication.

## Build and Verification Gates

The Windows `packaging/windows/build.ps1` gate must complete:

1. Python syntax compilation;
2. the complete hardware-independent test suite;
3. all three PyInstaller targets;
4. Inno Setup compilation.

Before accepting the installer, inspect the packaged tree for:

- `FT4222.dll` and `ftd2xx.dll` for optional FT-710 true spectrum;
- `opus.dll` for server-side Opus;
- bundled static assets;
- `mem_channels.json` seed data;
- the multi-radio backend package and Icom modules.

Compute SHA-256 on Windows and again after retrieval to macOS. The values and
byte counts must match exactly.

## Publication Flow

1. Verify the local source suite, syntax, clean Git state, and SDD constraints.
2. Commit and push the release-preparation metadata to `origin/main`.
3. Build and inspect the installer on the Windows KVM.
4. Recover the installer, verify size and SHA-256, and place identical copies
   in the evergreen and versioned website download paths.
5. Update bilingual pages and release documents with measured metadata.
6. Rebuild generated guide and SDD HTML where source documentation changed.
7. Re-run tests, link/version scans, hash checks, `git diff --check`, and staged
   SDD Guardian checks.
8. Commit and push the publication metadata to `origin/main`.
9. Deploy the site with `website/deploy.sh`, retaining its timestamped backup
   and nginx validation gate.
10. Download both live URLs and verify HTTP success, byte count, and SHA-256;
    verify English and Chinese pages identify v1.12.0 Stable.
11. Create and push the annotated `v1.12.0` tag only after live verification.

## Failure Handling and Rollback

- Stop before publication on any failed test, syntax check, PyInstaller target,
  Inno Setup compile, required-file inspection, or hash comparison.
- Do not publish guessed or stale size/hash values.
- If website deployment or live verification fails, do not create the tag.
  Restore the timestamped server backup created by `website/deploy.sh`, validate
  nginx, and reload it.
- Do not overwrite runtime `mem_channels.json`, `atr1000_tuner.json`, radio
  configuration, certificates, passwords, or serial-device settings.
- Do not describe KVM software tests as physical RF or audio acceptance.

## Acceptance Criteria

- `origin/main` contains the complete v1.12.0 source and release metadata.
- The Windows build passes the full suite and all packaging stages.
- Required FTDI, Opus, static, seed-data, and backend files are bundled.
- Local, evergreen, and versioned installers have identical byte counts and
  SHA-256 values.
- English and Chinese pages advertise v1.12.0 Stable and link to working
  downloads.
- Repository documentation consistently records the measured artifact metadata
  and the hardware-validation boundary.
- `git diff --check` and SDD Guardian are clean for both release commits.
- The annotated `v1.12.0` tag points to the verified publication commit and is
  present on `origin`.
