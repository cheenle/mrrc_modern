# 远程协助通道（Call help）设计

- **日期**：2026-10-12
- **状态**：待评审（本文件通过后进入实现计划）
- **范围**：四个平台同一条实现（macOS 应用 / Windows 安装包 / Linux 盒子 / 树莓派）
- **相关**：`cloud_hub.py`（隧道）、`mrrc_hub/portal/`（门户）、`static/support.html`、`support_bundle.py`、SDD 支持链（AD-021/AD-022）

---

## 1. 背景与动机

现在这条支持链是**异步**的：用户上传 🐞 诊断包 → 自动分诊 → 答复页。它能解决"日志里有答案"的问题，解决不了"我要进去看一眼、改一下、重启一次"的问题。客户打电话说"电台连不上了"，你能拿到的是一份几小时前的快照。

要做的是**同步**的那一半：客户主动开口说"你进来看看"，然后你真的能进去。三个约束来自操作者的明确要求：

1. **必须由客户主动开启**——不是一个常驻后门；
2. **用户名与口令控制在客户手里**——不是厂商内置凭据，也不是 portal 生成后下发；
3. **借助现有隧道**，**在 portal 现有功能里实现**——不新建一套远程访问基础设施。

现有拓扑给了三个便利，本设计完全站在它们之上：

| 既有事实 | 对设计的意义 |
| --- | --- |
| frps 把代理口**只绑在 hub 回环**（`deploy/frpc-instance.toml.example`），公网入口是 hub 的 nginx | 加一条 SSH 代理**不会**把 SSH 暴露到公网 |
| 实例→portal 是**唯一既有方向**（`/apply` `/status` `/claim` `/enroll`，callsign + request_token） | 申请、心跳、强制结束都走这条已有的出站通道 |
| portal 是**零第三方依赖**的 stdlib 服务，实例端口由 `registry` 统一分配（18802–18999） | 协助端口与实例端口**共用同一个池**，不动 frps 的 `allowPorts` |

---

## 2. 目标

1. 客户在应用界面点一次，即可开通一条**限时、可随时关闭**的 SSH 通道；支持人员在 hub 上用原生 `ssh` 连进去拿到一个真 shell。
2. 凭据（用户名 + 口令）由客户侧生成/设置，**portal 从头到尾看不到口令**（接口里没有这个字段）。
3. 三条关闭路径都可靠：客户本地、窗口到期、portal 强制结束。
4. 全程可审计：客户能看到"谁在什么时候连过"，支持包里带着同一份记录。
5. 四个平台同一套实现、同一套行为（Windows 上没有 sshd 也能用）。

### 非目标

- **不做提权**：会话拿到的是 app 进程本身的权限（Windows/macOS 是当前用户，Linux/盒子是 `mrrc`）。盒子上需要 root 的动作仍走既有的 `box_helper`。
- **不做常驻**：没有"永久开启"。窗口到期即断，要续期就是再点一次（等于再确认一遍）。
- **不做公网 SSH 端口**：通道两端都在回环上（frps 侧既有约束 + app 侧显式绑定）。
- **不做网页终端**（portal 里的 xterm 界面）：那是 P2，且复用 P1 的全部机制。
- **不做口令的保管/代管**：不在 portal 里生成、展示、存储、找回口令。

---

## 3. 决策（操作者已定）

| 决策 | 选择 | 直接后果 |
| --- | --- | --- |
| SSH 端点由谁提供 | **应用内自带（paramiko）** | 四个平台一致、不依赖 OS 功能、不需要管理员；代价是一个新依赖 + 一个**只在开启期间存在**的监听面 |
| 支持人员从哪进来 | **先上 hub，再用原生 ssh** | portal 只显示状态与那行命令；支持者手边要有终端（P2 再补网页终端） |
| 谁能关闭 | **三方都能**（客户 / 超时 / portal 强制） | 实例在协助期间要有一个 20 秒的心跳-轮询回路（复用既有出站方向） |
| 端口池 | **与实例端口共用 18802–18999**，由 `registry` 统一分配 | 不新增端口段、不动 frps `allowPorts`；`registry` 记录 `kind` 防互踩 |
| 隧道热加载 | **`frpc reload`**（走 admin API，不用 CLI） | 需要给隧道配置加 `webServer` 管理段；不支持时**明确失败**，不静默退回重启 |

## 4. 组件与接口

### 4.1 实例侧：`help_session.py`（新模块）

**状态机**（单一入口、单一出口）：

```
off ──enable()──► arming ──(隧道就绪)──► open ──close(reason)──► closed ──► off
                     │                      │
                     └──(失败)──► close("error") ──┘
```

`close(reason)` 是**唯一**的关闭路径。三条外部触发（客户 / 到期 / portal）与**arming 阶段的失败**都走它——后者尤其重要：
绑 127.0.0.1 成功但申请端口失败时，如果直接回 `off`，那个监听就留在那里了。

按逆序拆干净：停心跳 → 停监听 → 关 transport → 移除 frpc 代理（reload）→ 通知 portal → 清状态 → 写审计。
`reason ∈ {user, expired, portal, auth_failures, error}`。

**凭据**：

- `secrets.token_urlsafe` 生成用户名（短、好念）与口令（≥24 字符、含足够熵）；客户可**自己改**（界面上有输入框）。
- **只在内存**：不落配置、不落日志、不进支持包、关闭即丢弃。下次开启是新的一套。
- 校验用 `hmac.compare_digest`（常量时间）。
- 契约测试：把口令字符串拿去扫日志文件、支持包内容、portal 请求体——**一处都不许出现**。

**SSH 服务**（paramiko）：

- 先绑 `127.0.0.1:0` 拿到端口（OS 分配，避免与任何东西撞），再申请隧道端口。
- 只接受 `session` 通道；`check_auth_publickey` 恒返回失败（只允许口令认证）。
- shell：Windows `powershell.exe -NoLogo`、macOS `zsh -l`、Linux `bash -l`；转发 pty 的 term 与初始尺寸（动态 resize 记入"不做"）。
- 会话**继承 app 进程的环境**（含 `MRRC_*` 配置与日志路径）——这是**有意的**：支持者要看的就是这些，且这份环境对 app 的用户本来就是可读的，会话没有扩大任何东西。写进文档，免得被当成疏漏。

**审计**（内存 + 日志一行，事件里没有口令）：

```json
{"at": "...", "event": "connect|auth_fail|disconnect|closed",
 "user": "...", "peer": "127.0.0.1", "duration_s": 123, "reason": "user"}
```

界面上显示连接次数、最近一次时间、结束原因；同一份记录进支持包（`summary.txt` 旁）。

**限速**：认证失败累计 5 次 → `close("auth_failures")`。

### 4.2 隧道：给 frpc 加管理段与第二个代理

`cloud_hub.frpc_config_text()` 增加：

```toml
webServer.addr = "127.0.0.1"
webServer.port = <连接时选一个空闲端口、写进配置，从此每实例固定>
webServer.user = "mrrc"
webServer.password = "<随机，随配置文件一起 0600>"
```

热加载不用 frpc CLI，**直接 POST admin API**（stdlib `urllib`，与 `net_tls` 一条出站路径）：

```
POST http://127.0.0.1:<admin port>/api/reload   (Basic auth)
```

管理 API 自己也是一块面，所以三条约束一起写死：**只绑 127.0.0.1**、**必须有 Basic 认证**（无凭据的
frpc 管理端是不设防的本地端口）、**口令与隧道 token 同在 0600 的配置文件里**（§11）。

开启时写进配置的第二个代理：

```toml
[[proxies]]
name = "mrrc-help-<label>"
type = "tcp"
localIP = "127.0.0.1"
localPort = <本机 SSH 端口>
remotePort = <portal 分配的协助端口>
```

关闭时把它从配置里删掉并同样 reload。**reload 失败即失败**：`arming` 阶段报错给用户、`close()` 阶段记 `error` 审计——不静默退回"重启 frpc"（那会把一次可诊断的失败变成一次看不见的隧道抖动）。真机确认表里有一条专门验它。

### 4.3 portal：端口种类、记录、三个端点

**端口分配**：`registry` 的记录加 `kind`（`instance` / `help`）。`free_port()` 对两者一视同仁，但协助端口是**短命**的，且在实例端口被占用的排查文档（`docs/2026-10-11-instance-lifecycle-and-port-squatting.md`）之后，这里显式规定：**portal 只有在①实例确认关闭或②心跳消失超过 5 分钟**时才释放协助端口；释放事件写审计。

**存储**（`store.py` 复用，字段里没有口令）：

```
label, port, username, state(pending|open|closed), started, expires,
last_heartbeat, connections, closed_reason
```

**端点**（与 `/status` 同一套认证：`callsign` + `request_token`）：

| 端点 | 作用 | 返回 |
| --- | --- | --- |
| `POST /help/request` | 申请一次协助：窗口分钟数 + 上报 `username` | `{port, expires_at}` 或拒绝原因 |
| `POST /help/heartbeat` | 每 20 秒一次：刷新 `last_heartbeat`、上报 `connections` | `{"stop": bool}`（portal 的强制结束就靠这个） |
| `POST /help/close` | 客户侧主动关闭时通知 | `{"ok": true}` |

拒绝的情形：该实例已有进行中的协助、没有有效申请、窗口超出上限（>180 分钟）。

**portal UI**：实例详情页（`view_instance`）加一张"远程协助"卡。

- 未开启：说明 + 当前状态（"客户未开启"）。
- 开启中：`ssh -p <port> <username>@127.0.0.1`（**可复制**）、到期倒计时、心跳新鲜度（显示"客户在线/失联"）、连接次数，以及**"强制结束"**（admin 会话 + CSRF）。
- 已结束：最后一次的起止、连接次数与结束原因。
- 卡片上有一行固定提示：**口令不在门户里**——客户口头/短信告知。

### 4.4 应用界面：Support 页加一张卡

开启后显示：用户名（可复制）、口令（**`open` 期间可反复查看**——它就是要念给支持人员的那一个；
关闭即从内存消失，不落盘）、剩余时间倒计时、连接次数与最近连接时间、"停止协助"；
以及"自己设置用户名/口令"的入口。默认值随机生成。

## 5. 数据流

**开启**：点按钮 → 生成凭据 → 绑 `127.0.0.1:0` 拿到本地端口 → `POST /help/request` 拿远端端口 → 写第二个代理 → admin API reload → 进入 `open` → 起 20 秒心跳 → 界面开始倒计时。

**连接**：支持者 `ssh www.vlsc.net` → hub 上 `ssh -p <协助端口> <用户名>@127.0.0.1` → frps（回环）→ 实例的 paramiko 监听 → 平台 shell。

**关闭**：三条路径都调 `close(reason)`，动作一致（§4.1 的逆序）。

## 6. 安全围栏（逐条对应测试）

| # | 围栏 | 怎么测 |
| --- | --- | --- |
| 1 | 监听只绑 `127.0.0.1`，且只在 `open` 期间存在 | 断言绑定地址；`closed` 后连接被拒 |
| 2 | 口令不落盘/不落日志/不进支持包/不进 portal 请求体 | 扫描这些载体，断言零命中 |
| 3 | 口令比较用常量时间 | 断言代码用 `hmac.compare_digest` |
| 4 | 窗口上限 180 分钟、默认 60、到期即断、不自动续 | 假时钟推进；到期后连接被拒 |
| 5 | 认证失败 5 次即关闭 | 5 次错误口令后端口关掉 |
| 6 | 只允许口令认证，公钥一律拒 | 公钥认证被拒 |
| 7 | 无提权 | 会话进程与 app 同 uid |
| 8 | portal 接口结构上没有口令字段 | 请求体白名单（像 `WizardClaim` 那样） |
| 9 | 关闭路径唯一 | 三条触发都调 `close()`，无旁路 |
| 10 | 代理名带 label，不与其他实例/主代理互撞 | 配置生成断言 + 真机同时开两个实例 |
| 11 | 协助期间的活动对客户可见 | 界面与支持包里都有审计记录 |

## 7. 失败模式与处置

| 失败 | 处置 |
| --- | --- |
| portal 不可达 | `arming` 失败，界面明确报"门户连不上，协助未开启"；不进入 `open` |
| 端口分配被拒（池满/该实例已有协助） | 同上，报具体原因 |
| frpc reload 失败 | `arming` 失败并报错（含 frpc 的返回）；若发生在关闭阶段，记 `error` 审计并**重试一次**，仍失败则在界面留一条"隧道里可能残留代理"的提示 |
| frpc 子进程挂了 | 现有 supervisor 会重启；心跳发现协助端口不再注册 → `close("error")` |
| app 进程重启 | 内存里的凭据与会话状态消失 ⇒ 协助**不恢复**（这正是"不常驻"的语义）。portal 侧靠心跳消失把记录标为 `closed("heartbeat_lost")` |
| 客户断网 | 同上，心跳消失 → portal 5 分钟后释放端口 |
| portal 要强制结束，但实例已离线 | 隧道已经断了，没有活着的会话可关；portal 把记录标 `closed("heartbeat_lost")` 并释放端口，界面上不再给"打开终端/连接"的入口 |
| 支持者把 shell 挂住 | 不影响关闭路径；`close()` 主动关 transport |

## 8. 测试策略

- **单元（无外部依赖）**：状态机四态与全部转移、凭据生成与不落盘、常量时间比较、限速、审计事件形状、`frpc_config_text`（含/不含第二个代理、管理段）、reload 调用的构造（用假 HTTP 服务端）、portal 端口分配与 `kind`、心跳与 `stop`、到期与释放规则、`/help/*` 的认证与拒绝分支、UI 渲染（含 CSRF）。
- **集成（可进 CI，无需硬件）**：真 paramiko 服务端 + 真 paramiko 客户端——认证成功/失败、执行一条命令拿到输出、到期被断开、第 5 次失败后端口关闭。
- **真机端到端（人在场）**：Mac + 盒子（或 Pi）各一台，从 hub 用原生 `ssh -p …` 进去；同时验 `frpc reload` 的真实行为与"协助期间主隧道不抖"。
- **回归**：`python -m unittest discover -s tests` 与 `mrrc_hub/tests/`（portal 侧）。

## 9. 分期与边界

- **P1（本设计）**：隧道第二个代理 + `webServer` + reload；`help_session.py`；portal 的端口种类/记录/三端点/卡片/强制结束；app 的 Support 卡；审计与围栏测试；真机端到端一次。
- **P2**：portal 网页终端（复用 P1 的端口、凭据、心跳、审计；只加"人机界面"一层：WS + xterm 或自写终端）。
- **P3（可选）**：给已经开着系统 sshd 的 Linux 用户提供"复用系统账号"的高级模式（不做跨平台承诺）。

**需要真机确认、不放进"已完成"的边界**：

1. `frpc reload` 在本仓库钉的 0.71.0 上是否如预期（配置里加/删代理后主隧道不抖）；
2. Windows 上 paramiko 起 `powershell.exe` 的 pty 行为（换行、颜色、`Ctrl-C`）；
3. macOS 上从 launchd 启动的 app 起 `zsh -l` 的环境（PATH 与会话的可交互性）；
4. 盒子上 `mrrc` 用户跑该会话能做什么/不能做什么（预期：读写 `/opt/mrrc_modern`、看日志、重启服务；不能改系统）。这是**有意**的权限面，写进操作手册。

## 10. 明确不做（YAGNI）

- 不做常驻/后台开启；不做"记住上次口令"；不做多客户并发协助的会话管理（P1 一次一个）。
- 不做文件传输 UI、不做端口转发 UI（支持者用原生 `ssh` 的能力即可）。
- 不做 portal 侧的口令保管/代填/找回。
- 不改 frps 的 `allowPorts`、不新开端口段。
- 不给协助通道加"提权到 root"的能力（需要 root 的动词走 `box_helper`，那是另一条已审计的路径）。

## 11. 顺带要修的一处既有缺陷

`cloud_hub.connect()` 写隧道配置用 `conf.write_text(...)`，因此文件权限是 **umask 默认（通常 0644）**，而文件里有 **frps 的 `auth.token`**——本机任何用户都能读到并劫持这条隧道。本设计往同一文件里再加管理段口令，所以 P1 一并把写入改成显式 **0600**（`os.chmod` + 测试断言），并在真机确认表里加一条"改后主隧道仍能起来"。
