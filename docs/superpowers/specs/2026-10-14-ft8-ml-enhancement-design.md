# FT8 ML 增强（P3）设计

- 状态：设计（待实施）
- 日期：2026-10-14
- 上游：`2026-10-14-ft8-cloud-escalation-design.md`（A1：盒子 → 主机深解）、
  `.superpowers/sdd/2026-10-13-ft8-phase-a-unblock-deep-path/progress.md` Task 8a–8d
- 关系：P0（度量）→ P1（组合）→ P2a（旋钮）已把**经典配置空间榨干**；P3 是唯一能
  突破当前参照天花板的路线。

## 1. 为什么是现在这个形状

P0–P2a 的三条结论决定了 P3 的边界：

1. **经典解码器的天花板已经量到**：在 150 槽真实语料上，最深的单配置
   （`p1c3lt` + `sensitivity=3`，内部 9 趟减除 + 额外一趟 subpass）拿到
   可靠参照集的 **100.0%**；三配置组合、profile 1–4、low_threshold、
   cycles 1–3、sensitivity 1–3 全部扫过，并集不再增长（s3 相对三配置只多
   31 条 = +1.1%，反向只丢 2 条且可疑）。
2. **"100%" 是相对当前参照的**：参照 = 10 个经典配置的并集。想让召回再涨，
   要么换个更强的**判官**，要么让**输入变干净**。
3. **算力与位置都合适**：盒子 → ham 的云升级链路已经在跑（每槽 15 s 一次，
   200 kbps，ham 4 线程 ×2 s）。**任何重活都应该加在主机侧**——盒子是 4×A53，
   装不了 torch/onnxruntime，也不该为此改盒子。

## 2. 目标与非目标

**目标**：在**不降低**当前召回的前提下，用量级可控的算力，把
"解码器听得见的最低信噪比"往下推，从而在真实语料上**扩大并集**。

**非目标**（明确划出，避免项目膨胀）：

- 不训练端到端神经解码器（不动 LDPC/同步，不替换判官）。判官永远是现有的
  WSJT-X Improved 解码器——这样"提升"只有一个含义：**同一个判官在更好的输入上
  解出更多**，且任何退化都可由并集兜住。
- 不改 `ft8/dsp/`（改它要四平台重编；P3 全程在 Python 侧，ABI 只用现成的
  `decode`/`encode`）。
- 不碰盒子。P3 的第一版只存在于主机（ham）的 `mrrc-decode` 服务里。
- 不做"实时"承诺：增强本身每槽几十毫秒，但它是**加法**（增强一份 + 原样一份），
  不占关键路径的新预算。

## 3. 关键洞察与设计

### 3.1 编码器就是仿真器（已确认）

ABI 已经暴露 `wsjt_ft8_encode`（`wsjt_core_shim.f90:78` → `genft8` +
`gen_ft8wave(79 sym, nsps 7680, bt 2.0, 48 kHz)`），Python 侧
`CoreBinding.encode(message, frequency, 48000, out)` 直接可用。于是：

- **干净参照**：任意报文 → 精确的 12.64 s 波形（48 kHz → 抗混叠抽到 12 kHz）。
- **受控信噪比**：干净波形 × 增益 + **真实噪底**（来自语料的真实槽，不是白噪声）。
- 这是监督训练的全部前提，且不需要任何外部数据。

### 3.2 训练发生在 [仿真域]，判据发生在 [真实域]

两者的分工必须写死，否则会自欺：

- **仿真域**（快、无需标注、可控 SNR）：训练与超参选择。噪声取自真实槽
  （优先取解码数少的槽，其频段内既有真实 QRN/QSB 也有真实带内干扰），
  信号用 `encode()` 合成，SNR 按 WSJT-X 定义（2500 Hz 参考带宽）标定。
- **真实域**（慢、无标注、贵）：**最终判据**。做法是把增强当**前置级**接到
  现有解码上，在 500+ 槽语料上 A/B：
  - 召回 = 增强后 s3 的并集 ⊇ 原 s3 的并集？**并集只准涨**（损失由构造保证为 0：
    服务端同时跑"原样"和"增强"两份，结果并集，和 P1 的组合是同一个折叠函数
    `merge_batches`）。
  - 假解 = 新增报文中"无 QSO 上下文、且参照集里任何配置都没见过"的那部分；
    用**跨槽时间一致性**（相邻槽的 CQ/应答/报告序列）作为精度判据，
    而不是靠"看起来像呼号"。

### 3.3 增强的形态：软掩蔽 + 保底噪底

- 域：12 kHz、NFFT=1920（6.25 Hz 分辨率，正好等于 FT8 音调间隔）、
  hop 取符号周期的整数分之一，覆盖 0–3000 Hz。FT8 的 T-F 图像很小
  （≈480 × 190），小 U-Net 足够。
- 目标：理想复比掩蔽（cIRM）或理想幅度掩蔽（IAM），loss = MSE + SI-SNR。
- **保底噪底（关键设计约束）**：解码器的候选门限是 **SNR 相关**的
  （`ft8_decodevar` 里按噪声底决定阈值），而增强会改变被测到的噪声底——
  把噪声抹干净会让门限逻辑失准。因此掩蔽必须是**软的**：
  `mask^α`（α<1）或"增强 + 回注一部分噪声"，让整体噪声底可辨。
  α 是**在真实域上扫出来的**，不是在仿真域上挑的。
- 重建：iSTFT（用混合相位），重叠相加，回到 12 kHz int16。

### 3.4 插入点：主机侧服务，一个开关

`tools/hub_decode/service.py` 的 `_decode` 已经是"写一次 PCM → 跑 N 份配置 →
折叠并集"。增强就是**再加一份输入**：

```
原样 PCM   ─┬─> p1c3lt-s3 ─┐
            └─> (portfolio) │
增强 PCM   ─┬─> p1c3lt-s3 ─┴─> merge_batches → decode_ok
            └─> ...
```

CPU 代价 = 模型前向（~几十 ms）+ 一倍解码（现 4 线程 ×2 s）。主机 16 线程，
余量充足。开关：`--enhance <model-path>[:alpha]`；没有该参数时行为与今天**逐字节一致**。

### 3.5 为什么这不是"必然能涨"

诚实的预期管理：

- 经典 s3 已经在 −24 dB 量级解出东西（实测最弱 −24 dB、dt +2.19 s）。噪声主导的
  极限附近，**掩蔽能带来的增益可能只有零点几个 dB**，甚至为零。
- 增强的失败模式是**把弱信号一起抹掉**（掩蔽过激）——并集把它变成"不涨"而不是
  "变差"，但那就意味着项目没有产出。
- 因此 **Slice 1 必须先量"值不值得"**：解码器的 SNR–召回曲线在什么区间开始掉？
  真实语料的解码 SNR 分布有多少落在那个区间？如果真实语料几乎没有边缘样本，
  这个项目就该在 Slice 1 结束时停下——那也是一个结论。

## 4. 分片（每片都有独立的、可证伪的判据）

| 片 | 内容 | 判据 |
|---|---|---|
| **S1** | 仿真器 + **基线曲线**：合成信号 × 真实噪底，扫 −30…0 dB，量 fast / s3 的召回—SNR 曲线；统计真实语料解码 SNR 分布 | 曲线画得出；语料中"落在解码器悬崖附近"的样本比例可算 |
| **S2** | 训练集生成（批量、确定性种子、可复现）+ 掩蔽模型骨架（U-Net，CPU 可训） | 仿真域 SI-SNR 明显优于"不做处理"；训练可复现 |
| **S3** | 真实域离线 A/B：增强 → s3 解码，对比并集增减（先在 100 槽上做便宜的） | 并集**只涨不跌**；涨的报文通过跨槽一致性检查 |
| **S4** | 主机侧集成（`--enhance`）+ 500 槽全量 A/B + α 扫描 | 真实域召回净增 ≥ +0.5% 才上线；否则保留为工具 |
| **S5**（可选） | 若 S4 有效：扩语料、按频段/时段细分、把模型纳入 cloud 服务默认 | 每轮都要重现 S4 的判据 |

## 5. 风险

| 风险 | 处理 |
|---|---|
| 增强改变噪声底 → 解码器门限失准 | 软掩蔽 + 回注噪声；α 在真实域扫；并集兜底 |
| 仿真域好、真实域无用（域差异） | 真实域判据是**唯一**上线依据；仿真域只用于训练 |
| 真实语料缺边缘样本 → 无米可炊 | Slice 1 就量，早停；那时转 P4（检测器/神经 LDPC）或扩语料 |
| 假解（增强后 CRC 偶然通过） | 跨槽一致性 + 参照未见过 + `<...>` 哈希呼号单独计数 |
| 依赖膨胀（torch on ham） | 只在主机侧、只在研究环境；盒子的依赖表一字不改 |

## 6. 与既有约束的关系

- **不动 `ft8/dsp/`**：P3 只用现成 ABI（`encode`/`decode`），不需要四平台重编。
- **不动盒子**：盒子照旧发原始 PCM、收 `decode_ok`；协议零变更。
- **可回退**：`--enhance` 是服务端一个参数，删掉即回到今天的行为。
- **测试债**：仿真器与掩蔽模型进 `tests/ft8/ml/`；S1 的基线曲线脚本进
  `tools/ft8/`（与 `decode_matrix.py` 同一层）。
