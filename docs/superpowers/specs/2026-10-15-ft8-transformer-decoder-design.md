## 0. 一句话

用一个 **DETR 式集合预测 transformer** 取代"同步搜索 → 音调提取 → LDPC+OSD → CRC"
这整条链：输入整个时隙的时频图，输出该时隙里**所有**信号的
`(存在, 频率, dt, 91 信息比特)`；比特经 **CRC-14 + 呼号结构**校验后才成为报文。

## 1. 先划清"能不能赢"——免得白干

经典链路里有两段是**理论上接近最优**的：

- **匹配滤波**：已知波形在 AWGN 里的最优检测；
- **LDPC 置信传播**：174/91 码的近最优译码（外加 OSD 兜底）。

所以在**单信号 + 白噪声**条件下，端到端模型**只能追平，不可能超过** ✗。
P4 的价值必须来自经典链路**结构性处理不好**的地方。实测两条：

| 场景 | 实测 | 结论 |
|---|---|---|
| **同频重叠**（±25 Hz 且时间重叠） | 每槽 **16 对**（占信号对 3.3%） | 但 **s3 单配置已拿到并集的 98.8%** —— 内部 9 趟 `subtractft8var` 就是干这个的 ⇒ **这里没多少可捡** ✗ |
| **弱信号尾部** | s3 召回 −22 dB **100%** / −24 dB **63%** / **−26 dB 31%** | **69% 的信号在这里被漏掉** ⇒ **靶子在这** ✓✓ |

**为什么一个学习到的解码器有可能在这里赢**：经典链路是"逐候选、贪心、按符号相关"的
——它的同步相关在每个 0.16 s 符号上做判决；而在 −26 dB，单符号的判决早已淹没在噪声里，
判据来自**整个 12.64 s 的相干积累**与**码结构**。一个能看到全时隙、并对全部候选联合推理的
模型，理论上可以把"检测 + 译码"当成**一个联合推断**来做（类似把经典链路的
SIC 迭代学习化）✓。

**诚实的预期**：把悬崖从 −24 推到 −26 dB，量级是**几个百分点**召回（P0 已算过：
报告值 ≤ −18 dB 的报文占 10%、≤ −20 dB 占 2.9%，而悬崖在报告 −21…−19 dB ✓）。
不是革命，但它是经典配置榨干之后**唯一还能动曲线**的方向。

## 2. 设计

### 2.1 形式：集合预测（DETR 式），而不是"生成文本"

时隙里有 **0…30+ 个信号** ✓，数量可变 ✓，且**输出必须精确**（一个比特错 = 一个错呼号 = 一条错记录 ✗）。
所以：

- 模型输出 **N 个查询**（N 固定，取 40 ✓），每个查询输出
  `(present ∈ {0,1}, freq, dt, 174 比特码字)`；
- **绝不直接生成文本** ✗：文本由**标准打包**从比特解出（复用仓库已有的解析 ✓），
  模型只碰比特 ✓；
- **校验是不可绕过的**：CRC-14 必须通过 + 呼号结构检查（复用现有 `msgparse`/DB 过滤 ✓）
  ⇒ 模型**不可能"编造"一个呼号**（错一位而 CRC 仍通过的概率 1/16384 ✓✓）。
  这条设计让"精度"从"相信模型"变成**验证模型** ✓✓。

### 2.2 输入表示：复时频图（相位要留着）

6.25 Hz × 40 ms 的复 STFT（480 × 316）✓ —— **相位必须进模型**：低信噪比下
判据来自相干积累，丢掉相位等于把可用能量砍掉一半 ✗。实/虚两通道或幅度+相位两通道 ✓。

### 2.3 结构（小规模起步）

```
复 STFT (2×480×316)
  → conv stem（2 层，4× 下采样）
  → transformer encoder（6 层，d=256，8 头，窗口注意力：时频局部 + 频轴全局）
  → N=40 个可学习 query → transformer decoder（4 层）
  → 每 query: [present, freq, dt] + 174 比特（BCE）
```

参数量目标 **5–20 M**（可在 M2 的 MPS 上跑小规模、在租用 GPU 上跑全量 ✓）。

### 2.4 损失：匈牙利匹配 + 三项

- 集合匹配（freq/dt 距离 + 存在概率）✓ 标准 DETR 损失；
- 比特 BCE（只对匹配上的 query）✓；
- **可选**：把 `LDPC 校验子（syndrome）`当作辅助损失 ✓ —— 让模型直接朝着"码约束满足"
  优化，而不是逐个比特 ✓（这是 ECCT 一类工作的关键技巧 ✓）。

### 2.5 训练数据：仿真域免费且精确

- 信号：`wsjt_ft8_encode`（精确波形 ✓）+ **传播类增强**（衰落/多普勒/时钟漂移 ✓，P3 已实现）；
- 噪声：**真实槽的噪底**（P3 已实现 ✓，含陷波去内容 ✓）；
- 每槽 1…N 个信号，SNR 分布按**语料实测分布**加权（重点在 −26…−18 dB ✓）；
- 标签：精确（我们放的 ✓）；**验证仍用真实域**（判据与 P3 一致 ✓）。

### 2.6 与既有基础设施的关系

| 已有 | 复用方式 |
|---|---|
| `ml_simulate.py` | 编码器、噪底、SNR 定标、recall-vs-SNR 曲线（**判据**）✓ |
| `ml_dataset.py` | 噪底池、传播增强、STFT/iSTFT 往返（已验精确）✓ |
| `merge_batches` / 云服务 union | 部署形状：**新解码器与经典并集**，只增不减 ✓ |
| 真实域 A/B + 精度检查 | 同一套工具（QSO 结构 / 经典并集确认 ✓） |

## 3. 分片（每片一个可证伪的判据）

| 片 | 内容 | 判据（不达标就停） |
|---|---|---|
| **S1** | 数据/标签管线（集合标注）+ 小模型在**高信噪比单信号**上过拟合 | 训练能收敛、`freq/dt` 误差 < 2 Hz / 0.1 s、**比特全对率 > 99%**（0 dB、单信号） |
| **S2** | 单信号弱化：训到 −20 dB 单信号 | 与 s3 的曲线比：**−20 dB 处召回不低**（追平即可，这是"没做错"的下界） |
| **S3** | 弱信号尾部攻坚（重点在 −26…−22 dB） | **悬崖外推 ≥1 dB**（用同一把尺：`ml_simulate` 的曲线） |
| **S4** | 真实槽 A/B（并集 + 精度检查） | 净增 > 0 且新增报文通过 CRC + 结构检查 ✓ |
| **S5**（可选） | 多信号联合/重叠场景、SIC 学化 | 在重叠区间优于 s3 的**单配置**（不是并集） |

**S1 的判据故意很松**：它要回答的是"这条路走得通吗"（能不能学到音调结构 + 码结构），
而不是"能不能赢经典" ✗。**S3 才是价值判据**。

## 4. 风险与对策

| 风险 | 对策 |
|---|---|
| **算力**：全量训练可能数十小时 | 小规模先在 M2/MPS 上验证管线（S1/S2）；S3 视情况租 GPU（用户已表示可以 ✓） |
| **数据量**：学习 174/91 LDPC 需要大量样本 | 仿真免费 ✓；先用 10 万级验证趋势，再决定是否上百万级 |
| **模型"编造"报文** | CRC-14 + 呼号结构 + 经典并集确认（三重）✓ |
| **真实域泛化**（P3 踩过的坑） | 从第一天就用真实噪底 + 传播增强；S4 用真实域判据 ✓ |
| 与经典链路比"同 SNR 下的速度" | 不是本研究的目标 ✗；只比**同等预算下的召回**（延迟由主机侧为它单独设预算 ✓） |

## 5. 明确不做

- 不改 `ft8/dsp/`（四平台重编的代价不值得 ✗）——P4 全在 Python 侧 ✓；
- 不动盒子的依赖与协议 ✓（部署在主机侧，与 P3 同一个 union 架构 ✓）；
- 不用模型直接生成文本 ✗（只出比特，文本走标准打包 ✓）。
