# 安卓客户端横屏自适应设计（v1.1.33）

日期：2026-10-22
状态：已实现（`FT710Android/`，v1.1.33 / versionCode 36）
用户定案（逐条）：

1. 横屏**跟随系统自动旋转**（不再锁竖屏）；
2. 横屏**尽量一屏**，实在放不下的档位允许滚动（不做额外尺寸压缩）；
3. 手机横屏与平板横屏**共用一套双列**，尺寸按屏宽放大（不维护第二套结构）；
4. 底栏 `PTT ｜ CQ · TUNE · REC` **沿竖屏**（不改成右侧竖条、不挪进卡片）；
5. 旋转时**保持发射**（配置变更 ≠ 用户离开）。

---

## 1. 问题

`AndroidManifest.xml` 里 `MainActivity` 长期是 `android:screenOrientation="portrait"`。
平板横放、手机横握时界面被系统强制转成竖屏渲染，等于横屏不可用。

放开方向锁并不等于"横屏能用"：主屏是**一条单列**（工具行 → 主频+S 表 → 频谱 → 仪表 →
五键+芯片 → 音量/步进/VFO → 记忆格，底部固定四键）。

`ScreenFit` 的现有常量算出来：竖屏单列七个分区合计约 **620dp**，加底栏 88dp ≈ **709dp**。
而手机横屏可用高只有 **300~450dp**。直接放开方向锁的结果是"横过来要滚 400dp"。

### 关键算术：横屏不是"多了一块屏幕"，而是换了个形状

| 方向 | 可用面积 |
| --- | --- |
| 竖屏 344×620 | ≈ 213,000 dp² |
| 横屏 728×300 | ≈ 218,000 dp² |

面积几乎一样。所以横屏版**只能靠二维排布**（两行双列）把同样的内容摆进去，
而不是把竖屏压扁——任何"压尺寸"的思路都会立刻撞到可读性下限（记忆格字号、
S 表刻度、五键点击区）。

---

## 2. 方案选择

三种排法都算过真实高度（`ScreenFit` 常量，ATR 行开启）：

| 方案 | 摆法 | 手机横屏实际表现 |
| --- | --- | --- |
| 甲「左看右操」 | 左列 主频+S 表+瀑布；右列 四张卡 | 瀑布只有 ~330dp 宽（和竖屏差不多），**横屏收益接近 0**；右列要滚 ~150dp |
| **乙「上宽下操」** | 上行 主频 ｜ S 表 ｜ 瀑布（三者等高）；下行 四卡一排 | 瀑布真正变宽（~300dp 起，平板可达 600+dp）；总高 383dp |
| 丙「左操右看」 | 左列 四张卡；右列 主频+S 表+瀑布 | 瀑布 ~390dp，但主频显示屏只剩 179dp 宽（字号变小），两列都要滚 |

**选乙**：横握手机唯一说得过去的理由就是瀑布变宽，只有乙做到了；而且它把三块"看"的东西
压进同一行，竖向最省，滚动量最小（最紧档位 23dp）。

---

## 3. 布局

竖屏（**一个像素都没动**）：

```
工具行 → 主频显示屏 + S 表 → 频谱 → 仪表 → 控制 → 调谐 → 记忆     （单列滚动）
底栏 PTT ｜ CQ · TUNE · REC                                        （固定）
```

横屏：

```
工具行                                                             （全宽）
┌ 主频显示屏 ｜ S 表 ｜ 瀑布 ──────────────────────────────────┐   （同一行，三者等高）
├ 仪表 ｜ 控制 ｜ 调谐 ｜ 记忆（3×2）──────────────────────────┤   （一排，等高）
底栏 PTT ｜ CQ · TUNE · REC                                        （全宽）
```

- 整页仍是**一条竖向滚动**（`testTag("mainScroll")` 不变），横屏只是在里面放了两行。
- 四卡宽度权重 `1 : 1.35 : 1.45 : 1`（仪表 / 控制 / 调谐 / 记忆），记忆卡约 147dp@728。
- 记忆格横屏排 **3×2**：6×1 时每格只剩 ~14dp，"438.500" 会被省略号吃掉。
- 底栏横屏横跨 728dp → PTT ≈ 520dp，仍是底栏最宽的一块（与网页 `.ptt-button { flex:1 }` 同义）。

## 4. 尺寸模型

新增的都是**正交增量**，竖屏公式一行未改：

| 新增 | 取值 | 理由 |
| --- | --- | --- |
| `ScreenFit.isWide(w, h)` | `w > h` | 手机横屏与平板横屏共用一套（定案 3） |
| `LANDSCAPE_COMPACT_MAX_HEIGHT_DP` | 560 | 竖屏那条 900dp 规则会把**平板横屏**（高 800）误判成紧凑，把平板压成手机尺寸 |
| `isCompactFor(w, h)` | 横屏看 560、竖屏看 900 | 档位判定收口到一处 |
| `landscapeFreqWidth` | 屏宽 25%，夹 150~260 | 手机 ~182dp（字号仍比竖屏大）；平板停在 260 以免挤掉瀑布 |
| 仪表行高 | `spectrumHeight(compact, fftH, wfH)` | 主频/S 表/瀑布**三者等高**（显式高度） |
| `landscapeCardsHeight` | 四卡最高的那张（调谐卡） | 一排等高才不难看；**显式高度**，绝不用 `IntrinsicSize`（v1.1.16 事故） |
| `memoryCellWidthInCard` | 按**卡片**宽反推 | 按整屏宽反推会把字号估大一倍 → 真的溢出 |

`ScreenMetrics` 因此多一个 `wide`：`memoryColumns/RowsCount/CellWidth` 在横屏切到 3×2 那套，
`landscapeFreqWidth / landscapeInstrumentHeight / landscapeCardsHeight / landscapeCardWeights`
只在 `wide` 时被调用。

## 5. 旋转与 PTT

放开方向锁后 `onStop()` 每次旋转都会被调一次。原实现无条件 `vm.onPttRelease()` ——
**说着一半把手机转过去就断话**，用户只会以为断线了。

判定收敛成纯函数（`App/RotationPolicy.kt`，JVM 可测）：

```kotlin
internal fun shouldReleaseOnStop(isChangingConfigurations: Boolean): Boolean = !isChangingConfigurations
```

- 配置变更（旋转 / 深色模式 / 字体缩放）→ **不松手**，也不把连接层判一次后台；
- 真正的 `onStop`（切后台、锁屏、被别的界面盖住）→ 照旧**无条件释放**（安全铁律不退化）。

松手实现仍然只有一处（`MainActivity.onStop`），没有复制第二份。

---

## 6. 其余横屏可用性

- 登录页、波段选择、记忆管理：横屏可用高只有 300~400dp，都可能顶出屏幕 → 加 `verticalScroll`。
- 录音面板本身是 `LazyColumn`，无需改。
- `rememberSaveable` 的 `loggedIn / showSettings / immersive` 在旋转中保留；VM 经
  `by viewModels()` 存活，连接/音频/PTT 不受影响。

## 7. 验证

| 门槛 | 内容 |
| --- | --- |
| `ScreenFitTest`（新增 6 条） | 横屏档位预算；**首屏必须看全 主频/S 表/瀑布**；最紧档位超出 ≤ 32dp；竖屏常量逐值不变（含 `memoryCellWidth` 拆函数后的等价断言） |
| `OneScreenFitTest`（新增 4 档） | Robolectric 真 measure：728×360 / 832×384 / 892×411 / 1200×800，报告写 `build/screenshots/one-screen-fit.txt` |
| `MainScreenComposeTest`（新增 1 条） | 横屏真实布局：三者在同一行且等高、四卡同一排等高等宽、记忆 3×2、**控件一个都不少** |
| `RotationPolicyTest` | 旋转不松手 / 真退后台必松手 |
| `ScreenshotTest`（新增 2 张） | `main-landscape-phone-*.png`、`main-landscape-tablet-*.png`（给人看） |
| 结构 diff | `PadBtn` 15 / `MeterCell` 8 / `SmallChip` 6 / `HeaderIconButton` 4 / `vm.*` 61：改动前后逐项相同 |

实测（`one-screen-fit.txt`）：

```
小米/红米 横屏 728×360   可视 272dp  超出 23.0dp  ↕ 可滚
荣耀 横屏 832×384        可视 296dp  超出  0.0dp  ✅ 一屏
Pixel 横屏 892×411       可视 323dp  超出  0.0dp  ✅ 一屏
平板横屏 1200×800        可视 688dp  超出  0.0dp  ✅ 一屏
```

竖屏七档的实测数字与改动前**逐行相同**（荣耀末卡底 601dp、华为 608、中档 597、
小米 592、Pixel 603、平板 785），这是"竖屏零改动"的证据。

## 8. 已知取舍

- **最紧的手机横屏（728×360）要滚 23dp**：四卡一排的最下面 ~23dp（记忆卡最后一行的一半）
  需要滑动。定案 2 已接受；要消灭它只能压尺寸（四卡高度 120 → 97）或把底栏改成竖条，
  两者都被否了。
- **平板横屏不额外加列**：1200dp 宽下四卡仍然是一排（每卡更宽），不排成两排。
  定案 3 选了"一套双列"，将来若嫌空，在 `ScreenFit` 加 `wideColumns()` 是纯增量。
