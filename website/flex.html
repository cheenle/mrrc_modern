实验性机型 · 发射默认关

FlexRadio（SmartSDR）接入

FLEX-6400 那一族没有串口 CAT、也没有 USB 声卡 —— 控制和音频都走网线。 MRRC Modern 直接把 SmartSDR 协议讲了一遍，所以盒子只吃一根网线， 地址还能留空：盒子会听电台自己的广播把它找出来。

接线一根网线，盒子和电台同一网段。不需要串口线、不需要声卡。
发射默认关。盒子设置页「实验机型的发射」勾上才发，且电台面板里必须把 PC 音频选成发射源。
前提电台自己的 TX timeout 设到 30 秒。网线掉了，那一条是最后一道防线。

1. 为什么这台机器和别的机型不一样

Yaesu / Icom 是「串口 CAT + USB 声卡 + 电台自己的频谱口」；FlexRadio 是 「一条 TCP 控制通道 + 一路 UDP 二进制流」，频谱、收听音频、发射音频全在这条流里。

面 FlexRadio 的做法
控制 TCP 4992 文本命令（频率、模式、增益、PTT、天调…）
频谱 电台把 panadapter 的 FFT 直接推给客户端（UDP），不是我们采的
收听 24 kHz 浮点立体声，我们升采样到 48 kHz 单声道再给浏览器
发射 电台只收 Opus：24 kHz 立体声、10 ms 一帧。浏览器麦克风的声音由盒子编码后送出
发现 电台每秒在 UDP 4992 广播自己（型号、序列号、IP）——盒子听着就行

1.1 它其实是一台「有对象数据库的电台」

Yaesu / Icom 是「一台电台、一套寄存器」；FlexRadio 是电台自己维护对象，客户端只是订阅者之一（本机允许 licensed_clients=2，另一台 SmartSDR 的状态也会推给我们）。 搞清这四个对象的归属，绝大多数"连上了但不对"都会自己解释：

对象 它拥有什么 踩过的坑
SCU（频谱捕获单元） 天线插座：ANT1 ANT2 RX_A RX_B XVTA XVTB 名字只能向电台要（ant_list），不同型号数量不同
panadapter（一块瀑布） 中心频率、带宽、dBm 孔径；它的 FFT 数据流 id 就是 pan id 没有挂 slice 的 pan 照样推 FFT，但那是没有射频的底噪 —— 看起来像"瀑布没有信号"
slice（一条接收链） 频率、模式、滤波、音量、AGC、rxant/txant 命令是 slice set <n>；写成 slice s 会被静默接受且什么都不做
stream（音频） 收发音频流（发射只收 Opus） 流 id 与 pan id 不是一回事，别混用
两条由此定下的规矩：①瀑布要挂在我们自己的 slice 所在的那块 pan上 （盒子会自动这么做并写进日志）；②界面上选的接收天线盒子会记住并重放 —— 因为电台自己不保留 slice 的天线，换一次客户端会话它就回到默认口， 而默认口往往正是空着的那个。

2. 接线与电台侧的三件事

2.1 网线

盒子和电台接同一个交换机 / 路由器，同一网段。电台用 DHCP 或固定 IP 都可以 —— 地址留空时盒子靠广播发现它，不需要知道 IP。

2.2 把 PC 音频选成发射源

在电台的 P/CW 面板（或 SmartSDR 的发射设置）里，把发射音频源选成 PC / DAX 一侧的 PC 音频，不要停在麦克风。做不到这一步，按下发射键 电台会发一个没有声音的载波 —— 我们的软件会在按键后 1 秒内发现这件事并 自己放开按键（见 §4），但根因在电台面板上。

2.3 TX timeout 设到 30 秒

正常放手、关浏览器、心跳丢失，盒子都会主动放开 PTT。但网线被拔掉时盒子什么都发不出去 —— 那一秒只有电台自己的超时能救场。菜单里的 TX timeout 建议 ≤ 30 秒； 盒子发现它超过 60 秒时会在启动日志里点名，自检脚本也会把它列为红项。

3. 盒子上的设置

「连接设置」里机型选 FlexRadio (SmartSDR)：

  • 电台 IP 留空（默认）→ 自动发现。同一网段有多台时，填上想连的那台的 IP。
  • 不需要选串口，也不需要选声卡 —— 这两栏对这一族不显示。
  • 盒子重启后自动重连：先 1 秒、再 2/4/8 秒，最长 30 秒一次。

4. 能做什么，不能做什么

能力 状态 说明
频率 / 模式 / 滤波器 ✅ 含 CW 音调居中的窄带滤波
AGC / NB / NR / ANF / 压缩 ✅ 压缩映射到电台的语音处理器三档
功率 / 麦克风增益 / 发射带宽 ✅ 走 transmit set
瀑布与 S 表 ✅ 真 FFT；表来自电台自己的 meter 流，含功率/驻波/ALC
语音收发 / PTT ✅（需解锁） 见下面那张门禁说明
天调 TUNE 视机器 FLEX-6400 的 ATU 是选配；没有 ATU 就不显示 TUNE 按钮
接收天线选择（rxant） ✅ ☰ → 电台参数；候选来自电台自报的 ant_list，按 panadapter 生效（同一块瀑布上的 slice 共用）。发射天线每 slice 一个，界面同样列出
多 slice / 多 pan 界面 ❌ v1 协议层已按客户端隔离（状态按对象 id 分槽、FFT 按 stream id 过滤），界面先用 1 收 1 瀑布
CW 键控 / 电台电源 / VFO-B / split ❌ 界面不显示这些按钮，而不是显示一个假的
SmartLink 广域接入 ❌ 盒子本身就是远程接入层；电台与盒子必须在同一局域网

5. 发射：门禁与"静音载波"自证

这一族还没有真机验收，所以发射默认是关的（和 G7250、FTX-1F 同一条规矩）。 开启方式：设置 → 实验机型的发射（勾选并确认），立即生效，不用重启。

解锁之后仍然有两道检查：

  1. 按键要真的通电：盒子发 xmit 1 后 1.5 秒内，电台的收发状态机 必须进入「正在发射」，否则盒子自己取消按键并报错 —— 不会让你以为发了。
  2. 声音要真的进去：按键后 1 秒内，电台自己的 MIC 电平表 （SC_MIC）必须看到能量。没有能量而盒子明明在送音频，就立刻放开按键并 锁住后续发射，同时在日志和界面里说「去电台面板把 PC 音频选成发射源」。 这是刻意的：宁可拒绝发射，也不发一个静音载波。

解锁后想再关掉，取消勾选即可（关闭不需要确认）。

6. 上线前先跑自检

盒子上（或能 SSH 进去的机器上）：

python _diag_flex.py                  # 自动发现，只读
python _diag_flex.py --host 192.168.1.50
python _diag_flex.py --tx-check --allow-tx   # 假负载上发 200 ms 载波

报告里该看什么：

  • 机型 / 序列号 / 固件 —— info 通了才说明协议对得上
  • FFT 帧数 > 0，且 UI 字节的 min/mean/max 不是全 0 也不是全 255
  • 音频包数 > 0；表清单里能看到 SLC LEVEL 与 TX- FWDPWR
  • TX timeout 那一行：超过 60 秒是红项

脚本默认只读，结束时会删掉自己建的 pan 与音频流、并释放 PTT。加 --tx-check --allow-tx 才会发 200 ms 载波。

7. 排障

症状 先看这里
连不上，日志说没发现 是否同网段；交换机是否隔离广播；同网段多台时手动填 IP
连上了但没瀑布 电台是否已有两个 panadapter（6400 上限 2）；UDP 是否被防火墙拦
有瀑布没声音 电台音量与静音；盒子是否在「只听」角色；浏览器音量
有声音、瀑布里一个信号都没有 九成是天线：☰ → 电台参数里的接收天线是不是接天线的那一口 （例如天线在 ANT2，slice 却在 ANT1）。 判据：换天线时 S 表应跳变十几 dB，而瀑布纹丝不动 ⇒ 显示的不是接收射频的那块 pan，看日志里 our slice is already on panadapter 0x…
切了模式 / 滤波 / AGC，声音没变化 1.28.76 及之前的版本发的是 slice s <n>（少了 set），电台接受但不执行 —— 升级到 1.28.77 及以上
换完天线，重启盒子又变回去 电台不保留 slice 的天线；1.28.77+ 会把界面上的选择记进 MRRC_FLEX_RX_ANT 并在每次连上后重放
按了发射没反应 发射门禁没解锁，或被 §5 的静音载波自证锁住了
发射是"哑载波" 电台面板里 PC 音频不是发射源（§2.2）
拔网线后电台一直在发 电台 TX timeout 太长（§2.3）—— 这是唯一能在断网时放开 PTT 的东西

8. 适用型号与已知未验项

同一份协议覆盖 6000 族（FLEX-6300 / 6400 / 6400M / 6500 / 6600 / 6600M / 6700）与现行 Signature 族（8400 / 8400M / 8600 / 8600M）。机型、序列号、ATU 有无都由电台自述， 代码里没有按型号分支。6400 的 ATU 是选配 —— 没有就不显示 TUNE。

还没在真机上落锤的（验收清单在仓库设计记录 §11–§12）：PC 音频源默认值、收听音频包率、 pan 的刷新率/带宽上限、选配 ATU 的状态形状、主观音质、8400/8600 与 6000 族是否完全同构。 第一台真机到手时用 §6 那条命令跑一遍即可。
