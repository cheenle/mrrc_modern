Yaesu FTX-1F · 接入说明

能做什么、不能做什么

这台机器在我们这套里是实验性机型。它少了一条别人都有的 CAT 数据流（扫频），命令表也与其他八重洲机型不同。这一页把三件事分开：电台自己的限制、我们还要改的、你要做的一两步。

完整操作指南 取诊断包

1. 三句话，先说结论

你看到的真正的原因能不能解决
瀑布是一条光滑曲线，不是真频谱FTX-1 的 CAT 只提供频谱显示设置，没有一条命令能读扫频点不能，这是电台的限制（§2）
按 PTT 没反应未硬件验证机型默认只收不发（发射门禁），不是电台坏了能，加一行开关（§3）
某个开关点了没变化；频率改了又跳回去我们发出的 CAT 命令与 FTX-1 手册有出入部分已修（§6），其余等真机确认（§5）

2. 没有真瀑布 —— 这是这台电台的限制

FTX-1 的 CAT 手册里有一条 SS 命令，看着像「频谱命令」。它八个子参数全是显示设置：扫描速度、峰值保持、标记、颜色、参考电平、跨度、显示模式、AF-FFT 时间窗。整份手册里没有一条命令能把扫频点读出来。频谱在机器里画完给人看，没有对外的数据流。

所以本软件的瀑布/频谱曲线，在 FTX-1 上来自S 表合成：读信号强度，按时间铺成一条带形状的曲线。它能告诉你「有人在这个频率上、信号在变强还是变弱」，但它不是频谱：两个相隔 3 kHz 的强信号，在它上面分不开。

怎么用才不吃亏：

  • 把它当信号趋势图看，不要用它判断邻频干扰、带宽占用、频谱形状；
  • 精确定位靠电台自己的屏（FTX-1 有内置频谱）或 S 表读数；
  • 真的需要远程真瀑布，换 FT-710（FT4222 扫频）或 IC-7300（CI-V 0x27）这类把波形送上总线的机型。

这一条不会因为软件升级而改变，也不存在「有个开关没打开」。

3. 默认不发射：这是我们的门禁，不是电台的限制

第一次接上 FTX-1 按 PTT，日志里会是这一句：

Yaesu FTX-1F is not hardware-verified — transmit refused.
Set MRRC_ALLOW_UNVERIFIED_TX=1 and restart to enable TX after checking
the radio with _diag_yaesu.py.

原因：这台机型的配置档（profile）没有在我们手上的一台真机上验证过。发射这件事没有「大概对」的余地 —— 命令形状差一个字符，可能就是「按了没反应」或者「按下去不松」。

要开：

  1. 打开配置文件 mrrc_modern.env：Windows 在 %LOCALAPPDATA%\MRRC-Modern\，盒子在 /opt/mrrc_modern/env/mrrc.env。也可以在网页 ☰ →「连接设置」里改；
  2. 加一行 MRRC_ALLOW_UNVERIFIED_TX=1（已有的行改掉，别写成两行 —— 同一个键写两行时后一行胜出）；
  3. 保存并重启服务。

打开之后请按这个顺序试，别一上来就上功率：

  • 先最小功率：Field head 机身是 6/10 W 档，SPA-1 的功放是 5–100 W 档，软件会按电台的回读自动认是哪一种；
  • 先接假负载或确认天线正常，第一声「喂」用最短的时间；
  • 不要挂自动呼叫（一键 CQ、FT8 自动发射）直到你确认发射、释放、功率显示都正常。

发射失败的第一现场看这里：按住 PTT 之后，日志里应当有 TX1 与随后的 TX 表读数；松开后必须出现 TX0。如果没有 TX0，先按电台面板上的 PTT 或用电源开关断开，再回报。

4. 接上去：五分钟

步骤做什么判断成功的标志
1一根 USB 线连电台到主机（FTX-1 的 USB 同时提供 CAT 与 USB 声卡）系统里出现一个串口和一个 USB 音频设备
2网页 ☰ →「连接设置」→ 电台型号选 Yaesu FTX-1F（实验性，仅接收），串口选那个新出现的口，速率 38400保存后会重启服务，日志出现 Radio model: ftx1 与 Connected to Yaesu FTX-1F (ID=0840)
3转动电台的频率旋钮网页上的频率跟着动（这一步证明 CAT 通了）
4连接设置里把 RX/TX 音频设备显式选成实际的名字（见 §7）网页能听到接收音频，且日志不再反复出现 RX capture stalled
5接受一件事：瀑布是 S 表合成（§2）—

型号这一步有一个坑值得知道：选好的机型会被保留，启动器的串口探测只填空、不会覆盖你的选择。老版本（v1.28.1 及以前）会把不认识的新机型改回 FT-710，再用 FT-710 的说话方式去驱动它。症状是「选了 FTX-1，但什么都没对上」。如果你手上有旧版，先升级。

FTX-1 的串口出厂速率是 38400。配置的速率下电台一个字节都不回时，控制器会自己按 4800 → 9600 → 19200 → 38400 试一遍，并在日志里留一条告警。它不会改你的配置文件；要让下次开机也对，把电台菜单与连接设置改成一致。

5. 已知「点了可能没反应」的开关

FTX-1 的命令表与 FT-710 不是一套。有的命令多一个通道位，有的少一位数字，有的在 FTX-1 上根本不存在（换成了别的命令）。我们逐条核对过手册（38 条命令，18 条不符），但改这些东西必须在真机上看着面板改 —— 改错方向比不改更糟。所以下面这些开关目前可能「点了没变化」，或者变化的方向不对：

界面上的开关现在可能的表现临时办法状态
ATT（衰减）转过第 2 档之后没有变化在电台面板上设待真机：FTX-1 的 CAT 只有 ON/OFF 两档，菜单里的多档阶梯不给
COMP（压缩器）开关方向可能相反（按「开」反而关）在面板上确认一次再决定用不用手册与 FT-710 的现场勘误互相矛盾，必须真机量
DNR 等级拖动没有反应（甚至被电台拒收）面板设等级待真机：命令位宽差一位
CW 音调（侧音）改了没变化面板设待真机：同上
监听（MONI）开关与音量互相误触发面板设待真机
功率（W）拖动不生效（读回来的功率是对的）面板设功率，网页只看读数待真机：写命令缺一个机型位
麦增益 / 语音处理电平 / AMC改了没变化（只影响发射，接收听不出）面板设待真机：多了通道位
PRE（前置放大）144/430 段不生效面板设待真机：命令要带频段位
NB / NR / 天线选择 / RIT / XIT / 增量调谐点了没反应面板设这 6 条命令在 FTX-1 上不存在，要换成 NL / RL / 菜单项 / CF
ATU / TUNE按下去只发一段载波，内置天调的「自动调谐」不动天调在面板上调待真机：tune_via="tx2"，TX2 能不能当按键用手册没写

一句话：这些开关现在请以电台面板为准，网页上看状态、不要靠它改。

6. 「频率改了又跳回去」

这是 2026-10-28 那份报告里的症状：网页上把 29.600 改成 29.570，几秒后又变回 29.600。

有两种常见原因，都不是「软件不听话」：

① 电台停在存储信道上（最常见）。 FTX-1 在存储信道里收到的 CAT 设置只会当作临时覆盖，一读就回到信道本身的频率。在电台面板上按 VFO/MEM 切到 VFO 模式，再在网页上调。

② 写命令没被电台接受。 FA（设频率）是一条「只写不问」的命令：写出去之后电台不回话。所以我们以前既不知道它有没有生效，也无法在日志里留下证据，只能等下一轮轮询把界面改回去 —— 看起来是「跳回去」，实际是「从来没写进去」。

2026-10-28 的修复（随下一个版本发布：桌面版需要重新安装，盒子线走一次一键升级；升级后在 ☰ 菜单页脚能看到版本号）改了三件事，都只作用于 FTX-1：

  • 改频前先退出存储信道：读一次 VM，如果发现电台在存储信道上，先发 VM000 再改频率（每秒最多探一次，拖滑块不会一句一查）；
  • 写后由轮询回读判定：下一次读到电台的真实频率时，如果它与「设置前的值」一模一样，说明这次写根本没落地，日志里会留一条： 
    Yaesu FTX-1F: FA set to 29570556 Hz did not take — the radio still answers 29600000 Hz. ...
  • 被拒的命令会自己说出来：电台对不合法的命令会回一个 ?，现在会记成： 
    Yaesu FTX-1F: the radio rejected 'MG0123' (answered '?') — this firmware does not accept that command form or parameter

看到「did not take」、并且当时在存储信道上 → 按 ① 处理。切到 VFO 之后仍然「did not take」→ 交诊断包（§8），那说明命令本身还是不对。

7. 表头读数与音频

表头（S 表 / 功率 / SWR / ALC / COMP）的刻度还没在 FTX-1 真机上校准过：曲线是从 Hamlib 的机型定义转来的，可能与面板差一档。报信号报告、或者判断「功率够了没有」时，请以电台面板的读数为准，网页上的只当相对变化看。

音频两件事：

  • 设备名要对上。配置里写 USB Audio CODEC、而系统里实际叫 USB Audio Device 的时候，接收音频会周期性断一下再恢复（日志里是 RX capture stalled ... reopening the capture stream）。在 ☰ →「连接设置」里把 RX/TX 设备选成系统里真实存在的那个名字即可。
  • 采样率 44.1 kHz。FTX-1 的 USB 声卡走 44.1 kHz，服务端会重采样到 48 kHz 再编码下发，这是正常路径，不是故障。

8. 出问题怎么报

三件事，按顺序：

  1. 先在网页上把问题做一遍（改一次频率、按一次 PTT、切一次模式）—— 让日志里有这一次 CAT 交换。光交一个「没反应」的包，我们只能看到沉默。
  2. ☰ → 🐞 遇到问题 → 生成诊断包并上传。包里有日志、配置（口令已隐去）、设备清单。
  3. 在问题描述里写清三件事：哪一步、期望看到什么、实际看到什么。例如「在网页把频率改成 29.570，5 秒后自己变回 29.600；电台面板当时显示 M-01」。

我们会先看这四类行：

日志里的行说明
Radio model: ftx1 + Connected to Yaesu FTX-1F (ID=0840)机型与串口是通的
did not take写命令没落到电台（§6）
the radio rejected '...' (answered '?')电台明确拒收该命令（§5 那批就是这种）
TX session: frames=... written=... peak=...发射时音频到底有没有送进声卡

如果你愿意再帮一步：在盒子上跑一次只读自检（把端口换成实际串口；它只发查询、不按 PTT）：

python3 _diag_yaesu.py --model ftx1 --port /dev/ttyUSB0

把输出贴来。RM7/RM8 两项读数与表头曲线，就靠它一次拿全。

9. 边界：这台机型上我们明确不做的事

事项为什么
真频谱 / 真瀑布电台的 CAT 没有这条命令（§2）
双接收的第二通道FTX-1 是真双收，但协议里通道身份读不回来（SM 应答的通道字节恒为 0），要单独做一层「请求方持有身份」的设计，还没做。现在 VFO-A / VFO-B 可以分别选，不能同屏双显
内置天调的自动调谐见 §5 的 ATU 一行
7 段以上的菜单（EX）手册里有 444 行菜单寄存器，我们一条都没发；需要什么请提，我们按需求接
记忆信道的写回读/召回有，写回没接
