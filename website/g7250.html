协谷 G7250 · 接入说明

两条线，一条管控制，一条管瀑布

G7250 是这套系统里第一台非 Icom / 非 Yaesu 的机型，也是最容易接错的一台：它把控制与频谱放在了两个互不相干的接口上。这一页把两条线、怎么连、连上之后先验什么，一次说清。

完整操作指南 取诊断包

1. 三句话，先说结论

你看到的真正的原因能不能解决
瀑布是一条光滑曲线，不是真频谱还没配 MRRC_G7250_LAN_IP：这台机的频谱走网口 IQ，不走 CAT能，配一行就出真频谱（§3）
按 PTT 没反应未硬件验证机型默认只收不发（发射门禁），不是电台坏了能，加一行开关（§4）
日志说 did not answer on any CI-V address串口选错（机头有多个口）或波特率与电台菜单不一致逐个试串口即可（§2）

2. 这台机器有两条线

线路走什么能给你什么缺了它
USB 线（机头 USB 口 → 电脑）Icom CI-V（CAT）+ 内置 USB 声卡频率/模式/滤波/电平/表头/PTT/天调，以及收发音频什么都做不了——这是主控制面
网线（主机 RJ45 → 交换机）裸 IQ 基带（UDP，只收）真频谱 + 瀑布（±24 kHz）照样调谐、照样收发，只是瀑布变成 S 表合成曲线

关键一句话：网口的 IQ 流里没有 CAT、没有 PTT、没有模式。所以网线不插，机器照样能用；USB 不插，网页只能看个空壳。

两个常见误会先消掉：

  • 网口不是 wfview / Icom 那套「远程控制」协议。它是裸 IQ：电台在 UDP 50002 收一条 14 字节调谐命令，往电脑的 UDP 50001 推 768 字节 I/Q 包（48 kS/s）。协谷官方对应的用法是 Windows + HDSDR + 他们的 DLL，只给接收。
  • 目前没有现成的 wfview 机型文件可以抄：wfview 的机型库里没有任何协谷机型，Hamlib 停在 X6200，协谷也没发布 G7250 的 CI-V 文档。所以这台机的命令事实是「第三方逆向 + X6100/X6200 文档 + 待实测」三者混合，代码里每条都标了来源。

3. 接上去：USB 五分钟

步骤做什么判断成功的标志
1一根 USB 线：机头（7 寸屏那块）上的 USB 通信口 → 电脑系统里出现一个串口和一个 USB 音频设备
2网页 ☰ →「连接设置」→ 机型选 Xiegu G7250（实验性，仅接收） → 串口选那个新出现的口保存后服务重启，日志出现 Radio model: g7250, serial port: … @ 115200 baud
3看日志里这一行Xiegu G7250 answered on CI-V 0x__ …
4转一下电台旋钮 / 换个模式网页上的频率、模式跟着动（CAT 通了）
5在「连接设置」里把 RX/TX 音频设备选成真实存在的名字网页能听到接收音频

第 3 步那行是这台机特有的：协谷不公布 G7250 的 CI-V 地址，所以服务会把 0xA4 → 0x88 → 0x70 依次试（X6100/X6200 是 A4，G90 是 88/70），谁答了频率读取就用谁，并把它写进日志。请把这两个十六进制数记下来——它是这台机在你手上时的真值。

波特率默认 115200。电台菜单里的 CAT 速率若被改过，两边要对齐：在配置文件里写 MRRC_BAUD_RATE=<菜单里的值>，或把菜单改回 115200。

出现两个串口怎么办

协谷以往的机器一根 USB 线会枚举出两个串口（一个 Linux 控制台、一个 CAT）。G7250 的机头也有人抓到过 115200 上的启动打印，同一根线随后跑的是 CI-V 风格流量（这条未确认，也可能像 X6200 那样分成两个口）。不管哪种，选错口的表现都一样：连上了，但一个字节都不回来。把几个串口逐个试一遍，每次看日志有没有 answered on CI-V 0x__；答不上的会留 did not answer on any CI-V address 并列出所有可用串口。

4. 真频谱：网口三步

默认不开。没有配置时瀑布是 S 表合成的曲线：能看出「有人在、在变强」，但分不开相隔 3 kHz 的两个信号。要真频谱：

  1. 插网线：主机后部 RJ45 → 与电脑同一交换机（或直连）。电台默认地址 192.168.3.199（厂家 DLL 的默认值）；不同网段就把电脑临时改到 192.168.3.x，或进电台菜单看它实际拿了什么地址。
  2. 写一行配置：MRRC_G7250_LAN_IP=192.168.3.199，重启。日志应出现 G7250 LAN IQ listening on UDP 50001 (radio 192.168.3.199:50002), +/-24.0 kHz。
  3. 放行防火墙：电脑侧允许入站 UDP 50001（Windows 首次会弹窗，选允许）。
症状原因与处理
日志 cannot bind UDP 50001端口被占了——最常见是 HDSDR 正在跑（协谷官方那套接法）。关掉它再重启服务：一个 UDP 端口只能有一个主人
有 listening 但瀑布空白、包计数不动网线没通 / IP 写错 / 防火墙挡了。先 ping 192.168.3.199
有瀑布，但信号在中心线的错误一侧I/Q 极性反了：加 MRRC_G7250_SWAP_IQ=1 重启
瀑布只在 VFO 附近 ±24 kHz这是正常的：IQ 流就是 48 kS/s。想看整个波段靠电台自己的屏；网页上拖 VFO 会把 IQ 中心一起带走

还有一条未验证的事：机头与主机之间那条链路也是以太网，厂家没说同一个 RJ45 能不能既连机头又连局域网。如果插上网线后机头失联，请记下来报给我们。

5. 发射：默认关着，是你开的

第一次按 PTT，日志里是这句：

Xiegu G7250 is not hardware-verified — transmit refused.
Set MRRC_ALLOW_UNVERIFIED_TX=1 and restart to enable TX after checking the radio with _diag_civ.py.

这不是故障，是门禁：这台机型的 profile 没有在任何一台真机上验证过。发射命令差一个字节，后果可能是「按了没反应」，也可能是「按下去不松」。

开之前先接假负载（或确认天线、SWR 正常），然后：

  1. 配置文件加一行 MRRC_ALLOW_UNVERIFIED_TX=1（已有就改，别写两行），保存并重启；
  2. 用最小功率、最短时间试一次「喂」，同时盯网页功率表、SWR 表与电台面板；
  3. 松开 PTT，确认电台真的回到接收（面板 TX 灯灭、日志出现 TX0）；
  4. 这三件事都对，再考虑长发射。不要一上来挂一键 CQ 或 FT8 自动发射。

松开没反应：立刻用电源开关断开电台，再把日志发来——宁可断电源，不要等。

平台配置文件位置
Windows%LOCALAPPDATA%\MRRC-Modern\mrrc_modern.env
macOS~/Library/Application Support/MRRC-Modern/mrrc_modern.env
盒子 / Linux 镜像/opt/mrrc_modern/env/mrrc.env

6. 首次上车检查清单（这一步最值钱）

这台机的 profile 里还有十来处 TODO(hw-verify)。真机上跑一遍，就能把它们从「假设」变成事实：

#做什么记什么
1启动服务，看第一行answered on CI-V 0x__ 的地址
2跑一次只读自检（见下）报告里 refused (...) 的行＝这台机不认的命令
3面板与网页对比 S 表 / 功率 / SWR / ALC差几格、往哪个方向
4按一次 TUNE有没有真的调谐（继电器响、SWR 下降）
5系统音频里看声卡名精确名字
6接网线看瀑布有没有、正不正
7发射 2–3 秒功率/SWR/ALC，以及发射时瀑布有没有断

第 2 步的命令（只发查询、不按 PTT，除非你显式加 --tx-check --allow-tx）：

python _diag_civ.py --model g7250 --port /dev/ttyUSB0

它会自己按 0xA4 → 0x88 → 0x70 找一个能答的地址，把只读查询跑一遍（频率、模式、S 表、功率设置、前放、衰减、机型 ID、各表头原始值），写出一份 diag_civ_g7250_*.md。被拒的查询不会中断整轮，而是记成 refused (...)——那些行本身就是发现。把报告贴来即可。

8. 边界：这台机型上我们明确不做的事

事项为什么
网口发射（远程 PTT）网口协议里没有 PTT；协谷也说网络侧「当前只给接收」。远程发射走的是本软件的浏览器/手机端
超出 ±24 kHz 的瀑布厂家只给 48 kS/s 的 IQ 流
CI-V 频谱（0x27）这台机没有这条命令（X6100/X6200 也没有），所以我们不发、也不轮询
表头当刻度用曲线还是 IC-7300 的（同为 100 W 级），未在 G7250 上校准 ⇒ 以面板读数为准
天调自动调谐形式（1C 01 02）未验证，先用电台面板的 TUNE
双天线 / 语音呼叫器 / CW 预置电文 / 驻波扫描都是电台自身能力，CAT 里有没有对应命令未知，暂时只走面板
