雅司 SCU-LAN10 · 接入说明

一根网线，没有 USB，不能发射

FTDX101MP/D、FTDX10、FT-710 跟别的机型不一样：瀑布不在 USB 口上。USB 只有 CAT 和音频；瀑布要么走背后 13-pin ACC 的 SPI（得自己做转接板），要么走雅司那台 SCU-LAN10。这一页讲第二条：盒子和电台之间一根 USB 线都没有，只有网线到单位。

完整操作指南 取诊断包

1. 三句话，先说结论

你要做的怎么做做不好会怎样
把单位接到电台13-pin ACC + USB 两根（FT-710 还要给单位接 9–16 V 电源）电台的 USB 口被单位占着，所以盒子和 USB 二选一
抄四个值单位地址 / 用户名 / 口令 / 端口 50000（就抄雅司软件那一页）口令错时单位一声不响——这套协议不返回错误
知道它不能发射发射在这条路上关闭：单位的 TX 音频帧格式还没解出来按键只会得到静音载波，所以后端直接拒绝，不是坏了

2. 和别的机型比，这条路不一样

走 USB（别的机型那样）走 SCU-LAN10（这一页）
盒子到电台USB 一根一根网线到单位，没有 USB
串口 / 声卡都要都不要（电台的 USB 口被单位占着）
瀑布这几台拿不到真瀑布，只有 S 表合成的曲线真瀑布（850 点，约 25 行/秒）
发射正常关闭（§6）
谁在占着电台盒子独占串口单位会话独占：雅司软件和盒子只能二选一

关键一句话：没有 SCU-LAN10 这台配件，这几台的瀑布只能是合成的。它是另买的雅司配件（约 ¥2000），本页假设客户已经在用雅司官方软件、单位本来就是通的。

3. 接线

电台 ──ACC(13-pin) + USB──> SCU-LAN10 ──网线──> 客户路由器/交换机
                                                    │
                                              盒子（优先插网线）
  • 单位占着电台的 USB 口 ⇒「盒子插 USB」与「盒子走网络」不能同时。
  • FTDX101/DX10 不用给单位另接电源；FT-710 要给单位接 DC 9–16 V / ≥800 mA。
  • 盒子优先插网线：这条链路持续约 1.4 Mbit/s（频谱 822k + 音频 542k），盒子的 Wi-Fi 是 1×1 2.4 GHz，是这条路上最弱的一环。

4. 电台菜单里的三条（缺一条单位自己就不通）

菜单值
CAT RATE38400（单位到电台侧固定 38400，网线侧才是 115200）
CAT TIMEOUT10 ms
CAT RTSON
瀑布显示必须打开，否则我们收不到扫描数据
TX TIME OUT建议 1–3 分钟（按键卡住时的最后一层保护）

5. 参数从哪儿抄（雅司软件的「连接设置」）

客户机器上那套雅司软件，Setup → Connection Setup 里每一项都能直接对上：

雅司软件里抄到我们「SCU-LAN10 网络接入」
远程地址 192.168.49.49单位地址
用户 king7565用户名
密码 ••••••••口令（填一次就存住，以后留空＝不改）
控制端口 50000端口（只填这一个）
CAT 50001 / 音频 50002 / 频谱 50003不用填：我们按 base+0..+3 自己加
音频质量 PCM(48kHz)不用管：服务端按帧里声明的速率自适应，16k/48k 都跟得上
发送/接收缓冲 300ms不用管：那是雅司客户端自己的缓冲

出厂账号是 defaultuser / defaultuser；客户改过就用他改的。口令错的表现是「单位一声不响」——这套协议对错口令不返回任何错误。

6. 在盒子上打开它

浏览器进 http://<盒子地址>/settings，滚到接近底部，顺序是
音频电平 → CQ 呼叫录音 → 电台 → 实验机型的发射 → SCU-LAN10 网络接入 → 安全门禁。

  1. 勾上「用 SCU-LAN10 代替串口与声卡」；
  2. 填 §5 抄来的 单位地址 / 用户名 / 口令 / 端口；
  3. 点 「测试连接」（只握手，不保存任何东西）：成功会回报 会话 0x28、CAT 回话 FA007007000;、频谱 N / 音频 N 包；失败会直接说原因（口令不对 / 地址不通）；
  4. 点 「保存」，页面提示要重启服务（接线是在后端启动时定的），弹窗里可以直接重启。

盒子正在用这条链路时，「测试连接」是灰的 —— 多开一个客户端会把盒子自己的会话顶掉。

查什么结果说明什么

8. 排障

症状原因处置
测试连接说口令不对（或日志 session not up … rejected the credentials）用户名/口令错；单位对错口令不回应任何包照雅司软件的「登录账户」重填
测试连接说连不上地址不通：不同网段 / 写了 IPv6 / UDP 被拦从盒子 ping 单位；确认是 IPv4
会话通了、CAT 不回话电台 CAT RATE 不是 38400照 §4 改电台菜单
有 CAT、没瀑布电台瀑布没开；或单位被雅司软件占着打开瀑布；退出雅司软件（不是最小化）
声音慢、音调低旧版把采样率写死 16 kHz，而单位按 48 kHz 送升到 1.28.64 · FP51 以上
盒子突然"卡住"不动雅司软件抢先连上，把盒子会话顶掉关掉雅司软件；盒子会自动重连，日志里有点名
音频断续盒子在 Wi-Fi 上，1.4 Mbit/s 撑不住插网线

9. 愿意跑命令的：现场自检

python _diag_scu_lan.py --host 192.168.49.49 --user king7565 --pass 口令 \
    --spans --wav rx.wav --report scu1.md

它做四件事，报告是 Markdown，可直接发我们：① 七阶段握手（会话号）；② CAT 往返耗时；③ 频谱的边界标记与可用点数（--spans 会逐档扫）；④ 音频包率、声明采样率、峰值/RMS，并存一份能直接听的 rx.wav。--tx --allow-tx 会真的按键 2 秒，只在需要验证 TX; 读回时用。

10. 边界与已知未知（写在这里，免得当故障）

  1. 发射关闭：单位那一帧 668 字节的 TX 音频内层头还没解出来。
  2. FTDX101 没被第三方验证过：这份协议是别人从 FTDX10 抓包逆向的（约 7.6 万包，含一个跑通的客户端），作者明写欢迎 FTDX101 / FT-710 的抓包。协议层大概率同构，频谱编码要真机确认。
  3. 跨度/模式（SS）的应答形状是按手册推断的；解析不出来时保持原轴，不会画一条编造的刻度。
  4. 不要把单位的端口暴露到公网：这套协议没有加密也没有抗重放。远程一律走我们的云入口。

一句话记法：网线代替 USB，单位独占电台，能看能听不能发。
