What's New Since V2.20

The Tunnel Sweep Ran On Windows Only — So macOS Never Cleaned Up (V2.73)

v1.25.2 fixed the growing pile of leftover frpc processes by changing how they are enumerated (wmic → Get-CimInstance) — but the sweep opened with if os.name != "nt": return, a guard added to keep a second instance on the same machine untouched. On macOS that returned before doing anything, so nothing was ever swept. Measured on macOS: six starts after one boot left six orphans (all reparented to PID 1), and the failure then feeds itself — the one clean child that finally got the proxy name became the orphan that blocked the next start, whose own child retried already exists every 33 seconds for the rest of the log (67 of 86 lines). The sweep now enumerates with ps -eo pid=,command= and accepts a process only when the basename of its first command word is frpc — a vim holding that same .toml has the path in its command line too — and terminates with SIGTERM so frpc closes its control connection and the hub releases the name immediately. It never raises: a process may exit between the snapshot and the kill. Shutdown now stops the tunnel as well, because frpc outlives the server that spawned it.

FT-891 Joins The Yaesu Family — And A Latent Crash It Uncovered (V2.72)

The eleventh registry key and the fifth profile on the shared Yaesu ASCII-CAT core. Its one protocol difference is a write format: filter-width SET is SH01NN, not the family's SH00NN (Hamlib newcat.c:9658, int on = is_ft891), so YaesuModelProfile gained filter_width_prefix and the core reads it — no per-model branch, and the four shipped models still emit byte-identical commands. Filter slots are transcribed from Hamlib's get side (17 for CW/RTTY/PKT, 21 for SSB) and machine-compared against it; AM/FM carry no slots because their width is set through NA alone. Three facts no offline source carries come from a 2026-09-17 field report: 38400 8N1 (Hamlib's stop_bits=2 is self-marked assumed), no USB sound card — so no auto-match hints, 48 kHz for an external interface, and the connection dialog says so — and an S reading 1–1.5 S high (recorded, curve deliberately unchanged). Wiring it up also exposed a crash latent in the whole family: get_preamp/get_attenuator were called by initial_state_sync() and the settings poll tier but never defined, so the first successful connect raised AttributeError — invisible until now because no model in the family has hardware to connect to. Fixed, plus a structural guard that resolves every method a poll item or the sync references. Unverified throughout: TX gated, id_answer empty, 11 TODO(hw-verify).

A Keyed Carrier Is No Longer Sent Without Voice (V2.71)

The TX uplink has a single owner, and a key-up claims it by session token — but the token is a 30-day cookie, so one browser session can hold several mic sockets at once (a reload leaves its predecessor half-open for tens of seconds; two tabs of one login share it outright). The claim took the first match scanned out of a set, so it could land on the dead socket: the radio keyed and every frame of the live page was dropped as non-owner (frames=0 non_owner_drops=236, peak=0% — silence on a keyed carrier) until the stale socket was reaped 58 s later. The claim now takes the last-connected socket of that session, and a same-session socket that is actually streaming takes the uplink over on its first frame. A different session still cannot steal it, neither by connecting nor by streaming.

A Fresh Press Is No Longer Unkeyed By The Safety Gate (V2.70)

Cloud Hub enables the liveness gate that releases a transmitting session when it stops proving it is alive. The heartbeat is sent at key-up, but the server cannot read that beat until the key-up handler returns — and a watchdog tick landing in those 20–70 ms saw a session that was both the owner and silent. One field log recorded seven releases of the operator's own healthy press. Keying now refreshes the liveness clock, while a session that never sent txhb stays ungated. The fix lives in the frozen server.py, so it ships as an installer — and its first build is why artifact-level checks exist: every gate was green while the package still held the pre-fix bytecode, a trap now closed by purging PyInstaller's workpath cache before a build.

A Tunnel That Leaked One Process Per Start (V2.69)

The hub logged 7143 proxy already exists lines in a single day, and the cause was on the tenant's own machine: the code that sweeps a leftover frpc before starting a new one used wmic, which Windows 11 no longer ships — and the bare except turned that into a silent no-op. Six processes had accumulated over two days, five of them orphans, all claiming one proxy name. It now enumerates with PowerShell's CIM cmdlets, compares config paths the way Windows does (insensitive to case and slash), and says so when the look-up fails — because a stale tunnel only ever shows up in the hub's log, not in this app. The launcher also holds a named mutex, so two starts can no longer both find the port free.

Two Packaging Defects Only the Build Machine Cannot See (V2.68)

Two reports from one Mac had the same shape: something that exists on the build machine was assumed to exist everywhere. The bundle carried the builder's OpenSSL, whose compiled-in CA path is the builder's own /opt/local/… — so the trust store came up empty, and portal enrolment, the diagnostics upload and the update check all failed with CERTIFICATE_VERIFY_FAILED. Outbound HTTPS now goes through net_tls.py, which falls back to a bundle we ship and then to the platform's system bundle, and a build gate empties the CA environment on purpose before requiring a real handshake. The same report showed a spectrum that had never once been real: the launcher anchored the relative MRRC_FTDI_LIB_DIR on Contents/MacOS while the signed bundle keeps that tree in Contents/Resources, so the scope worker exited with "FTDI libraries not found" — and the parent logged the reason at DEBUG only.

v1.25.0 Released — It Works After Installing (V2.67)

Three field reports, three root causes. A launcher could hang forever before it ever started a server: the first-run serial probe wrote to every candidate port, the radio's real description matched none of the keywords meant to put it first (CP2105 is not "cp210x"), so the port probed first was the machine's Intel AMT port — one that opens and then never accepts a byte, written with pyserial's default of no write timeout. An approved instance stayed on "waiting for approval" because the only poll loop lived in the settings dialog; polling now runs in the server every 30 seconds and reports what it found. And the certificate reload check compared the wrong two things, so an enrolled instance answered 502 while nothing offered to restart it.

v1.24.6 Released — The Launcher Asks Before It Opens (V2.66)

A field machine that had installed v1.24.5 still showed a black screen. Its own server.log plus a run of the packaged server proved the app was healthy on plain HTTP (/login → 200) while the browser had been sent to https:// — a protocol error rendered as a blank page. The launcher derived the scheme from its own ability to produce a certificate while the server derived TLS from its own ability to load one: two independent decisions, one socket. Both launchers now probe /api/health first (shared launcher_net.py) and open whichever scheme actually answers, announcing any switch instead of degrading silently.

Also fixed: Windows now binds the port exclusively — SO_REUSEADDR there lets a second process bind a port that is already listening, so two servers could both report Server ready! and the browser might land on the one holding no radio (the field log showed every line duplicated 1–10 ms apart); a bare Server start no longer aims its password file and recordings/ at the read-only install directory, which meant a new password every start that was never saved — the real cause of "I installed the new package and still cannot log in"; a bare start now reads the user's mrrc_modern.env; log lines are written once instead of twice; and a stdlib-AST gate fails the build when an app module is used as name.attr without ever being imported — the defect class that shipped twice (cloud_hub in v1.24.1, ssl_bootstrap in v1.24.5).

MRRC Rebrand + Env Migration (V2.21–V2.22)

FT710_* environment variables renamed to MRRC_* with automatic legacy fallback; launchers, auth cookie, and logging rebranded to MRRC Modern; launcher config template exposes MRRC_RADIO_MODEL.

IC-7300/MK2 Runtime Reliability (V2.24)

Backend-aware serial baud defaults (FT-710 38400; IC-7300/MK2 115200), CI-V 0x27 demux queue bounded at 44 segments dropping oldest on overflow, and 30 Hz spectrum broadcasting that only emits newly completed real frames.

Official CI-V Conformance (V2.25–V2.26)

Scope startup enables display (27 10 01) + waveform output (27 11 01); SCROLL-C decoded as lower/upper edges; per-model Transceive items (IC-7300 0071 / MK2 0089); documented 03 liveness polling; official raw-120 ALC full scale. Full-repo audit recorded open issues I8–I11.

v1.12.0 Windows Stable (V2.27)

Published after 633/633 tests on macOS and Windows 11, three PyInstaller targets, Inno Setup compilation, and cross-host SHA-256 verification. FT-710 CAT, audio, PTT, and spectrum behavior unchanged.

ICOM SDR Models: IC-705 / IC-7610 / IC-7760 (V2.41)

Three more CI-V radios behind a profile-driven core, with an explicit unverified boundary: capability flags, a transmit gate (MRRC_ALLOW_UNVERIFIED_TX=1 to opt in) and a read-only 19 00 model identity check. No unit of any of the three was available, so nothing is presented as verified.

Server-Side QSO Recording (V2.42–V2.45)

16 kHz mono MP3 written incrementally while recording (lameenc), with RX/TX placed on one monotonic timeline; recordings panel with list/seek/download/delete; the browser encoder was retired. A writer-liveness fix ended the silent second recording in the same process.

CAT Reconnect Recovery (V2.43)

A USB serial re-enumeration no longer replays the 24-query full state sync on reconnect — the poll tiers already cover every field — so a link that used to cost ~62 s of dead CAT recovers in seconds, with per-attempt log discipline and an actionable ENXIO hint.

v1.15.0 Released (V2.44–V2.45)

macOS DMG, Windows installer and the rpi64 image published with cross-host SHA-256 verification, including the recording feature above and the reconnect fix.

v1.18.1 Released (V2.54)

A patch that makes the macOS download usable at all: every earlier bundle carried a failed signature (the step failed silently), so Gatekeeper refused it with "is damaged and can't be opened" — and it declared no audio-input permission key, which macOS answers by opening the capture stream and filling it with zeros, i.e. RX plays silence with no error and a log line that blames the radio. Both are fixed at the packaging layer, and a failed signature now aborts the build.

v1.18.0 Released (V2.54)

macOS DMG and Windows installer built from one commit and verified before publication: the frozen macOS server boots with the new support endpoints and finally writes a server log; the VM ran 1261 tests and Inno Setup produced the installer. latest.json is live, so 1.17.0 installs now see the update.

Update Channel (V2.54)

A generated latest.json says whether a newer release exists and carries the installer's size and SHA-256 taken from the artifact itself; GET /api/update/check reports it read-only. Success is defined as a fact only the new version can write (state.json.lastResult) — "installer launched" is explicitly not success. Download/install is slice 2 (AD-022).

Autopilot Triage & Answers (V2.52)

A maintainer-side autopilot polls the receiver every 10 minutes, has a read-only agent map the log evidence onto real code positions, and publishes the resulting answer card. Drafts by default; “needs more info” never publishes. The public page filters operator identifiers.

Diagnostics Bundle & Report Loop (V2.51)

The menu gains 🐞 Report a problem: one press builds a redacted bundle (logs + config + environment/radio/audio snapshot + auto-triage summary) and uploads it to this project's own receiver; without a network it can be saved locally instead. No passwords, keys, tokens, recordings or memory channels are ever included (AD-021).

v1.17.0 Released — CQ key on all three platforms (V2.50)

macOS DMG, Windows installer and the rpi64 image built from one commit and each verified before publication: frozen HTTPS smoke on macOS, PYZ walk plus in-package asset check on Windows, debugfs spot-check (incl. static/audio/cq.wav) on the Pi image.

One-Touch CQ Key (V2.48–V2.50)

The server keys the radio, plays the packaged CQ recording once and unkeys — no microphone, no network timing in the transmitted audio. Mic frames are dropped while the call runs, PTT/TUNE are refused, and the initiator disconnecting cuts the carrier (MRRC_CQ_FILE replaces the recording; AD-020).

v1.21.0 Released — iPhone Wake-Lock Race Fixed (V2.61)

The iOS system mic-permission dialog shown at power-on released the just-acquired screen wake lock, and every automatic re-request (no user gesture) was rejected — the main UI still auto-locked ~30 s after power-on. The lock is now re-acquired when the prompt settles and on window focus. The listen page gains an FFT trace above the waterfall, frequency step buttons, WAN-sized audio buffering, and the public proxy backend moved to the DNS name radio.vlsc.net with a 300 s resolver (survives home IPv6 changes). macOS DMG and Windows installer published with cross-host SHA-256 verification.

v1.20.0 Released — Listen-Only Interface (V2.59)

A second, separate password (MRRC_LISTEN_PASSWORD) opens /listen: frequency and mode tuning, memory recall, S-meter, waterfall and RX audio with browser-side volume. The role is enforced on the server — the /WSradio gate passes only frequency/mode sets and memory recall, the TX and tuner channels close with 4003, and REST is read-only — so transmit, recording and every device setting are unreachable from the page. The same release fixes the iPhone main-UI auto-lock (Wake Lock from a real user gesture) and activates the iOS audio session at power-on. macOS DMG and Windows installer published with cross-host SHA-256 verification.

v1.19.0 Released — ATR-1000 Tunes Itself (V2.57–V2.58)

With the optional networked tuner, a transmission into SWR > 2.0 starts one full tune by itself — 30 s cooldown, three tries per frequency, and the tuned relays are stored when the match improves. It never keys the radio: it acts only inside a transmission you started (measured power ≥ 5 W), and learning follows measured power (≥ 3 W) so panel and external-software transmissions are learned too. macOS DMG and Windows installer published with cross-host SHA-256 verification.

Yaesu SDR Family: FTDX10 / FTDX101D / FTDX101MP / FTX-1F / FT-891 (V2.46)

Profile-driven shared ASCII-CAT core (backends/yaesu/) whose transport is ported from the verified FT-710 path, with per-model tables and provenance. No unit tested: transmit is gated, the Yaesu scope waveform is undocumented (S-meter fallback covers the waterfall), dual receive is deferred. The verified FT-710 backend is deliberately untouched (AD-018/AD-019).
