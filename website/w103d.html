4. 烧到 U 盘

认准盘符，别烧错盘。（这一步会把目标盘整个擦掉。）

macOS：

diskutil list                      # 找到你的 U 盘，记下 /dev/diskN（N 是数字）
diskutil unmountDisk /dev/diskN
gzip -dc MRRC-Modern-1.25.5-w103d.img.gz | sudo dd of=/dev/rdiskN bs=4m
sync                               # 等它真的写完

⚠️ 用 /dev/rdiskN（裸设备）不是 /dev/diskN——后者慢十倍以上。

Windows：用 Rufus 或 balenaEtcher，选那个 .img.gz（两者都能直接吃 gz）。 目标是"从镜像写入"模式，不是解压后复制文件。

Linux：

lsblk                              # 找盘
gzip -dc MRRC-Modern-1.25.5-w103d.img.gz | sudo dd of=/dev/sdX bs=4M status=progress conv=fsync

烧完把 U 盘安全弹出（macOS：diskutil eject /dev/diskN）。系统可能提示"此磁盘无法读取"—— 那是正常的，镜像是 Linux 分区，Windows/macOS 读不懂。

4.1 让系统用满整根 U 盘（推荐，一条命令）

镜像的根分区只有 2.9 GB，而且不会在首启自动长（里面带 /root/.no_rootfs_resize）—— 所以 U 盘剩下的大片空间默认是闲着的。系统跑起来后在盒子上补一句就行，ext4 支持在线扩容， 不用停机、不用拔盘：

apt-get install -y cloud-guest-utils     # 提供 growpart（镜像里没有这个包）
growpart /dev/sda 2                      # 只改分区表尾，不动起始扇区
resize2fs /dev/sda2                      # 文件系统跟着长
lsblk /dev/sda; df -h /                  # 2.9G → 整盘容量

为什么要这一步：/ddbr 里的 eMMC 全盘备份约 2.3 GB（§17.1），根分区只有 2.9 GB 时 放不下；录音与日志也需要余地。实测（231 GB 的 U 盘）：growpart + e2fsck -f + resize2fs 之后 df 从 2.9G / 剩 894M 变成 227G / 剩 226G。

扩容不动 UUID —— uEnv.txt 与 /etc/fstab 里的 root=UUID=… 照旧有效。 （想先在电脑上扩也可以：Linux 上离线跑同一组命令；macOS/Windows 没有 ext4 工具，到盒子上做。）

想在烧盘后立刻核对写入是否正确（Linux / 有 cmp 的环境）： ``bash sync; echo 3 | sudo tee /proc/sys/vm/drop_caches >/dev/null # 让下面的读真的落到盘上 sudo cmp <(gzip -dc MRRC-Modern-<ver>-w103d.img.gz) /dev/sdX -n <镜像解压后字节数> ` 一致即"盘上这份 = 镜像那份"（1.26.0 实测 IMAGE_MATCH_OK）。<镜像解压后字节数> 用 gzip -l MRRC-Modern-<ver>-w103d.img.gz` 看最后一行。

5. 让盒子从 U 盘启动（新机器最容易卡的一步）

原理：已从镜像里核实，不是猜的

原厂安卓的 u-boot 有一个 update 模式。进去以后它会到 U 盘上找并运行 aml_autoscript——这个脚本就在镜像的启动分区里，内容是：

setenv bootcmd 'run start_autoscript; run storeboot'
setenv start_autoscript '... SD 卡 → USB(0..3) → eMMC ...'
setenv upgrade_step 2
saveenv        # 写入 u-boot 环境
reboot

它做的就是把启动顺序改成「先 U 盘/SD、再 eMMC」，存进 u-boot 环境，然后重启。 重启后 u-boot 从 U 盘加载 s905_autoscript → 读 uEnv.txt（里面写着本板的 FDT=/dtb/amlogic/meson-g12a-w103d.dtb）→ 引导 Linux 内核。

所以整件事的关键只有一条：让原厂 u-boot 进 update 模式。

⚠️ 更正一处说法

之前写「eMMC 一个字节不动」不准确——上面的 saveenv 确实会写 eMMC（写的是 u-boot 环境变量， 不是 Android 的分区数据）。

准确的说法：不碰 Android 的分区与数据，只改 u-boot 的启动顺序偏好。 回滚依然简单（见下）。

三种触发方式（按独立性排）

① 复位孔（最不依赖原厂软件，第一次建议用它）

  1. 断电，U 盘插好
  2. 用回形针按住复位孔里的按钮
  3. 通电，按住约 10 秒再松手

② adb（原厂安卓里打开了 USB/ADB 调试）

adb connect <盒子IP>:5555
adb shell reboot update

③ 盒子上的终端 App

su -c 'reboot update'

reboot update 就是让安卓把 u-boot 的 upgrade_step 置位——u-boot 下次启动看到它就运行 U 盘上的 aml_autoscript ✅

成功的样子

HDMI 上是 Linux 内核日志（不再有安卓开机动画）。因为 uEnv.txt 里配的控制台是 console=ttyAML0,115200n8 console=tty0——串口和 HDMI 都能看，所以刷机失败时接上 HDMI 就能看到卡在哪 ✅

第一次开机要几分钟：扩 rootfs、生成 SSH 密钥。

回滚：断电 → 拔 U 盘 → 上电。u-boot 在 U 盘上找不到脚本，走 eMMC → 回安卓。 （u-boot 环境里那条“优先 U 盘”的偏好还在，但没有 U 盘时它是无害的。）

6. 首启会自动完成什么

镜像里已经烘好了不需要硬件的全部东西（用户、代码、venv、依赖、frpc、FTDI 库、11 份机型配置、systemd 单元）。 首启只做必须碰硬件的几件事：

首启做为什么不能提前做
生成 Web 登录口令每台机器应当不同；写死在镜像里等于公开口令（发货版例外：卖家在构建期固定，见 §7）
生成自签证书证书要绑定本机名/IP，且私钥不该随镜像分发
探测串口（/dev/ttyUSB / ttyACM）端口号只有在真机上插了电台才知道
探测声卡（电台的 USB 声卡）同上

首启不需要联网：上面几件事全在本机完成（生成/写入口令、自签证书、探测串口与声卡）， 不下载任何东西。开机后 mrrc-firstboot.service 跑完会把自己标记成"已做"，之后不再重复 （没定型时不会标记，见下）。

2026-10-17 更正（对 1.28.1 产物的只读检查）：上表里两条探测在 1.28.1 及更早的镜像上从未运行过 —— 包装器在“env 文件存在”（即所有镜像）那条分支上带 MRRC_PRESEED=1 调 first_run.py，而那个键在第一行 就短路返回。口令也不是首启生成的，而是服务启动时 server.py 生成的。本版起两条探测真的会跑，且完成 判据改成“配置已定型”（needs_first_run 为假、且记下的串口节点在场）：没插电台的盒子下次开机再探一次， 探到为止。顺带一个不在本次范围内的现状：/setup 的免密引导窗口（§9.8）同样因为“口令已存在”而 从未打开过；改它等于重新开一个免口令窗口，是安全决策，另开一次变更处理。

首次上线有两条路：最省事是插网线（eth0 默认 DHCP，插上就拿地址，见 §9.2）；没有网线时， 刷盘前在 FAT 启动分区写一份 /boot/mrrc-wifi.txt（SSID=/PSK=），首启会用它把盒子连上 Wi-Fi 并删掉这个文件（见 §9.3）。两个都不可用时，接 HDMI + USB 键盘在盒子上用 nmtui 直接连 （§9.4）。⚠️ 曾经用于这一步的开放热点已在 W103D 上退役：MT7663S 起得来 AP 却不发信标， 手机扫不到，2026-10-11 真机验证失败（详见 §9.6）。

7. 进系统，第一件事改口令

从路由器 DHCP 列表里找到盒子的 IP，然后：

ssh root@<盒子IP>       # 出厂口令 1234（ophub Armbian 的默认值）

进去第一件事就改掉它：

passwd root

⚠️ 出厂 root/1234 是公开知识，不改等于把盒子送人。

口令一览（初始值都在这里，别去别处找）

用途出厂 / 初始值怎么拿、怎么改注意
SSH root1234（ophub Armbian 出厂值）passwd root公开知识，第一件事就改
Web 登录首启当场生成，每台不同mrrc-show-password（必须 root 跑）；首启 HDMI 横幅也印一次；也可在 /settings 页面改改口令会关掉免密引导窗口（§9.8）
收听专用空＝未启用自己写 MRRC_LISTEN_PASSWORD（§13）只读访客：能听、能改频率，不能发射
Cloud Hub无，要自己申请界面「设置 → Cloud Hub」apply → 等批准 → connect（§14）与呼号绑定
Wi-Fi无/boot/mrrc-wifi.txt 预置（§9.3）、/settings 页面（§9.8）、或 nmcli（§9.4）只连 2.4 GHz（§9.8）
镜像里不含任何密钥：Web 口令与自签证书都是首启在盒子上现生成的（见开头第 2 条前置说明）。

发货版（--preflash）的三条固定口令

卖家代刷、快递给用户的盒子用另一条构建通道：bash packaging/box/build-image.sh --preflash。 它把下面三条固定下来，用户开箱不需要任何初始化（插上电、浏览器登录即可）：

用途发货版初始值怎么改
SSH rootabcd1234passwd root（SSH/HDMI），或构建时 MRRC_PREFLASH_ROOT_PASSWORD=…
系统用户 mrrcabcd!1234passwd mrrc，或构建时 MRRC_PREFLASH_USER_PASSWORD=…
Web 登录abcd!1234/settings 页面的「登录口令」，或构建时 MRRC_PREFLASH_WEB_PASSWORD=…

同一通道还会把时区定为 Asia/Shanghai、区域定为 zh_CN.UTF-8（可用 MRRC_PREFLASH_TIMEZONE / MRRC_PREFLASH_LOCALE 覆盖）。默认关：不传 --preflash 的镜像一字不改，口令照旧每台现生成。

⚠️ 固定口令就是公开知识：拿到镜像或任何一台同批盒子的人都能进同批的所有盒子。这是“先固定”的 已知代价；Web 口令在页面上能改，root/mrrc 要改得上 SSH 或 HDMI。

8. 拿到 Web 口令，打开界面

mrrc-show-password

这个命令必须用 root 跑——口令存在一个 0640 root:root 的文件里。

首启时 HDMI 控制台的横幅上也会印一次；之后想不起来就用这个命令取回。

浏览器打开：

https://<盒子IP>:8888

自签证书会警告一次 → 高级 → 继续前往。

⚠️ 必须走 HTTPS，不要关。 手机浏览器要调用麦克风发射（PTT），而在 HTTP 下浏览器不给麦克风权限—— 这是浏览器安全策略，不是我们的设置问题。

登录后你应该看到主界面：频率、模式、S 表、瀑布图。这时候还没有电台——下一步接上。

9. 接网络（有线 / Wi-Fi）

⚠️ 这条的第一版是「盒子自己开热点」，它在 W103D 上真机验证失败（2026-10-11） —— MT7663S 的驱动能把 AP 模式激活（系统日志一切正常），但信标不上空，手机扫不到 MRRC-Setup。现在的版本是「盒子接入你的局域网 → 打开网页配置盒子 OS」：首次上线走 网线（§9.2）或预置 Wi-Fi（§9.3），没有网线也没预置时用 HDMI + nmtui（§9.4）。热点的 退役说明见 §9.6（设计见 2026-10-11 的 LAN 盒子设置页 spec）。

9.1 按你手边有什么选

#你手边有方式现在能用吗

⚠️ 预置分两份文件、各写各的域：口令与电台设置走 /boot/mrrc.env（§9.3），Wi-Fi 凭据走 /boot/mrrc-wifi.txt —— Wi-Fi 归 NetworkManager 管，不写进 env 文件（设计 D-4：两个域各有 唯一写入者；env 文件会被复制进 0640 的配置层、可能进支持包，Wi-Fi 密码不能和配置键混在一起）。 两份都用得上时同时写即可。（第 4 条本板已退役，见 §9.6。）

9.2 第 1 条：网线（推荐）

插上就通，确认一下：

9.3 第 2 条：预置（刷盘时就写进去，零键盘零网线）

镜像的 FAT 启动分区会被挂到 /boot（在别的电脑上打开，macOS 上那个分区叫 BOOT， 直接拖文件进去也行）。这里可以放两份文件，各写各的域：

① 电台与口令 → /boot/mrrc.env：首启会采纳它并改名成 mrrc.env.applied。支持任意 MRRC_* 键（就是 §13 那张表里的那些）✅

cat > /Volumes/BOOT/mrrc.env <<'EOF'
MRRC_WEB_PASSWORD=你自己定一个
MRRC_RADIO_MODEL=ft710
MRRC_PTT_MAX_TX_SECONDS=120
EOF

② Wi-Fi 凭据 → /boot/mrrc-wifi.txt：让盒子没有网线也能自己连上 Wi-Fi。两行， 键名不分大小写，值两端的空格与 Windows 编辑器留下的 \r 会被去掉：

cat > /Volumes/BOOT/mrrc-wifi.txt <<'EOF'
SSID=我的WiFi
PSK=密码
EOF

首启时 mrrc-wifi-preseed.service 会读这个文件、用 nmcli 连上那个 Wi-Fi，然后把文件删掉 （FAT 没有权限位，明文 PSK 不能一直躺在卡上）。它刻意与 mrrc.env 分开：Wi-Fi 是 NetworkManager 的领域，不走 MRRC_* 配置层——env 文件会被复制进 0640 的配置层、可能进支持包， 一条 Wi-Fi 密码一旦落进那儿就和配置键混在一起了（设计 D-4）。这也是文件名用 .txt 而不是 .env 的原因：别把两份文件弄混。

Guided/发货流程不用预置这条路（2026-10-17 起）：实际流程是刷完 eMMC → 上电 → 插 LAN 线 → 在 /settings 页面里改 Wi-Fi（§9.8），那已经是零键盘的一条路；预置能力仍在镜像里， 将来想用随时可用，只是操作单不再要求它。

⚠️ 这条只在"镜像刷到 U 盘/SD 卡"时成立：把系统写进 eMMC 时没有用户能碰到的 FAT 分区 （§17 的 eMMC 路线不适用预置）。

连上以后想确认，接 HDMI 看控制台，或 SSH 进去看：

journalctl -u mrrc-wifi-preseed -b     # 连上后该 unit 应显示文件已删、网络已就绪

10. 接电台

FT-710 的线插口别搞错：用上方 Enhanced 口，它同时承载 CAT 串口和 FT4222 scope。 插 Standard 口的话 CAT 可能通但没有真频谱。

aplay -l                            # 播放设备（TX）

11. 选机型

mrrc-radio list        # 11 个型号，带 ✅已验证 / ⚠实验性

已验证的三个：ft710、ic7300、ic7300mk2。其余 8 个是实验性（默认只收不发，见下）。

mrrc-radio use ft710                          # 自动探测串口 → 写配置 → 重启服务
mrrc-radio use ic7300 --port /dev/ttyACM0     # 或者你直接指定端口
mrrc-radio show                               # 核对当前生效的配置

use 做了四件事：停服务 → 探测串口（真发包问电台）→ 写配置 → 起服务。 所以它需要电台是开机状态。

换机型时旧串口会被自动清掉。 FT-710 是 ttyUSB0/1、IC-7300 是 ttyACM0—— 留着上一个型号的串口等于配了一条没有报错的死链路。

关于 8 个实验性机型（重要）

ic705 ic7610 ic7760 ftdx10 ftdx101d ftdx101mp ftx1 ft891 —— 这些机型的指令表来自 Hamlib 与设备手册，不是真机实测。默认只收不发。

（在镜像里看得出来：这三个已验证机型的 profile 根本不写 MRRC_ALLOW_UNVERIFIED_TX 这一行， 而那 8 个都显式写着 =0——默认是安全的，要发射得主动改。）

理由（AD-019）：在没有实测过的频率/功率语义上发射，对电台和天线都不好。

19. 三条红线（会踩出"没有报错的故障"）

① 停服务只用 systemctl，不要 kill 进程。

Linux 上 frpc 的残留清理是 Windows-only 的。一个残留的 frpc 会占住 proxy 名，导致下次启动 隧道起不来而界面毫无提示。systemctl stop 会连带清掉 frpc，kill 不会。

② 登录限流是全局桶，误锁影响所有人。

经公网访问时所有登录共享同一个来源 IP，限流是 5 次失败 / 300 秒，而且全局。 不是你一个人被锁 5 分钟——是所有人。

③ 内核升级只走 armbian-update，保持 w103d 变体。

W103D 的 WiFi 完全依赖专属内核补丁 + MT7663S 固件 overlay。 换成通用内核 = 静默丢 WiFi：没有报错，只是连不上。
