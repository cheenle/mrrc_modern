公网入口连不上时，怎么把诊断包拿出来

适用：盒子在你家局域网里打得开网页，但 你的呼号.mrrc.vlsc.net 打不开，或者「🐞 遇到问题」里的诊断包传不上去。

为什么会这样

诊断包原来只有一条出路：上传给我们。上传要盒子能上网。 当坏掉的偏偏就是网络那一环时，包在盒子里生成好了、也确实存住了，却谁也拿不到。

这个小工具补上第二条路 —— 在你自己的局域网里，把那个 zip 直接拷到你的 Windows 电脑上。它不需要盒子能上网，也不需要你懂 SSH。

下载

  MRRC-Diag.cmd

约 10 KB，单个文件，不用安装。放在桌面或下载文件夹， 双击运行即可。它只读取盒子的状态并在本机保存一个 zip， 不上传任何东西，也不改盒子上的任何设置。

系统要求：Windows 10（1809 及以上）或 Windows 11。脚本用的是系统自带的 curl.exe 与 PowerShell，不需要额外装软件。

三步

  1. 先准备一个能 SSH 登录的账号（推荐，但非必需）。
    浏览器打开盒子 → 设置 →「系统账号口令（SSH / HDMI 登录用）」 → 账号选 root → 设一个新口令（至少 8 位）。
    这里不校验旧口令，所以忘了也没关系，直接设新的就行。 注意它和上面那张「登录口令」卡不是一回事：那张是网页登录，这张是 SSH/HDMI 用的系统账号。
  2. 双击 MRRC-Diag.cmd，按提示输入两样东西：
    • 盒子的 IP —— 就是你浏览器地址栏里那个，例如 192.168.1.50（也可以试 mrrc.local）
    • 网页登录口令 —— 你平时打开盒子页面用的那个
    然后脚本会先把盒子的公网入口状态打在屏幕上（这一步不需要 SSH）。
  3. 看到 SSH account [mrrc]: 时，输入第 1 步设过口令的账号名（例如 root），回车， 再输入那个账号的口令。文件就开始拷回来了。

结束后，脚本旁边会多出一个 mrrc-diag-<你的电脑名>.zip —— 把它发给我们即可。

最后一步失败了，也没关系

zip 里最要紧的那份 cloud-state.json 在 SSH 之前就已经写好了。它记着隧道到底为什么没起来。 把屏幕上这一段截图发来，通常就够定位： 

entry         : https://bg7sb.mrrc.vlsc.net/
tunnel_running: false
tunnel_error  : 缺少 frpc：/opt/mrrc_modern/fleet/frpc

诊断包本体仍然留在盒子里，不会丢。等盒子的网络恢复， 在「🐞 遇到问题」里点一次「上传」，它还能补发出去。

屏幕上那几行是什么意思

字段 含义
entry 你的公网入口地址。空 = 还没有申请过入口。
tunnel_running false = 隧道进程没在跑，公网入口必然打不开。
tunnel_error 没跑起来的原因，一句话。这一行最有用。
cert 盒子当前出示的证书文件。空 = 还没接通入口。
cert_reload true = 新证书已就位但进程还没重载（重启一次服务即可）。

这个工具不会做什么

  • 不上传任何东西到外网 —— 所有流量都在你的局域网里
  • 不重启盒子、不改配置、不碰电台
  • 不把网页登录口令或会话令牌写进 zip（令牌只留在系统临时目录）
  • 诊断包里凡是口令都已被打码（生成时就会处理）
