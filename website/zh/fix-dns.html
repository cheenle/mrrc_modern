盒子的 DNS 坏了：在 Windows 上一条命令修好

适用：盒子的网页打得开、ping 192.168.x.x 也通，但 ping portal.mrrc.vlsc.net 要卡好几秒才失败；软件更新、公网入口、 诊断包上传一起失灵。

先确认是不是这个问题

在盒子的 SSH 里看两样东西（两行就够）：

ls -l /etc/resolv.conf          # 是普通文件，而不是 -> /run/systemd/resolve/stub-resolv.conf
cat /etc/resolv.conf            # 里面有一个"不属于你"的地址

典型的样子长这样 —— 那个 192.168.65.7 是 做镜像那台 Docker Desktop 的内部 DNS，在任何客户网络上都不存在： 

-rw-r--r-- 1 root root 97 10月11日 11:58 /etc/resolv.conf
# DNS requests are forwarded to the host. DHCP DNS options are ignored.
nameserver 192.168.65.7
判据一句话：能 ping 通 IP、ping 不通域名，而且 resolvectl status 第一行写着 resolv.conf mode: foreign。 这时系统里真正的 DNS（systemd-resolved，手里有路由器给的正确地址）根本没被用上。

为什么会这样

镜像构建时为了让安装程序能联网，构建脚本把构建机的 /etc/resolv.conf 借给了正在组装的系统，而基底原本的那条 -> ../run/systemd/resolve/stub-resolv.conf 符号链接没有还原。 于是每台盒子出厂就带着一个"别人家的 DNS"。2026-10-11 之后、2026-10-25 之前 构建的镜像都有这个毛病。

下载修它的小工具

  MRRC-FixDNS.cmd

约 9 KB，单个文件，不用安装。只要网页登录口令，不需要 root 口令、不需要 SSH。 它做的事：登录盒子 → 让盒子自己的 root 助手跑 linux/fix_resolv_conf.sh（与软件升级跑的是同一个脚本）→ 把结果打给你 → 再跑一遍证明已经是幂等的。

系统要求：Windows 10（1809 及以上）或 Windows 11。用的都是系统自带的 curl.exe 与 PowerShell，不装任何东西。

三步

  1. 双击 MRRC-FixDNS.cmd（或 mrrc-fix-dns.cmd 192.168.1.50）。
  2. 输入盒子的 IP —— 就是浏览器地址栏里那个。
  3. 输入网页登录口令（不是 SSH 的）。脚本会打印它查到什么、改了什么。

正常会看到这样两段：

fix_resolv_conf: /etc/resolv.conf is a static file: # DNS requests are forwarded ... nameserver 192.168.65.7
fix_resolv_conf: backup written to /etc/resolv.conf.mrrc-bak
fix_resolv_conf: /etc/resolv.conf -> ../run/systemd/resolve/stub-resolv.conf
fix_resolv_conf: restarting systemd-resolved so the old global server is dropped
fix_resolv_conf: done

--- running it once more: it must be a no-op now ---
fix_resolv_conf: /etc/resolv.conf is already a symlink (../run/systemd/resolve/stub-resolv.conf) — nothing to do

第二段出现 "already a symlink" 就是修好了。 文件本身备份在盒子的 /etc/resolv.conf.mrrc-bak，随时可以还原。

修完怎么验

在盒子上（SSH 或接显示器）：

resolvectl status | head -3      # 应显示 resolv.conf mode: stub
getent hosts portal.mrrc.vlsc.net   # 应立刻返回一个 IP

然后回到浏览器刷新页面：软件更新、公网入口、诊断包上传都应该恢复。 如果 getent 还是慢，那说明盒子连不到自己的路由器 —— 那是另一个问题 （网线 / Wi-Fi 信号 / DHCP），见 盒子用户指南 的排障表。

脚本说 404 / 提示"这台盒子还不认识这个接口"

说明盒子固件比这个修复早。两条路：

  1. 先升级盒子（页面 ☰ →「软件更新」，或者 从 Windows 远程升级）， 再跑一次这个工具 —— 升级本身会顺手修掉它。
  2. 或者有 root 口令的话，SSH 进去手工三行： 
    cp -a /etc/resolv.conf /etc/resolv.conf.mrrc-bak
ln -sfn ../run/systemd/resolve/stub-resolv.conf /etc/resolv.conf
systemctl try-restart systemd-resolved

我们这边做了什么

三处，缺一不可：镜像（构建结束时还原符号链接，新盒子不再带这个毛病）、 升级（mrrc-update 每次都以 root 跑一遍同一个修复脚本， 已发货的盒子升级一次自动好）、页面与这个工具（没有 root 口令也能修）。 脚本自己也是幂等的：已经是对的机器上跑，它只说一句 "already a symlink" 就退出。
