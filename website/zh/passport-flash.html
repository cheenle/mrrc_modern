插上就刷：盒子替 Passport 写固件与配网

一台刚出厂的手持终端什么都不知道：它没有 Wi-Fi，不知道盒子在哪，也不知道盒子的口令。 以前的流程是——连它自己开的热点（iOS 还会警告「本网络无法上网」），然后在手机小键盘上 敲 Wi-Fi 名、Wi-Fi 口令、盒子地址、盒子口令。而盒子本来就知道这一切。

现在只有三步

  1. 拔掉电台线，把 Passport 插到盒子的 USB 口上。
  2. 浏览器打开 https://<盒子地址>:8888/passport。
  3. 选固件、选设备、填四个值，点 开始刷写。

刷完拔线，把终端插到 USB 电源上——它自己连上 Wi-Fi，在盒子上作为一个终端会话出现。

页面上的四步

1 · 固件

点一次 读取目录，盒子从本站取回可刷版本清单；选一个版本，点 下载并校验。镜像在刷写开始之前就下载完并核对 SHA-256， 所以写入阶段里没有下载，失败了也不会留下半张镜像。

2 · 设备

只列 ESP32 类串口，而且电台自己的串口永远不在候选里—— 不是只挡那一个路径，而是挡整颗 USB 设备：FT-710 的 CP2105 从一颗芯片暴露 CAT 与 scope 两个串口，按路径只挡一个等于没挡。板子没出现就按住它上面的 BOOT 键再插 USB，然后点 重新识别。

3 · 要写进设备的配网

字段 预填
Wi-Fi 名称 盒子当前连着的那个网络（可改）
Wi-Fi 口令 空 —— 每块板子手输一次。系统不会把口令交给网页
设备要连的地址 本盒子的局域网地址（在外面用就改成公网入口），只填主机名 或 IP —— 端口在它旁边单独一格
盒子网页口令 留空 = 用本盒子自己的口令；这个值不出现在响应里，也不进日志

4 · 写入

日志面板显示 esptool 自己的输出。任务是一把单槽锁：跑着的时候再点一次会得到 409。状态胶囊最后变成 done 或 failed 并给出原因。

它到底写了什么，以及为什么不会「看起来成功」

步骤 含义
chip id 认芯片。不是 ESP32-C3 的板子在第一次写之前就被拒绝
firmware 1.3.2 合并镜像写到 0x0（bootloader + 分区表 + 应用），带 --verify
wifi config NVS 分区写到 0x9000，带 --verify
read back 把 0x9000 读回来，与要写进去的配置逐项比对
reset 硬复位，板子带着新配置启动

NVS 的编码与 ESP-IDF 自己的 esp-idf-nvs-partition-gen 逐字节相等——这一点由测试钉死。格式写错不会抛异常，设备只会静默退回 编译期默认值，也就是刚写进去的 Wi-Fi 悄悄丢了；逐字节相等是唯一可信的证据。

固件 1.3.2 改了什么

  • 发射一次之后，瀑布不再永久掉档。 旧逻辑在松键时恢复的是「当前档位」， 而按键那一下刚把它改成了低档；结果每次发射都把链路留在最便宜的那一档，要等健康看门狗 两分钟后才升回来。现在「链路能承载的档位」和「当前生效的档位」是两个变量，松键恢复前者。 现场日志：12:32:55 发射，12:36:26 还在低档——两分半。
  • 长按 UP 3 秒可以重开配网热点。 以前只有「一块完全没有配置的板子」 能进配网页；如果 Wi-Fi 填错了、或者要换一台盒子，唯一的办法是擦掉 flash。现在长按 UP 会置一个一次性标志并重启，下一次启动在电台模式占用射频之前进配网，堆还是干净的。

三条边界

  • 口令不进页面、不进日志。 Wi-Fi 口令只进内存里的 NVS 镜像；每一行 进页面和 server.log 的文字都经过脱敏（日志面板会被截图、会进支持包）。 盒子网页口令在字段留空时由服务端自己代入，从不经过 HTTP。
  • 电台永远不会成为候选。 往 FT-710 的 CAT 口写 1.7 MB 不是「刷失败」， 是事故。
  • 错芯片在第一次写之前就停，插错的板子不会被刷一半； read back 不一致时任务会故意失败，短回读不算「截断成功」。

前提与排障

这条功能需要盒子 1.29.0 及以后。刷机工具跟着代码走（ vendor/esptool/），所以不需要 pip、不需要联网、 不需要重启——一次搬文件的热修就够了。

现象 处理
开始按钮是灰的，`本机 esptool 没有` 树太旧或不完整：更新盒子，或在盒子上装一次 esptool
那个串口不在可选列表里 端口在「列出」与「开始」之间消失了，或那是电台的口。点 重新识别
已经有一次刷写在进行 同时只允许一次。等它结束或刷新页面
catalog: … / download: … 盒子够不到本站，或镜像 SHA 不匹配。检查盒子网络后重试
刷成功了但板子连不上 多半是 Wi-Fi 口令或地址填错。用同一个固件重跑第三步即可（NVS 写入很快）。如果串口日志是 login failed, retry in 30s 而面板显示 完成，那是填的端口不对。固件把端口 存在独立的 NVS 键里，键缺失时会退回 443，所以必须和 盒子实际监听的端口一致（默认 8888），页面会预填
