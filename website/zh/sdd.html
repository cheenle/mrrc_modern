V2.20 之后的变更重点

隧道清理只跑在 Windows 上 —— 于是 macOS 从来没清理过 （V2.73）

v1.25.2 修「每启动一次就多留一个 frpc」时改的是枚举方式（wmic → Get-CimInstance）， 而清理函数开头那句 if os.name != "nt": return —— 当初为「同机上第二个实例不受影响」加的 —— 把整段清理关进了 Windows：在 macOS 上它立刻返回，什么都没做。 在 macOS 上实测到同一个故障的第二个平台样本：一次开机后启动 6 次留下 6 个孤儿（PPID 全为 1），而且它自我循环 —— 终于拿到代理名的那一个干净子进程，正是下一次启动的拦路石； 新实例的子进程从那一刻起每 33 秒打一次 already exists （86 行日志里 67 行都是这段重试）。现在枚举改走 ps -eo pid=,command=，只认命令行第一个词的 basename 是 frpc 的进程（用编辑器打开同一份 .toml 的 vim 命令行里也有这个路径，不能误杀），终止改走 SIGTERM， 让 frpc 自己关掉控制连接、hub 当场释放代理名；而且永不抛出 —— 快照与 kill 之间进程可能已自己退出，那是「无事可做」而不是失败。 关停时也会停掉隧道了：frpc 是服务进程的子进程，父进程没了它照样活着， 把代理名占给下一次启动。

FT-891 加入 Yaesu 家族 —— 以及它揭出来的一个潜伏崩溃 （V2.72）

第 11 个注册键、Yaesu ASCII-CAT 共享核心上的第 5 个 profile。 它唯一的协议差异是写格式：滤波宽度 SET 是 SH01NN，而不是家族的 SH00NN（Hamlib newcat.c:9658，int on = is_ft891）， 所以 YaesuModelProfile 多了一个 filter_width_prefix 字段、由核心去读它 —— 核心里没有任何按机型分支，四款已发布机型发出的字节也完全不变。 滤波档位逐档抄自 Hamlib 的 get 侧（CW/RTTY/PKT 17 档、SSB 21 档）并与它机器比对过；AM/FM 不给档位，因为它们的宽度只由 NA 决定。有三件离线源推不出的事实来自 2026-09-17 的一份现场上报：38400 8N1（Hamlib 的 stop_bits=2 自承是假设值）、 没有 USB 声卡——所以不做设备名自动匹配、外接接口按 48 kHz、连接对话框里直接写明——以及 S 表比机显高 1–1.5 S（只记录，曲线刻意不改）。接线过程还揭出一个潜伏在整个家族里的崩溃： get_preamp/get_attenuator 被 initial_state_sync() 与设置轮询层调用，却从未定义， 于是首次连接成功即抛 AttributeError —— 至今没人发现，是因为这个家族没有任何真机可连。已修，并补了一个结构性守卫： 把每个轮询项与同步逻辑引用到的方法逐个解析一遍。全程未验证：TX 设闸、id_answer 留空、11 处 TODO(hw-verify)。

键控了的载波不会再没有声音 （V2.71）

TX 上行只有一个 owner，按键时按会话令牌认领 —— 但令牌是 30 天 Cookie，一个浏览器会话可以同时持有多条麦克风 socket （页面重载会把旧的那条留成半开几十秒，同一登录的两个标签页则干脆共用）。 认领原先取的是从集合里扫到的第一个匹配，于是可能落到那条已经死掉的 socket 上：电台键控了，活页面的每一帧却被当作非 owner 丢弃 （frames=0 non_owner_drops=236、peak=0% —— 键控着的载波上是纯静默），直到 58 秒后旧 socket 被回收才自愈。 现在认领取该会话最后连接的那条，并且真正在送音频的同会话 socket 会在首帧接管上行；异会话依然既不能靠连接、也不能靠发流抢占。

刚按下的一键不会再被存活闸门自己放开 （V2.70）

Cloud Hub 打开的存活闸门只应释放不再证明自己活着的发射会话；心跳在按键时发送， 而服务端要等按键处理返回后才能读到 —— 落在那 20–70 ms 窗口里的检查，会把刚按下的健康一键 当成静默会话放开（一份现场日志里记了 七次）。现在按键本身会刷新存活时钟， 从未发过 txhb 的会话依旧不被门控。修复在冻结的 server.py 里， 所以只能随安装包发布 —— 而它的第一个构建恰好说明了为什么必须查产物本身：所有门禁都是绿的， 包里却还是修复前的字节码；现在构建前会清掉 PyInstaller 的 workpath 缓存。

一条每启动一次就漏一个进程的隧道 （V2.69）

hub 的日志一天里刷了 7143 行 proxy already exists，而根因在租户自己的机器上：启动前回收旧 frpc 的那段代码用的是 wmic，而 Windows 11 已经不再自带它 —— 那个裸 except 把这一步变成了静默的空操作。两天里累积了 六个进程，其中五个是孤儿，全都在抢同一个代理名。现在改用 PowerShell 的 CIM 命令枚举，路径比较按 Windows 的规则（大小写不敏感、两种斜杠）， 并且查不到时会出声告警 —— 因为残留在 hub 的日志里才现形，这台机器自己看不到。启动器另加了一个命名互斥， 两次启动不会再同时认为端口是空的。

两个「只有构建机看不见」的打包缺陷 （V2.68）

同一台 Mac 报的两件事是同一个形状：构建机上有、用户机上没有的东西 被当成了常驻假设。包里带着构建机的 OpenSSL，它的编译期默认 CA 路径 就是构建机自己的 /opt/local/… —— 于是信任库为空，接入云端、 诊断包上传、软件更新检查全部 CERTIFICATE_VERIFY_FAILED。现在 外发 HTTPS 统一走 net_tls.py（先包内 bundle、再系统 bundle）， 并有构建期闸门故意把 CA 环境打空后要求真握手。另一件是频谱：界面一直 画的是 S 表合成曲线，真频谱一次都没启动过 —— 启动器把相对 路径的 MRRC_FTDI_LIB_DIR 锚到了 Contents/MacOS， 而签名后的包把数据树放在 Contents/Resources，于是采集进程 直接以 “FTDI libraries not found” 退出，而原因只被记在 DEBUG 里。

v1.25.0 发布 —— 装完就能用 （V2.67）

三条现场报障、三个不同根因。启动器可能在起 server 之前就永久卡死： 首次运行的串口探测会往每个候选口写，而电台的真实描述一个关键词都不命中 （CP2105 不是 "cp210x"），于是第一个被探测的是那台机器的 Intel AMT 口 —— 它 open 正常、却一个字节也写不进去，而写入用的是 pyserial 默认的 无超时。另一台已批准的实例停在"等待批准"：当时唯一的轮询循环住在设置 对话框里；现在轮询在服务端每 30 秒自查一次并报告结果。还有证书重载判据比错了 两个对象，导致登记完成的实例入口 502，而没有任何东西会去重启它。

v1.24.6 发布 — 启动器先问、再打开 （V2.66）

一台装了 v1.24.5 的现场机仍然黑屏。它自己的 server.log 加上直接跑包内服务器证明：应用是健康的 —— 纯 HTTP 的 /login 回 200，而浏览器被送到了 https://，于是显示的是协议错误空白页。根因是启动器按 自己能不能签出证书算 scheme，服务器按自己能加载到什么 决定 TLS —— 两次独立决策、一个 socket。现在两端启动器都先探 /api/health（共用 launcher_net.py），打开真正应答的那个 scheme，切换必提示、绝不静默降级。

同版还修了：Windows 端口改为独占绑定 —— 那里的 SO_REUSEADDR 允许第二个进程绑到正在监听的端口，于是两个 服务器可以同时报 Server ready!，浏览器可能落到没拿到电台那一个（现场日志 每行成对、相差 1–10 ms）；直接启动 Server 不再把密码文件与 recordings/ 指向只读的安装目录 —— 那意味着每次启动换一个 新密码且永远存不下，正是「装了新包还是登不上」的真因；裸启动现在会读用户的 mrrc_modern.env；日志不再每行写两遍；并新增标准库 AST 门禁：应用模块被 name.attr 使用却从未 import 时直接让构建失败 —— 这类缺陷已经 进过两次发布包（v1.24.1 的 cloud_hub、v1.24.5 的 ssl_bootstrap）。

MRRC 品牌统一 + 环境变量迁移 （V2.21–V2.22）

FT710_* 环境变量更名为 MRRC_* 并自动兼容旧前缀；启动器、认证 Cookie 与日志命名统一为 MRRC Modern；启动配置模板暴露 MRRC_RADIO_MODEL。

IC-7300/MK2 运行可靠性 （V2.24）

按后端选择串口默认波特率（FT-710 38400；IC-7300/MK2 115200）；CI-V 0x27 分路队列上限 44 段、积压丢最旧，防止暂停后回放陈旧波形；频谱以 30 Hz 广播且只发送新完成的真实帧。

官方 CI-V 一致性对齐 （V2.25–V2.26）

频谱启动同时开启显示（27 10 01）与波形输出（27 11 01）；SCROLL-C 解码为下/上边缘；按型号选择 Transceive 菜单项（IC-7300 0071 / MK2 0089）；改用文档化的 03 在线探测；ALC 采用官方 raw 120 满刻度。全仓审计记录了开放问题 I8–I11。

v1.12.0 Windows 稳定版发布 （V2.27）

经 macOS 与 Windows 11 双端 633/633 测试、三个 PyInstaller 目标、Inno Setup 编译与跨主机 SHA-256 校验后发布。FT-710 的 CAT、音频、PTT 与频谱行为保持不变。

ICOM SDR 机型：IC-705 / IC-7610 / IC-7760 （V2.41）

再添三台 CI-V 机型，采用 profile 驱动核心并带显式未验证边界：能力位、发射门禁（MRRC_ALLOW_UNVERIFIED_TX=1 显式开启）与只读 19 00 型号身份校验。三台均无真机，因此不声称已验证。

服务端 QSO 录音 （V2.42–V2.45）

边录边落的 16 kHz 单声道 MP3（lameenc），RX/TX 落在同一条单调时间轴上；录音面板支持列表/拖动定位/下载/删除；浏览器端编码器退役。写入端生命周期修复终结了"同一进程第二次录音静音"。

CAT 掉线恢复成本 （V2.43）

USB 串口重枚举后不再重放 24 条全量状态同步（轮询分层本已覆盖所有字段），原先约 62 秒的 CAT 死区降为秒级恢复；重试日志分级并给出 ENXIO 可操作提示。

v1.15.0 发布 （V2.44–V2.45）

macOS DMG、Windows 安装包与 rpi64 镜像发布，跨主机 SHA-256 校验一致，含上述录音功能与掉线恢复修复。

v1.18.1 发布 (V2.54)

一个让 macOS 包真正可用的补丁：此前每个包的应用签名都没成功（该步骤静默失败）， Gatekeeper 因此报「已损坏，无法打开」；同时包内没有任何音频输入权限说明键，而 macOS 对此的回应是 让捕获流打开成功、却把缓冲填零 —— 于是 RX 完全无声、不报错，日志还把矛头指向电台。 两者都在打包层面修掉，且签名失败现在会直接中止构建。

v1.18.0 发布 （V2.54）

macOS DMG 与 Windows 安装包由同一提交构建并各自验证：macOS 冻结版能启动、支持端点齐备、**首次真的写出服务端日志**；VM 内 1261 项测试 + Inno Setup 出包。latest.json 已上线，1.17.0 客户端检查即得「有新版本」。

更新通道（只读检查） （V2.54）

生成式 latest.json（size/SHA-256 取自产物本身）回答“有没有新版本”；GET /api/update/check 只读上报。成功被定义为**只有新版本能写下的事实**（state.json.lastResult），“已拉起安装器”明确不算成功；下载/安装是 slice 2（AD-022）。

自动分诊与答复页 （V2.52）

维护者侧的 autopilot 每 10 分钟轮询接收端，用只读 agent 把日志现象对到代码位置，产出结论卡并发布到答复页；默认只出草稿，证据不足时判「需要更多信息」且不发布。公开页过滤邮箱/手机号/设备路径/内网地址。

诊断包与上报闭环 （V2.51）

菜单新增 🐞 遇到问题：一键生成脱敏诊断包（日志 + 配置 + 环境/电台/音频快照 + 自动体检结论）并上传到本项目专属接收端；无网络时可只保存到本地。包内不含密码、证书私钥、令牌、录音与记忆频道（AD-021）。

v1.17.0 发布：三平台同步 （V2.50）

macOS DMG、Windows 安装包与 rpi64 镜像由同一提交构建，发布前各自验证：macOS 冻结包无头 HTTPS 冒烟、Windows PYZ 走查 + 包内资产核对、树莓派镜像 debugfs 抽查（含 static/audio/cq.wav）。

一键 CQ 按键 （V2.48–V2.50）

由服务端键控电台、播送打包的 CQ 录音并松键 —— 发射内容不经过网络，因此不受抖动影响。呼叫期间麦克风帧被丢弃，PTT/TUNE 被拒绝，发起端断开即切断载波（MRRC_CQ_FILE 可替换录音；AD-020）。

v1.21.0 发布 —— iPhone 开机锁屏竞态修复 （V2.61）

开机时弹出的 iOS 系统麦克风权限框会释放刚拿到的屏幕锁， 而所有无用户手势的自动重申请都被拒绝 —— 主控界面开机后 约 30 秒仍会黑屏。现在权限框结束时立即重申请，并新增 window focus 兜底。收听页新增瀑布上方的 FFT 迹线、频率步进按钮、公网尺寸音频缓冲；公网代理后端 改用 DNS 名 radio.vlsc.net（300 秒重解析， 家中 IPv6 变化自愈）。macOS DMG 与 Windows 安装包均已发布并做了跨主机 SHA-256 校验。

v1.20.0 发布 —— 收听专用界面 （V2.59）

用另一个独立密码（MRRC_LISTEN_PASSWORD）可进入 /listen：调频率与模式、 调用记忆频道、看 S 表与瀑布、听 RX 音频（浏览器端音量）。管控全在服务端——/WSradio 角色门只放行频率/模式与记忆调用，TX 与天调通道直接 4003 断开，REST 只读——因此发射、录音与 设备设置从页面根本到不了。同一版还修掉 iPhone 主控界面自动锁屏（Wake Lock 改由真实用户手势发起）， 并在开机时激活 iOS 音频会话。macOS DMG 与 Windows 安装包均已发布并做了跨主机 SHA-256 校验。

v1.19.0 发布 —— ATR-1000 自己动手调谐 (V2.57–V2.58)

接了可选网络天调后，发射中驻波超过 2.0 会自动做一次完整调谐：30 s 冷却、同频最多 3 次， 调好且匹配改善时把继电器值写回学习库。它绝不自行键控电台——只在你已经发射时动手 （实测功率 ≥ 5 W），学习门限也改为跟随实测功率（≥ 3 W），因此面板 PTT 与外部软件的发射同样会被学习。 macOS DMG 与 Windows 安装包均已发布并做了跨主机 SHA-256 校验。

Yaesu SDR 家族：FTDX10 / FTDX101D / FTDX101MP / FTX-1F / FT-891 （V2.46）

profile 驱动的共享 ASCII-CAT 核心（backends/yaesu/），传输层移植自已验证的 FT-710 路径，每机型表均带溯源。四台均无真机：发射默认拒绝、Yaesu 频谱波形无文档（瀑布走 S 表回退）、双接收留二期；已验证的 FT-710 路径刻意不动（AD-018/AD-019）。
