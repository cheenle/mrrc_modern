W103D · 遥控器指南

一支遥控器，站着把电台调好

配对一次，之后按着语音键就能发射，方向键调频率；菜单在「VFO / 频道」之间切换，频道模式下方向键直接换你保存的频道；电视键换波段、主页键一键 CQ、OK 一步回 7.050 LSB。1.28.49 起，小米蓝牙遥控器 2 / 2 Pro 的麦克风也能进发射链路。这页从“能用的遥控器”讲到配对、按键、语音麦克风、音量、换键位和排障，按顺序看即可。

1. 能用的遥控器与版本

盒子认的是标准蓝牙 HID 遥控器——就是能和手机、电视、盒子配对的那一类。配好之后内核会多出一个 <遥控器名字> Keyboard 输入设备（bluez 有时把它叫 bluez-hog-device，名字不重要），按键从这里进来。

遥控器按键麦克风实测
小米蓝牙遥控器 2（RC001）/ 2 Pro（RC003）✅ 方向、OK、返回、主页、菜单、电视、音量、语音✅ 1.28.49 起（ATVV，16 kHz IMA ADPCM）2026-11-10，W103D 实机
CMCC_Voice_Remote（中国移动语音遥控器）✅ 方向、OK、返回、首页、菜单、设置、频道、数字、音量❌ 不走 ATVV：讯飞 XFRCB22 私有通道（HID report 0xFC → 3×16 B 拼帧 → 40 B G.722.1 16 kbps，需解白化）；当前固件只做按键2026-10-17，W103D 实机；协议见社区项目
其他标准 BLE HID 遥控器✅ 名字不认识也能用：内核报 Bus=0005 + EV_KEY 的设备会被自动选中看是否实现 Google ATVV；否则只当按键用协议通用，键位可能要补

版本要求：按键功能 1.28.44 起就有；遥控器麦克风要 1.28.49 · FP45 起。1.28.48 只是过渡版本（只有代码，没有自动补服务/依赖），1.28.49 才把 unit、依赖和兜底补齐。更新卡显示 1.28.49 · FP45 就对了。

本页 §3 的键位是 2026-11-14 重排后的版本（确定 → 7.050 LSB、主页 → CQ、菜单 → VFO/频道、电视 → 换波段）：更早的盒子上这些键要么没动作、要么只提交数字。升级到带这套键位的盒子线固件后即生效，不用改任何配置。

现在不行、别再折腾的：

  • 红外遥控器：这批 W103D 的 meson-ir 接收器在设备树里，但没有焊接收头，对着盒子按键 /dev/lirc0 一直是空的。
  • 只发红外控电视的键（例如电视键）：盒子收不到蓝牙事件，任何软件都读不到。
  • 把遥控器当标准声卡 / 蓝牙耳机麦克风：它没有 HFP/HSP/LE Audio，系统不会出现录音设备；麦克风走的是 ATVV 私有服务，由 remote_mic.py 专门解码，见 §5。

2. 配对（一次，之后不用再配）

前提：服务账号 mrrc 要在 input 组里 —— /dev/input/eventN 是 root:input 0660。镜像已经加好；自己装的环境用 id mrrc 查，缺组时 mrrc-localctl 每次打开都是 Permission denied，界面不会提示这一点。

  1. 让遥控器进入配对模式（指示灯快闪）。组合因型号而异：CMCC 实测是同时长按「OK + 返回」约 5 秒；小米遥控器 2 / 2 Pro 常见的是同时长按「主页 + 菜单」约 3 秒。以指示灯快闪为准；不闪就换组合或看说明书。
  2. 浏览器打开盒子的 /settings →「遥控器」→「搜索附近的遥控器」（约 12 秒，现在会同时扫 BR/EDR 和 LE，BLE-only 的小米也能出现）。
  3. 在列表里找写着「遥控器/键盘」、带信号强度的那一行，点「配对」。只有一台正在广播的 HID 设备时，页面也会自动配对，不用再点。
  4. 看到「已配对，按键可用 ✓」后，按一下方向键验证。

名字不匹配也能用。自动配对默认认 CMCC_Voice_Remote、MI RC（小米遥控器 2 的广播名）、Xiaomi、小米；别的遥控器手动点「配对」即可。名单可以在 /opt/mrrc_modern/env/mrrc.env 或 systemd drop-in 里改（逗号分隔，子串匹配，大小写不敏感）：

[Service]
Environment="MRRC_BT_REMOTE_NAME=CMCC_Voice_Remote,Xiaomi,Mi Remote,MiBox"

加完 systemctl daemon-reload && systemctl restart mrrc-modern。甚至不改名单也能用：local_ctl.find_device() 在名字不匹配时会回落到「蓝牙总线（I: Bus=0005）+ 有 EV_KEY」的第一台设备，所以遥控器叫什么名字都不影响按键。

2.1 配好了但按键没反应

Paired: yes 不等于能用，判据只有一个：/proc/bus/input/devices 里出现这台遥控器的键盘节点，并且连续几秒都在（bluez 建了又拆时，单点采样会骗人）。按这个顺序查：

现象 / 日志原因处理
Device … not available遥控器已经退出配对模式（列表里的名字只是 bluez 缓存）重新进配对模式再点一次；页面会自动重试 6 轮，每轮 5 秒
unlikely error（ATT 0x0E）刷屏，读不到属性链路没加密，遥控器拒掉每次 GATT 读先重启 bluetoothd（不动 bond）；仍不行再清 bond、控制器上下电、重配
Paired/Bonded 都是 yes，但没有键盘节点bluez 的 HOG 数据库残缺（No attribute found within the given range）systemctl restart bluetooth；还不行再清 bond 重配
节点存在，mrrc-localctl 却 Permission deniedmrrc 不在 input 组usermod -aG input mrrc，重启 mrrc-localctl

2.2 没有网页时（命令行）

bluetoothctl --timeout 25 pair  <地址>
bluetoothctl trust <地址>
bluetoothctl info <地址>       # Paired: yes / Bonded: yes / Connected: yes
cat /proc/bus/input/devices    # 找 Name=… Keyboard，Handlers=… eventN

命令行一次性 pair 不注册配对 agent，BLE HID 可能因为“绑定位为 0”被拒；页面走的是 pty + --agent NoInputNoOutput，会发出 Bonding 请求，成功率更高。能用页面就用页面。

3. 按键表（CMCC / 小米 2 · 2 Pro）

按键按扫描码（usage）优先、键码兜底识别：u:0x… 是 HID usage，k:… 是内核 keycode。不同遥控器可能发同一个键码但不同 usage（CMCC 的「设置 / M / #」都是 240），所以表里以 usage 为准。

小米没有数字键和「频道 + / −」，所以 §4.1 的数字输入和 §4.2 的七个固定频道只适用于 CMCC 这类带数字/频道键的遥控器。小米的频道这样用：按一次菜单进「频道」模式，▲▼ 就在网页「记忆频道」里保存的那几个之间换，到底回绕；再按一次菜单回到 VFO，▲▼ 又是普通步进。

频道回放是整条恢复：频率、模式一次到位（内部按「先频率 → 再模式 → 再补一次频率」发，中间跳过轮询，所以不会被电台的波段栈把模式改回去），不是先跳频率再补模式。遥控器没有屏幕，所以「现在在 VFO 还是频道」只能由下一次 ▲▼ 的行为看出来 —— 切模式本身不发命令、也不改频率，按错了不会丢掉频点。

5. 语音键与遥控器麦克风（ATVV，1.28.49 · FP45+）

小米蓝牙遥控器 2 / 2 Pro 的麦克风不是声卡，也不会在系统里多出录音设备。它走 Google 的 ATVV 蓝牙服务：

服务：AB5E0001-5A21-4F05-BC7D-AF01F617B664
  ...0002  写命令（MIC_OPEN 0C 00 / MIC_CLOSE 0D）
  ...0003  音频通知（120 字节 = 15 ms 的 16 kHz 单声道 IMA ADPCM）
  ...0004  控制通知（能力帧 0x0B / 流开始 0x04 / 同步 0x0A / 流结束 0x00）

型号与蓝牙版本：2 = RC001，2 Pro = RC003；两者都是 BLE 5.0（HOGP 按键 + ATVV 语音），不是经典蓝牙、也不是 LE Audio。ATVV 的 CAPS 版本是 0x0100（v1.0），音频 IMA ADPCM 16 kHz。

5.1 怎么用

  1. 先按 §2 配对，按方向键确认「按键可用」。
  2. 按住语音键，正常说话。电台会被 key 上去，遥控器的麦克风音频同时进发射链路。
  3. 松开语音键：停止发射、关闭麦克风。松手、掉线、服务停止都会 unkey，和网页 PTT 同一套保护；单次发射仍受 MRRC_PTT_MAX_TX_SECONDS（默认 120 秒）限制。

不需要 SSH，也不需要 root。没有 mrrc-remote-mic.service 的盒子（只做过网页热修）由服务端自己拉起守护进程，并把缺失的 bleak / dbus-fast 直接 pip install 进盒子自己的 venv；有 unit 的镜像继续由 unit 持有。两者用 /run/mrrc/remote-mic.lock 的 flock 单实例交棒：后到者阻塞等待，前者退出（unit stop / server restart）后自动接管，不会两个 ATVV 客户端同时推流，也不会让 Restart=always 进入重启循环。

5.2 链路

遥控器 ──蓝牙 HID──> 盒子内核 → mrrc-localctl（按键、PTT）→ 电台
      └─蓝牙 ATVV──> remote_mic.py（ADPCM → 48 kHz PCM）
                        │  /run/mrrc/mic.pcm（0600，和服务同一用户）
                        ▼
                  服务端 TX（盒级 tx_mic_db、录音 tap、feed_tx_audio）→ 电台

remote_mic.py 解码后写 48 kHz int16 PCM；服务端按 20 ms 切帧，走和浏览器麦克风同一条 _feed_tx_from_uplink 路径。没有配对遥控器时守护进程只等待，不占资源。

5.3 相关环境变量

变量默认作用
MRRC_REMOTE_MICautooff 关掉服务端兜底（有 unit 的盒子仍由 unit 跑）
MRRC_REMOTE_MIC_GAIN_DB12解码后的软件增益；服务端还会再叠加 tx_mic_db（默认 +10 dB）
MRRC_REMOTE_MIC_LOCK/run/mrrc/remote-mic.lock单实例锁路径
MRRC_MIC_SOCKET/run/mrrc/mic.pcmPCM socket 路径（两端要一致）

CMCC_Voice_Remote 不适用本节。它是讯飞 XFRCB22 方案：语音走 HID report 0xFC 的私有通知（3 条 16 B 拼成 48 B 帧，前 40 B 是 G.722.1 / Siren7 16 kbps 码流，还要按 0x0416 做解白化），不是 ATVV，也不是 IMA ADPCM。当前 remote_mic.py 只实现 ATVV，所以这只遥控器目前只能当按键遥控器；要做支持需要另写一条 HID/0xFC + G.722.1 的采集解码链。协议、解白化表和独立解码器见社区项目 jackielozet/cmcc-voice-remote-bridge；TheElderFrog/cmcc-sharjeck-voice-bridge 则是通过原厂讯飞服务桥接，不自己解码。

6. 音量：有 AF 增益调 AF，没有就调 RX 电平

音量键是能力驱动的，由服务端在状态行和每次回复里告诉守护进程：

  • 后端有 has_af_gain（Yaesu / Icom 等）：发 af_gain，每次 5 %，满格映射到 0–255 的最上沿；和以前一样。
  • 后端没有 AF 增益（SunSDR2DX）：发盒级 rx_db —— 就是网页上 🔊 Vol 那个值，范围 −20…+30 dB，每次 3 dB，可长按连发。网页和遥控器改的是同一个数。

电台切换/重连后能力位会跟着刷新；如果电台拒绝 af_gain，日志会写「此电台不支持 AF 增益（请用 🔊 Vol 音频电平）」，此时应走 rx_db。音乐/语音电平在服务端的音频链路里生效，不影响录音 tap 和 FT8 解码。

7. 换遥控器、自定义键位

按键和动作的对应关系在 local_ctl.py 的 DEFAULT_KEYMAP，一张「usage / keycode → 动作」的表。换遥控器的步骤：

  1. 先认出它发什么：evtest /dev/input/eventN，每个键会有 MSC_SCAN（usage，如 0x70052）和 keycode（如 103）。
  2. 在表里加一条，例如 "u:0x70052": "freq_up"；
  3. 不想改代码就写一份 JSON 覆盖文件，用环境变量指过去：
{ "u:0x70052": "freq_up", "u:0x70051": "freq_down" }
# /etc/systemd/system/mrrc-localctl.service.d/keymap.conf
[Service]
Environment=MRRC_LOCALCTL_KEYMAP=/opt/mrrc_modern/env/keymap.json

改完 systemctl daemon-reload && systemctl restart mrrc-localctl；它跑的是自己进程里的键位表，只重启 mrrc-modern 不会生效。

动作名含义动作名含义
ptt按住发射 / 松开停freq_up / freq_down按当前步进调频
step_up / step_down步进档位band_up / band_down固定频道
enter / cancel提交 / 取消数字mode_next模式循环
vol_up / vol_down音量（AF 或 RX，见 §6）level_up / level_down显式盒级 RX 电平（一般不用）
digit:0 … digit:9数字输入home / menu / aux / star / hash / power预留，暂无动作

设备匹配：MRRC_LOCALCTL_DEVICE 钉死 /dev/input/eventN；MRRC_LOCALCTL_MATCH 按名字子串（默认 Voice_Remote）；都不匹配时自动回落到「蓝牙总线 + EV_KEY」的第一台设备。配对名单用 MRRC_BT_REMOTE_NAME，扫描会同时走 BR/EDR 和 LE。

8. 排障

现象先看什么
按键完全没反应bluetoothctl info <地址> 是否 Paired: yes；/proc/bus/input/devices 有没有键盘节点；id mrrc 是否含 input；journalctl -u bluetooth -n 40 有没有 unlikely error（有就按 §2.1 重配）
只有部分键有用按键表按 usage 认键；用 evtest 看实际 usage，补 DEFAULT_KEYMAP 或 JSON 覆盖（§7）
按电源把盒子关了grep HandlePowerKey /etc/systemd/logind.conf 应为 ignore；不是就改掉再 systemctl restart systemd-logind
遥控器连上又断，反复BLE 遥控器空闲会自己断、按键时重连，正常；只要按键有效就不必管
Wi-Fi 偶尔卡一下这颗芯片蓝牙/Wi-Fi 共用 SDIO，连续操作遥控器时 Wi-Fi 可能短暂抖动，几秒自愈
服务没在跑systemctl status mrrc-localctl；日志 journalctl -u mrrc-localctl
语音键只 key 电台、没有声音有 unit：systemctl status mrrc-remote-mic、journalctl -u mrrc-remote-mic；没有 unit：grep "Remote mic" /opt/mrrc_modern/logs/server-stdout.log。应看到 connected / ATVV caps / voice session started
日志里有 installing bleak/dbus-fast服务端在自动补依赖，等 20–60 秒，装完打印 daemon started；失败每 5 分钟重试
看到两个 remote_mic.py 进程正常：unit 和服务端兜底各一个；后者打印 waiting for it，不推流。前者退出后它自动接管
音量键没反应确认电台连接；SunSDR 没有 AF 增益，音量键改的是网页 🔊 Vol 的 RX 电平，看网页滑块是否跟着动（§6）
更新卡没有 1.28.49 · FP45设置 → 软件更新 → 检查；清单 https://www.vlsc.net/mrrc_modern/downloads/latest.json。1.28.48 装 129 KB 热修，1.28.44–47 装整包

9. 架构与安全

遥控器 ──蓝牙 HID──> 盒子内核（/dev/input/eventN）
                      │
                      ▼
              mrrc-localctl（读按键、查表、PTT）
                      │  /run/mrrc/localctl.sock（0600，同用户即认证）
                      ▼
                 电台服务（和网页同一套命令）──> 电台

遥控器 ──蓝牙 ATVV──> remote_mic.py（ADPCM → 48 kHz PCM）
                      │  /run/mrrc/mic.pcm（0600）
                      ▼
                 服务端 TX（tx_mic_db、录音 tap、feed_tx_audio）──> 电台
  • 两条链路都只走本机（HID + Unix socket / 回环），不经过局域网、不经过云端；遥控器配在盒子上就只对这台盒子有效。
  • 本地 socket 的权限（0600、和服务器同一用户）就是认证——物理按键没有网页口令，也不需要登录。
  • PTT 保护：松开、遥控器掉线、守护进程收到 SIGTERM/SIGINT、控制链路断开，都会发 ptt:false；服务端另有单次发射上限。
  • 电源键已在 logind 层设为 ignore，不会把盒子关掉。
  • 没有配对遥控器时，mrrc-localctl 等待输入节点、remote_mic.py 等待锁/遥控器，两个守护进程都不占资源。
